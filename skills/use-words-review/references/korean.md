# 한국어 글과 문구 판정 기준

한국어가 포함된 결과물에서만 이 자료를 사용한다. 여러 언어가 섞인 결과물에서는 한국어 부분에만 적용한다. 후보 표현이 있다는 이유만으로 문장을 고치지 말고, 독자와 분야, 지칭 대상, 행동 주체, 행동, 조건과 결과를 확인해 판정한다.

해당 분야에서 확립된 용어이고 문장 안에서 뜻이 하나로 정해지면 `pass`로 판정한다. 문장이 불분명하지만 저장소 근거로 실제 행동이나 조건을 확인할 수 있으면 `needs revision`으로 판정한다. 뜻을 하나로 정할 근거가 없으면 단어를 임의로 바꾸지 않고 `needs human input`으로 판정한다.

## 직역과 번역체

영어를 낱말 단위로 옮기지 않는다. 원문이 가리키는 대상, 행동, 조건과 책임 주체를 확인한 뒤 한국어 문장을 새로 쓴다.

- `~에 대해서`, `~에 의해서`, `~에 있어서`, `~와의`를 빼도 뜻이 같으면 조사나 문장 구조를 바꾼다.
- `~에 의해서`처럼 행동 주체를 감추는 피동문은 실제 행동 주체를 주어로 삼는다.
- `~하지 않으면 안 된다`는 `~해야 한다`로, `회의를 가지다`는 `회의하다`나 `회의를 열다`로 쓴다.
- 영어식 무생물 주어, 명사만 이어 붙인 문장과 `사용자-facing` 같은 혼합 표기는 자연스러운 한국어로 다시 쓴다.
- 영어 기술 용어를 정해진 한국어 한 단어로 자동 변환하지 않는다. 문맥에 따라 실제 동작이나 조건을 드러낸다.

문제가 있는 문장:

> 이 계약은 두 모듈 사이의 경계를 좁혀 안정적인 지원을 보장합니다.

`contract`, `boundary`, `narrow`, `support`, `ensure`를 고정된 한국어 단어로 바꾸면 무엇이 달라지는지 알기 어렵다.

문맥을 드러낸 문장:

> 두 모듈이 주고받는 값의 형식을 정하고, 외부에서 사용할 수 있는 호출 방법을 줄여 잘못된 입력을 검사합니다.

법률 계약, 수학의 경계처럼 해당 분야에서 확립된 뜻을 가리킬 때는 `계약`, `경계`를 그대로 사용할 수 있다.

문제가 있는 문장:

> 본 기능은 다양한 측면에서 강력하고 효과적으로 원활한 경험을 제공합니다.

필요한 정보를 담은 문장:

> 연결이 끊기면 입력 내용을 브라우저에 보관하고, 다시 연결됐을 때 전송을 재개합니다.

수정문은 형용사를 바꾼 것이 아니라 독자가 알아야 할 동작과 조건을 적었다.

## 일반 산문의 U+00B7

일반 산문에서는 U+00B7을 사용하지 않는다. 병렬 관계는 쉼표와 조사로 나타내거나 문장을 나눈다. 이 규칙은 맞춤법의 정오 판정이 아니라, 일반 키보드로 반복해서 입력하고 고치기 쉬운 문장을 쓰기 위한 기준이다.

다음 경우에는 정확한 문자를 보존한다.

- 원문을 그대로 보여 주는 짧은 인용문
- 승인된 제품명, 화면 이름 또는 표준 표기
- 코드, 정규식과 문자 처리 검사
- 코드 포인트를 설명하는 최소 예시
- 평가할 원문 입력

문제가 있는 일반 산문:

> 설계·구현·검증 결과를 한 문서에 기록합니다.

- **판정:** `needs revision`
- **위치:** 병렬 항목 사이의 U+00B7 두 곳
- **고친 문장:** 설계, 구현과 검증 결과를 한 문서에 기록합니다.

정확한 문자 설명:

> 검사기는 U+00B7(·)을 찾는다.

- **판정:** `pass`
- **유지 근거:** 코드 포인트와 검사할 문자를 대응시키는 예시다.

승인 여부를 알 수 없는 이름:

> 화면에는 서비스·관리자라는 이름을 표시한다.

- **판정:** `needs human input`
- **빠진 정보:** 승인된 화면 이름을 인용한 것인지 새 산문을 작성한 것인지 알 수 없다.

문자를 발견했다는 이유로 자동 치환하지 않는다. 원문 보존 목적을 먼저 확인하고, 일반 산문으로 확인된 경우에만 고친다.

## 후보 용어를 판정하는 순서

후보 단어 목록은 검토 시작점을 제공할 뿐이다. `계약`, `경로`, `공개`, `좁히다`, `박다`, `지원하다`, `보장하다`, `다루다`, `노출하다`, `포착하다`, `정렬하다`, `표면화하다` 밖의 표현에도 같은 질문을 적용한다.

1. 해당 분야의 승인된 자료가 같은 뜻으로 사용하는 확립된 용어인가?
2. 문장이 지칭 대상과 행동 주체를 밝히는가?
3. 독자가 행동, 조건과 결과를 하나로 이해할 수 있는가?
4. 앞의 조건을 충족하지 못한다면 저장소 근거로 실제 행동이나 조건을 확인할 수 있는가?

처음 세 조건을 모두 충족하면 표현을 유지한다. 하나라도 충족하지 못했지만 마지막 질문의 근거가 있으면 실제 행동이나 조건을 적는다. 뜻을 정할 근거가 없으면 익숙해 보이는 대체어를 고르지 않고 확인을 요청한다.

## 행동 주체를 감추는 문장

문제가 있는 문장:

> 검토에 의해서 변경이 승인되도록 처리됩니다.

행동 주체와 조건을 드러낸 문장:

> 검수자가 변경 내용을 확인하고 승인 책임자가 배포를 승인하면 배포 담당자가 배포를 시작합니다.

피동문 자체를 일괄 금지하지 않는다. 행동 주체를 숨겨 독자가 책임과 조건을 알 수 없을 때 고친다.

## 의무나 규칙을 가리키는 계약

`계약`은 법률이나 거래에서 당사자가 지킬 의무를 정한 약속을 가리킬 때 유지한다. 소프트웨어 문서에서는 저장소가 인터페이스 계약, 이벤트 계약 또는 계약 기반 설계를 승인된 용어로 사용하고, 문장이 입력, 출력, 위반 조건이나 호환 조건을 밝힐 때 유지할 수 있다.

문제가 있는 문장:

> 두 모듈의 계약을 강화한다.

- **판정:** `needs human input`
- **빠진 정보:** 두 모듈이 지킬 입력, 출력, 오류 처리 또는 호환 조건이 없다.
- **독자에게 생기는 영향:** 개발자와 검수자는 무엇이 바뀌고 어떤 결과를 확인해야 하는지 알 수 없다.

규칙을 밝힌 문장:

> 주문 모듈은 주문 번호와 결제 상태를 문자열로 전달한다. 필드가 없으면 수신 모듈이 요청을 거부한다.

- **판정:** `pass`
- **확인 근거:** 전달할 값, 자료형, 위반 조건과 처리 결과가 드러난다.

법률 용례:

> 납품 계약은 양 당사자가 서명한 날부터 효력이 생긴다.

- **판정:** `pass`
- **유지 근거:** 당사자와 효력 조건을 설명하는 법률 계약이다.

## 위치나 절차를 가리키는 경로

`경로`는 파일이나 디렉터리 위치, URL 구성 요소 또는 네트워크에서 데이터가 전달되는 구간을 가리킬 때 유지한다. 방법, 절차, 선택지나 진행 순서를 뜻하면 실제 행동을 적는다.

문제가 있는 문장:

> 검수자는 시험 환경 접근 경로를 정리한다.

- **판정:** `needs human input`
- **위치:** `접근 경로를 정리한다`
- **빠진 정보:** 접속 주소, 접속 방법, 권한 신청 절차 가운데 무엇을 정하는지 알 수 없다.
- **독자에게 생기는 영향:** 개발자는 어떤 정보를 확인하거나 어떤 절차를 따라야 하는지 결정할 수 없다.

정확한 기술 용례:

> 설정 파일 경로는 `config/app.yml`이다.

- **판정:** `pass`
- **유지 근거:** `경로`가 파일의 저장소 내 위치를 가리킨다.

## 공개라는 표현이 가리키는 상태

`공개`는 암호 기술의 `공개 키`, 법률에 따른 `정보공개`처럼 고유한 기술 개념이나 행위를 구분할 때 유지한다. 단순히 인터넷에서 찾을 수 있거나 배포됐다는 뜻이면 누가 무엇을 찾고, 읽고, 내려받고, 수정할 수 있는지 적는다.

문제가 있는 문장:

> 외부 자료는 공개 저장소에서 확인한다.

- **판정:** `needs human input`
- **위치:** `공개 저장소`
- **빠진 정보:** 로그인 없이 읽을 수 있어야 하는지, 내려받거나 수정할 권한도 필요한지 알 수 없다.
- **독자에게 생기는 영향:** 조사자는 자료의 포함 조건을 같은 기준으로 적용할 수 없다.

독자가 확인할 상태를 적은 문장:

> 외부 자료는 한국어 문서가 있고 인터넷으로 배포되는 소프트웨어 저장소에서 확인한다.

- **판정:** `pass`
- **확인 근거:** 필요한 자료의 언어와 배포 형태가 드러난다.

제품에서 정한 명칭을 쓴 문장:

> GitHub 프로필의 `고정됨` 섹션은 공개 저장소를 최대 여섯 개까지 보여 준다. 여기서 공개 저장소는 별도의 읽기 권한 없이 누구나 코드를 볼 수 있는 저장소를 가리킨다.

- **판정:** `pass`
- **유지 근거:** 제품 기능에서 사용하는 명칭과 누구에게 읽기 권한이 있는지가 함께 드러난다.
- **용어 근거:** [GitHub 프로필 기여 문서](https://docs.github.com/ko/account-and-profile/concepts/contributions-on-your-profile)는 `고정됨` 섹션에서 `공개 저장소`라는 표현을 사용한다.
- **열람 조건 근거:** [GitHub 리포지토리 표시 유형 문서](https://docs.github.com/ko/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)는 퍼블릭 상태의 코드를 모든 사용자가 볼 수 있다고 설명한다.

`공개 API`와 `공개 미리 보기`는 제공 기관의 한국어 문서가 그 명칭을 쓴다는 이유만으로 통과시키지 않는다. API를 호출할 수 있는 대상과 인증 조건, 미리 보기에 참여할 수 있는 대상과 정식 출시 전 조건을 문맥에서 확인한다.

## 대상이나 조건을 줄이는 좁히다

`좁히다`는 폭이나 면적을 줄이는 기본 뜻, 후보 수나 기간처럼 줄이기 전과 후를 비교할 수 있는 경우에 유지한다. 저장소가 `타입 좁히기`처럼 분야 용어를 채택했다면 판정 대상과 결과가 드러나는 문장에서도 유지할 수 있다.

문제가 있는 문장:

> 기능 범위를 좁혀 품질을 보장한다.

- **판정:** `needs human input`
- **빠진 정보:** 제외할 기능, 남길 기능, 품질 판정 기준과 관찰할 결과가 없다.
- **독자에게 생기는 영향:** 구현 담당자는 만들 기능을 정할 수 없고 검수자는 완료 여부를 판정할 수 없다.

대상과 결과를 밝힌 문장:

> 첫 배포에서는 파일 업로드와 검색만 제공한다. 공유와 알림은 다음 배포에서 다시 검토한다.

- **판정:** `pass`
- **확인 근거:** 이번 배포에 남길 기능과 제외할 기능이 드러난다.

## 서로 다른 동작을 감추는 박다

`박다`는 물체를 두드려 꽂는 실제 동작, 승인된 인용문이나 정확한 이름에서 유지한다. 기술 문서의 `값을 박다`, `규칙을 박다`, `문구를 박다`는 실제 동작이 서로 다르므로 검토 후보로 삼는다.

문제가 있는 문장:

> 기본 주소를 코드에 박는다.

- **판정:** `needs human input`
- **빠진 정보:** 주소를 리터럴, 상수, 빌드 값 또는 설정 가운데 어디에 둘지 알 수 없다.
- **독자에게 생기는 영향:** 개발자는 값을 저장할 위치와 배포별 변경 방법을 정할 수 없다.

행동을 밝힌 문장:

> 기본 주소는 배포 환경의 `SERVICE_URL` 환경 변수에서 읽는다.

- **판정:** `pass`
- **확인 근거:** 값의 출처와 실행 환경별 변경 방법이 드러난다.

## 분야와 판정 대상이 필요한 전문용어

`범위`, `경계`, `루브릭`, `유효성`, `정합성`과 `가시성`은 분야와 판정 대상이 분명해 정확한 뜻을 가질 때 유지한다.

문제가 있는 문장:

> 범위와 경계를 맞춰 계약의 유효성, 데이터 정합성, 화면 가시성과 루브릭을 확인한다.

- **판정:** `needs human input`
- **위치:** `범위와 경계`, `계약의 유효성`, `데이터 정합성`, `화면 가시성과 루브릭`
- **빠진 정보:** 무엇의 적용 범위인지, 어떤 규칙이나 값을 어떤 기준으로 확인하는지 적혀 있지 않다.
- **독자에게 생기는 영향:** 검수자는 확인할 대상과 통과 조건을 정할 수 없다.

정확한 전문용례:

- **수학:** 도형의 경계에 포함된 점을 별도로 표시한다.
- **데이터:** 두 테이블의 주문 식별자가 일치하는지 비교해 데이터 정합성을 확인한다.
- **교육:** 채점 루브릭은 답안의 정확성, 근거와 설명을 각각 평가한다.
- **제품 설정:** Power Pages 사이트 가시성을 `공개`로 바꾸면 링크를 아는 모든 인터넷 사용자가 페이지를 볼 수 있다.

각 문장은 분야, 판정 대상과 확인 조건이 드러나므로 `pass`다.

## 행동을 대신하기 쉬운 동사

`지원`, `보장`, `대응`, `다루다`, `노출`, `포착`, `정렬`과 `표면화`가 실제 행동, 책임이나 조건을 감추는지 확인한다. 대상과 행동이 분명한 전문용례는 유지한다.

문제가 있는 문장:

> 새 기능은 오류에 대응하고 여러 형식을 지원해 결과를 보장한다.

- **판정:** `needs human input`
- **위치:** `대응하고`, `지원해`, `보장한다`
- **빠진 정보:** 어떤 오류를 어떻게 처리하는지, 허용하는 형식과 보장하는 결과가 무엇인지 알 수 없다.
- **독자에게 생기는 영향:** 사용자는 허용되는 입력과 실패했을 때의 동작을 예측할 수 없다.

행동과 조건을 적은 문장:

> 변환기는 JSON과 CSV 파일을 읽는다. 필수 열이 없으면 파일 이름과 빠진 열을 오류 메시지에 표시하고 변환을 중단한다.

- **판정:** `pass`
- **확인 근거:** 허용 형식, 오류 조건과 처리 결과가 드러난다.

보안 문서의 `개인정보 노출`, 카메라가 움직임을 감지한 순간의 `포착`, 화면 요소의 `정렬`처럼 대상과 동작이 분명하면 해당 표현을 유지한다. `다루다`나 `표면화하다`가 주제나 동작을 대신하면 실제로 설명하거나 표시할 내용을 적는다.

## 정보를 더하지 않는 평가 표현

`핵심`, `효과적`, `원활`, `강력`, `견고`, `포괄적`, `다양한`과 `본질적`은 삭제했을 때 사실, 조건이나 독자가 해야 할 일이 달라지는지 확인한다. 저장소 근거로 실제 행동이나 조건을 확인할 수 있으면 `needs revision`으로 판정하고 구체적으로 다시 쓴다. 정확한 뜻과 행동을 정할 근거가 없으면 수식어만 지워 제품 동작을 추측하지 않고 `needs human input`으로 판정한다.

문제가 있는 문장:

> 핵심 기능이 다양한 상황에서 강력하고 견고하며 원활한 결과를 제공한다.

- **판정:** `needs human input`
- **위치:** `핵심`, `다양한`, `강력하고 견고하며 원활한`
- **빠진 정보:** 적용되는 상황, 실제 동작과 측정 결과가 없다.
- **독자에게 생기는 영향:** 사용자는 기능이 해결하는 문제나 제한을 알 수 없다.

측정 결과를 적은 문장:

> 연결이 끊기면 입력 내용을 브라우저에 저장하고, 다시 연결된 뒤 한 번만 전송한다.

- **판정:** `pass`
- **확인 근거:** 조건, 저장 위치와 재전송 횟수가 드러난다.

## 내용과 무관하게 반복하는 글의 짜임

도입, 소제목 수, 목록 수, 문단 길이와 결론을 실제 내용에 따라 정한다. 다음 형태가 반복되면 독자가 새 정보를 얻는지 확인한다.

- `핵심은 다음과 같습니다`처럼 뒤의 내용을 예고할 뿐인 도입
- 실제 관계와 무관하게 만든 세 항목
- 소제목마다 같은 길이로 반복하는 문단
- 앞의 답을 다시 말할 뿐인 결론과 요약
- 문단마다 반복하는 같은 연결 표현

문제가 있는 구조:

> 핵심은 세 가지입니다.

이 도입 뒤에 근거 없이 같은 길이의 항목 세 개를 만들고, 끝에서 같은 내용을 다시 요약하면 `needs revision`이다. 도입과 결론을 지우고 실제로 필요한 문장과 항목만 남긴다.

항목이 실제로 세 부분이고 각 항목이 서로 다른 조건이나 행동을 설명한다면 세 항목을 유지할 수 있다. 숫자나 문단 길이만으로 판정하지 않는다.

## 대상을 알 수 없는 지칭 표현

`해당`, `관련`, `이 내용`, `결과`, `출력`, `데이터`, `기능`과 `범위`가 가까운 문장에서 하나의 대상을 가리키는지 확인한다.

문제가 있는 문장:

> 관련 데이터를 확인한 뒤 해당 기능의 결과를 출력한다.

- **판정:** `needs human input`
- **위치:** `관련 데이터`, `해당 기능`, `결과`
- **빠진 정보:** 확인할 값, 실행할 기능과 출력할 내용이 정해져 있지 않다.
- **독자에게 생기는 영향:** 개발자는 입력과 출력의 관계를 구현할 수 없고 검수자는 완료 여부를 확인할 수 없다.

대상을 밝힌 문장:

> 변환기는 주문 파일의 `total` 열을 합산하고 합계를 표준 출력에 기록한다.

- **판정:** `pass`
- **확인 근거:** 입력 데이터, 실행할 계산과 출력 위치가 드러난다.
