# 화면과 매체별 내용 배치 검토

서비스의 기능과 이용 시나리오를 기준으로 화면과 UI 요소를 제안한다. 기존 화면에서 빠지거나 중복된 요소와 불필요한 안내 문구를 찾는다. 슬라이드와 문서는 [내용 배치](#슬라이드와-문서의-내용-배치)을 적용한다.

## 대상 서비스와 현재 상태 확인

- 사용자 요청과 프로젝트 문서에서 대상 서비스, 사용자 유형과 권한, 지원 환경, 검토할 기능이나 화면을 식별한다. 모노레포에서는 서비스별 요구사항과 설계 결정을 구분한다.
- 기존 UI는 요구사항과 대조한다. 실행 화면에서 관찰한 동작, 코드에서 확인한 동작, 스크린샷에서 확인한 요소와 배치를 구분한다.
- 특정 화면이나 기능을 검토할 때는 진입과 복귀 경로, 화면 상태, 공유 컴포넌트가 구성안에 미치는 영향을 확인한다. 요구사항이 바뀌면 영향을 받는 화면과 요소를 다시 검토한다.

## 필요한 화면 조사

1. 사용자 유형별로 기능을 시작하는 조건, 주요 판단과 조작, 완료 시 확인할 정보를 파악한다. 권한이나 실행 결과에 따라 달라지는 경로도 확인한다.
2. 필요한 정보와 조작을 독립 페이지, 기존 화면의 영역이나 상태, 대화상자 중 어디에서 제공할지 비교한다. 별도 진입이나 재방문, 현재 정보와 선택 유지, 별도 확인이 필요한지를 기준으로 결정한다.
3. 유사 서비스의 실행 화면과 공식 도움말, 대상 플랫폼의 디자인 지침을 조사한다. 사례의 요소와 표시 조건을 프로젝트 요구사항에 대조해 적용 여부를 판단한다.

## 기기와 이용 환경별 화면 구성

지원 기기나 이용 환경에 따라 화면 구성 또는 조작 방식이 달라지는 경우에 적용한다.

- 지원 환경마다 사용자가 완료해야 할 시나리오를 확인한다. 창 크기, 화면 방향, 접힘 상태, 입력 방식에 따라 어떤 조작 단계가 달라지는지 확인한다.
- 환경별 정보 우선순위, 가능한 조작, 탐색과 화면 전환을 정한다. 예를 들어 목록과 상세를 함께 표시할지, 상세에서 목록으로 어떻게 돌아갈지 결정한다. 제공 기능이 환경마다 다르면 완료할 수 있는 시나리오와 차이가 생기는 이유를 명시한다.
- 창 크기나 기기 자세가 바뀌거나 이전 화면으로 돌아올 때 유지할 선택 항목, 입력값, 스크롤 위치를 정한다.

## 화면별 UI 요소 구성

특정 요소를 검토할 때는 요청받은 결정에 영향을 주는 단계만 적용한다.

1. **요소의 역할과 조작 대상을 정한다.** 먼저 볼 정보, 입력할 값, 이동할 곳, 실행할 조작과 그 결과를 식별한다. 조작이 필드, 항목, 설정 그룹, 화면 전체 중 어디에 적용되는지 확인한다.
2. **표시 조건과 상태를 정한다.** 어떤 입력이나 선택이 다른 요소를 표시하거나 활성화하는지, 변경이 언제 적용되는지 확인한다. 처리 중, 결과 없음, 실패, 권한 제한이 다음 조작을 바꾸면 표시할 정보와 가능한 조작을 정한다.
3. **컴포넌트를 선택한다.** 요소의 역할, 입력값의 형식, 선택지 수와 동시 비교 필요성, 변경 적용 시점, 기기의 입력 방식, 접근성 요구사항에 따라 후보를 비교한다.
4. **시각적 표현과 접근성 정보를 정한다.** 디자인 시스템과 정보 및 조작의 우선순위에 따라 레이블, 아이콘, 배경, 테두리, 상태 표시를 선택한다. 각 조작 요소의 접근 가능한 이름과 역할, 보조 기술에 전달할 상태를 명시한다. 구현 검토 시 실제 제공 여부를 확인한다.
5. **요소를 묶고 순서를 정한다.** 조작 요소와 적용 대상, 선택 요소와 조건부 입력처럼 함께 확인할 요소를 묶는다. 정보의 관계와 조작 순서가 읽기 순서와 키보드 초점 순서에 드러나도록 배치한다. 실행 화면에서는 키보드로 초점 순서를 확인한다.
6. **화면 전체를 구성한다.** 비교할 정보와 항목 간 관계에 맞춰 표, 목록 등의 표시 형식을 선택한다. 요소 그룹을 배치하고 동시에 표시할 영역과 화면 전환이 필요한 영역을 구분한다. 배치안이 여럿이면 같은 요구사항을 기준으로 처음 보이는 정보, 주요 조작의 위치, 상태 표시를 비교한다.

## 표시 문구의 필요성 검토

- 문구가 없으면 사용자가 알 수 없는 조작의 이름, 입력 형식, 현재 상태, 오류 원인과 해결 방법을 식별한다.
- 화면 제목, 레이블, 조작 요소의 이름, 기존 상태 표시로 전달되는 내용을 반복하는 안내는 제외한다. 입력에 필요한 레이블과 지침은 유지한다.
- 문구가 필요한 상태에서만 표시한다. 예를 들어 입력 오류의 원인과 수정 방법은 해당 필드 가까이에 표시하고 필드에 연결한다.

## 패널의 타이포그래피와 간격

- 제목, 본문, 레이블, 보조 정보의 위계와 읽기 순서에 따라 글자 크기, 굵기, 행간을 제안한다.
- 함께 읽을 요소 사이의 간격, 그룹 사이의 간격, 패널 안쪽 여백을 각각 정한다.
- 프로젝트에 타이포그래피와 간격 토큰이 있으면 적용할 토큰을 명시한다. 기준이 없고 수치가 필요하면 제안값과 적용 조건을 제시한다. 긴 문구, 텍스트 확대, 가장 좁은 지원 화면에서 줄바꿈이나 잘림이 읽기와 조작에 지장을 주는지 확인한다.

## 서비스 전반의 톤 앤 매너 검토

실행 화면이나 시안의 색상, 타이포그래피, 여백을 브랜드 지침이나 디자인 시스템과 대조한다. 같은 역할의 요소가 화면마다 일관되게 표현되는지 확인한다.

## 참고 사이트와 이미지에서 디자인 규칙 도출

참고 자료에서 디자인 규칙을 도출하거나 적용 가능성을 검토해 달라는 요청에 적용한다.

### 자료별 확인 범위

- **이미지.** 배치, 정렬, 시각적 위계, 상대적 크기와 간격을 확인한다. 여러 이미지에서 반복되는 표현과 상태별 차이를 비교한다. 화면 전환 조건, 원본 CSS 값과 디자인 토큰은 이미지로 확인할 수 없는 항목으로 표시한다.
- **실행 사이트.** 화면, 창 크기, 상태와 직접 확인한 조작을 기록한다. 계산된 스타일은 브라우저에서, 원본 선언과 디자인 토큰은 적용된 스타일 규칙과 변수 정의에서 확인한다. 접근하지 못한 화면과 재현하지 않은 상태의 동작은 미확인으로 표시한다.
- **원본 디자인 파일.** 열람할 수 있는 레이어 속성, 간격, 컴포넌트, 변수와 프로토타입 동작을 확인한다. 구현 여부와 실제 동작은 실행 사이트나 코드에서 확인한다.

### 미확인 항목과 규칙 제안

1. 규칙의 적용 여부나 수치를 정하는 데 필요한 정보가 없어서 후보를 비교할 수 없으면, 확인할 항목과 필요한 자료를 요청한다.
2. 후보를 비교할 수 있거나 추가 자료를 확보할 수 없으면, 확인한 범위에서 선택지를 제시한다. 선택지마다 근거, 판단 과정, 가정과 적용 조건을 설명한다.
3. 관찰한 특징과 제안할 규칙을 구분한다. 각 규칙의 적용 대상, 조건, 예외와 구현 후 대조할 화면 및 상태를 명시한다.

## 제안 및 검토 결과

- 기존 화면이나 자료에서 확인한 내용과 추가, 변경, 삭제를 제안하는 내용을 구분한다. 제안별로 적용 조건과 근거가 되는 요구사항, 화면 관찰, 공식 지침이나 사례를 제시한다.
- 확인하지 못한 정보에 따라 결론이 달라지면 필요한 정보와 영향을 받는 제안을 명시한다.

## 슬라이드와 문서의 내용 배치

슬라이드나 문서의 내용 배치를 요청받았을 때만 적용한다.

1. 독자, 열람 목적, 열람 환경을 확인한다. 슬라이드는 발표와 함께 보는지 발표 없이 읽는지, 문서는 순서대로 읽는지 필요한 정보를 찾아보는지 확인한다.
2. 먼저 읽을 정보, 비교할 정보, 보충 설명을 구분한다. 같은 목적과 매체의 공식 지침과 사례에서 제목 계층, 페이지와 문단의 구분, 표와 그림의 위치를 조사한다.
3. 슬라이드는 장별 정보량과 제목, 본문, 도표의 배치를 제안한다. 문서는 제목 계층과 페이지 및 문단의 구성, 표와 그림 및 그 설명의 위치를 제안한다. 시각적 읽기 순서와 보조 기술의 탐색 순서에서 정보 위계가 유지되는지 확인한다.
