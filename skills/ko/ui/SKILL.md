# 화면과 매체별 내용 배치 검토

서비스 기능과 이용 시나리오를 기준으로 필요한 화면과 UI 요소를 제안한다. 기존 화면에서는 요구사항을 충족하는지 확인하고 누락되거나 중복된 요소와 불필요한 안내 문구를 식별한다. 슬라이드와 문서를 검토할 때는 [슬라이드와 문서의 내용 배치](#슬라이드와-문서의-내용-배치) 절을 적용한다.

## 대상 서비스와 현재 상태 확인

- 요청과 관련 프로젝트 자료에서 대상 서비스, 사용자 유형과 권한, 지원 환경, 검토할 기능이나 화면을 확인한다. 모노레포에서는 서비스별로 적용되는 요구사항과 설계 결정을 확인한다.
- 기존 UI는 요구사항과 대조한다. 실행 화면에서 관찰한 동작, 코드에서 확인한 동작, 스크린샷에서 확인한 요소와 배치를 구분한다.
- 특정 화면이나 기능을 검토할 때는 화면 상태, 진입 및 복귀 경로, 다른 화면과 공유하는 컴포넌트가 UI에 미치는 영향을 확인한다. 요구사항이 갱신되면 영향을 받는 화면과 요소를 다시 검토한다.

## 필요한 화면 조사

1. 사용자 유형별 이용 시나리오에서 기능의 시작 조건, 주요 판단과 조작, 완료 시 확인할 정보를 식별한다. 권한이나 실행 결과에 따라 이동 경로가 달라지는 경우도 포함한다.
2. 각 단계에 필요한 정보와 조작을 기준으로 독립 페이지, 기존 화면의 영역이나 상태, 대화상자를 비교한다. 독립 진입이나 재방문 가능성, 현재 화면의 정보와 선택 유지, 별도 확인의 필요성에 따라 화면을 분리하거나 통합한다.
3. 유사한 시나리오를 제공하는 서비스의 실행 화면과 공식 도움말, 대상 플랫폼의 디자인 지침을 조사한다. 자료에서 확인한 요소와 표시 조건을 프로젝트의 요구사항에 대조해 적용 여부를 판단한다.

## 기기와 이용 환경별 화면 구성

지원 기기나 이용 환경에 따라 화면 구성 또는 조작 방식이 달라지는 경우에 적용한다.

- 지원하는 환경별로 사용자가 완료할 시나리오를 확인한다. 데스크톱, 태블릿, 스마트폰, 폴더블, 웨어러블 등 대상 기기의 창 크기, 화면 방향, 접힘 상태와 입력 방식에 따라 달라지는 조작 단계를 식별한다.
- 각 환경에서 먼저 표시할 정보, 사용 가능한 조작, 탐색 방식과 화면 전환을 결정한다. 목록과 상세의 동시 표시 여부, 상세에 진입하고 돌아오는 방식, 보조 정보의 표시 위치를 시나리오에 따라 비교한다. 시나리오를 완료하는 데 필요한 기능과 정보가 구성안에 포함되는지 확인한다.
- 창 크기나 기기 자세가 바뀌거나 이전 화면으로 복귀할 때 유지해야 할 선택 항목, 입력값과 스크롤 위치를 식별한다. 환경마다 제공하는 기능이 달라지면 각 환경에서 완료할 수 있는 시나리오와 그 차이의 이유를 명시한다.

## 화면별 UI 요소 구성

1. **UI 요소의 역할과 조작 대상을 식별한다.** 화면에서 먼저 확인할 정보, 입력할 값, 실행하거나 이동할 대상, 조작 후 확인할 결과를 명시한다. 조작이 필드, 항목, 설정 그룹, 화면 전체 중 어디에 적용되는지 확인한다.
2. **표시 조건과 요소 간 의존 관계를 확인한다.** 다른 요소를 표시하거나 활성화하는 입력과 선택, 변경이 적용되는 시점을 식별한다. 처리 중, 결과 없음, 실패, 권한 제한 중 다음 조작에 영향을 주는 상태에서 표시할 정보와 가능한 조작을 결정한다.
3. **컴포넌트와 표현 방식을 선택한다.** 정보 열람, 값 입력, 항목 선택, 이동, 기능 실행, 상태 확인 등 요소의 역할에 맞는 후보를 비교한다. 입력 형식, 선택지의 수와 비교 필요성, 상태 변경 방식, 대상 기기의 입력 방식과 접근성 요구사항을 판단 기준으로 사용한다. 정보와 조작의 우선순위, 사용자가 요소의 의미와 상태를 구별할 수 있는지, 프로젝트 디자인 시스템의 규칙을 기준으로 레이블, 아이콘, 배경과 테두리의 사용 여부를 결정한다. 텍스트 레이블을 표시하지 않는 조작 요소에는 접근 가능한 이름을 확인한다.
4. **요소의 상대적 위치와 화면 배치를 결정한다.** 레이블과 입력 필드, 선택 요소와 조건부 입력, 조작 요소와 적용 대상처럼 함께 확인해야 하는 요소를 묶는다. 정보와 조작의 선후 관계가 읽기 순서와 키보드 탐색 순서에 반영되는지 확인한다. 비교할 정보와 항목 간 관계에 따라 표, 리스트, 그리드와 패널을 선택한다. 배치안이 여럿이면 동일한 요구사항에서 정보 우선순위, 주요 조작의 위치, 상태 표시가 어떻게 달라지는지 비교한다.

## 표시 문구의 필요성 검토

- 문구가 어떤 요소를 설명하거나 어떤 상태를 전달하는지 확인한다. 조작의 이름, 입력 형식, 현재 상태, 오류 원인이나 해결 방법처럼 문구를 생략했을 때 사용자가 확인할 수 없게 되는 정보를 명시한다.
- 화면 제목, 레이블, 버튼 이름, 기존 상태 표시로 전달되는 내용을 반복하는 안내는 제외한다. 입력에 필요한 레이블과 지침, 접근성에 필요한 이름은 유지한다.
- 특정 조건에서만 필요한 문구는 그 조건이 충족될 때 표시하도록 제안한다. 예를 들어 입력 오류가 발생한 이유와 수정 방법은 오류가 발생한 필드 가까이에 표시하고 필드와 연결한다.

## 패널의 타이포그래피와 간격

특정 패널의 글자 크기나 간격을 검토할 때 적용한다.

- 패널 제목, 본문, 입력 레이블, 보조 정보의 역할과 읽기 순서를 식별한다. 각 역할에 적용할 글자 크기, 굵기와 행간을 제안한다.
- 레이블과 입력처럼 함께 읽는 요소 사이의 간격, 그룹 사이의 간격, 패널 안쪽 여백을 구분한다. 중첩된 그룹과 나란히 배치된 영역은 어떤 정보가 같은 단위로 읽혀야 하는지에 따라 간격을 결정한다.
- 프로젝트에서 정의한 타이포그래피와 간격 토큰이 있으면 적용할 토큰을 명시한다. 기준이 없고 수치가 필요하면 제안값과 적용 조건을 제시한다. 긴 문구, 텍스트 확대, 가장 좁은 지원 화면에서 줄바꿈이나 잘림이 정보 위계와 조작에 영향을 주는지 확인한다.

## 서비스 전반의 톤 앤 매너 검토

톤 앤 매너를 검토할 때는 실행 화면이나 제공된 시안에서 색상, 타이포그래피, 여백 등 화면 간에 반복되는 시각적 표현을 확인한다. 프로젝트의 브랜드 지침이나 디자인 시스템과 대조하고, 같은 역할의 요소에 표현 규칙이 일관되게 적용되는지 검토한다. 설계 방향을 조사할 때는 참고 화면에서 적용할 표현과 그 이유를 설명한다.

## 제안 및 검토 결과

- 검토 대상의 구성안과 적용 조건, 선택 이유를 제시한다. 기존 화면이나 자료를 검토했다면 확인한 내용과 추가, 변경 또는 삭제를 제안하는 내용을 구분한다.
- 제안을 뒷받침하는 요구사항, 관찰한 화면이나 동작, 참고한 공식 지침이나 사례를 제시한다. 자료에서 확인한 사실과 제안을 구분하고, 확인하지 못한 정보에 따라 결론이 달라지면 필요한 정보와 영향을 받는 제안을 명시한다.

## 슬라이드와 문서의 내용 배치

**명시적인 요청이 발생했을 때에만 수행한다.**

1. 독자, 매체, 열람 환경과 목적을 확인한다. 슬라이드는 발표와 함께 보는지 독립적으로 읽는지 구분한다. 문서는 순서대로 읽는지 특정 정보를 찾아보는지 확인한다.
2. 먼저 읽을 정보, 비교할 정보, 보충 설명을 식별한다. 목적과 매체가 유사한 공식 지침과 실제 사례에서 제목 계층, 표와 그림을 본문에 배치하는 방식, 장이나 절을 구분하는 기준을 조사한다.
3. 슬라이드는 전달 순서에 따라 장별 정보량과 제목, 본문, 도표의 배치를 제안한다. 문서는 제목 계층과 절의 구성, 표와 그림을 설명하는 본문의 위치를 제안한다. 시각적 읽기 순서와 보조 기술의 탐색 순서에서 정보의 위계와 순서가 유지되는지 확인한다.
