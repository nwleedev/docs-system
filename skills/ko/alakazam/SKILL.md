## 스킬 생성

- 지정된 이름을 그대로 사용한다. 이름 없이 설명만 주어지면 핵심 기능을 나타내는 이름을 정한다. 이름은 1~64자의 영문 소문자, 숫자, 하이픈으로 구성하며, 하이픈을 연속으로 쓰거나 양 끝에 두지 않는다. 지정된 이름이 규격에 맞지 않으면 수정 후보를 제시한다.
- 설명에는 수행할 작업과 적용 상황을 담는다. 이름만으로 용도를 파악할 수 있으면 설명을 작성한다. 용도가 모호하면 생성 전에 용도를 확인한다.
- 이 스킬 디렉터리의 `scripts/create.mjs`를 Node.js로 실행한다. 아래 명령의 스크립트 위치는 이 파일의 위치를 기준으로 해석한다. 별도의 출력 위치가 지정되면 `--output-dir`로 전달한다. 레포 전용 생성 요청에는 해당 레포의 `.agents/skills`를 지정한다.
- 이 스킬로 다른 스킬을 구성할 때 표를 사용하지 않는다.

```sh
node scripts/create.mjs --name code-review --description '작성한 코드를 리뷰한다.'
```

- 생성 결과의 `SKILL.md`에는 `name`과 `description`만 포함한다. `scripts/`, `references/`, `assets/`는 빈 디렉터리로 생성한다. 실행 결과에서 생성된 파일의 위치 & 실패 원인을 확인한다.

## 지침 검토

- 입력된 지침이나 지정된 `SKILL.md`를 읽고 스킬의 목적과 의도, 적용 방식, 규칙 간 충돌, 누락된 조건을 체크한다.
- 구조상 문제가 있는 부분과 내용에 맞는 재구성 방안을 제시한다. 추가할 지침이 있으면 필요한 상황과 문구 후보를 제시한다. 인물이나 역할을 지칭하지 않고 무엇을 해야 하는지를 직접 작성한다.
- 검토나 제안 요청에는 검토 결과만 제시한다.
- 명시적인 수정 요청이 발생할 때에만 스킬을 수정한다.

## 지침 재작성

- 재구성을 요청하면 지침 사이의 관계를 파악하고 그에 맞는 구조로 재작성한다. 순서에 의존하는 작업은 단계로 구성한다. 입력이나 요청 유형에 따라 동작이 달라지는 부분은 분기로 구성한다. 공통 규칙과 개별 예외의 적용 범위가 드러나도록 정리한다.
- 존재하지 않는 내용을 임의로 작성하지 않는다. 누락된 규칙이 있다고 판단되면 제안한다.
- 구조에 맞춰 제목을 새로 붙이고 문장이나 목록을 나누거나 합칠 수 있다. 원문의 용어, 어조, 종결 표현을 가능한 한 살리고 문맥에 필요한 표현을 다듬어야 한다. 기존 메타데이터, 명령어, 파일 위치, 인용문은 보존한다.
- 적용 대상, 조건, 예외, 우선순위를 보존한다. 필수, 권장, 허용, 금지해야 할 사항을 구분하고 각 지침을 적용해야 하는 조건을 보존한다.
- 중복은 의미와 적용 범위가 같을 때 통합한다. 충돌이 발생할 때 충돌 사항을 해결할 기준은 별도로 제안한다.
- 파일에 반영해 달라는 요청은 지정된 파일에만 적용하고, 초안 요청에는 재작성한 본문을 제시한다.
- 재작성 전후를 스킬 지침을 비교하여 내용적 의미가 유지되었는지를 확인한다. AI 편향이 발생하는 것을 방지하기 위해 스킬을 직접 실행시키지 않는다.
