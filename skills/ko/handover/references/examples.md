# 인수인계할 정보와 원본에 보존할 정보의 사례

다음 인용문은 정보의 용도를 비교하기 위한 예문이다.

## 사용자가 행동하거나 판단하는 위치에 남길 안내

**버튼 위에 반복된 저장 안내.** `저장 후 계속` 버튼이 입력값을 저장한 뒤 다음 화면을 연다면 “아래 버튼을 누르면 입력한 내용을 저장하고 다음 단계로 이동합니다”는 생략한다. 별도의 예외나 후속 확인 사항이 없으면 인수인계 기록에도 추가하지 않는다. 저장 없이 다음 화면만 여는 버튼이라면 `계속`으로 표시한다.

**점수 입력 화면의 자동 저장 안내.** 점수를 변경하면 자동으로 저장되는 화면을 가정한다. 입력란에서 저장 중인 상태와 성공 또는 실패를 구분할 수 있다면 “점수는 바꿀 때마다 저장됩니다.”라는 상시 안내는 생략할 수 있다. 저장 버튼도 상태 표시도 없어 사용자가 별도로 저장해야 하는지 판단하기 어렵다면 입력란에 자동 저장 방식을 안내한다. “저장됨”은 이번 변경의 저장 성공을 확인한 경우에만 표시한다.

다음 AI가 이 화면을 수정할 때 저장 시점을 알아야 하면 인수인계 기록에 저장 조건과 이를 구현한 코드의 위치를 기록한다.

**장식 이미지와 대피 안내도의 대체 텍스트.** 화면 배경으로만 사용하는 이미지에 “파스텔 색상의 친근한 분위기로 생성한 배경”이라는 제작 지시를 대체 텍스트로 입력한 경우다. HTML의 장식용 이미지에는 `alt=""`를 지정해 화면 낭독기가 건너뛰게 한다. 대피 안내도라면 이미지가 전달하는 출구 위치와 이동 방향을 텍스트로 제공한다. 다음 AI가 배경을 같은 방식으로 다시 제작해야 할 때만 확인된 색상이나 제작 조건을 인수인계한다.

**화면 시연과 사용자 도움말.** "Submit an empty form to inspect the error state, then close the dialog with X."가 시안 검토용 메모라면 시안의 인수인계 기록으로 이관할 수 있다.

양식의 입력 안내 "Enter the date as YYYY-MM-DD."와 오류 안내 "Enter an email address."는 양식에 표시한다. 대화상자를 닫는 절차도 튜토리얼의 주제라면 보존한다. 정렬 방법을 설명하는 문구는 화면의 정렬 요건일 수 있으므로 용도를 확인한다.

**코드 주석과 운영 절차.** "I added retries in this task"는 작성 이력이다. "The request body must be replayable for a retry"는 재시도할 때 호출자가 충족해야 하는 조건이다. 코드만으로 확인하기 어려운 조건이라면 유지보수자가 참조할 수 있도록 코드 옆에 보존한다.

"The next maintainer should check deployment"는 인수인계 메모일 수 있다. "Verify the backup before applying the migration"는 마이그레이션의 선행 조건이므로 운영 지침에 유지한다. 데이터 손실과 보안 경고도 해당 절차 옆에 표시한다.

## 요청한 문서와 실제 완료한 행동에 따라 구별할 내용

**번역문과 번역 검토서.** 행사 안내 번역문에 “이 인사말은 이전 번역을 참고해 자연스럽게 조정했습니다”라는 문장이 포함돼 있다. 참가자용 안내에는 번역한 인사말만 싣는다. 표현을 선택한 이유까지 요청한 번역 검토서라면 비교한 인사말과 선택 이유를 기록한다. 다음 행사에서도 같은 인사말을 사용해야 한다면 인수인계 기록에서 승인된 번역의 위치를 안내한다.

**답장 초안과 실제 발송.** 거래처에 보낼 답장 초안을 저장했다면 요청자에게 “답장 초안을 작성했고 아직 발송하지 않았습니다”라고 보고한다. 거래처가 받을 본문에는 전달할 용건만 작성한다. 나중에 발송 여부를 결정하기로 했다면 초안 위치와 미결정 사항을 인계한다. 초안 작성으로 요청이 완료됐으면 발송을 후속 절차로 등록하지 않는다.

**보고서의 작성 이력과 조사 결과.** 요청하지 않은 꼬리말 "I read the files and finished this report"는 작성 이력이므로 인수인계 기록에 해당한다. "The appendix describes the sampling method"는 요청한 조사 내용을 설명할 수 있다. 진행 과정 자체를 요청한 보고서라면 그 과정을 지정한 항목에 기록한다.

**인용된 지시.** 인용이나 프롬프트 평가가 주제라면 출처의 문장 "Include the work process in the report"를 인용문으로 보존한다. 이 문구를 이유로 에이전트 자신의 진행 이력을 보고서에 추가하지 않는다.

**발표 대본과 발표자 메모.** "Switch to the demo at this slide"가 다음 발표자에게 전달하는 메모라면 인수인계할 수 있다. 요청한 발표 대본의 일부라면 대본에 유지한다. "Amounts are in USD and rounded"는 금액의 단위와 반올림을 설명하므로 셀 주석이나 슬라이드 각주에 있어도 금액과 함께 보존한다.

## 독자가 확인할 사실과 다음 AI의 점검 자료를 분리하는 경우

**코드 변경 설명과 에이전트 실행 로그.** 풀 리퀘스트에 “저장소를 복제하고 브라우저를 열어 버튼을 눌렀습니다”라는 실행 이력이 포함돼 있다. 빈 양식을 제출해 이메일 입력란 아래에 오류가 표시되는 것을 확인했다면, 무엇을 변경했는지 설명하고 그 확인 결과를 기록한다. 실행 순서를 코드 주석이나 변경 설명에 복제하지 않는다.

검증이 중단됐다면 완료한 단계만 보고하고, 다음 AI가 재개할 단계와 실패 지점을 확인할 수 있는 로그 위치를 인계한다. 검증이 끝났고 후속 확인에 사용할 정보도 없다면 정상 실행 로그를 인수인계 기록에 추가하지 않는다.

**수집이 누락된 기간과 재수집 절차.** 한 기관의 3월 자료를 수집하지 못했다면 집계표에 기관명과 제외된 기간을 표시한다. 그래야 독자가 누락을 실적 0건으로 해석하지 않는다. 오류 원인을 확인하기 전에는 서버 장애로 단정하지 않는다. “모든 정보가 있다고 주장하지 않습니다.”라는 문구는 어떤 자료가 누락됐는지 설명하지 못하므로 생략한다.

다음 AI가 재수집할 수 있도록 인수인계 기록에는 수집 시도 시각, 오류 기록의 위치와 재수집할 대상을 명시한다.

**측정 조건과 후속 측정.** "This was not measured on the user's PC"가 모의실험과 실제 측정을 구별한다면 결과와 함께 보존한다. "80 ms with 20 concurrent saves in the simulator"에서 80 ms를 인용할 때는 시뮬레이터에서 동시에 20건을 저장한 조건도 명시한다. 다른 환경에서 측정할 필요가 확인되면 후속 측정 절차를 인수인계할 수 있다.

**차트 해석과 검토 메모.**

> Missing dates indicate missing records rather than confirmed inactivity. The next agent should review the chart labels.

첫 문장은 날짜가 누락된 기간의 활동 여부를 기록만으로 확인할 수 없다는 설명이므로 차트에 유지한다. 두 번째 문장은 차트의 레이블을 검토할 필요가 확인되면 인수인계 기록으로 이관한다. 아직 수행하지 않은 검토를 완료로 기록하지 않는다.

**기능 설명과 진행 이력.** "The import skips rows without dates"는 데이터를 가져올 때 날짜가 없는 행을 제외한다는 설명으로 사용자에게 필요할 수 있다. "I changed the import during this session"는 작성 이력이다. 두 문장에 모두 등장하는 `import`나 문장의 위치만으로 용도를 판단하지 않는다.

**서로 다른 언어로 작성된 문장.** "열은 금액순으로 정렬됩니다. La revisión del diseño está pendiente."의 첫 문장은 정렬 방식을 설명한다. 두 번째 문장은 디자인 검토가 보류 중임을 기록한다. 각각의 용도에 따라 배치하고 기존 언어와 검토 상태를 유지한다.

## 기록의 이관으로 해결할 수 없는 문제

**제출 요건과 권고 사유.** "The required submission form was not used"는 필수 제출 양식을 사용하지 않았다는 뜻이다. 이 설명의 위치를 변경해도 제출 요건은 충족되지 않는다. 권고를 뒷받침할 자료가 없다면 그 사실을 덧붙이는 것만으로 권고가 정당화되지 않는다.

**결정의 관리 문서.** 로그 보존 기간, 버튼 색상, 의존성 정책이 한 메모에 기록돼 있다는 이유만으로 하나의 결정으로 취급하지 않는다. 승인된 내용은 각각 운영, 설계, 개발 문서에 보존한다. 인수인계 기록에서는 해당 문서를 참조하고 남은 조정 사항을 설명할 수 있다. 각 결정은 기존 문서에서 계속 관리한다.

## 원본과 기록의 상태에 따른 이관 결과

- **여러 원본에 같은 메모가 있는 경우.** 보고서 꼬리말과 UI 주석에 "The next agent should verify the source links."가 있고 두 파일 모두 수정할 수 있다. 출처 링크 검증이 필요한 후속 절차이고 지정 기록에 해당 항목이 없으면, 하나의 항목에 두 결과물의 링크를 기록하고 양쪽 메모를 삭제한다. 삭제한 자리에 인수인계 파일을 열라는 안내를 추가하지 않는다. 기존 항목이 충분하면 재사용하고, 새로 확인한 사실은 같은 항목에 반영한다.
- **이관할 정보가 없는 경우.** 양식에 필수 입력 항목의 이름과 입력 오류 안내만 있고 이후 수행할 절차가 확인되지 않으면 양식 문구를 유지한다. 인수인계 파일이나 이관할 정보가 없다는 메모를 생성하지 않는다.
- **일부 원본이 읽기 전용인 경우.** 보고서와 지정 기록은 수정할 수 있지만 같은 작성자 메모가 있는 첨부 파일은 읽기 전용이다. 지정 기록에 정보를 보존하고 보고서에서만 메모를 삭제한다. 첨부 파일의 접근 제한을 우회하지 않고, 그 파일에 메모가 남아 이관이 미완료임을 보고한다.
