# 설계 문서

이 디렉터리에 주제별 요구사항, 조사 근거, 승인된 결정과 실행 플랜을 관리한다. 요청 범위에서 검토, 조사, 계획과 검증을 수행한다. 문서 생성은 요청 범위에 포함될 때만 수행한다. 기존 문서를 수정하면 변경 항목을 보고한다.

## 주제별 디렉터리와 문서 구성

```text
docs/designs/
  README.md
  <topic>-<nonce>/
    requirements.md
    references/
      <reference>.md
    decisions/
      <decision>.md
    plan.md
```

주제별 요구사항은 해당 주제 폴더의 `requirements.md`에 기록한다. 같은 주제에는 기존 폴더를 사용한다. 참고 자료, 결정과 플랜은 각 항목의 생성 조건을 충족할 때 해당 파일을 추가한다. 하위 디렉터리는 저장할 파일이 있을 때 생성한다.

## `requirements.md` — 원하는 결과와 유지할 조건

요구사항 문서가 없거나 별도 문서 작성을 요청받으면 `requirements.md`를 생성한다. 기존 문서를 보완할 때는 요청받은 부분만 수정한다. 빈 문서를 요청받으면 내용은 비워 둔다.

요구사항마다 적용 상황과 입력, 실행해야 할 기능과 필요한 결과나 산출물, 변경 대상과 유지할 제약을 명시한다. 검증할 결과나 산출물과 통과 조건도 명시한다. 실행 플랜에서 참조할 수 있도록 항목에 제목이나 식별자를 부여한다. 답에 따라 결과, 변경 대상, 제약 또는 완료 기준이 달라지는 사항은 미결정 질문으로 기록한다. 이미 플랜이 있으면 영향을 받는 단계도 명시한다. 결정이 확인되면 요구사항을 갱신한다.

### 기록 예시

- **댓글 끄기의 완료 조건.** 관리자가 댓글을 끄고 기존 게시물을 열면 댓글 영역에 비활성 안내가 표시된다. 이미 달린 댓글은 그 화면에 보이지 않는다.
- **침수 수리 서비스의 미결정 질문.** 집이 침수됐을 때 여러 업체의 견적을 비교할 수 있으면 충분한가? 견적을 기다리지 않고 바로 출동을 요청할 수도 있어야 하는가?

## `references/*.md` — 다시 사용할 조사 근거

조사 결과를 이후 계획이나 검토에서 다시 참고해야 할 때 작성한다. 조사한 질문과 출처, 각 자료에서 확인한 사실을 기록한다. 이를 근거로 방법을 제안할 때는 그 이유와 자료만으로 판단할 수 없는 점도 설명한다.

### 기록 예시

- **레고 건축물 세트의 시험 판매.** 시카고의 일부 매장에서는 블록 수가 같은 다른 세트보다 높은 가격에도 건축물 세트가 팔렸다. 이 시험 판매만으로는 다른 지역에서도 같은 가격에 팔릴지 알 수 없다.

## `decisions/*.md` — 승인된 선택과 이유

후속 단계의 내용이나 순서에 영향을 주는 선택이 승인됐고 그 이유를 기록할 필요가 있을 때 결정 문서를 생성한다. 무엇을 결정해야 했는지 밝히고, 실제로 검토한 선택지 중 무엇을 왜 채택했는지 기록한다. 그 선택에 따라 달라지는 단계도 명시한다. 승인 전에는 선택지를 조사 자료나 미결정 질문으로 남긴다.

### 기록 예시

- **오리건 도로 관제 시스템의 홈 화면 개편.** 기존에는 홈 화면만 바꾸어도 시스템 전체를 테스트하고 배포해야 해 지역 관제센터들이 필요한 변경을 오래 기다렸다. 오리건주 교통부와 오리건주립대 개발팀은 시스템을 개별 배포할 수 있는 서비스로 나누기로 하고 홈 화면부터 개편했다.

## `plan.md` — 실행 순서, 완료 기준과 진행 상태

플랜의 문서 기록이 요청 범위에 포함되면 `plan.md`를 생성하거나 기존 파일을 갱신한다. 문서 상단에 원하는 결과와 유지할 제약을 요약하고 근거가 되는 `requirements.md` 항목을 링크한다. 결정 기록이 있으면 플랜의 근거가 되는 결정도 링크한다. 단계마다 다음 항목을 기록한다.

- 단계의 근거가 되는 요구사항, 변경 대상과 수행할 작업
- 선행 단계의 산출물 또는 검증 결과, 이 단계에서 생성할 산출물
- 검증 방법과 통과 조건
- 현재 완료 여부, 실제 검증 결과와 근거, 남은 작업 또는 재개 조건
- 미확정 단계에서 필요한 결정 또는 조사 결과와 확정 조건

단계별 검증을 마치거나 실행이 중단될 때 진행 상태를 갱신한다. 통과 조건을 충족한 단계만 완료로 표시한다. 최종 검증에서는 요청 범위에 포함된 요구사항과 유지할 제약 각각의 검증 결과를 기록한다.

구현 방법을 변경하면 변경 이유와 영향을 받는 단계 및 검증 항목을 플랜에 기록한다. 결정이 필요한 요구사항 변경은 미결정으로 표시한다. 변경이 확정되면 수정 권한이 있는 `requirements.md`에 반영한 뒤 플랜을 갱신한다.

### 기록 예시

- **시안 검토 결과에 의존하는 화면 구현.** 시안에 반영할 수정 사항이 확정되기 전까지 화면 구현 단계를 미확정으로 표시한다. 수정 사항과 무관하게 구현 도구를 선정할 수 있으면 도구 선정은 계획한다. 두 선행 조건이 충족되면 구현 단계를 확정한다. 합의한 수정 항목마다 화면에 표시되는 내용과 화면에서 조작한 뒤 나타나는 결과를 검증한다.
