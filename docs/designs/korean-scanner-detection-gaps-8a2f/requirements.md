# 한국어 스캐너 탐지 공백 해소 요구사항

## 목표

`use-words-review` 검사 스크립트가 놓치는 것으로 확인된 네 가지 표현 공백을 검토 후보로 찾도록 개선한다.

첫째, 형용사 `좁다`의 활용형을 찾지 못한다. `좁은 경계를 유지합니다`, `모듈을 불러오는 범위를 좁게 유지합니다`, `이 작업이 너무 좁았습니다`처럼 `좁은`, `좁게`, `좁았`, `좁아졌`이 나타나도 `ko.narrow` 경고가 발생하지 않는다. 현재 규칙은 사동사 `좁히다`의 `좁히`와 `좁혀`만 검사한다.

둘째, `박다`와 `박히다`의 활용형 대부분을 찾지 못한다. 현재 `ko.fix-in-place` 규칙은 `박다`, `박아`, `박은`, `박힌`, `박혀` 다섯 literal만 검사해 `박고`, `박는`, `박았`, `박음`, `박힘`, `박히는`, `박혔` 출현에는 경고가 발생하지 않는다.

셋째, `다루다`와 `회의를 가지다`는 사전형만 찾는다. `다룬다`, `다룹니다`, `회의를 가집니다`처럼 실제 문서에 흔한 활용형에는 경고가 발생하지 않는다.

넷째, NFD로 분해되어 저장된 한글 원문은 모든 literal 규칙이 찾지 못한다. 같은 문장이라도 음절이 자모로 분해된 상태로 저장되면 경고가 발생하지 않는다.

## 적용 조건

- 검사 스크립트는 외부 패키지 없이 Node.js 표준 기능만으로 실행하는 기존 조건을 유지한다.
- 경고를 자동 실패나 수정 명령으로 다루지 않는 [한국어 문서 검토 재발 방지 요구사항](../korean-writing-review-6f3a/requirements.md)의 기준을 유지한다.
- 검사 결과의 JSON 구조는 [출력 구조 유지와 대체 표현 우선 탐색](../korean-scanner-coverage-9b4e/decisions/output-structure-and-alternative-search.md) 결정을 따르며, 이와 충돌하는 변경은 결정 소유자의 승인 없이 확정하지 않는다.

## 완료 증거

- 네 가지 공백을 재현한 실행 결과와 탐지 방법 비교가 조사 문서에 기록되어 있다.
- 매칭 방식에 대한 승인된 결정과 구현 계획이 설계 패키지에 기록되어 있다.
- 구현 후 검사 스크립트 실행에서 네 가지 공백의 대표 표현이 경고 후보로 발견되고, self-test가 해당 사례를 검사한다.

## 해결된 질문

매칭 방식에 대한 네 가지 질문은 해결되었다. 어간 중심 NFD 매칭을 채택해 형용사 `좁다`는 어간 `좁`으로, `박다` 계열의 자음 어미형은 허용 어미 집합으로, NFD로 저장된 원문은 매칭 평면의 NFD 통일로, `다루다`와 `회의를 가지다`는 어간 표현과 축약형 열거로 잡는다. [어간 NFD 매칭과 허용 어미 집합 채택](decisions/stem-nfd-matching.md)에 기록되어 있다.
