# 어간 NFD 매칭 구현 계획

## 기준 문서

- [요구사항](requirements.md)의 목표, 적용 조건, 완료 증거 절이 이 계획의 기준이다.
- [어간 NFD 매칭과 허용 어미 집합 채택](decisions/stem-nfd-matching.md)이 매칭 구조를 정한다.
- [활용형 탐지 공백 재현과 공개 프로젝트의 어간 매칭 방식 조사](references/stem-matching-research.md)와 [외부 패키지 없는 스캐너의 TDD 시나리오 테스트 방법 조사](references/tdd-scenario-testing.md)가 근거 자료다.
- 구현 시 [Node.js MJS 명령줄 검사기 지침](../../dev/node/mjs-cli.md)과 [개발 지침 안내](../../dev/README.md)를 적용한다. 특히 literal 탐색의 겹침 보존, 위치와 quote의 원문 보존, locale 무관 결과 순서, 계산 함수의 순수성, 실패 메시지 제한 절이 새 매칭 엔진에도 그대로 적용된다.

## 작업 단위

### 1. 규칙 데이터 설계와 오탐 평가

결정이 정한 개념(용언 규칙의 어간, 허용 어미 집합, 어간 변이형, 명사 규칙의 NFD 완전 일치)을 `korean-expressions.mjs`의 규칙 자료 구조로 설계한다. 네 공백의 대상 규칙(`ko.narrow`, `ko.fix-in-place`, `ko.cover-topic`, `ko.hold-meeting`)의 어간, 어미 집합과 변이형을 확정하고, 받침 없는 음절로 끝나는 모든 표현의 오탐 후보를 평가한다.

**검증.** 평가한 표현 목록, 오탐 후보와 판단이 이 패키지의 참고 문서로 기록되어 있다. 무관한 단어를 반복해서 잡는 표현이 발견되면 구현을 시작하지 않고 결정 소유자에게 보고한다.

### 2. 특성화 테스트 확보

새 엔진을 만들기 전에 현행 스캐너의 출력을 고정한다. 개발 저장소에 `node --test`로 실행하는 테스트 파일을 추가하고, 대표 입력(기존 self-test의 표현과 문단 사례, 요구사항의 재현 입력 세 가지)에 대한 현재 JSON 출력을 기대값으로 기록한다. CLI 수준은 자식 프로세스 실행으로 stdin 입력, 파일 입력, 종료 상태를 고정한다.

**검증.** `node --test`가 통과하고, 기대값이 구현 계산의 복사가 아니라 실행으로 확인된 현재 동작임이 테스트 이름과 구조에서 드러난다.

### 3. TDD로 매칭 엔진 재작성

Canon TDD 절차를 따른다. 네 공백의 시나리오 목록(형용사 `좁다` 활용형, `박다` 계열의 받침 추가형과 자음 어미형, `다루다`와 `회의를 가지다`의 활용형과 축약형, NFD로 저장된 원문, 기존 탐지가 유지되어야 하는 사례)을 먼저 작성하고, 한 항목씩 실패하는 테스트를 만들어 통과시킨다. 규칙 단위 테스트는 규칙마다 통과 사례와 실패 사례(`ruleId`, `line`, `startUtf16`)를 데이터 표로 두고 공용 도우미가 순회한다.

구현은 결정이 승인한 구조를 따른다. 매칭 평면을 NFD로 통일하고, 음절 literal 색인과 `NFD_MATCHED_EXPRESSIONS` 허용 목록의 이중 구조를 제거하며, 어간 일치 뒤 연결 검증(종성 자모 또는 허용 어미)을 수행하고, 매칭 시작을 음절 시작으로 제한하며, 경고 위치와 인용은 원본 UTF-16 offset 기준을 유지한다. 의도된 동작 변화는 해당 특성화 기대값만 갱신해 드러낸다.

**검증.** 새 시나리오 테스트 전체와 갱신된 특성화 테스트가 `node --test`로 통과한다. 요구사항의 재현 입력 세 가지를 다시 실행해 네 공백의 대표 표현이 경고 후보로 발견된다. 검사 결과의 JSON 구조가 바뀌지 않았음을 특성화 테스트가 확인한다.

### 4. self-test 재구성

배포본의 `--self-test`를 새 엔진의 대표 시나리오를 검사하는 스모크 검증으로 재구성한다. 개발 시점 테스트가 본체이고 self-test는 외부 패키지 없는 실행 환경에서의 최소 검증이라는 역할 분담을 유지한다.

**검증.** Node.js 22.0.0 조건에서 `node scan.mjs --self-test`가 종료 상태 0으로 끝나고, 잘못된 인수와 입력 실패 사례가 기존과 같은 오류 코드로 끝난다.

### 5. 지침과 스킬 문서 정합 확인

`docs/dev/node/mjs-cli.md`의 literal 탐색 절과 self-test 관련 서술이 새 엔진과 충돌하는지 확인한다. 지침 문서의 변경이 필요하면 임의로 고치지 않고 필요한 갱신 범위를 보고한다. `skills/use-words-review/SKILL.md`는 입력 방식과 출력 구조가 유지되므로 변경이 필요하지 않다는 것을 확인한다.

**검증.** 충돌 여부와 필요한 후속 문서 작업이 보고되어 있다.

### 6. 전체 검증

ESLint, `node --test`, `--self-test`를 모두 실행하고, 변경된 한국어 문서와 코드 주석을 스캐너 자신으로 검사한다.

**검증.** 세 검사의 실행 결과가 보고되고, 요구사항의 완료 증거 항목이 각각 실제 실행 결과로 확인된다.

## 순서와 의존

1번이 확정되어야 2번 이후를 시작한다. 2번은 3번보다 먼저 끝나야 한다. 4번은 3번 완료 후, 5번과 6번은 4번 완료 후 진행한다.

## 중단 조건

- 1번의 오탐 평가에서 무관한 단어를 반복해서 잡는 표현이 확인되어 결정의 매칭 구조로 해소되지 않으면 중단하고 결정 소유자에게 보고한다.
- 구현 중 검사 결과의 JSON 구조를 바꿔야만 진행할 수 있는 상황이 확인되면 중단한다. [출력 구조 유지 결정](../korean-scanner-coverage-9b4e/decisions/output-structure-and-alternative-search.md)과 충돌하기 때문이다.
- 개발 지침의 승인된 규칙과 충돌하는 구현이 필요해지면 중단하고 지침 갱신 범위를 보고한다.
