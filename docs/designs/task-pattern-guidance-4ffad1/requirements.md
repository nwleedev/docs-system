# 작업 목적에 맞는 코딩 판단과 예시

## 목표

`use-flexible-coding`은 작업의 목적과 특성을 파악하고, 코드 변경 판단과 그 이유, 적용할 작성 방법과 피해야 할 문제를 설명한다. 사용자가 기록할 파일을 제시하면 그 파일에 프로젝트에 맞는 코드 예시와 함께 작성한다. 어떤 파일도 제시하지 않으면 적절한 후보를 찾아 제안한다.

작업을 수행하는 AI 에이전트가 컨텍스트 압축 뒤에도 기록을 다시 읽고 필요한 기술 판단을 파악할 수 있어야 한다. 특정 폴더나 문서 체계, 여러 절차로 나뉜 작업이 존재한다고 전제하지 않는다.

## 스킬 이름과 변경 권한

`use-flexible-coding`을 신규 스킬로 추가하고 기존 `use-dev-guidance`는 유지한다. 이번 추가 작업에서 기존 스킬의 파일과 동작을 변경하지 않는다. 새 스킬은 조사, 기술 판단과 코드 예시 작성을 기본으로 한다.

기록할 파일이 지정됐다는 이유만으로 실제 소스 코드나 테스트 파일 등을 변경하지 않는다. 소스 코드 등을 변경하려면 코드 구현 또는 개발을 명시적으로 지시한 명령이 있어야 한다.

## 스킬의 작성 언어

여러 나라의 사용자가 영어로 읽고 활용할 수 있도록 스킬을 영어로 구성한다. 스킬 본문, 사용 설명과 기본 호출문을 영어로 작성한다.

## 사용자가 지정한 파일에 기록

스킬은 먼저 파일을 수정하거나 작성하지 않고 작업과 기록할 대상을 확인한다. 사용자가 기록 대상으로 제시한 파일에 작성하며, 그 파일의 목적과 구성에 맞게 내용을 반영한다.

기록할 파일이 제시되지 않았으면 저장소 규칙과 현재 작업에 맞는 후보를 찾아 선택 이유와 함께 제안한다. 후보를 찾았다는 이유만으로 파일을 수정하거나 새로 작성하지 않는다.

지정한 파일이 없거나 수정할 수 없으면 영향을 받는 기록 작업을 보류하고, 대화에 반영할 내용과 후보를 제시한다. 저장소 규칙과 조사 근거가 충돌하면 영향을 받는 판단을 보류하고 차이와 선택에 필요한 정보를 알린다. 영향을 받지 않는 읽기와 조사는 이어갈 수 있다.

스킬은 전용 작업 기록이나 조사 파일을 만들도록 요구하지 않는다. 수집한 자료를 기록할 위치가 필요하면 먼저 저장소 규칙을 파악하며, 무조건 임시 파일을 선택하지 않는다. 자료를 저장할 때도 사용자가 지정한 파일에 기록하는 조건을 따른다.

## 작업 특성에 따른 조사와 변경 판단

조사 대상에는 코드 디자인 패턴뿐 아니라 파일과 폴더 구성을 포함한 모듈 아키텍처와 시스템 아키텍처도 포함한다. `use-flexible-coding`으로 이들 주제를 함께 조사할 수 있어야 한다.

작업의 목적, 변경 대상과 사용하는 기술의 버전을 확인한 뒤, 그 작업에서 발생할 수 있는 실패와 영향에 따라 추가로 조사할 문제를 정한다. 여러 작업이 있으면 각 작업의 특성을 따로 판단하며, 일률적인 조사 항목으로 차이를 없애지 않는다.

필요한 디자인 패턴과 안티패턴은 조사할 문제를 기준으로 빠짐없이 파악한다. 패턴 이름을 채우는 것을 목표로 삼지 않으며, 적용할 작성 방법과 피해야 할 문제를 목적에 연결해 설명한다. 근거를 찾지 못했거나 확인하지 않은 부분을 해결한 것으로 취급하지 않는다.

어떤 코드를 추가, 제거, 통합, 분리하거나 수정할지와 그 이유를 명시한다. 코드나 테스트를 추가할 필요가 없으면 추가하지 않는 판단과 이유도 명시한다. 변경 방향을 설명하는 것과 실제 변경을 실행하는 것은 구분한다.

## 읽을 파일의 선택과 예시 대조

프로젝트의 모든 파일을 발견하거나 읽었다고 전제하지 않는다. 현재 판단에 필요한 파일을 다음 기준으로 선택하고, 어떤 기준으로 선택했는지 설명한다.

- 작업의 목적과 변경 대상을 직접 설명하는 파일인지
- 사용하는 기술의 버전과 실행 조건을 확인할 수 있는 파일인지
- 예시에서 사용하는 타입, 호출 관계와 연결 부분을 확인할 수 있는 파일인지
- 유지할 동작과 테스트할 대상을 확인할 수 있는 파일인지

선택한 자료와 공식 문서를 대조하여 예시가 프로젝트의 기술 버전, 타입, 호출 관계와 규칙에 맞는지 판단한다. 기존 코드는 적용 조건을 파악하는 자료이며, 같은 작성 방식을 그대로 복제할 근거로 삼지 않는다. 선택하지 못했거나 확인하지 않은 자료 때문에 판단할 수 없는 부분은 밝힌다.

확인 방식은 문서와 프로젝트 근거 대조로 정한다. 예시를 확인한다는 이유로 소스나 테스트 파일을 새로 만들거나 실행 검사를 필수로 요구하지 않는다. 실행하지 않은 예시를 실행 확인한 코드로 표현하지 않는다.

## 프로젝트에 맞는 코드와 테스트 예시

사용자가 제시한 파일에 기술 판단을 기록할 때는 단순 지침만 남기지 않고 프로젝트에 맞는 코드 예시를 포함한다. 어떤 코드를 어떻게 작성하고 왜 그렇게 작성하는지 이해할 수 있어야 한다.

테스트를 선택할 때는 무엇을 테스트하는지, 왜 테스트를 사용해야 하는지와 어떤 테스트를 사용할지 명시한다. 테스트 코드 작성 방법을 조사하고 프로젝트에 맞는 예시를 포함한다. 테스트를 추가할 필요가 없다고 판단한 경우에는 불필요한 예시를 만들지 않고 그 이유를 기록한다.

테스트 예시가 설명한 대상과 목적을 검사하도록 작성됐는지 문서와 선택한 프로젝트 파일을 대조한다. 테스트할 동작까지 가짜 구현으로 바꾸고 그 가짜 구현만 검사하는 예시를 작성하지 않는다.

## 작업 시작과 재개 시 기록 확인

스킬로 작업을 시작하거나 재개할 때, 또는 다음 작업 단위로 넘어갈 때 사용자가 지정한 기록에서 필요한 부분을 다시 읽는다. 작업 목적, 변경 판단과 적용할 예시를 확인하며, 압축 발생을 감지하는 것만을 재읽기의 조건으로 삼지 않는다.

기록할 파일이 아직 지정되지 않았으면 후보를 제안하는 조건을 따른다. 다시 읽을 기록을 마련한다는 이유로 전용 파일을 생성하지 않는다.

## 간결한 스킬 구성

스킬은 필요한 판단과 행동을 설명하는 필수 지침으로 구성한다. 같은 조건을 여러 절에 반복하거나, 조사 자료와 기술 설명 전체를 스킬 본문에 나열해 장황하게 만들지 않는다.

## 완료를 판단할 근거

- 파일이 제시된 경우 그 파일의 목적과 구성에 맞는 설명과 프로젝트 코드 예시가 있다.
- 파일이 제시되지 않은 경우 후보와 선택 이유를 제안하며, 제안 과정에서 파일을 수정하거나 새로 작성하지 않는다.
- 작업 특성, 조사할 문제, 필요한 변경과 이유 및 추가하지 않는 판단을 확인할 수 있다.
- 코드 디자인 패턴, 파일과 폴더 구성을 포함한 모듈 아키텍처와 시스템 아키텍처를 함께 조사할 수 있는 지침이 있다.
- 읽을 파일의 선택 기준과 확인하지 못한 부분을 알 수 있으며, 모든 파일을 확인했다고 주장하지 않는다.
- 코드 예시를 기술 버전, 타입과 호출 관계에 대조한 판단을 확인할 수 있고, 실행 여부를 구분한다.
- 테스트 대상, 필요성, 사용할 테스트와 예시가 연결된다. 테스트가 필요하지 않은 경우에도 이유가 있다.
- 압축 전 대화 없이 지정된 기록을 읽고 현재 작업에 적용할 판단을 설명할 수 있다.
- 기록이 불가능하거나 기준이 충돌할 때 영향을 받는 작업은 보류하고 대화에 반영안과 선택에 필요한 정보를 제시한다.
- 명시적인 구현 또는 개발 명령 없이 실제 소스와 테스트 파일 등을 변경하지 않는다.
- 스킬 이름과 호출에 `use-flexible-coding`을 사용하며, 특정 폴더나 전용 파일을 필수로 요구하지 않는다.
- 기존 `use-dev-guidance`의 파일과 동작을 유지하면서 신규 스킬을 별도로 사용할 수 있다.
- 스킬 본문, 사용 설명과 기본 호출문이 영어로 작성돼 있다.
- 스킬 본문에는 실행에 필요한 지침만 남고 같은 조건을 반복해서 설명하지 않는다.
