# 필수 지침으로 구성하는 코딩 판단 스킬 추가 계획

## 목표와 기준

기존 `use-dev-guidance`를 유지하고 `use-flexible-coding`을 사용자가 지정한 파일에 코딩 판단과 예시를 기록하는 신규 스킬로 추가한다. 코드 디자인 패턴뿐 아니라 파일과 폴더 구성을 포함한 모듈 아키텍처와 시스템 아키텍처도 함께 조사할 수 있도록 한다. 필수 행동을 설명하는 지침만 본문에 두고, 특정 폴더, 기준 README나 작업 문서 체계를 실행 조건으로 요구하지 않는다.

구현 기준은 [요구사항 전체](./requirements.md)다. [조사 근거](./references/recording-options.md)는 구현 선택의 근거이며 요구사항을 대신하지 않는다. 이 계획을 마지막으로 수정한 커밋의 요구사항을 기준으로 변경 영향을 비교한다. 추가로 적용해야 할 개발 지침 파일은 없으며, 이 작업은 신규 스킬 문서와 별도 호출 안내의 추가로 한정한다.

아래 작업은 구현 순서다. 완료한 작업과 남은 확인은 마지막 진행 상태에 기록한다.

## 최종 스킬 파일 구성

신규 스킬은 다음 두 파일로 구성한다. 기존 스킬의 파일을 이동하거나 복제하지 않고 새 역할에 맞게 작성한다. 내부 참고 파일이나 실행 스크립트는 추가하지 않는다.

```text
skills/use-flexible-coding/
  SKILL.md
  agents/
    openai.yaml
```

### 실행 지침

`skills/use-flexible-coding/SKILL.md`를 새로 작성한다. [스킬의 작성 언어](./requirements.md#스킬의-작성-언어)에 따라 설명 필드와 지침 본문을 영어로 작성한다. 작업 목적, 권한, 기록 대상, 조사와 예시, 재개 및 미확인 사항 처리를 이 파일에서 설명한다.

### 도구 표시와 호출 정보

`skills/use-flexible-coding/agents/openai.yaml`을 새로 작성하고 `display_name`, `short_description`과 `default_prompt`를 새 역할에 맞는 영어로 작성한다. 기본 호출문에는 `$use-flexible-coding`을 사용한다.

### 기존 스킬 유지

`skills/use-dev-guidance/`의 `SKILL.md`, `agents/openai.yaml`과 `references/_README.md`는 그대로 유지한다. 기존 스킬의 이름, 동작과 호출 안내를 바꾸지 않는다. 과거 문서에서 기존 스킬과 기본본을 가리키는 링크도 유지한다.

신규 스킬에는 위 두 파일 외의 파일을 만들지 않는다. `references/` 디렉터리와 기본본을 포함하지 않으며, 프로젝트 기준 문서를 복사하거나 준비하는 절차도 넣지 않는다.

## 함께 수정할 기존 파일

신규 스킬의 사용 안내와 호출 조건을 다음 네 파일에 별도 항목으로 추가한다. 기존 스킬에 관한 내용은 유지하고, 한국어와 영어 안내의 의미를 맞추되 각 안내 문서의 언어는 유지한다.

- `README.md`
- `README.ko.md`
- `src/AGENTS.en.md`
- `src/AGENTS.ko.md`

기존 파일은 이동하거나 제거하지 않으므로 과거 설계와 조사 문서의 링크를 바꿀 필요가 없다. 과거 요구사항, 측정치와 당시 이름은 유지한다. 이 설계 묶음의 `references/recording-options.md`는 기존 스킬과 신규 스킬의 관계 설명만 요구사항에 맞춘다.

구현 진행 기록은 이 `plan.md`와 `HANDOFF.md`에서 갱신한다. 다른 변경 대상이 발견되면 그 파일과 변경 이유를 먼저 계획에 반영한다. 대상 프로젝트에서 기록할 파일은 스킬 사용자가 정하며 이 저장소의 스킬 파일 구성과 구분한다.

## 간결한 본문 구성

[간결한 스킬 구성](./requirements.md#간결한-스킬-구성)을 만족하도록 이름과 호출 조건을 설명하는 필드와 실제 행동 지침을 구분한다. 본문에는 다음 판단만 남긴다.

- 작업 목적과 실제 소스 변경 권한 확인
- 기록 파일 지정 여부와 지정이 없을 때의 후보 제안
- 작업 특성, 실패 영향과 읽을 파일 선택에 따른 조사
- 코드 변경 판단과 이유, 프로젝트 코드 및 테스트 예시 작성
- 지정한 기록을 다시 읽는 조건과 기록 불가 및 미확인 사항 처리

각 문장이 실행할 행동을 바꾸는지 확인하고 같은 조건은 한 번만 설명한다. 요구사항과 외부 조사 자료 전체, 기술별 패턴 목록, 도구별 자동화 설정을 본문에 옮기지 않는다. 임의의 줄 수나 단어 수를 통과 기준으로 정하지 않는다.

프로젝트에 생성할 전용 파일, 고정된 기록 양식이나 새 스크립트는 추가하지 않는다. 스킬을 설치한 뒤에도 이 저장소의 설계 문서를 읽어야만 실행할 수 있는 구조로 만들지 않는다.

## 구현 순서

### 신규 스킬 본문 작성

[스킬 이름과 변경 권한](./requirements.md#스킬-이름과-변경-권한), [파일 지정](./requirements.md#사용자가-지정한-파일에-기록), [재개 조건](./requirements.md#작업-시작과-재개-시-기록-확인)을 단일 진입점에 반영한다.

`skills/use-flexible-coding/SKILL.md`에 새 이름, 설명과 본문을 작성한다. 기존 스킬의 고정 기준 문서 검색, 생성 승인과 기본본 복사 절차는 가져오지 않는다. 기존 스킬을 호출하거나 읽어야 하는 조건도 넣지 않는다.

본문은 사용자 파일이 없으면 제안까지만 하고, 지정된 파일에는 목적과 구성에 맞게 기록하도록 한다. 기본 작업인 예시 작성과 명시적인 개발 명령이 필요한 실제 변경을 구분한다. 압축 발생을 알아야만 기록을 다시 읽는 방식으로 제한하지 않는다.

실행 로직을 추가하지 않으므로 이 단계의 구현 전 테스트 코드는 작성하지 않는다. 문구 일치만 검사하는 테스트로 행동 준수를 증명할 수 없기 때문이다. 최종 확인에서는 파일 지정 여부, 변경 권한과 재개 조건을 요구사항에 대조한다.

### 조사와 예시 지침 연결

[작업별 조사와 변경 판단](./requirements.md#작업-특성에-따른-조사와-변경-판단), [파일 선택과 대조](./requirements.md#읽을-파일의-선택과-예시-대조), [판단에 맞는 예시](./requirements.md#프로젝트와-판단에-맞는-예시)를 앞 작업의 본문에 연결한다.

작업마다 목적, 변경 대상과 기술 버전을 확인하고 실패 영향에 따라 조사할 문제를 정한다. 읽을 파일은 목적, 버전, 타입과 호출 관계, 유지할 동작을 근거로 선택하도록 한다. 모든 자료를 발견했다고 전제하거나 패턴 이름을 채우는 지침은 넣지 않는다.

추가, 제거, 통합, 분리와 수정 및 추가하지 않는 판단과 이유를 설명하도록 한다. 코드 예시는 프로젝트 근거와 대조하며, 테스트가 필요하면 대상, 필요성, 선택한 테스트와 예시를 연결한다. 문서 대조와 실행 확인을 구분하고 검사 실행이나 테스트 파일 생성을 새 기본 행동으로 추가하지 않는다.

앞 작업과 이번 작업의 조건이 중복되면 기존 문장을 보완하며 같은 설명을 별도 절에 다시 만들지 않는다. 본문에서 기본 행동을 완결해서 설명하고, 실제로 분리할 필요가 입증되지 않은 내부 참고 파일은 새로 만들지 않는다.

이 단계는 스킬의 지침을 작성하는 작업이므로 구현 전 테스트 코드를 추가하지 않는다. 최종 확인에서는 조사할 문제, 읽을 파일의 선택 기준, 변경 이유와 테스트 예시 조건이 연결되는지 사례에 대조한다. 스킬 자체를 확인한다는 이유로 애플리케이션 예시나 가짜 테스트 파일을 만들지 않는다.

### 호출 정보와 별도 사용 안내 추가

본문이 정해진 뒤 `skills/use-flexible-coding/agents/openai.yaml`에 표시 이름, 설명과 기본 호출문을 작성한다. `README.ko.md`와 `README.md`에는 신규 스킬의 역할과 기록 대상 선택 방식을 별도 항목으로 추가한다. `src/AGENTS.ko.md`와 `src/AGENTS.en.md`에는 작업별 기술 판단과 코드 예시를 기록하는 요청에 사용할 호출 조건을 별도로 추가한다.

기존 호출 규칙을 신규 호출로 대체하거나 두 스킬을 서로의 필수 실행 조건으로 연결하지 않는다. 신규 호출에는 고정된 개발 지침 폴더나 기준 README를 준비하라는 조건을 넣지 않는다. 과거 문서와 기존 개발 지침 문서의 삭제, 링크 제거와 재작성은 이 계획에 포함하지 않는다.

실행 로직 변경이 없어 이 단계에도 구현 전 테스트 코드를 작성하지 않는다. 최종 확인에서 YAML, 이름과 디렉터리의 일치, 두 언어의 의미와 추가한 링크를 검사한다. 기존 스킬의 파일과 호출 규칙은 변경 전 내용과 대조한다.

별도 사용 안내를 추가하려면 다른 스킬의 실행 규칙이나 과거 요구사항의 뜻을 바꿔야 하는 문제가 발견되면 멈추고 필요한 결정을 알린다. 사용자 환경에 설치된 스킬이나 설정은 이 저장소 변경과 함께 자동으로 바꾸지 않는다.

### 아키텍처 조사 대상 추가 반영

[작업 특성에 따른 조사와 변경 판단](./requirements.md#작업-특성에-따른-조사와-변경-판단)에 추가된 모듈 및 시스템 아키텍처 조사 조건을 기존 본문에 반영한다. 별도 스킬로 나누지 않고 `skills/use-flexible-coding/SKILL.md`의 설명과 조사 지침을 보완한다. 파일 및 폴더 구성과 시스템 구조를 코드 디자인 패턴과 함께 조사할 수 있음을 명시하되, 조사할 문제는 기존의 작업 특성과 실패 영향에 따라 선택한다.

예시 지침은 [프로젝트와 판단에 맞는 예시](./requirements.md#프로젝트와-판단에-맞는-예시)에 맞춰 보완한다. 구현 방법에는 코드, 모듈 구성에는 파일과 폴더 구성 및 의존 관계, 시스템 구성에는 통신과 데이터 흐름 예시를 선택하도록 한다. 필요한 예시를 함께 사용하고 테스트 예시의 대상과 필요성 판단 조건은 유지한다.

본문을 보완한 뒤 `skills/use-flexible-coding/agents/openai.yaml`, 두 README와 두 `src/AGENTS` 파일의 신규 스킬 설명 및 호출 조건을 같은 조사 대상과 예시 선택 기준에 맞춘다. 기존 스킬과 사용자 지정 파일 기록 조건 및 변경 권한은 유지한다. 스킬 파일 구성도 두 파일로 유지한다.

실행 로직을 추가하지 않으므로 구현 전 테스트 코드는 작성하지 않는다. 후속 확인에서는 코드 디자인 패턴과 모듈 및 시스템 아키텍처가 함께 필요한 요청을 지침에 대조하고, 각 조사 대상이 누락되지 않는지와 지정 파일 기록 조건을 확인한다. 형식, 문구와 링크 검사는 변경한 파일에 적용한다.

## 마지막에 확인할 동작

구현 뒤 아래 사례를 요구사항과 최종 문구에 한 번 대조한다. 별도 테스트 코드, 가짜 프로젝트나 평가 프로그램을 만들지 않는다. 문서 대조와 실제 에이전트 실행으로 확인한 증거를 구분한다.

- 기록 파일과 정해진 문서 체계가 없는 요청에서는 후보와 선택 이유만 제안하며 파일을 바꾸지 않는다.
- 사용자가 파일을 지정하면 그 파일의 목적과 구성에 맞춰 기록하고, 명시적인 개발 명령 없이 다른 소스와 테스트 파일을 바꾸지 않는다.
- 서로 다른 작업에서는 각 특성과 실패 영향에 맞는 조사를 선택하며 같은 항목을 기계적으로 채우지 않는다.
- 코드 디자인 패턴과 파일 및 폴더 구성, 시스템 구조가 함께 필요한 요청에서 세 대상을 함께 조사할 수 있는 지침이 있다.
- 예시가 구현 방법, 모듈 구성과 시스템 구성의 판단 목적에 맞게 선택된다. 구현 방법을 설명할 때는 프로젝트에 맞는 코드 예시를 포함한다.
- 모든 파일을 읽지 못해도 선택 기준과 미확인 사항을 설명하며, 예시를 프로젝트의 버전, 타입과 호출 관계에 대조한다.
- 코드를 추가하는 경우뿐 아니라 제거, 통합, 분리, 수정과 추가하지 않는 경우에도 이유를 설명한다.
- 테스트가 필요하면 대상, 필요성, 사용할 테스트와 예시가 연결된다. 필요하지 않으면 불필요한 예시 없이 이유를 설명한다.
- 압축 전 대화가 없더라도 지정된 기록을 읽고 현재 작업의 목적, 변경 판단과 예시를 설명할 수 있는 지침이 있다.
- 파일을 기록할 수 없거나 판단 기준이 충돌하면 영향을 받는 작업을 보류하고 대화에 반영안과 필요한 선택을 제시한다.
- 스킬 전용 파일, 고정 폴더나 기준 README를 생성하거나 준비해야 하는 조건이 없다.
- 기존 스킬의 파일과 호출 규칙이 유지되고, 신규 스킬을 별도로 선택할 수 있다.

신규 스킬의 이름과 디렉터리 일치, YAML 필드와 기본 호출문, 별도 사용 안내와 저장소 링크를 확인한다. 신규 스킬 파일이 명시한 두 파일과 일치하고 `references/` 디렉터리와 기본본이 없는지 확인한다. 스킬 본문과 사용 설명 및 기본 호출문이 영어인지 확인한다. 기존 스킬의 세 파일과 기존 호출 규칙, 과거 문서의 링크가 유지됐는지 변경 내역에 대조한다. 한국어 문구, 민감정보와 변경 파일 목록을 함께 확인하고 신규 본문에 같은 조건을 반복한 부분이 없는지 대조한다.

## 의존 관계와 중단 조건

호출 정보와 별도 사용 안내는 본문 작성 뒤에 추가하고, 최종 확인은 모든 수정 뒤에 한 번 진행한다. 이 계획은 새 의존성, 빌드 및 검사 설정 변경이나 애플리케이션 구현을 요구하지 않는다.

필수 지침이나 자료를 읽을 수 없거나, 해결할 수 없는 기술 문제가 발생하거나, 선택에 사람의 결정이 필요하면 즉시 멈추고 대기한다. 요구사항이 바뀌면 구현을 멈추고 변경 영향을 확인한 뒤 요구사항과 영향을 받은 조사 자료 및 계획을 먼저 갱신한다. 임의로 실제 구현이나 별도 운영 규칙을 추가하지 않는다.

## 진행 상태

### 신규 스킬 본문 작성 완료

`skills/use-flexible-coding/SKILL.md`에 이름, 설명과 기본 지침을 영어로 작성했다. 파일 지정 여부, 기록 권한, 기록 불가 시 대화 반영안, 작업 시작과 재개 시 재읽기 및 충돌 시 보류를 포함한다. 기존 스킬 파일은 변경하지 않았다. 실행 로직이 없어 구현 전 테스트 코드는 추가하지 않았다.

### 조사와 예시 지침 연결 완료

`SKILL.md`에 작업 특성과 실패 영향에 따른 조사, 읽을 파일의 선택 기준, 변경 판단과 이유 및 프로젝트 예시 작성 지침을 연결했다. 테스트의 대상, 필요성, 선택할 종류와 예시의 관찰 조건을 포함하고, 불필요한 테스트 예시는 작성하지 않도록 했다. 실행하지 않은 예시와 문서 대조를 구분한다. 실행 로직이 없어 이 단계에도 구현 전 테스트 코드는 추가하지 않았다.

### 호출 정보와 별도 사용 안내 추가 완료

`skills/use-flexible-coding/agents/openai.yaml`에 영어 표시 이름, 설명과 기본 호출문을 추가했다. 두 README와 두 `src/AGENTS` 파일에 신규 스킬의 역할과 호출 조건을 별도로 추가했다. 기존 스킬의 파일과 호출 규칙은 유지했다. 실행 로직 변경이 없어 구현 전 테스트 코드는 추가하지 않았다.

### 초기 구현 최종 확인 완료

아키텍처 조사 대상 추가 전의 요구사항과 본문을 사례별로 대조했다. 아래 판정은 당시 지침의 내용과 파일 형식에 대한 확인이며 별도 모델 실행으로 행동을 평가한 기록은 아니다. 새 조사 조건의 반영 여부는 아래 확인에 포함하지 않는다.

- `pass`: [기록 대상 확인](../../../skills/use-flexible-coding/SKILL.md#establish-the-task-and-destination)에 파일 미지정 시 제안만 하는 조건, 지정 파일의 목적과 구성에 따른 기록, 지정 파일 부재 및 기록 불가 시 대화 반영안과 보류가 있다. 실제 변경 권한은 본문 첫 문단에서 구분한다.
- `pass`: [작업별 조사](../../../skills/use-flexible-coding/SKILL.md#research-each-task)에 작업 특성과 실패 영향, 파일 선택 기준과 누락 가능성, 기술 버전 및 공식 자료 대조 조건이 있다.
- `pass`: [변경과 예시](../../../skills/use-flexible-coding/SKILL.md#explain-changes-and-examples)에 추가, 제거, 통합, 분리와 수정의 이유 및 코드와 테스트를 추가하지 않는 판단이 있다. 프로젝트 코드 예시, 테스트 대상과 필요성, 종류와 예시 작성 방법 조사, 가짜 동작만 검사하는 테스트 금지 및 실행 여부 구분도 포함한다.
- `pass`: [재개](../../../skills/use-flexible-coding/SKILL.md#start-and-resume)와 [미확인 사항 처리](../../../skills/use-flexible-coding/SKILL.md#handle-uncertainty)에 압축 감지와 무관한 재읽기, 기준 충돌 시 판단 보류와 대화 설명이 있다. 신규 본문은 고정 폴더나 전용 기록 파일을 준비하도록 요구하지 않는다.
- `pass`: 신규 스킬의 두 파일 구성, 이름과 디렉터리 일치, 영어 문구와 호출 정보 필드를 Ruby 표준 YAML 파서 및 파일 검사로 확인했다. 변경한 Markdown의 상대 링크와 절 연결 52개, 변경 파일 8개, 기존 스킬과 기존 호출 문구 및 과거 링크 보존을 확인했다. `pnpm lint`를 통과했다.

기본 스킬 검사기는 Python YAML 모듈 부재로 실행하지 못해 Ruby 표준 YAML 파서로 형식 조건을 대신 확인했다. 기존 lockfile의 개발 의존성을 설치했으며 manifest, lockfile과 검사 설정은 변경하지 않았다. 별도 에이전트 실행 평가는 수행하지 않았다. 실행 로직과 애플리케이션 테스트를 추가하지 않아 가짜 프로젝트, fixture와 테스트용 스크립트도 만들지 않았다.

### 아키텍처 조사 대상 추가 반영 대기

요구사항에 코드 디자인 패턴과 모듈 및 시스템 아키텍처를 함께 조사하는 조건과 판단에 맞는 예시 선택 기준을 추가했다. 본문의 조사 및 예시 지침과 설명, 호출 정보 및 두 언어의 사용 안내가 영향을 받는다. 지정 파일 기록, 실제 변경 권한과 기존 스킬 유지 조건은 영향을 받지 않는다. 이번에는 요구사항과 계획만 갱신했으며 스킬 및 사용 안내의 보완과 후속 확인은 남아 있다.
