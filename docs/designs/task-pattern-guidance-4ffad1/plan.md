# 필수 지침으로 구성하는 코딩 판단 스킬 전환 계획

## 목표와 기준

`use-flexible-coding`을 사용자가 지정한 파일에 코딩 판단과 예시를 기록하는 스킬로 전환한다. 필수 행동을 설명하는 지침만 본문에 남기고, 특정 폴더, 기준 README나 작업 문서 체계를 실행 조건으로 요구하지 않는다.

구현 기준은 [요구사항 전체](./requirements.md)다. [조사 근거](./references/recording-options.md)는 구현 선택의 근거이며 요구사항을 대신하지 않는다. 이 계획을 마지막으로 수정한 커밋의 요구사항을 기준으로 변경 영향을 비교한다. 추가로 적용해야 할 개발 지침 파일은 없으며, 이 작업은 스킬 문서와 호출 안내의 전환으로 한정한다.

아래 작업은 후속 구현의 순서다. 현재는 요구사항과 계획을 작성한 상태이며 스킬 구현은 시작하지 않았다.

## 최종 스킬 파일 구성

스킬은 다음 두 파일로 구성한다. 기존 실행 지침과 호출 정보만 이동하며 내부 참고 파일이나 실행 스크립트는 추가하지 않는다.

```text
skills/use-flexible-coding/
  SKILL.md
  agents/
    openai.yaml
```

### 실행 지침

`skills/use-dev-guidance/SKILL.md`를 `skills/use-flexible-coding/SKILL.md`로 이동하고 이름, 설명과 본문을 바꾼다. [스킬의 작성 언어](./requirements.md#스킬의-작성-언어)에 따라 설명 필드와 지침 본문을 영어로 작성한다. 작업 목적, 권한, 기록 대상, 조사와 예시, 재개 및 미확인 사항 처리를 이 파일에서 설명한다.

### 도구 표시와 호출 정보

`skills/use-dev-guidance/agents/openai.yaml`을 `skills/use-flexible-coding/agents/openai.yaml`로 이동하고 `display_name`, `short_description`과 `default_prompt`를 새 역할에 맞는 영어로 작성한다. 기본 호출문에는 `$use-flexible-coding`을 사용한다.

### 기존 기본본 제외

`skills/use-dev-guidance/references/_README.md`는 새 스킬로 이동하지 않고 전환 작업에서 제거한다. 새 스킬에는 `references/` 디렉터리와 기본본을 포함하지 않으며, 프로젝트 기준 문서로 복사하는 동작도 넣지 않는다.

기존 디렉터리에는 이전 이름의 스킬을 남기지 않는다. 새 스킬 디렉터리에는 위 두 파일 외의 파일을 만들지 않는다.

## 함께 수정할 기존 파일

현재 사용 안내와 호출 규칙은 다음 네 파일에서 바꾼다. 한국어와 영어 안내의 의미를 맞추되 각 안내 문서의 언어는 유지한다.

- `README.md`
- `README.ko.md`
- `src/AGENTS.en.md`
- `src/AGENTS.ko.md`

현재 확인된 이전 위치의 링크는 다음 네 파일에서 정리한다. 과거 요구사항, 측정치와 당시 이름은 유지한다. 이동한 파일의 링크는 새 위치를 가리키도록 바꾸고, 제거하는 기본본의 링크는 파일명을 일반 코드 표기로 남긴다. 파일 내용의 변경이나 링크 제거 때문에 근거의 뜻도 바뀐다면 그 수정은 보류한다.

- `docs/designs/agent-instruction-responsibilities-8c1e/plan.md`
- `docs/designs/agent-workflow-reliability-c7e4/references/instruction-optimization-evaluation.md`
- `docs/designs/public-output-audience-4d2c/references/reusable-output-checks-research.md`
- `docs/designs/task-pattern-guidance-4ffad1/references/recording-options.md`

구현 진행 기록은 이 `plan.md`와 `HANDOFF.md`에서 갱신한다. 다른 변경 대상이 발견되면 그 파일과 변경 이유를 먼저 계획에 반영한다. 대상 프로젝트에서 기록할 파일은 스킬 사용자가 정하며 이 저장소의 스킬 파일 구성과 구분한다.

## 간결한 본문 구성

[간결한 스킬 구성](./requirements.md#간결한-스킬-구성)을 만족하도록 이름과 호출 조건을 설명하는 필드와 실제 행동 지침을 구분한다. 본문에는 다음 판단만 남긴다.

- 작업 목적과 실제 소스 변경 권한 확인
- 기록 파일 지정 여부와 지정이 없을 때의 후보 제안
- 작업 특성, 실패 영향과 읽을 파일 선택에 따른 조사
- 코드 변경 판단과 이유, 프로젝트 코드 및 테스트 예시 작성
- 지정한 기록을 다시 읽는 조건과 기록 불가 및 미확인 사항 처리

각 문장이 실행할 행동을 바꾸는지 확인하고 같은 조건은 한 번만 설명한다. 요구사항과 외부 조사 자료 전체, 기술별 패턴 목록, 도구별 자동화 설정을 본문에 옮기지 않는다. 임의의 줄 수나 단어 수를 통과 기준으로 정하지 않는다.

프로젝트에 생성할 전용 파일, 고정된 기록 양식이나 새 스크립트는 추가하지 않는다. 스킬을 설치한 뒤에도 이 저장소의 설계 문서를 읽어야만 실행할 수 있는 구조로 만들지 않는다.

## 구현 순서

### 스킬 본문과 이름 전환

[스킬 이름과 변경 권한](./requirements.md#스킬-이름과-변경-권한), [파일 지정](./requirements.md#사용자가-지정한-파일에-기록), [재개 조건](./requirements.md#작업-시작과-재개-시-기록-확인)을 단일 진입점에 반영한다.

기존 `SKILL.md`와 `agents/openai.yaml`만 각 파일의 상대 위치를 유지하여 `skills/use-flexible-coding/` 아래로 옮기고 `SKILL.md`의 이름, 설명과 본문을 바꾼다. 기존 기본본은 제거한다. 기존의 고정 기준 문서 검색, 생성 승인과 기본본 복사 절차는 새 본문에서 제거한다. 이전 이름의 스킬이나 호환용 호출은 남기지 않는다.

본문은 사용자 파일이 없으면 제안까지만 하고, 지정된 파일에는 목적과 구성에 맞게 기록하도록 한다. 기본 작업인 예시 작성과 명시적인 개발 명령이 필요한 실제 변경을 구분한다. 압축 발생을 알아야만 기록을 다시 읽는 방식으로 제한하지 않는다.

### 조사와 예시 지침 연결

[작업별 조사와 변경 판단](./requirements.md#작업-특성에-따른-조사와-변경-판단), [파일 선택과 대조](./requirements.md#읽을-파일의-선택과-예시-대조), [코드와 테스트 예시](./requirements.md#프로젝트에-맞는-코드와-테스트-예시)를 앞 작업의 본문에 연결한다.

작업마다 목적, 변경 대상과 기술 버전을 확인하고 실패 영향에 따라 조사할 문제를 정한다. 읽을 파일은 목적, 버전, 타입과 호출 관계, 유지할 동작을 근거로 선택하도록 한다. 모든 자료를 발견했다고 전제하거나 패턴 이름을 채우는 지침은 넣지 않는다.

추가, 제거, 통합, 분리와 수정 및 추가하지 않는 판단과 이유를 설명하도록 한다. 코드 예시는 프로젝트 근거와 대조하며, 테스트가 필요하면 대상, 필요성, 선택한 테스트와 예시를 연결한다. 문서 대조와 실행 확인을 구분하고 검사 실행이나 테스트 파일 생성을 새 기본 행동으로 추가하지 않는다.

앞 작업과 이번 작업의 조건이 중복되면 기존 문장을 보완하며 같은 설명을 별도 절에 다시 만들지 않는다. 본문에서 기본 행동을 완결해서 설명하고, 실제로 분리할 필요가 입증되지 않은 내부 참고 파일은 새로 만들지 않는다.

### 호출 안내와 기존 참조 정리

본문이 정해진 뒤 `skills/use-flexible-coding/agents/openai.yaml`의 표시 이름, 설명과 기본 호출문을 맞춘다. `src/AGENTS.ko.md`, `src/AGENTS.en.md`, `README.ko.md`와 `README.md`의 현재 사용 안내를 새 이름과 역할에 맞춘다. 고정된 개발 지침 폴더를 찾거나 준비하라는 안내도 새 호출의 전제에서 제외한다.

현재 사용 안내와 과거 조사 기록은 구분한다. 과거 요구사항의 내용이나 측정 당시의 스킬 이름을 일괄 치환하지 않는다. 이동 때문에 깨지는 링크는 같은 자료의 새 위치를 가리키도록 고친다. 제거하는 기본본을 참조한 `instruction-optimization-evaluation.md`에서는 기본본의 링크를 일반 코드 표기의 기존 파일명으로 바꾸고 당시 설명과 측정치는 유지한다. 기본본 외의 기존 개발 지침 문서 전체를 삭제하거나 재작성하는 작업은 이 계획에 포함하지 않는다.

이름 전환으로 다른 스킬의 실행 규칙이나 과거 요구사항의 뜻을 바꿔야 하는 문제가 발견되면 그 변경만 보류하고 영향을 알린다. 사용자 환경에 설치된 스킬이나 설정을 이 저장소 변경과 함께 자동으로 바꾸지 않는다.

## 마지막에 확인할 동작

구현 뒤 아래 사례를 요구사항과 최종 문구에 한 번 대조한다. 별도 테스트 코드, 가짜 프로젝트나 평가 프로그램을 만들지 않는다. 문서 대조와 실제 에이전트 실행으로 확인한 증거를 구분한다.

- 기록 파일과 정해진 문서 체계가 없는 요청에서는 후보와 선택 이유만 제안하며 파일을 바꾸지 않는다.
- 사용자가 파일을 지정하면 그 파일의 목적과 구성에 맞춰 기록하고, 명시적인 개발 명령 없이 다른 소스와 테스트 파일을 바꾸지 않는다.
- 서로 다른 작업에서는 각 특성과 실패 영향에 맞는 조사를 선택하며 같은 항목을 기계적으로 채우지 않는다.
- 모든 파일을 읽지 못해도 선택 기준과 미확인 사항을 설명하며, 예시를 프로젝트의 버전, 타입과 호출 관계에 대조한다.
- 코드를 추가하는 경우뿐 아니라 제거, 통합, 분리, 수정과 추가하지 않는 경우에도 이유를 설명한다.
- 테스트가 필요하면 대상, 필요성, 사용할 테스트와 예시가 연결된다. 필요하지 않으면 불필요한 예시 없이 이유를 설명한다.
- 압축 전 대화가 없더라도 지정된 기록을 읽고 현재 작업의 목적, 변경 판단과 예시를 설명할 수 있는 지침이 있다.
- 파일을 기록할 수 없거나 판단 기준이 충돌하면 영향을 받는 작업을 보류하고 대화에 반영안과 필요한 선택을 제시한다.
- 스킬 전용 파일, 고정 폴더나 기준 README를 생성하거나 준비해야 하는 조건이 없다.

이름과 디렉터리 일치, YAML 필드와 기본 호출문, 현재 호출 안내와 저장소 링크를 확인한다. 최종 스킬 파일이 명시한 두 파일과 일치하고 `references/` 디렉터리와 기본본이 없는지 확인한다. 스킬 본문과 사용 설명 및 기본 호출문이 영어인지 확인한다. 링크를 검사할 때는 변경한 파일뿐 아니라 이동하거나 제거한 파일의 이전 위치를 가리키던 파일도 선택한다. 한국어 문구, 민감정보와 변경 파일 목록을 함께 확인하고 스킬 본문에 같은 조건을 반복한 부분이 없는지 대조한다.

## 의존 관계와 중단 조건

호출 안내와 링크 정리는 본문 및 파일 이동 뒤에 진행하고, 최종 확인은 모든 수정 뒤에 한 번 진행한다. 이 계획은 새 의존성, 빌드 및 검사 설정 변경이나 애플리케이션 구현을 요구하지 않는다.

필수 지침이나 자료를 읽을 수 없거나, 이전 자료의 링크를 고치는 것만으로 뜻을 보존할 수 없거나, 요구사항이 바뀌면 영향을 받는 작업을 보류한다. 영향을 받지 않는 작업만 이어가며, 임의로 실제 구현이나 별도 운영 규칙을 추가하지 않는다.
