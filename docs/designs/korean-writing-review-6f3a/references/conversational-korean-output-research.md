# 채팅 답변의 한국어 품질 적용 조사

## 조사 목적과 현재 누락

이 문서는 [한국어 문서 검토 재발 방지 요구사항의 목표](../requirements.md#목표)에 따라, 저장소 파일을 만들지 않는 채팅 답변에도 번역체, 정형화된 AI 문체와 일반 산문의 U+00B7 금지를 적용하는 방법을 조사한다. 두 배포용 AGENTS 문서와 `use-words-review`의 변경 담당자는 상시 자체 점검, 참조 파일 로딩과 독립 검토의 적용 시점을 나눌 수 있어야 한다. 특히 서브에이전트를 사용할 수 없는 환경에서 주 에이전트만으로 실행할 최소 절차와 그 한계를 구분한다.

현재 `src/AGENTS.ko.md`는 사용자와 한국어로 의사소통하라고 지시하고 자연스러운 글쓰기 원칙을 두지만, `use-words-review` 표시 구간은 커밋하거나 공유할 글과 이름을 만든 뒤의 검토를 중심으로 한다. `src/AGENTS.en.md`도 같은 구조다. 따라서 파일 변경이 없는 답변은 스킬 호출 조건에 포함되지 않을 수 있고, `korean.md`를 읽지 않은 상태에서 최종 답변을 만들 수 있다.

## 채팅 답변의 기본 규칙은 AGENTS에 있어야 한다

Codex는 작업을 시작하기 전에 AGENTS 문서를 읽고, 저장소 루트부터 현재 디렉터리까지 발견한 지침을 순서대로 합친다. 프로젝트에서 나오는 답변 전체에 적용할 작성 조건은 선택된 뒤에만 본문을 읽는 스킬보다 AGENTS에서 먼저 전달하는 편이 적합하다. 2026년 8월 1일에 현재 문서를 확인했다. [OpenAI의 AGENTS.md 지침 로딩 문서](https://developers.openai.com/codex/guides/agents-md)

OpenAI Model Spec은 모델이 응답을 만들 때 적용 가능한 개발자와 사용자 지침을 식별해 따르도록 설명한다. 프로젝트 지침이 개발자 수준으로 전달되는 환경이라면 한국어 답변 규칙도 응답 생성에 영향을 줄 수 있다. 다만 공개 Model Spec은 목표 동작을 설명하며 현재 모델이 항상 그대로 동작한다고 보장하지 않는다. 2025년 12월 18일 판을 2026년 8월 1일에 확인했다. [OpenAI Model Spec의 지침 우선순위](https://model-spec.openai.com/2025-12-18.html#follow-all-applicable-instructions)

OpenAI의 프롬프트 지침은 개발자 메시지에 모델이 지켜야 할 규칙, 하지 말아야 할 행동, 원하는 입력과 출력의 예를 함께 둘 수 있다고 설명한다. 다양한 예시를 소수 제공하는 방식도 권한다. 이는 짧은 금지 규칙과 대조 사례를 AGENTS에 직접 넣는 방안을 뒷받침한다. 2026년 8월 1일에 현재 지침을 확인했다. [OpenAI의 프롬프트 구성 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)

따라서 두 AGENTS 문서의 `use-words-review` 표시 구간에 파일 변경 여부와 관계없는 답변 전 자체 검토 조건을 넣는 방안을 제안한다.

- 한국어 답변을 보내기 전에 각 문장의 대상, 행동 주체, 행동, 조건과 결과가 드러나는지 확인한다.
- 일반 산문의 U+00B7, 낱말 단위 번역, 사실을 더하지 않는 수식어와 같은 짜임을 반복하는 문단을 다시 쓴다.
- 한국어로 설명, 조사, 검토, 권고 또는 재사용할 문구를 제공하기 전에 설치된 `use-words-review`의 `references/korean.md`를 읽는다.
- 짧은 진행 알림과 단순 확인 답변에도 자체 검토는 적용하되, 참조 파일 로딩과 독립 검토를 매번 되풀이하지 않는다.

`src/AGENTS.en.md`에서는 영어 지침을 사용하는 저장소라도 한국어 결과물을 작성할 때 같은 조건이 적용된다고 적어야 한다. 영어 답변 전체에 한국어 기준을 적용하거나, 현재 언어 규칙을 한국어로 바꾸는 뜻으로 쓰면 안 된다.

## `korean.md`는 작성 전 기준이고 스킬은 고위험 답변 검토 수단이다

OpenAI의 스킬 문서는 ChatGPT와 Codex가 스킬 이름과 설명을 먼저 보고, 필요하다고 판단한 뒤 `SKILL.md`를 읽는다고 설명한다. 스킬을 선택하지 않으면 보조 자료도 자동으로 읽히지 않는다. 2026년 8월 1일에 현재 문서를 확인했다. [OpenAI의 스킬 로딩 지침](https://developers.openai.com/codex/skills)

Anthropic도 스킬 설명, 본문과 보조 자료를 단계적으로 읽는 구조를 설명하고, 실제 작업에서 스킬이 예상과 다르게 선택되는지 관찰하라고 권한다. 이 구조는 상세 사례를 `korean.md`에 유지하는 근거가 되지만, 매 채팅 답변에서 자동으로 적용된다는 증거는 아니다. 2025년 10월 16일 공개되고 2025년 12월 18일에 공개 명세 안내가 추가된 자료를 확인했다. [Anthropic의 Agent Skills 구조 설명](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

채팅 답변에는 다음 두 단계를 나누는 방안이 적합하다.

### 모든 한국어 답변에는 주 에이전트의 자체 검토를 적용한다

최종 답변을 보내기 전에 AGENTS의 짧은 기준으로 문장을 다시 읽는다. 문자 검색 도구를 사용할 수 있는 작업 환경에서는 답변 초안에 U+00B7이 있는지 찾을 수 있지만, 도구를 사용하지 않는 짧은 답변도 같은 기준으로 직접 확인한다. 자체 점검에도 생성 시간과 토큰이 들지만 별도 에이전트 호출에서 생기는 지연은 추가하지 않는다.

서브에이전트를 사용할 수 없을 때에는 AGENTS가 다음 순서를 주 에이전트의 완료 조건으로 직접 요구해야 한다.

1. 답변 초안을 만든다.
2. 사용자에게 보낼 문장만 대상으로 고정된 점검 질문을 적용한다.
3. 한 항목이라도 어기면 해당 문장을 다시 쓴다.
4. 고친 최종 답변만 보낸다.

고정 점검 질문은 다음 범위가 적합하다.

- 일반 산문에 U+00B7이 남았는가? 남았다면 정확한 원문, 이름, 코드, 검증 입력을 보존하는 경우인가?
- 대상, 행동 주체, 행동, 조건과 결과를 독자가 구분할 수 있는가?
- 영어 낱말을 고정된 한국어로 옮긴 결과 실제 동작이 감춰졌는가?
- 사실을 더하지 않는 수식어, 상투적인 도입과 결론, 내용과 무관한 세 항목 묶음, 같은 문단 구조의 반복이 있는가?
- 후보 용어가 분야에서 확립됐고 문맥이 충분한가? 그렇지 않다면 저장소 근거로 실제 행동을 적었는가?

이 절차는 모델의 숨은 추론을 공개하라는 뜻이 아니다. 최종 출력에 점검 과정을 덧붙이면 답변 자체가 상투적인 작업 보고가 될 수 있다. AGENTS는 점검 결과를 사용자에게 설명하라고 요구하지 말고, 사용자가 판정 근거를 요청하거나 검토 결과가 산출물인 경우에만 지적 위치와 이유를 보여 주도록 해야 한다.

### 영향이 큰 답변에는 `use-words-review`의 독립 검토를 적용한다

다음 답변은 보내기 전에 초안을 만들고 `use-words-review`의 읽기 전용 의미 검토를 적용할 수 있다.

- 요구사항, 결정문, 정책, 외부에 전달할 문구처럼 그대로 재사용될 답변
- 보안, 개인정보, 라이선스, 책임이나 승인 주체를 설명하는 답변
- 사용자가 문구나 한국어 품질 검토를 요청한 답변
- 긴 조사 결과처럼 여러 역할, 조건과 근거를 연결하는 답변

현재 `use-words-review`는 독립 검토마다 별도 서브에이전트 한 명을 호출하고 주 에이전트가 결과를 종합하도록 한다. 이 절차를 단순 확인, 짧은 상태 알림과 도구 실행 전 안내까지 확대하면 호출 횟수와 결과 종합 단계가 늘어난다. 따라서 이 문서는 모든 답변의 독립 검토를 권장하지 않는다. 실제 응답 지연과 토큰 증가량은 아직 측정하지 않았으므로 수치나 증가율을 단정할 수 없다.

독립 검토 수단이 없다는 이유로 검토 자체를 생략해서는 안 된다. 이 경우 `use-words-review` 호출을 주 에이전트 자체 점검으로 대체하되, 독립성이 없다는 한계를 완료 주장과 분리한다. 사용자가 문구 검토를 명시적으로 요청했는데 독립 검토가 필요한 현재 스킬 절차를 실행할 수 없다면, 자체 점검은 수행하고 독립 검토를 하지 못했다는 사실만 알린다.

현재 저장소 지침과 스킬에는 사용자가 보게 될 최종 채팅 문자열을 전송 직전에 기계 검사기로 가로채는 실행 지점이 정의되어 있지 않다. 따라서 AGENTS 자체 점검과 조건부 독립 검토는 제안할 수 있지만, 모든 답변의 U+00B7을 전송 전에 기계적으로 차단한다고 주장할 수는 없다. 해당 실행 지점이 제품에 제공되는지는 구현 전에 별도로 확인해야 한다.

## AGENTS에 전체 사례를 복사하는 방법은 권장하지 않는다

OpenAI의 프롬프트 지침은 개발자 메시지에 규칙과 예시를 함께 두고 다양한 입력과 원하는 출력을 보여 주는 방법을 설명한다. 예시는 채팅 답변의 문체를 유도하는 데 도움이 될 수 있다. 2026년 8월 1일에 현재 지침을 확인했다. [OpenAI의 프롬프트 구성 및 예시 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)

그러나 두 AGENTS 문서에 `korean.md`의 전체 실패 및 통과 사례를 복사하면 다음 문제가 생긴다.

- 모든 작업에서 긴 사례를 문맥에 넣어 토큰을 사용한다.
- 한국어와 영어 배포본, `korean.md` 가운데 한 파일만 수정되면 판정이 달라진다.
- 사례에 나온 단어를 금칙어로 오해하고 정상 전문용례까지 고칠 수 있다.
- 새 실패가 생길 때 세 파일을 함께 갱신해야 한다.

AGENTS에는 일반 산문의 U+00B7, 불명확한 `계약`, `경로`, `공개`, `좁히다`, `박다`와 사실을 더하지 않는 수식어를 짧은 검토 신호로만 제시하고, 판정과 대조 사례는 `korean.md`에 남겨야 한다. 다섯 단어는 닫힌 목록이 아니라 문맥별 판정의 예시라고 밝혀야 한다. 자세한 제안은 [한국어 용어 제한과 AGENTS 예시 배치 조사](./korean-terms-and-agent-examples-research.md)가 소유한다.

## 채팅 답변 검사 방안 비교

### 매 답변마다 독립 검토를 실행하는 방안

독립된 관점으로 문장을 확인할 수 있지만, 현재 스킬 절차에서는 짧은 답변도 초안 작성, 위임, 결과 종합과 재작성 단계를 거친다. 도구나 서브에이전트가 없는 환경에서는 실행할 수 없다. 단계 수가 늘어난다는 저장소 근거를 바탕으로, 오류 영향이 큰 답변에만 사용하는 방안을 제안한다. 실제 지연과 토큰 비용은 대표 실행에서 측정해야 한다.

### 서브에이전트가 없을 때 AGENTS의 자체 점검을 사용하는 방안

모든 답변에 적용하기 쉽고 추가 호출 비용이 없다. AGENTS에 고정 점검 질문과 짧은 실패 및 통과 사례를 직접 넣으면 스킬을 선택하지 않은 답변에도 기준을 전달할 수 있다. 그러나 같은 모델이 작성과 검토를 모두 맡으므로 자기 문장의 문제를 다시 놓칠 수 있고, 실행 기록만으로 의미 검토의 충실도를 입증하기 어렵다.

### AGENTS, 조건부 참조 로딩과 선택적 독립 검토를 결합하는 방안

세 수단을 결합하는 방안이 적합하다. AGENTS는 모든 한국어 답변의 짧은 자체 점검을 요구하고, 설명, 조사, 검토, 권고 또는 재사용할 문구를 만들 때 `korean.md`를 읽게 한다. `use-words-review`는 영향이 큰 답변과 사용자가 검토를 요청한 답변에 적용한다. 서브에이전트가 없으면 고정 점검 질문을 적용한 주 에이전트 자체 검토로 낮추되 생략하지 않는다. 상세 규칙은 한 파일에서 관리하면서도 짧은 대화의 비용을 제한할 수 있다.

## 실제 답변으로 동작을 검증해야 한다

OpenAI는 생성형 AI의 출력이 같은 입력에서도 달라질 수 있으므로 실제 사용 분포를 반영한 과제별 평가, 가능한 자동 검사와 사람 판단의 보정을 함께 사용하라고 안내한다. 2026년 8월 1일에 현재 지침을 확인했다. [OpenAI의 평가 설계 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

Anthropic은 대화형 에이전트의 완료 결과와 상호작용 품질을 함께 평가하고, 열린 답변의 모델 판정을 분야 전문가의 판단과 자주 비교해 평가 기준을 보정해야 한다고 설명한다. 2026년 1월 9일 공개본을 확인했다. [Anthropic의 대화형 에이전트 평가 지침](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

변경 뒤에는 파일 존재가 아니라 다음 응답 동작을 확인해야 한다.

- 한국어로 설명을 요청하면 답변 전 `korean.md`를 읽는다.
- 영어 AGENTS를 사용하는 저장소에서 한국어 산출물을 요청해도 같은 참조 자료를 읽는다.
- 짧은 확인 답변은 별도 서브에이전트 없이 자연스러운 한국어로 응답한다.
- 긴 조사 답변은 U+00B7, 추상적인 후보 용어와 정형화된 수식어를 찾아 문맥에 맞게 판정한다.
- 법률 계약, 파일 경로, 공개 키와 같은 정상 용례는 삭제하지 않는다.
- 사용자가 한국어 문구 검토를 요청하면 파일 변경이 없어도 `use-words-review`를 실행한다.
- 참조 파일이나 독립 검토 수단이 없으면 검토가 완료됐다고 주장하지 않고 제한을 알린다.
- 서브에이전트가 없는 실행에서도 주 에이전트가 고정 점검 질문을 적용하고, 일반 산문의 U+00B7과 대표 번역체를 고친 답변을 낸다.

평가에는 실패 사례와 정상 대조 사례를 함께 넣어야 한다. 정형화된 표현을 줄인 횟수만 세면 정확한 전문용어까지 삭제하는 과잉 수정을 찾을 수 없다. 이번 조사에서 사용할 초기 기대 판정은 [한국어 답변 검토 평가 사례](./korean-review-evaluation-cases.md)에 한 번 제시한다. 이는 후속 실행을 시작하기 위한 제안이며, 갱신한 체계를 적용한 결과로 보정해야 한다.

## 한계와 구현 전 판단

- AGENTS와 스킬 지침은 모델의 행동을 유도하지만 모든 답변의 준수를 보장하지 않는다. 모델, 문맥 압축과 도구 제공 방식이 바뀌면 다시 실행해야 한다.
- 답변을 보내기 전 자체 검토는 별도 실행 기록이 없을 수 있다. 대표 평가에서는 참조 파일 읽기와 독립 검토 호출을 도구 기록으로 확인하고, 최종 문장은 별도 판정으로 확인해야 한다.
- `korean.md`를 매 답변마다 다시 읽는 방식과 한 작업에서 처음 필요한 때 읽고 재사용하는 방식의 비용 차이는 아직 측정하지 않았다.
- 채팅 제품이 최종 문자열을 전송 직전에 검사하거나 차단하는 기능을 제공한다는 근거는 확인하지 못했다. AGENTS 지침만으로 기계적 차단을 보장할 수 없으며, 제품 수준의 전송 훅이 확인되면 별도 설계가 필요하다.
