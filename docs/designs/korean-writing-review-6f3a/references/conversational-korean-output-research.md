# 채팅 답변의 한국어 품질 적용 조사

## 조사 목적과 현재 누락

이 문서는 [한국어 문서 검토 재발 방지 요구사항의 목표](../requirements.md#목표)에 따라, 저장소 파일을 만들지 않는 채팅 답변에도 번역체, 정형화된 AI 문체와 일반 산문의 U+00B7 금지를 적용하는 방법을 조사한다. 두 배포용 AGENTS 문서와 `use-words-review`의 변경 담당자는 채팅 작성 규칙과 저장 결과물의 독립 검토를 구분해야 한다. 사용자가 특정 채팅 문구의 검토를 명시적으로 요청한 경우는 일반 채팅의 예외로 다룬다.

현재 두 배포용 AGENTS 문서는 모든 한국어 답변을 자체 점검하도록 요구하고, 요구사항이나 정책처럼 영향이 큰 답변에는 `use-words-review`를 실행하도록 지시한다. 현재 스킬 설명과 적용 범위도 영향이 큰 사용자 답변과 전송 전 검토를 포함한다. 이 구성에서는 일반 채팅과 저장 결과물의 구분이 없고, 답변 분류, 초안 작성, 서브에이전트 호출과 결과 대조가 반복될 수 있다.

## 채팅 답변의 기본 규칙은 AGENTS에 있어야 한다

Codex는 작업을 시작하기 전에 AGENTS 문서를 읽고, 저장소 루트부터 현재 디렉터리까지 발견한 지침을 순서대로 합친다. 프로젝트에서 나오는 답변 전체에 적용할 작성 조건은 선택된 뒤에만 본문을 읽는 스킬보다 AGENTS에서 먼저 전달하는 편이 적합하다. 2026년 8월 2일에 현재 문서를 확인했다. [OpenAI의 AGENTS.md 지침 로딩 문서](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

OpenAI Model Spec은 모델이 응답을 만들 때 적용 가능한 개발자와 사용자 지침을 식별해 따르도록 설명한다. 프로젝트 지침이 개발자 수준으로 전달되는 환경이라면 한국어 답변 규칙도 응답 생성에 영향을 줄 수 있다. 다만 공개 Model Spec은 목표 동작을 설명하며 현재 모델이 항상 그대로 동작한다고 보장하지 않는다. 2025년 12월 18일 판을 2026년 8월 2일에 확인했다. [OpenAI Model Spec의 지침 우선순위](https://model-spec.openai.com/2025-12-18.html#follow-all-applicable-instructions)

OpenAI의 프롬프트 지침은 개발자 메시지에 모델이 지켜야 할 규칙, 하지 말아야 할 행동, 원하는 입력과 출력의 예를 함께 둘 수 있다고 설명한다. 다양한 예시를 소수 제공하는 방식도 권한다. 이는 짧은 금지 규칙과 대조 사례를 AGENTS에 직접 넣는 방안을 뒷받침한다. 2026년 8월 2일에 현재 지침을 확인했다. [OpenAI의 프롬프트 구성 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)

따라서 두 AGENTS 문서에는 파일 변경 여부와 관계없이 적용되는 채팅 작성 조건을 직접 두되, 별도의 검토 단계로 표현하지 않는 방안을 제안한다.

- 각 문장은 대상, 행동 주체, 행동, 조건과 결과를 독자가 구분할 수 있게 처음부터 작성한다.
- 일반 산문의 U+00B7, 낱말 단위 번역, 사실을 더하지 않는 수식어와 같은 짜임을 반복하는 문단을 사용하지 않는다.
- 짧은 진행 알림은 확인한 사실과 다음 행동만 직접 적고, 답을 되풀이하는 도입이나 작업 절차 보고를 덧붙이지 않는다.
- 일반 채팅 때문에 `references/korean.md`를 읽거나 `use-words-review`를 실행하지 않는다.

`src/AGENTS.en.md`에서는 영어 지침을 사용하는 저장소라도 한국어 결과물을 작성할 때 같은 조건이 적용된다고 적어야 한다. 영어 답변 전체에 한국어 기준을 적용하거나, 현재 언어 규칙을 한국어로 바꾸는 뜻으로 쓰면 안 된다.

## `korean.md`와 스킬은 저장 결과물의 상세 검토 수단이다

OpenAI의 스킬 문서는 ChatGPT와 Codex가 스킬 이름과 설명을 먼저 보고, 필요하다고 판단한 뒤 `SKILL.md`를 읽는다고 설명한다. 스킬을 선택하지 않으면 보조 자료도 자동으로 읽히지 않는다. 2026년 8월 2일에 현재 문서를 확인했다. [OpenAI의 스킬 로딩 지침](https://learn.chatgpt.com/docs/build-skills)

Anthropic도 스킬 설명, 본문과 보조 자료를 단계적으로 읽는 구조를 설명하고, 실제 작업에서 스킬이 예상과 다르게 선택되는지 관찰하라고 권한다. 이 구조는 상세 사례를 `korean.md`에 유지하는 근거가 되지만, 매 채팅 답변에서 자동으로 적용된다는 증거는 아니다. 2025년 10월 16일 공개되고 2025년 12월 18일에 공개 명세 안내가 추가된 자료를 확인했다. [Anthropic의 Agent Skills 구조 설명](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

이 단계적 로딩은 상세 사례를 `korean.md`에 유지하고, 저장할 한국어 결과물을 검토할 때만 읽는 구성을 뒷받침한다. AGENTS에는 채팅을 작성할 때 필요한 최소 규칙과 대표 신호만 남긴다.

### 일반 채팅에는 별도 검토를 실행하지 않는다

OpenAI의 지연 최적화 지침은 독립된 모델 요청마다 왕복 지연이 추가되므로 요청 횟수를 줄이라고 안내한다. 현재 스킬도 독립 검토마다 별도 서브에이전트를 호출하고 주 에이전트가 결과를 대조하도록 요구한다. 입력 지침을 줄이는 것만으로 얻는 지연 감소는 제한적일 수 있으므로, AGENTS를 지나치게 늘리는 것보다 일반 채팅의 별도 검토 호출을 없애는 변경이 먼저다. 2026년 8월 2일에 현재 지침을 확인했다. [OpenAI의 지연 최적화 지침](https://developers.openai.com/api/docs/guides/latency-optimization)

AGENTS는 다음 작성 조건을 짧게 직접 요구해야 한다.

1. 확인한 사실, 결정과 다음 행동을 직접 쓴다.
2. 대상, 행동 주체, 행동, 조건과 결과가 필요한 문장에서는 그 관계를 생략하지 않는다.
3. 일반 산문의 U+00B7, 낱말 단위 번역과 사실을 더하지 않는 수식어를 사용하지 않는다.
4. 진행 알림과 짧은 확인에 형식적인 도입, 결론과 검토 보고를 덧붙이지 않는다.

AGENTS에 넣는 대표 신호는 다음 범위가 적합하다.

- 일반 산문에 U+00B7이 남았는가? 남았다면 정확한 원문, 이름, 코드, 검증 입력을 보존하는 경우인가?
- 대상, 행동 주체, 행동, 조건과 결과를 독자가 구분할 수 있는가?
- 영어 낱말을 고정된 한국어로 옮긴 결과 실제 동작이 감춰졌는가?
- 사실을 더하지 않는 수식어, 상투적인 도입과 결론, 내용과 무관한 세 항목 묶음, 같은 문단 구조의 반복이 있는가?
- 후보 용어가 분야에서 확립됐고 문맥이 충분한가? 그렇지 않다면 저장소 근거로 실제 행동을 적었는가?

이 조건은 검토 보고서를 만들라는 뜻이 아니다. 점검 과정을 출력하면 짧은 진행 알림까지 상투적인 작업 보고가 될 수 있다. AGENTS는 작성 결과만 사용자에게 보내도록 해야 한다.

### 저장하거나 전달할 결과물에는 `use-words-review`를 적용한다

다음 결과물은 완성된 공유 단위로 묶어 저장, 커밋, 게시 또는 전달하기 전에 `use-words-review`의 읽기 전용 의미 검토를 적용한다.

- AI가 만들거나 고친 한국어 문서
- 커밋, 풀 리퀘스트, 이슈, 릴리스 안내와 같이 저장하거나 게시할 문구
- 화면 문구, 코드 주석과 같이 애플리케이션 저장소에 기록할 한국어
- 채팅에서 작성했지만 그대로 저장하거나 외부에 전달할 초안
- 사용자가 채팅에서 특정 문구의 검토를 명시적으로 요청한 경우

일반적인 요구사항 설명, 조사 결과나 보안 관련 안내도 대화로만 전달된다면 스킬 호출 조건이 아니다. 내용의 종류나 답변 길이로 분류하지 않고, 문구가 저장 또는 전달될 결과물인지로 구분해야 추가 분류 비용과 해석 차이를 줄일 수 있다.

저장 결과물이나 명시적인 문구 검토 요청에서 독립 검토 수단을 사용할 수 없으면 스킬의 주 에이전트 대체 절차를 따르고 독립 검토를 수행하지 못한 사실을 결과에 밝힌다. 일반 채팅에는 이 대체 절차도 실행하지 않는다.

현재 저장소 지침에는 사용자가 보게 될 채팅 문자열을 전송 직전에 기계 검사기로 가로채는 실행 지점이 정의되어 있지 않다. AGENTS 작성 규칙은 문장 생성에 영향을 줄 수 있지만, 모든 답변의 U+00B7을 전송 전에 기계적으로 차단한다고 주장할 수는 없다.

## AGENTS에 전체 사례를 복사하는 방법은 권장하지 않는다

OpenAI의 프롬프트 지침은 개발자 메시지에 규칙과 예시를 함께 두고 다양한 입력과 원하는 출력을 보여 주는 방법을 설명한다. 예시는 채팅 답변의 문체를 유도하는 데 도움이 될 수 있다. 2026년 8월 2일에 현재 지침을 확인했다. [OpenAI의 프롬프트 구성 및 예시 지침](https://developers.openai.com/api/docs/guides/prompt-engineering)

그러나 두 AGENTS 문서에 `korean.md`의 전체 실패 및 통과 사례를 복사하면 다음 문제가 생긴다.

- 모든 작업에서 긴 사례를 문맥에 넣어 토큰을 사용한다.
- 한국어와 영어 배포본, `korean.md` 가운데 한 파일만 수정되면 판정이 달라진다.
- 사례에 나온 단어를 금칙어로 오해하고 정상 전문용례까지 고칠 수 있다.
- 새 실패가 생길 때 세 파일을 함께 갱신해야 한다.

AGENTS에는 일반 산문의 U+00B7, 불명확한 `계약`, `경로`, `공개`, `좁히다`, `박다`와 사실을 더하지 않는 수식어를 짧은 검토 신호로만 제시하고, 판정과 대조 사례는 `korean.md`에 남겨야 한다. 다섯 단어는 닫힌 목록이 아니라 문맥별 판정의 예시라고 밝혀야 한다. 자세한 제안은 [한국어 용어 제한과 AGENTS 예시 배치 조사](./korean-terms-and-agent-examples-research.md)가 소유한다.

## 채팅과 저장 결과물의 검사 방안 비교

### 매 답변마다 독립 검토를 실행하는 방안

독립된 관점으로 문장을 확인할 수 있지만, 현재 스킬 절차에서는 짧은 답변도 초안 작성, 위임, 결과 종합과 재작성 단계를 거친다. 중간 진행 알림을 같은 방식으로 가로채는 실행 지점도 확인되지 않았다. 일반 채팅에는 적용하지 않는다.

### AGENTS에 채팅 작성 규칙을 두는 방안

작업 시작 시 읽는 지침에 짧은 규칙과 대표 신호를 두면 중간 메시지와 최종 답변을 생성할 때 같은 기준을 전달할 수 있다. 추가 호출은 없지만 지침이 전송 직전 검사를 강제하지는 않으므로 실제 출력 평가가 필요하다.

### 채팅 작성과 저장 결과물 검토를 분리하는 방안

AGENTS는 채팅의 짧은 작성 조건을 소유하고, `korean.md`와 `use-words-review`는 저장하거나 전달할 결과물의 상세 검토를 소유한다. 사용자가 특정 채팅 문구의 검토를 명시적으로 요청한 경우만 채팅 예외로 둔다. 이 구분은 [한국어 채팅과 저장 결과물의 검토 구분](../decisions/chat-and-stored-output-review-boundary.md)에 승인된 결정으로 기록했다.

## 실제 답변으로 동작을 검증해야 한다

OpenAI는 생성형 AI의 출력이 같은 입력에서도 달라질 수 있으므로 실제 사용 분포를 반영한 과제별 평가, 가능한 자동 검사와 사람 판단의 보정을 함께 사용하라고 안내한다. 2026년 8월 2일에 현재 지침을 확인했다. [OpenAI의 평가 설계 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

Anthropic은 대화형 에이전트의 완료 결과와 상호작용 품질을 함께 평가하고, 열린 답변의 모델 판정을 분야 전문가의 판단과 자주 비교해 평가 기준을 보정해야 한다고 설명한다. 2026년 1월 9일 공개본을 확인했다. [Anthropic의 대화형 에이전트 평가 지침](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

변경 뒤에는 파일 존재가 아니라 다음 응답 동작을 확인해야 한다.

- 한국어 설명, 진행 알림과 최종 답변에서는 `korean.md`와 `use-words-review`를 호출하지 않는다.
- 중간 진행 알림과 최종 답변이 AGENTS의 한국어 작성 조건을 지킨다.
- 영어 AGENTS를 사용하는 저장소에서도 일반 한국어 채팅에는 같은 작성 조건이 적용된다.
- 한국어 문서를 저장하거나 공유하기 전에는 `korean.md`를 읽고 `use-words-review`를 한 번 실행한다.
- 법률 계약, 파일 경로, 공개 키와 같은 정상 용례는 삭제하지 않는다.
- 사용자가 한국어 문구 검토를 요청하면 파일 변경이 없어도 `use-words-review`를 실행한다.
- 저장 결과물이나 명시적인 검토 요청에서 독립 검토 수단이 없으면 검토가 완료됐다고 주장하지 않고 제한을 알린다.

평가에는 실패 사례와 정상 대조 사례를 함께 넣어야 한다. 정형화된 표현을 줄인 횟수만 세면 정확한 전문용어까지 삭제하는 과잉 수정을 찾을 수 없다. 이번 조사에서 사용할 초기 기대 판정은 [한국어 답변 검토 평가 사례](./korean-review-evaluation-cases.md)에 한 번 제시한다. 이는 후속 실행을 시작하기 위한 제안이며, 갱신한 체계를 적용한 결과로 보정해야 한다.

## 한계와 구현 전 판단

- AGENTS와 스킬 지침은 모델의 행동을 유도하지만 모든 답변의 준수를 보장하지 않는다. 모델, 문맥 압축과 도구 제공 방식이 바뀌면 다시 실행해야 한다.
- AGENTS의 작성 규칙이 각 문장에 적용됐는지 별도 실행 기록으로 입증할 수 없다. 대표 평가에서는 최종 문장을 별도 판정해야 한다.
- 일반 채팅에서 추가 검토 호출을 없애면 요청 단계는 줄어들지만 실제 지연 감소량은 실행 환경에 따라 달라진다. 같은 대표 과제에서 호출 기록과 제공되는 경과 시간을 함께 확인해야 한다.
- 채팅 제품이 최종 문자열을 전송 직전에 검사하거나 차단하는 기능을 제공한다는 근거는 확인하지 못했다. AGENTS 지침만으로 기계적 차단을 보장할 수 없으며, 제품 수준의 전송 훅이 확인되면 별도 설계가 필요하다.
