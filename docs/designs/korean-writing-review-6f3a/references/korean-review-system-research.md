# 한국어 작성 기준을 실제 검토로 연결하는 방법

## 조사 질문과 적용 범위

이 문서는 [한국어 문서 검토 재발 방지 요구사항의 목표](../requirements.md#목표)에 따라, 한국어 작성 기준이 이미 있는데도 가운뎃점과 뜻이 모호한 표현이 남는 원인을 조사한다. 이후 `use-words-review`와 배포용 AGENTS 문서를 고칠 담당자가 어느 파일에서 어떤 책임을 관리할지 판단하는 데 필요한 근거를 제공한다.

일반적인 한국어 판정 원칙은 기존 [번역투와 정형화된 AI 문체 조사](../../public-output-audience-4d2c/references/natural-korean-and-ai-writing-research.md)가 소유한다. 이 문서는 작성 시점의 지침 로딩, 공유 전 검토 호출, 기계 검사와 의미 검토의 분담, 복사 설치 뒤의 확인 방법만 다룬다.

조사자는 2026년 8월 1일에 현재 저장소 파일, 공식 문서와 공개된 원문 자료를 확인했다. 외부 자료는 한국어 문장부호 규범, 한국어 현지화 지침, 에이전트 지침 로딩 방식, 스킬의 단계별 로딩 방식, 문장 검사 도구와 평가 설계 자료로 나누어 대조했다.

## 현재 구조의 실패 지점

### 한국어 기준이 없어서 생긴 문제는 아니다

`AGENTS.md`의 `Writing Natural Korean` 절과 `skills/use-words-review/references/korean.md`에는 직역, 불분명한 전문용어, 행동을 감추는 동사와 장식적인 평가 표현을 문맥으로 판정하는 규칙이 이미 있다. `skills/use-words-review/SKILL.md`도 한국어 결과물을 검토할 때 `references/korean.md`를 읽도록 명시한다.

문제는 `SKILL.md`가 스킬이 호출된 뒤의 절차만 정한다는 점이다. 현재 루트 `AGENTS.md`에는 `use-words-review` 호출 구간이 없고, 배포용 `src/AGENTS.ko.md`와 `src/AGENTS.en.md`의 표시 구간은 공유 직전 스킬 호출만 요구한다. 작성 중인 에이전트가 스킬을 호출하지 않으면 한국어 참조 자료도 읽지 않는다. 따라서 기준의 내용보다 호출이 시작되는 조건을 먼저 고쳐야 한다.

### 복사 설치는 지침과 스킬의 버전을 갈라놓을 수 있다

`README.md`와 `README.ko.md`는 스킬 디렉터리와 배포용 AGENTS의 표시 구간을 각각 복사하도록 안내한다. 이 저장소는 대상 저장소의 AGENTS 문서를 자동으로 만들거나 합치지 않으며, 두 언어의 배포 문서도 같은 규칙을 가진다고 보장하지 않는다. 사용자가 스킬만 갱신하거나 AGENTS 구간만 갱신하면 호출 조건과 상세 판정 기준이 서로 다른 시점의 내용으로 남을 수 있다.

복사 설치 자체를 없애지 않더라도 설치 뒤 다음 세 가지를 확인해야 한다.

1. 도구가 실제로 읽는 AGENTS 문서에 `use-words-review` 호출 구간이 있는지 확인한다.
2. 호출 구간이 가리키는 설치된 스킬에 `references/korean.md`가 있는지 확인한다.
3. 한국어 결과물을 만든 대표 작업에서 작성 전 참조와 공유 전 검토가 모두 실행됐는지 확인한다.

## 가운뎃점은 저장소 작성 규칙으로 제한할 수 있다

국립국어원 `한글 맞춤법`의 문장 부호 규정은 같은 계열의 어구나 공통 성분을 줄여 묶을 때 가운뎃점을 쓸 수 있다고 설명하면서, 해당 용례에서 쉼표를 쓰거나 부호를 생략할 수 있다고 명시한다. 특정 날짜 표기에서는 컴퓨터 자판 입력이 편리하다는 점을 들어 마침표를 원칙으로 바꾼 이유도 설명한다. 2026년 8월 1일에 현재 규정과 해설을 확인했다. [국립국어원 한글 맞춤법의 문장 부호 규정](https://korean.go.kr/kornorms/regltn/regltnView.do?regltn_code=0001)

따라서 가운뎃점이 한국어 규범에 맞는 문장부호라는 사실과 이 저장소가 입력하기 쉬운 문장부호를 선택하는 일은 충돌하지 않는다. 이 저장소는 일반 산문에서 가운뎃점 대신 쉼표, 조사 또는 문장 분리를 쓰는 작성 규칙을 둘 수 있다. 다만 다음 경우에는 문자를 자동으로 바꾸지 않고 원문 보존 필요성을 먼저 확인해야 한다.

- 승인된 화면 문구나 인용문에서 문자가 원문의 일부인 경우
- 수식, 제품명, 표준 표기나 시험 입력에서 정확한 문자가 필요한 경우
- 코드, 정규식 또는 문자 처리 검증에서 해당 코드 포인트 자체가 대상인 경우

가운뎃점 문자는 정확한 패턴으로 찾을 수 있으므로 공유 전 기계 검사 대상으로 적합하다. [일반 산문 문장부호와 문맥별 용어 판정](../decisions/general-prose-and-contextual-wording.md)은 일반 산문에서 U+00B7을 사용하지 않기로 정했다. 검사는 변경한 산문에서 문자를 찾고 예외 목적이 확인되지 않은 항목을 `needs revision`으로 보고해야 한다. 자동 치환은 원문, 코드와 시험 입력을 손상할 수 있으므로 기본 동작으로 사용하지 않는다.

## 번역체는 단어 치환으로 해결할 수 없다

Microsoft의 한국어 현지화 스타일 가이드는 대상 독자와 문장의 의도를 먼저 파악하고, 표준 번역어를 그대로 쓰는 것보다 한국어 독자가 작업을 마치는 데 필요한 내용을 자연스럽게 다시 쓰도록 안내한다. 낱말 단위 번역은 문단과 화면의 문맥을 잃으므로 필요하면 문장을 나누거나 불필요한 수식어를 덜어 내라고 설명한다. PDF 메타데이터의 최종 수정일은 2024년 9월 5일이며, Microsoft의 공식 배포본을 2026년 8월 1일에 확인했다. [Microsoft 한국어 현지화 스타일 가이드](https://aka.ms/korean-styleguide)

이 근거는 `공개`, `경로`, `계약`, `지원` 같은 단어를 일괄 금지하는 방법보다 문장이 가리키는 대상과 행동을 확인하는 현재 `korean.md`의 방향을 뒷받침한다. 법률 계약, 파일 위치, 누구나 읽을 수 있는 저장소처럼 뜻과 조건이 드러난 용례는 유지해야 한다. 반대로 `측정 계약`, `경험 확보 경로`처럼 규칙이나 방법을 한 단어로 압축한 문장은 독자가 실제 행동과 조건을 알 수 있는 표현으로 다시 써야 한다.

Vale는 정규식 기반 규칙으로 특정 표현의 존재, 치환 후보, 반복과 일관성을 검사하고, 규칙마다 적용 범위와 예외를 정할 수 있다. 프로젝트별 허용어와 피해야 할 표현도 별도 어휘 목록으로 관리한다. 2026년 8월 1일에 현재 문서를 확인했다.

- [Vale 스타일과 규칙](https://docs.vale.sh/topics/styles)은 YAML 규칙이 문서 형식과 적용 범위를 구분해 검사할 수 있음을 설명한다.
- [Vale 치환 검사](https://docs.vale.sh/checks/substitution)는 정규식, 추천 표현과 예외를 함께 정의할 수 있음을 설명한다.
- [Vale 프로젝트 어휘](https://docs.vale.sh/keys/vocabularies)는 허용 목록과 거부 목록을 독립적으로 관리하고 대소문자 및 정규식 예외를 적용하는 방법을 설명한다.

Vale와 같은 검사는 가운뎃점, 미완성 표시, 개인 절대 경로와 정해진 표기처럼 문자만으로 판정할 수 있는 항목에 알맞다. `계약`이나 `경로`의 뜻, 문장 사이의 관계와 독자에게 필요한 설명은 정규식으로 확정할 수 없다. 이 표현들은 기계 검사의 오류가 아니라 의미 검토의 후보로만 전달해야 한다.

## AGENTS에서 `korean.md`를 직접 가리키는 방안이 적합하다

Codex는 작업을 시작하기 전에 `AGENTS.md`를 읽고, 저장소 루트부터 현재 디렉터리까지 발견한 지침을 순서대로 합친다. 루트 지침은 저장소 전체 작업의 시작 조건을 전달하기에 적합하다. 2026년 8월 1일에 현재 문서를 확인했다. [OpenAI의 AGENTS.md 지침 로딩 문서](https://developers.openai.com/codex/guides/agents-md)

Anthropic의 Agent Skills 설명은 모든 스킬의 이름과 설명만 먼저 읽고, 선택한 스킬의 `SKILL.md`와 필요한 보조 자료를 단계적으로 불러오는 구조를 제시한다. 자세한 한국어 용례를 AGENTS 문서에 복사하지 않고 스킬의 참조 파일에 유지하는 현재 구조와 맞는다. 2025년 10월 16일 공개되고 2025년 12월 18일에 공개 명세 안내가 추가된 자료를 확인했다. [Anthropic의 Agent Skills 구조 설명](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)

두 근거를 함께 적용하면, AGENTS 문서에는 짧은 호출 조건과 참조 파일 이름을 직접 적고 상세 판정 기준은 `korean.md` 한 곳에서 관리하는 구성이 적합하다. 조사자는 배포용 표시 구간에 다음 의미를 추가하는 방안을 제안한다.

- 커밋하거나 공유할 한국어 글이나 이름을 작성하거나 바꾸기 전에 설치된 `use-words-review`의 `references/korean.md`를 읽는다. 파일을 바꾸지 않는 채팅 답변의 로딩 조건은 [채팅 답변의 한국어 품질 적용 조사](./conversational-korean-output-research.md)를 따른다.
- 같은 공유 단위의 변경을 마친 뒤 `use-words-review`로 검토하고, 스킬이 같은 참조 파일을 한국어 부분에 적용하게 한다.
- 용어별 허용 조건과 전체 대조 사례는 AGENTS 문서에 복사하지 않는다. 놓치기 쉬운 표현은 짧은 검토 신호로만 제시한다.

`src/AGENTS.ko.md`만 고치면 영어 배포 문서를 선택한 저장소에서 한국어 결과물을 만들 때 같은 누락이 반복될 수 있다. 따라서 조사자는 두 배포 문서의 표시 구간과 이 저장소가 실제 사용하는 루트 `AGENTS.md`를 함께 검토하는 방안을 제안한다. 문장 단위로 번역할 필요는 없지만, 한국어 결과물이 생겼을 때 같은 참조 자료를 읽고 같은 검토를 실행한다는 조건은 세 파일에서 확인해야 한다.

## 실패 사례를 회귀 평가로 바꾸는 방안을 제안한다

OpenAI의 평가 지침은 실제 사용 분포에 맞는 과제별 평가를 만들고, 가능한 검사는 자동화하되 사람의 판단으로 점수를 보정하며, 운영에서 발견한 사례를 계속 평가 자료에 추가하라고 안내한다. 2026년 8월 1일에 현재 지침을 확인했다. [OpenAI의 평가 설계 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)

Anthropic의 에이전트 평가 지침은 실제 실패에서 시작한 20개에서 50개의 작은 평가 과제로도 초기 개선을 확인할 수 있다고 설명한다. 기계 판정이 가능한 항목은 결정적인 검사로 확인하고, 정답이 하나로 정해지지 않는 문장 품질은 명확한 평가 기준을 사용하는 모델 검토와 승인받은 기대 판정으로 보정하라고 권한다. 2026년 1월 9일 공개된 자료를 확인했다. [Anthropic의 에이전트 평가 설계 지침](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

현재 `examples.md`는 의미가 끊긴 문장과 정상 문장을 판정하는 예시를 제공하지만, 가운뎃점이 대량으로 들어간 문서와 한국어 참조 자료를 읽지 않은 호출 자체를 검증하지 않는다. 이후 변경에서는 [한국어 답변 검토 평가 사례](./korean-review-evaluation-cases.md)를 시작점으로 다음 평가를 같은 묶음에서 실행한다.

- **문자 검사:** 일반 산문에 가운뎃점이 있으면 실패하고, 코드 포인트를 설명하는 최소 재현 입력은 보존한다.
- **문맥 판정:** `계약`, `경로`, `공개`가 정확한 전문용어인 정상 문장과 행동을 감춘 실패 문장을 모두 포함한다.
- **호출 검사:** 한국어 결과물을 만드는 작업에서 AGENTS 지침이 `korean.md`를 작성 전에 읽게 하고, 공유 전에 스킬을 호출하게 하는지 확인한다.
- **회귀 검사:** 기존 `examples.md`의 정상 대조문이 새 규칙 때문에 실패하지 않는지 확인한다.
- **검수 결과 보정:** 초기 사례는 현재 설정의 실패를 찾는 데 바로 사용한다. 다른 모델이나 더 가벼운 추론 설정의 채택은 기대 판정과 지적 위치를 승인할 역할이 저장소 근거에서 확인되지 않았으므로 `needs human input`으로 남기고 현재 설정을 유지한다.

## 파일별 개선 제안

다음 내용은 조사 결론을 바탕으로 한 제안이며 승인된 변경 결정이 아니다.

### `AGENTS.md`

이 저장소가 실제로 사용하는 루트 지침에도 배포용 문서와 같은 호출 구간을 두고, 커밋하거나 공유할 한국어 글이나 이름을 작성하기 전에 설치된 스킬의 `references/korean.md`를 읽도록 적는다. 상세 판정 규칙은 복사하지 않는다. 채팅 답변은 별도 조사 문서가 정한 조건부 로딩과 자체 점검을 적용한다.

### `src/AGENTS.ko.md`와 `src/AGENTS.en.md`

기존 표시 구간에 `references/korean.md`의 파일명을 직접 적고 작성 전 읽기와 공유 전 검토를 구분한다. 한국어 배포 문서만 수정하지 말고, 영어 배포 문서를 선택한 저장소가 커밋하거나 공유할 한국어 글이나 이름을 만들 때도 같은 조건이 적용되는지 확인한다.

파일을 바꾸지 않는 채팅 답변까지 적용할 조건과 AGENTS에 둘 짧은 예시의 범위는 [채팅 답변의 한국어 품질 적용 조사](./conversational-korean-output-research.md)와 [한국어 용어 제한과 AGENTS 예시 배치 조사](./korean-terms-and-agent-examples-research.md)가 설명한다.

### `skills/use-words-review/SKILL.md`

한국어 결과물이 있으면 `korean.md`를 선택 사항이 아니라 필수 참조로 읽었다는 사실을 검토 입력과 보고에 남긴다. 독립 의미 검토 전에 변경 산문에서 가운뎃점을 찾고, 보존 목적을 확인할 수 없는 항목을 보고하도록 한다. 단어 후보는 자동 실패로 바꾸지 않는다.

### `skills/use-words-review/references/korean.md`

문장부호 절을 추가해 일반 산문에서는 가운뎃점 대신 쉼표, 조사나 문장 분리를 쓰고, 정확한 문자 보존이 필요한 경우만 예외로 판정하도록 한다. `계약`, `경로`, `공개`와 비슷한 표현은 문제 사례와 정상 전문용례를 함께 유지한다.

용어별 허용 조건, `좁히다`와 `박다`를 포함한 대조 사례와 현재 문서에서 보강할 위치는 [한국어 용어 제한과 AGENTS 예시 배치 조사](./korean-terms-and-agent-examples-research.md)가 설명한다.

### `skills/use-words-review/references/examples.md`

이 파일은 언어 공통 사례를 계속 소유한다. 가운뎃점 일반 산문, 정확한 문자 표기, 전문용어 정상 용례와 행동을 감춘 번역체의 한국어 대조 사례는 `korean.md`에 둔다. 작성 전 참조 로딩과 공유 전 스킬 호출은 문장 판정 사례가 아니므로 구현 계획의 실행 검증 또는 승인된 별도 평가 자료에서 확인한다.

## 요구사항과 이후 작업에 미치는 영향

일반 산문의 U+00B7 금지와 용어 수를 고정하지 않는 문맥별 판정은 승인됐다. 이후 계획은 AGENTS 호출 조건, 스킬의 기계 검사, 한국어 문장부호 기준, 대조 사례와 설치 확인을 하나의 변경 단위로 다뤄야 한다. 한 파일만 고치면 복사 설치된 저장소에서 다시 연결이 끊길 수 있다. 구현 결과는 문서 변경만으로 증명하지 않고, 한국어 결과물을 실제로 작성하고 검토하는 에이전트 실행으로 확인해야 한다.

## 한계와 남은 판단

- 공식 자료는 AGENTS와 스킬이 지침을 단계적으로 읽는 방법을 설명하지만, 모든 에이전트가 지시를 항상 실행한다는 결과를 제공하지 않는다.
- 예시 저장소 한 곳에서 관찰한 빈도는 다른 저장소의 발생률을 예측하지 못한다.
- Microsoft 자료는 제품 현지화 지침이므로 모든 설계 문서의 문체를 그대로 정하지 않는다. 낱말 단위 번역을 피하고 독자와 의도를 확인하는 원칙만 현재 문제와 직접 연결된다.
- 가운뎃점 제한은 국립국어원의 맞춤법 판정이 아니라 이 저장소에서 복사해 쓰는 문서 체계의 작성 방식이다. 다른 체계의 일반 한국어 규칙으로 확대하려면 별도 결정이 필요하다.
- `korean.md`를 작성 전에 읽으면 입력 토큰이 늘어난다. 초기 사례로 실패와 비용을 탐색할 수 있지만, 다른 모델이나 더 가벼운 설정은 기대 판정의 승인 역할이 정해지기 전까지 채택할 수 없다. 현재 자료만으로 절감률이나 개선률을 단정할 수 없다.
