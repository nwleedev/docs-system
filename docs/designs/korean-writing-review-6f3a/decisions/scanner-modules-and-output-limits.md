# 한국어 검사기의 모듈과 출력 상한

## 결정이 필요한 이유

[한국어 문서 검토 재발 방지 요구사항](../requirements.md)은 후보 표현과 긴 문단을 같은 실행에서 검사하고, 모든 후보를 센 뒤 제한된 상세 경고와 생략 수를 제공해야 한다. 두 검사는 원문을 함께 사용하지만 규칙 자료, 탐지 방법과 결과 증가 양상이 다르다. 단일 실행 파일에 두 탐지 책임을 계속 두면 파일별 역할이 흐려지고, 한 검사의 경고가 많을 때 다른 검사의 상세 결과가 전체 상한에서 밀릴 수 있다.

## 검토한 선택지

단일 파일과 전체 출력 상한을 유지하는 방법, 실행 진입점과 두 탐지 모듈을 나누되 전체 상한을 공유하는 방법, 세 파일로 나누고 검사별 상한과 집계를 제공하는 방법을 비교했다.

`scan.mjs`, `korean-expressions.mjs`와 `korean-paragraphs.mjs`는 모두 문법적으로 가능한 이름이다. 다만 세 번째 모듈은 한국어 문단 전체가 아니라 길이 기준에 해당하는 Markdown 플레인 텍스트 문단을 찾으므로 `long-paragraphs.mjs`가 실제 책임을 더 정확하게 나타낸다.

## 승인된 결정

`scan.mjs`는 명령줄 인수, 입력, 전체 실행, 결과 조립, 직렬화, 표준 오류 메시지와 self-test를 맡는다. `korean-expressions.mjs`는 외부에서 선택할 수 없는 표현 규칙과 모든 literal 출현 탐색을 맡는다. `long-paragraphs.mjs`는 Markdown 플레인 텍스트 문단 구분, 문장 수 계산과 긴 문단 후보 탐색을 맡는다.

`scan.mjs`만 두 탐지 모듈을 정적 import할 수 있다. 정확한 두 상대 위치 이외의 로컬 import, 외부 package import와 동적 import는 허용하지 않는다. 두 탐지 모듈은 진입점이나 서로를 import하지 않는다.

표준 출력은 단일 JSON 객체를 유지하고 `sources`와 `checks`를 제공한다. `checks`는 표현 검사와 긴 문단 검사 순서를 유지하며, 각 결과는 `id`, `catalog`, `rules`, `warnings`와 `summary`를 독립적으로 가진다. 각 검사는 모든 후보를 끝까지 센다. 상세 경고는 검사마다 최대 20,000개, 직렬화한 검사 결과는 검사마다 최대 32 MiB다. 각 `summary`는 `total`, `shown`과 `omitted`를 제공한다.

## 결정 이유

세 파일은 실행 환경의 부수 효과, 표현 규칙과 Markdown 문단 판정을 서로 다른 변경 이유에 맞춰 나눈다. `long-paragraphs.mjs`는 검사 대상의 언어보다 실제 탐지 조건을 이름에 드러낸다. 검사별 상한은 한 검사의 많은 경고가 다른 검사의 상세 결과를 없애지 않게 하며, 각 집계가 어느 검사에서 생략됐는지 바로 보여 준다.

정적 import 두 개만 허용하면 모든 정상 실행에서 두 탐지기를 확인하고 실행할 수 있다. 스크립트 위치 전체의 import 금지를 풀지 않으므로 이후 추가되는 파일이 같은 예외를 자동으로 받지 않는다.

## 예상되는 영향

기존 `scan-korean-expressions.mjs`를 `scan.mjs` 진입점과 두 탐지 모듈로 나눈다. `SKILL.md`와 두 배포용 AGENTS 문서는 새 진입점만 실행하도록 바꾼다. `eslint.config.mjs`는 `scan.mjs`의 정확한 위치에서 두 승인된 상대 import만 허용하고, 다른 파일의 기존 제한을 유지한다.

기존 전체 `catalog`, `rules`, `warnings`와 `summary`는 검사별 결과로 이동한다. self-test는 두 검사의 경고 수 및 byte 상한, 독립된 전체 및 생략 수, 고정된 검사 결과 순서와 온전한 단일 JSON 출력을 각각 확인해야 한다.

## 다시 검토할 조건

두 탐지 모듈에서 입력과 반환 의미가 같은 계산이 실제로 중복될 때에만 책임이 드러나는 공용 계산 모듈을 검토한다. 단일 JSON의 메모리 사용량이나 첫 출력 지연이 측정 가능한 문제가 되거나 완료 전에 경고를 소비할 필요가 생기면 JSONL을 다시 비교한다. 한 검사에서 20,000개 또는 32 MiB의 축약이 반복되어 의미 검토에 필요한 경고를 안정적으로 가리면 상한과 정렬 기준을 다시 검토한다.
