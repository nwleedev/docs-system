# 한국어 채팅 작성과 저장 결과물 검토 변경 계획

## 기준 문서와 적용 범위

이 계획은 [한국어 문서 검토 재발 방지 요구사항](./requirements.md)의 `목표`, `적용 조건`과 `완료 증거`를 기준으로 한다. 일반 산문의 문자와 문맥별 용어 판정은 [일반 산문 문장부호와 문맥별 용어 판정](./decisions/general-prose-and-contextual-wording.md)을 따르고, 채팅과 저장 결과물의 검토 범위는 [한국어 채팅과 저장 결과물의 검토 구분](./decisions/chat-and-stored-output-review-boundary.md)을 따른다.

이번 변경은 배포용 AGENTS 문서, `use-words-review` 스킬과 이 설계 패키지를 대상으로 한다. 애플리케이션 코드, 실행 환경과 제품 기능은 바꾸지 않으므로 `docs/dev/` 아래의 개발 지침은 적용하지 않는다.

## 실행 순서

### 설계 기준과 평가 사례를 먼저 맞춘다

구현 담당자가 채팅의 종류나 답변 길이로 검토 여부를 다시 판단하지 않도록 승인된 구분을 설계 문서에 먼저 반영한다.

- `requirements.md`에는 일반 채팅에서 스킬을 실행하지 않는 조건, 저장하거나 전달할 결과물의 검토 조건과 명시적인 채팅 문구 검토 예외를 기록한다.
- `decisions/chat-and-stored-output-review-boundary.md`에는 검토한 선택지, 승인된 구분, 예상 영향과 다시 검토할 조건을 기록한다.
- `references/conversational-korean-output-research.md`에서는 영향이 큰 채팅 답변을 스킬로 검토하던 기존 권고를 폐기하고, AGENTS의 채팅 작성 규칙과 저장 결과물의 독립 검토를 구분한다.
- `references/korean-review-evaluation-cases.md`에는 일반 채팅, 저장 결과물, 명시적인 문구 검토 요청과 채팅에서 작성한 저장 예정 문구의 실행 사례를 둔다.

**완료 증거.** 네 문서가 같은 검토 구분을 사용하고, 일반 채팅에 독립 검토를 요구하는 상충 문장이 남아 있지 않아야 한다. 문서 링크가 저장소 안에서 해석되고, 승인되지 않은 요구사항이나 개인 환경 정보가 없어야 한다.

### `use-words-review`를 저장 결과물 중심으로 제한한다

`skills/use-words-review/SKILL.md`의 스킬 선택 조건과 본문을 함께 고친다. 설명만 고치고 본문에 채팅 검토 절차를 남기거나, 본문만 고쳐 스킬 설명이 일반 답변에서 계속 선택되게 해서는 안 된다.

- 머리말의 `description`에서 영향이 큰 사용자 답변을 자동 검토하는 조건과 요구사항, 정책, 보안 등의 답변을 보내기 전 실행하는 조건을 제거한다.
- AI가 만들거나 고친 한국어 문서, 저장하거나 공유할 문구와 이름, 사용자가 명시적으로 요청한 문구 검토를 선택 조건으로 남긴다.
- 채팅에서 작성한 문구를 그대로 저장, 게시 또는 전달할 예정이면 저장 결과물로 분류한다고 명시한다.
- `Establish the review scope`의 사용자 답변 항목은 명시적인 문구 검토 요청으로 제한한다. 진행 알림과 일반 설명은 검토 범위에서 제외한다.
- 주 에이전트 대체 절차는 저장 결과물과 명시적인 문구 검토 요청에만 적용한다. 일반 채팅을 자체 점검으로 대체하라는 문장을 제거한다.
- 전송 전 사용자 답변 검토를 전제로 한 보고 절차는 명시적인 문구 검토 결과에만 적용되도록 고친다.
- `references/korean.md`는 한국어 저장 결과물의 상세 판정 기준으로 유지한다. 채팅 규칙을 추가하기 위해 상세 사례를 스킬 본문에 복사하지 않는다.

**완료 증거.** `SKILL.md`에서 일반 채팅, 영향이 큰 답변과 전송 전 자동 검토를 요구하는 문장을 찾을 수 없어야 한다. 한국어 문서, 저장 예정 문구와 명시적인 문구 검토 요청에는 기존 읽기 전용 의미 검토, U+00B7 검사와 판정 상태 보고가 계속 적용되어야 한다.

### 두 배포용 AGENTS 문서의 채팅 작성 규칙을 맞춘다

`src/AGENTS.ko.md`와 `src/AGENTS.en.md`의 `USE WORDS REVIEW` 표시 구간을 같은 동작으로 바꾼다. 영어 배포본에서도 실제 한국어 문제 표현은 번역하지 않고 같은 문자열을 예로 든다.

- 일반 채팅, 진행 알림과 설명 답변은 `use-words-review`와 `references/korean.md`를 호출하지 않는다고 명시한다.
- 채팅은 별도 검토 단계를 만들지 않고 처음부터 대상, 행동 주체, 행동, 조건과 결과가 드러나게 작성하도록 지시한다.
- 일반 산문의 U+00B7 금지, 낱말 단위 번역 금지, 사실을 더하지 않는 수식어, 상투적인 도입과 결론, 근거 없이 맞춘 세 항목과 반복되는 문단 짜임을 짧은 작성 규칙으로 둔다.
- 진행 알림에는 확인한 사실과 다음 행동만 적고 검토 보고나 형식적인 요약을 덧붙이지 않도록 한다.
- `korean.md`를 읽고 `use-words-review`를 실행하는 조건은 AI가 만들거나 고친 한국어 문서, 저장하거나 공유할 문구와 이름으로 제한한다.
- 사용자가 특정 채팅 문구의 검토를 명시적으로 요청하면 예외로 스킬을 실행한다.
- 채팅에서 만든 문구를 그대로 저장하거나 전달할 때에는 실제 저장 또는 전달 전에 한 번 검토한다.
- 서브에이전트 선택, 대체 절차와 검토 결과 보고는 스킬이 실행되는 경우에만 적용한다.

AGENTS에는 `korean.md`의 용어별 허용 조건과 전체 대조 사례를 복사하지 않는다. AGENTS는 놓치기 쉬운 신호와 작성 행동을 소유하고, `korean.md`는 저장 결과물의 상세 판정을 소유한다.

**완료 증거.** 두 배포본에서 한국어 채팅, 저장 결과물과 명시적인 검토 요청의 실행 조건이 같아야 한다. 한쪽에만 남은 스킬 호출 조건이나 서로 다른 한국어 예시가 없어야 한다. 일반 채팅에서는 스킬 호출을 요구하지 않으면서도 중간 메시지와 최종 답변에 같은 작성 조건이 적용되어야 한다.

### 설계 문서와 배포 원본의 연결을 다시 확인한다

`docs/designs/korean-writing-review-6f3a/`의 요구사항, 두 결정 기록, 채팅 조사, 용어 조사와 평가 사례를 실제 변경과 대조한다. 배포 방식 설명이 영향을 받는지도 `README.md`와 `README.ko.md`에서 확인하되, 현재처럼 스킬을 커밋하거나 공유할 글과 이름의 검토 도구로 설명하는 문장이 새 범위와 일치하면 바꾸지 않는다.

**완료 증거.** 설계 문서가 구현 준수를 주장하지 않고, 실제 `src`와 `skills` 변경을 파일별로 추적할 수 있어야 한다. 루트 README를 바꾸지 않았다면 현재 설명이 새 스킬 범위와 일치한다는 검토 근거를 남긴다.

## 검증 방법

### 정적 대조

- `src/AGENTS.ko.md`, `src/AGENTS.en.md`와 `skills/use-words-review/SKILL.md`에서 일반 채팅의 `korean.md` 로딩, 영향이 큰 답변의 스킬 호출과 전송 전 자동 검토 문구를 검색한다. 결과가 없어야 한다.
- 저장, 커밋, 게시 또는 전달할 한국어 결과물과 사용자가 명시적으로 요청한 문구 검토 조건을 검색한다. 세 파일에서 각 역할에 맞게 확인되어야 한다.
- 두 배포용 AGENTS 문서의 표시 구간을 항목별로 대조해 동작 차이가 없는지 확인한다.
- 변경된 문서에서 U+00B7을 검색하고, 코드 포인트 설명, 평가 입력, 인용이나 승인된 이름에 필요한 경우만 남았는지 문맥별로 판정한다.
- 저장소 상대 링크, 빈 제목, 임시 표시, 개인 절대 위치, 비공개 식별자와 내부 작업 문구가 변경 문서에 없는지 확인한다.

### 대표 실행

- 짧은 진행 알림, 단순 확인, 일반 설명과 긴 조사 답변을 한국어로 요청한다. 각 실행에서 `korean.md`, `use-words-review`와 검토용 서브에이전트 호출은 0회여야 한다.
- 같은 실행의 중간 메시지와 최종 답변을 `references/korean-review-evaluation-cases.md`의 문자, 용어와 문체 사례로 판정한다.
- 한국어 문서를 만들거나 고쳐 저장하는 작업에서는 공유 단위마다 `use-words-review`가 1회 실행되어야 한다.
- 파일 변경 없이 특정 한국어 문구의 검토를 요청하면 예외에 따라 `use-words-review`가 1회 실행되어야 한다.
- 채팅에서 문구 초안을 만든 뒤 저장을 요청하면 초안 작성 중에는 실행하지 않고 저장 직전에 1회 실행되어야 한다.

호스트가 제공하는 스킬 호출 수, 서브에이전트 호출 수와 경과 시간을 기록한다. 호출 횟수는 위 조건으로 판정한다. 경과 시간은 실행 환경에 따라 달라지므로 첫 적용에서는 측정값을 남기고, 반복 자료가 쌓이기 전에는 임의의 시간 기준을 만들지 않는다.

## 중단 조건과 후속 판단

일반 채팅과 저장 결과물의 구분을 실제 호스트에서 식별할 수 없거나, 명시적인 문구 검토 요청이 일반 설명 요청과 반복해서 혼동되면 배포를 멈추고 스킬 설명과 평가 입력을 보완한다. 일반 채팅에서 스킬 호출은 없어졌지만 대표 평가의 한국어 결함이 반복되면 AGENTS의 짧은 예시를 조정한 뒤 다시 실행한다. 이때 `korean.md` 전체를 AGENTS에 복사하거나 일반 채팅의 독립 검토를 임의로 되살리지 않는다.

예시 저장소 집계를 다시 검증할 역할과 원본 자료의 보관 방식은 이번 계획에서 정하지 않는다. 갱신한 체계를 다른 저장소에 적용한 뒤 후속 작업에서 다시 검토한다.

## 후속 백로그

### 문맥 검토 후보를 찾는 MJS 검사기

`use-words-review`가 저장 결과물을 검토할 때 `계약`, `경계`, `경로`, `공개`, `포화`처럼 문맥에 따라 판정이 달라지는 표현의 위치를 먼저 찾는 MJS 검사기를 구현 후보로 보관한다. 검사 대상 표현의 수를 고정하지 않고, 실제 실패 사례와 평가 결과에 따라 후보를 늘릴 수 있어야 한다.

이 검사기는 금칙어 판정이나 자동 치환을 하지 않는다. 법률상 계약, 수학적 경계와 같이 유지해야 할 용례도 검토 후보로 알리고, `references/korean.md`에 따른 후속 의미 검토가 `pass`, `needs revision`, `needs human input`을 결정한다. 목록에 없는 번역체와 정형화된 표현은 기계 검사로 찾았다고 간주하지 않고 기존 문장 단위 검토를 계속 적용한다.

이 항목은 구현 승인이 아니다. 구현을 시작하기 전에 요구사항 소유자가 실제 스크립트 변경을 요구사항 범위에 포함해야 한다. 기술 결정을 승인할 역할은 현재 문서에서 확인되지 않는다. 해당 역할을 확인한 뒤 실행 환경에서 지원할 Node.js 버전, Git 변경 줄의 비교 기준과 경고를 실패로 바꿀 실행 지점을 정해야 한다.

구현이 승인되면 다음 조건을 설계와 평가 입력에 반영한다.

- 스크립트는 `skills/use-words-review/scripts/`에 두고 Node.js를 명시적으로 호출한다. 외부 npm 패키지를 추가하지 않는다.
- Git이 추적하는 문서는 승인된 비교 기준에서 추가되거나 바뀐 줄을 우선 검사하고, 새 파일은 전체를 검사한다. 파일로 저장되지 않은 전달 문구와 사용자가 명시적으로 검토를 요청한 채팅 문구는 표준 입력으로 받을 수 있게 한다.
- 일반 채팅, 진행 알림과 설명 답변에는 실행하지 않는다.
- 결과에는 규칙 ID, 발견한 표현, 줄, 열과 `references/korean.md`의 판정 위치를 담는다. 파일 입력에는 저장소 상대 경로를, 표준 입력에는 호출자가 지정한 입력 이름을 출처로 표시한다. 원문 전체는 기본 출력에 포함하지 않는다.
- 후보 발견은 경고로 처리하고 검사 실패와 구분한다. CI나 훅에서 후보를 실패로 취급하는 동작은 별도 선택 사항으로 둔다.
- Node.js를 사용할 수 없거나 파일을 읽지 못한 경우에는 검사를 실행한 것처럼 보고하지 않고 기존 검색과 수동 검토 절차로 돌아간다.
- 한글 조사와 결합한 명사, 동사 활용형과 한 줄의 여러 후보는 빠짐없이 경고해야 한다. LF와 CRLF 문서는 같은 위치를 보고하고, 이름이 바뀐 파일과 공백이 있는 경로 및 새 파일은 실제 검사 대상을 가리켜야 한다. 바이너리와 잘못된 문자 인코딩은 내용을 출력하지 않고 검사 불가로 보고해야 한다.
- 정상 전문용어도 후보로 찾는지, 후속 의미 검토가 정상 용례를 그대로 두는지, 목록에 없는 문제 표현을 문장 단위 검토가 찾는지를 함께 확인한다.

검사 결과 형식은 나중에 pre-commit 검사, CI 또는 Codex 훅에서도 재사용할 수 있게 정하되, 해당 연결은 별도 결정 없이 이 백로그의 구현 범위에 넣지 않는다. 스킬 절차만으로 스크립트 실행을 강제할 수 없으므로, 대표 작업에서 실제 호출 여부와 경고 이후의 판정 결과를 함께 기록한다.
