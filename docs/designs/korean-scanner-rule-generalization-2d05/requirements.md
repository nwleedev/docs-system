# 한국어 스캐너 규칙 일반화 요구사항

## 목표

한국어 스캐너가 실행 코드에 직접 적은 일부 표현과 활용형에만 엄격한 검사를 적용하는 문제를 해소한다. 진단 규칙을 표현별 분기 없이 일관되게 검사하고, 문맥을 자동으로 확정할 수 없는 표현은 검토 후보로 보고한다.

## 적용 조건

- 특정 표현만 별도 형태 판정 규칙에 연결하지 않는다.
- 검사 대상 표현별 표면 변이형, 어미와 예외를 실행 코드의 조건문이나 표제어별 목록으로 직접 열거하지 않는 방법을 조사한다.
- NFD를 계속 중심 메커니즘으로 사용할지, NFC 정규화, Unicode 문자열 구간 분리, 형태 분석, 자료에서 생성한 규칙 가운데 더 적합한 방법이 있는지 비교한다.
- 배포 스크립트가 외부 패키지와 네트워크 없이 Node.js 22.0.0 이상에서 실행되는 현재 조건을 유지할 수 있는 방법을 우선한다.
- 원문 UTF-16 위치와 기존 검사 결과의 JSON 구조를 보존할 수 있어야 한다.
- 형태 규칙이 허용하는 `박지`를 다른 활용형 후보와 같이 보고하며, 이 입력만 제외하는 문맥 규칙을 두지 않는다.
- `작은`은 실제 크기와 다른 뜻을 스캐너가 확정하지 않고 검토 후보로 보고한다.
- `흐름`은 물의 이동과 작업 방식 같은 다른 뜻을 스캐너가 확정하지 않고 검토 후보로 보고한다.
- 새 내부 객체 속성명은 영문 소문자만 사용하고 하이픈을 사용하지 않는다.
- 객체의 문맥으로 알 수 있는 같은 개념을 여러 속성명에 접두어나 접미어로 반복하지 않는다.
- 기존 공개 JSON 속성명은 호환성을 위해 유지한다.
- 특정 입력의 외부 용례를 추정한 설명은 코드, 설계 문서와 커밋 메시지에 기록하지 않는다.

## 완료 증거

- 현재 스캐너에서 특정 표현과 활용 자료가 실행 코드에 직접 연결된 위치와 그 영향이 조사 문서에 기록되어 있다.
- NFD, NFC, `Intl.Segmenter`, Unicode 문자 속성, 자료 주도 형태 규칙과 외부 형태 분석기를 현재 실행 조건에 맞춰 비교한 결과가 기록되어 있다.
- 표현별 실행 분기를 없애면서도 진단 규칙 목록과 한국어 형태 자료를 관리할 수 있는 권고안, 남은 한계와 구현 전에 승인할 항목이 기록되어 있다.
- `박지`, `작은`과 `흐름`을 포함한 대표 입력이 의도한 규칙 ID, 원문 UTF-16 위치와 인용문으로 보고된다.
- 지원하기로 정한 활용 종류의 새 용언을 추가할 때 진단 규칙 자료만 바뀌고 스캐너의 표현별 조건문과 표면형 배열은 바뀌지 않는다.
- 새 내부 객체 속성명이 `/^[a-z]+$/`를 만족하고 객체의 문맥으로 알 수 있는 개념을 반복하지 않는다.
- 기존 JSON 필드, 결과 순서, 경고 상한, 입력 mode, 오류 형식과 종료 상태가 유지된다.
