# 한국어 스캐너 규칙 일반화 구현 계획

## 결론

구현은 `korean-expressions.mjs` 안에서 진단 정책, 정준 동등 비교와 용언 활용 판정을 분리한다. 진단 규칙은 고정 표현, 표제어와 표제어를 포함한 구문 가운데 하나의 검사 방식을 선언한다. 스캐너는 모든 고정 표현에 같은 정준 동등 비교를 적용하고, 모든 표제어에 같은 활용 규칙을 적용한다.

`작은`과 `흐름`은 사용자가 지정한 문자열만 검토 후보로 추가한다. `작다`의 다른 활용은 이번 계획에서 추론하지 않는다. 형태 규칙이 허용하는 `박지`는 다른 후보와 같이 보고하며 별도의 문맥 제외 조건을 두지 않는다.

## 기준 문서와 적용 범위

요구사항 기준은 [`requirements.md`](requirements.md)의 `목표`, `적용 조건`과 `완료 증거`다. 구현은 [한국어 표현 검사 일반화 조사](references/generalized-korean-matching-research.md)의 정규화와 형태 판정 비교를 사용한다.

실행 방법과 검증 기준은 [`docs/dev/node/mjs-cli.md`](../../dev/node/mjs-cli.md)의 `literal 탐색은 빈 표현을 거부하고 겹침을 보존한다`, `위치와 quote는 원문 문자를 보존한다`, `계산 함수는 입력과 실행 환경을 바꾸지 않는다`, `실행 조정과 두 탐지 책임만 나눈다`, `추가 공용 모듈을 만들지 않는다`와 `self-test는 순수 검사와 실제 프로세스를 나눈다`를 따른다.

다음 파일만 구현 범위에 포함한다.

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`
- `docs/designs/korean-scanner-rule-generalization-2d05/`
- 제거 대상 설명이 남은 기존 한국어 스캐너 설계 문서

새 배포 파일, runtime dependency, 네트워크 요청, 외부 형태 분석기와 공개 JSON 필드는 추가하지 않는다. Unicode 속성으로 token 범위를 넓히는 변경도 포함하지 않는다.

새로 추가하거나 이름을 바꾸는 내부 객체 속성명은 `/^[a-z]+$/`를 만족해야 한다. 하이픈, 대문자와 숫자를 사용하지 않는다. 객체가 이미 규칙, 표제어 또는 원문이라는 문맥을 제공하면 `ruleid`, `rulekind`처럼 같은 개념을 각 속성명에 반복하지 않고 `id`, `kind`처럼 뜻을 한 번만 쓴다. 컴파일한 후보 자료도 `ruleIndex`, `declarationIndex`, `surfaceNfd`를 되풀이하지 않고 객체 문맥에 맞는 `rule`, `order`, `surface`처럼 짧고 구별되는 이름을 사용한다. 기존 공개 JSON의 `ruleId`, `sourceName`과 같은 속성명은 호환성을 위해 바꾸지 않는다.

## 구현 결정

### 진단 정책과 검사 방식을 한 규칙에서 연결한다

`rules`는 기존 공개 자료인 `id`, `expressions`, `message`, `queries`, `negatives`와 `positives`를 유지한다. 비공개 검사 자료에는 다음 세 방식만 둔다.

- 고정 표현은 선언된 문자열을 정준 동등 비교로 찾는다.
- 표제어는 표제어, 품사와 활용 종류를 선언하고 공통 활용 판정기로 찾는다.
- 표제어를 포함한 구문은 고정된 앞부분과 마지막 표제어를 나누어 검사한다.

공개 `catalog`에는 기존 `kind`와 `expressions`를 유지한다. 검사 방식은 내부 자료이며 외부 JSON에 새 필드를 추가하지 않는다.

용언 규칙은 `좁다`, `좁히다`, `닫다`, `박다`, `박히다`와 `다루다`를 표제어 자료로 옮긴다. `회의를 가지다`는 `회의를`과 `가지다`를 분리한 구문 자료로 옮긴다. `작은`과 `흐름`은 정확한 문자열 요구이므로 고정 표현으로 둔다.

### 정준 동등 비교는 기존 NFD 위치 변환을 일반화한다

고정 표현과 한글 원문은 같은 NFD 비교 문자열에서 찾는다. 이는 NFC와 NFD 가운데 하나를 스캐너의 의미 판정기로 삼는 선택이 아니다. NFD는 정준 동등한 한글 문자열을 같은 비교값으로 만들고 원문 위치를 복원하기 위한 내부 표현으로만 사용한다.

현재 `buildNfdMapping()`의 원문 code point와 NFD 위치 대응을 일반 고정 표현에도 적용한다. 규칙 표현은 초기화할 때 한 번 NFD로 바꾸고 첫 NFD 단위로 색인한다. 일치는 NFD 범위에서 찾은 뒤 `mapOriginalRange()`로 원문 UTF-16 범위에 되돌린다. 원문, `quote`, 줄과 열 계산은 정규화하지 않는다.

이 계획은 현대 한글 음절과 정준 분해 자모의 NFC 및 NFD 표기 일치를 보장한다. 임의의 Unicode 결합 문자 순서를 모두 정규화하는 범용 검색기는 만들지 않는다. 그 범위가 필요해지면 Unicode normalization boundary 자료와 배포 비용을 별도로 승인받는다.

### 공통 활용 규칙으로 표면형 자료를 만든다

`morphologyMatchers`의 표제어별 `variants` 배열은 제거한다. 초기화 단계는 각 표제어에서 `다`를 뺀 어간을 구하고, 품사, 받침과 모음 조건에 따라 공통 활용 규칙을 적용한다.

첫 구현은 현재 규칙과 새로 연결할 표제어에 필요한 규칙 활용만 다룬다.

- 자음과 모음 뒤에 붙는 종결, 연결, 관형과 명사형 어미
- 모음 어간에 붙는 `ㄴ`, `ㄹ`, `ㅂ`과 `ㅁ`
- `아`와 `어` 선택
- `ㅣ`와 `어`, `ㅜ`와 `어`의 축약
- 과거 표현을 만드는 `ㅆ`
- 현재 표제어가 사용하는 규칙 활용과 `ㅣ` 및 `ㅜ` 축약

어미 목록은 모든 표제어가 공유하는 언어 자료로 유지한다. 특정 표제어의 표면 문자열이나 예외 조건은 이 목록에 넣지 않는다. 이번 구현은 위 규칙과 축약으로 만들 수 있는 표제어만 받는다. 새 불규칙 활용은 이번 범위에 넣지 않으며, 필요해지면 표현 이름을 검사하는 분기가 아니라 재사용할 활용 종류와 그 근거를 먼저 승인받는다.

초기화 결과는 정규화한 token 전체를 key로 하고 규칙 위치, 표현 표시값과 원문에서 보고할 어간 범위를 값으로 갖는 색인이다. 실행 중에는 한글 token을 한 번 순회하고 이 색인을 조회한다. 선언된 `expressions` 가운데 생성된 표면형의 가장 긴 NFD 접두를 `warning.expression`으로 선택해 기존 표시 의미를 유지한다.

### 문맥을 확정하지 않고 검토 후보를 보고한다

형태상 허용되는 token은 뒤 문자열에 따른 단일 예외 없이 보고한다. `isExcludedMorphologyContext()`와 호출부는 제거한다. 명사처럼 표제어 활용으로 해석되지 않는 완전한 token은 현재와 같이 보고하지 않는다.

`작은`과 `흐름` 규칙은 문맥을 자동 분류하지 않는다. 각각 다음 질문을 제공한다.

- `작은`: 측정할 수 있는 실제 크기인지, 파일 수나 변경량처럼 다른 수량을 뜻하는지 확인한다.
- `흐름`: 물처럼 이동하는 대상을 뜻하는지, 작업 단계, 실행 순서 또는 상태 변화를 뜻하는지 확인한다.

두 규칙은 어떤 문맥도 자동 통과시키지 않는다. 경고를 받은 검토자가 원문과 판정 질문을 함께 읽고 유지 여부를 정한다.

## 작업 순서

### 문맥 예외와 관련 설명 제거

**목표:** 형태 규칙이 허용하는 token을 일관되게 보고하고 저장된 문서에서 제거 대상 설명을 없앤다.

**선행 작업:** 없음

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`
- `docs/designs/korean-scanner-rule-generalization-2d05/references/generalized-korean-matching-research.md`
- `docs/designs/better-terms-scanner-reliability-5063/plan.md`
- `docs/designs/better-terms-scanner-reliability-5063/references/korean-morphology-rule-practices.md`
- `docs/designs/korean-scanner-detection-gaps-8a2f/references/main-mechanism-comparison.md`

**작업 내용:**

1. `collectMorphologyMatches()`에서 문맥 제외 호출을 제거한다.
2. `isExcludedMorphologyContext()`와 그 설명을 제거한다.
3. 기존 자체 검사에서 명사 token은 계속 제외하고 `박지 씨`의 `박`은 `ko.fix-in-place`로 보고하도록 기대 결과를 바꾼다.
4. 설계 문서에는 `박지`를 형태 판정 입력과 검사 결과로만 기록한다.

**검증:** `박지 씨`, `박지.`와 `못을 박다.`에서 각각 의도한 `ko.fix-in-place` 경고가 나오며 `박물관`, `박사`, `박수`, `호박`, `압박`과 `대박`은 보고하지 않는다. 변경된 문서와 커밋 메시지에는 요구사항이 금지한 외부 용례 설명이 없어야 한다.

### 진단 규칙 자료 확장

**목표:** 새 고정 표현과 모든 기존 용언 규칙이 검사 방식을 직접 선언하게 한다.

**선행 작업:** 문맥 예외와 관련 설명 제거

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 고정 표현, 표제어와 표제어 포함 구문을 구분하는 비공개 규칙 자료를 추가한다.
2. `ko.small`에 `작은`을 추가하고 실제 크기와 다른 수량을 구분할 판정 질문 및 대조 사례를 기록한다.
3. `ko.flow`에 `흐름`을 추가하고 물의 이동과 작업 단계 및 실행 순서를 구분할 판정 질문 및 대조 사례를 기록한다.
4. 기존 용언 규칙을 표제어 자료로 옮기되 공개 `catalog`, 규칙 ID와 기존 표현 배열은 유지한다.
5. 규칙 검증이 검사 방식별 필수값, 중복 표제어, 잘못된 품사와 기존 JSON에 기록할 표현을 확인하게 한다.
6. 새 내부 객체 속성명은 영문 소문자만 사용하고, 객체 문맥으로 알 수 있는 개념을 속성마다 되풀이하지 않는다.

**검증:** `작은 변경`, `작은 부품`, `업무 흐름`과 `물의 흐름`이 각각 한 번 보고된다. 판단이 필요한 후보를 찾는 검사이므로 물리적 용례도 자동 제외하지 않는다. 기존 48개 규칙에 두 규칙이 추가되고 선언 순서가 결과 순서를 결정한다. 새 내부 객체 속성명은 `/^[a-z]+$/`를 만족하며 같은 객체 안에서 문맥을 나타내는 단어를 반복하지 않는다.

### 고정 표현 정준 동등 비교

**목표:** 형태 matcher에 연결되지 않은 한국어 표현도 NFC와 NFD 원문에서 같은 결과를 내게 한다.

**선행 작업:** 진단 규칙 자료 확장

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 일반 표현을 초기화할 때 NFD 비교값과 선언 순서를 색인한다.
2. source별 NFD 비교 문자열과 원문 위치 대응을 한 번 만든다.
3. 현재 겹침 보존, 선언 순서와 원문 시작 위치 정렬을 유지하며 일반 표현을 찾는다.
4. 모든 경고 범위를 원문 UTF-16 위치로 복원한 뒤 기존 위치와 인용문 계산에 전달한다.

**검증:** NFC와 NFD로 각각 저장한 `경계`, `작은`과 `흐름`이 같은 규칙 ID와 같은 원문 범위를 보고한다. 같은 위치의 여러 규칙, 겹치는 표현, emoji 뒤 표현과 최대 quote 길이는 기존 결과를 유지한다. 원문 입력과 규칙 자료는 검사 전후에 바뀌지 않는다.

### 표제어 공통 활용 판정

**목표:** 새 용언을 추가할 때 표제어 자료만 바꾸고 실행 코드와 표면형 배열은 바꾸지 않게 한다.

**선행 작업:** 진단 규칙 자료 확장, 고정 표현 정준 동등 비교

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 한글 음절 분해, 받침 판정, 모음 결합과 종성 추가를 표제어에 독립적인 계산 함수로 만든다.
2. 공통 어미 자료와 승인된 규칙 및 축약 종류에서 허용할 표면형 색인을 초기화한다.
3. `좁다`, `좁히다`, `닫다`, `박다`, `박히다`와 `다루다`를 같은 판정기로 옮긴다.
4. `회의를 가지다`는 고정 앞부분과 `가지다` 활용 token을 결합해 찾는다.
5. `morphologyMatchers`, 표제어별 `variants`와 matcher ID를 제거한다.
6. 실행 중에는 token을 한 번 읽고 생성된 색인을 조회한다.

**검증:** 현재 지원하는 `좁다`, `좁히다`, `박다`와 `박히다` 활용 결과가 유지된다. `닫습니다`, `다룹니다`, `다뤄`, `회의를 가집니다`와 `회의를 가져`가 해당 기존 규칙으로 보고된다. `좁쌀`, `박물관`, `호박`, `압박`과 `대박`은 보고하지 않는다. 새 규칙 자료에 이번 계획이 지원하는 활용 종류의 검사용 임시 표제어를 추가한 자체 검사는 실행 코드 변경 없이 규칙 활용을 찾는다.

### 통합 검증과 변경 정리

**목표:** 새 비교 방식이 기존 CLI와 JSON 동작을 바꾸지 않았는지 확인한다.

**선행 작업:** 앞선 모든 작업

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 자체 검사가 운영 규칙 검증, 정준 동등 비교, 활용형 색인, 원문 위치 복원과 결과 상한을 직접 실행하게 한다.
2. 정상 stdin 입력으로 규칙 ID, `warning.expression`, 위치, 인용문, 순서와 전체 수를 확인한다.
3. 잘못된 규칙 자료가 기존 공개 오류와 분리된 내부 규칙 오류로 끝나는지 확인한다.
4. 변경 파일에 표현별 표면형 배열, 단일 문자열 예외, 외부 package, 새 import와 네트워크 접근이 없는지 검토한다.
5. 새 내부 객체 속성명과 기존 공개 JSON 속성명을 나누어 확인하고, 새 내부 속성에는 이름 형식과 반복 금지 규칙을 적용한다.

**검증:** `node skills/use-better-terms/scripts/scan.mjs --self-test`와 `pnpm lint`가 통과한다. 대표 stdin 실행의 JSON은 새 경고와 정준 동등 입력 차이를 제외하고 기존 필드, 정렬, 상한과 종료 상태를 유지한다.

## 실행 중단 조건

다음 조건이 확인되면 영향을 받는 작업을 멈추고 요구사항 또는 결정 담당자의 판단을 받는다.

- 현재 JSON 필드나 기존 규칙 ID를 바꾸지 않고 검사 방식을 연결할 수 없다.
- 기존 `warning.expression` 의미를 유지하려면 다시 표제어별 표면형 배열을 만들어야 한다.
- 요구된 활용형에 외부 형태 분석기, runtime dependency, 모델 또는 네트워크가 필요하다.
- 임의의 Unicode 결합 문자까지 지원해야만 완료할 수 있다.
- 공통 활용 규칙이 기존 명사 부정 사례를 형태 후보로 보고한다.
- 적용할 개발 지침을 따르려면 이번 작업과 무관한 배포 파일 또는 import 규칙을 바꿔야 한다.

현재 확인된 착수 차단 사항은 없다.

## 완료 조건

- 모든 고정 표현이 같은 정준 동등 비교를 사용한다.
- 모든 용언 규칙이 같은 활용 판정기를 사용한다.
- `박지`, `작은`과 `흐름`이 요구한 검토 후보로 보고된다.
- 새 용언은 이번 계획이 지원하는 규칙 및 축약 종류 안에서 표제어 자료 추가만으로 지원할 수 있다.
- 표현별 표면형 배열과 단일 문자열 문맥 예외가 실행 코드에 남지 않는다.
- 새 내부 객체 속성명은 영문 소문자로만 이루어지고 객체 문맥으로 알 수 있는 같은 개념을 반복하지 않는다.
- 원문 UTF-16 위치, 인용문, 공개 JSON, 결과 순서, 상한과 CLI 오류 동작이 유지된다.
- 배포 스크립트는 Node.js 22.0.0 이상에서 외부 package와 네트워크 없이 실행된다.
