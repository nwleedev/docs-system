# use-progressive-user-interfaces 재설계 요구사항

`use-progressive-user-interfaces`는 완성된 서비스 화면으로 느껴지는 시안을 제공하고, 현재 작업과 정보 구조에서 도출한 독창적이고 사용하기 쉬운 UI 방향을 제시해야 한다. 스킬 이름과 디렉터리 이름은 유지한다.

이 문서는 스킬 문서를 수정하고 검토할 때 사용할 요구사항 기준이다.

## 해결할 문제와 결과

기능만 배치한 화면을 완성된 UI로 취급하지 않는다. 현재 화면에 필요한 정보 위계, 배치, 상태, 화면 크기에 따른 동작과 시각적 일관성을 갖춘다. 생성 시안에서도 완성된 화면 구성을 확인할 수 있어야 한다.

외부 서비스의 화면을 복제하거나 여러 서비스의 시각적 속성을 조합하는 방식으로 디자인 방향을 정하지 않는다. 핵심 작업, 정보 관계와 도메인 특성에서 구조와 표현을 도출한다. 익숙한 상호작용과 접근성 관습은 유지한다.

외부 UI는 해결 전략, 상호작용 관습과 대안을 비교하는 근거로 사용한다. 초기 디자인 근거는 외부 조사 전에 마련한다. 필요한 경우에만 조사하고, 서비스 이름 없이 최종 구조와 선택 이유를 설명할 수 있어야 한다.

전문 UI 용어, CSS 값이나 디자인 토큰 지식 없이 진행할 수 있어야 한다. 근거로 해결할 판단과 결과 차이가 미미한 선택은 별도 질문 없이 처리하고, 실제 결과가 달라지는 유효한 방향이 남으면 관찰 가능한 차이와 장단점을 비교한다.

스킬 문서는 책임에 따라 통합하거나 다시 작성해 중복 규칙과 모호한 단계 책임을 줄인다. 실행 지침의 특정 주체 지칭은 조건과 동작을 설명하는 문장으로 바꾼다. 정확한 스킬 이름에 포함된 `user`는 이름 유지 조건에 따른 예외다.

## 유지할 조건

검색 설명, 실제 화면 관찰, 자료에 명시된 내용, 해석과 미확인 사항을 구분한다. 출처가 불명확한 이미지나 생성 시안을 실제 서비스 관찰 근거로 취급하지 않는다. 정확한 구현 수치를 화면 외형만으로 확정하지 않는다.

확정된 선택, 잠정안, 미결정 사항과 실행 화면에서 검증된 규칙을 구분한다. 생성 시안 확인과 실제 UI 검증을 구분하고, 공통 규칙을 검증하지 않은 대상까지 확대하지 않는다. 처음부터 전체 토큰이나 컴포넌트 체계를 만들지 않는다.

이번 결과물은 검토를 반영한 실행 플랜이다. 애플리케이션이나 테스트 코드를 작성하는 작업을 포함하지 않는다.

## 완료를 판단할 근거

후속 스킬 변경에서는 신규 UI, 기존 UI 개선, 일반적인 SaaS 화면, 전문 디자인 판단이 없는 입력과 특정 레퍼런스가 지정된 입력에 적용한 결과를 확인한다. 작업과 정보 구조에서 출발했는지, 현재 화면에 필요한 공통 규칙을 갖췄는지, 복제 없이 선택 이유를 설명하는지와 불필요한 전문 선택을 요구하지 않는지 확인한다.

생성 시안의 화면 구성과 실제 실행 UI에서 작업 적합성, 시각적 일관성, 완성도와 차별성을 각각 확인한다. 문서 수정이나 컴포넌트 존재만으로 개선 완료를 판단하지 않는다.
