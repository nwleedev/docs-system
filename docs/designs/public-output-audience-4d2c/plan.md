# 공개 산출물 리뷰 스킬과 배포 지침 계획

## 기준과 변경 영향

이 계획은 `requirements.md`를 기준으로 한다. 새 변경은 `리뷰 에이전트` 절에 사람용 `README.md`, AGENTS 연결 지침, 한국어 글쓰기 예시의 소유 위치 검토를 추가했다.

`docs/designs/README.md`와 `docs/dev/README.md`에는 공개 산출물 기준이 반영돼 있다. 새 요구는 두 README의 규칙을 바꾸지 않으므로 해당 변경은 다시 수행하지 않는다. `skills/use-design-docs/SKILL.md`와 `skills/use-dev-guidance/SKILL.md`도 각 README를 현재 규칙의 소유 문서로 사용하므로, 새 검토 절차를 두 스킬에 복사하지 않는다.

[공개 산출물 검사 체계 조사](references/reusable-output-checks-research.md)는 스킬 실행 파일, 사람용 안내 문서, AGENTS 호출 조건과 범용 서브에이전트의 책임을 구분한다. 조사 결과에 따라 다음 원칙을 적용한다.

- `SKILL.md`는 자동·명시 호출의 진입점이며 README를 먼저 읽지 않아도 실행할 수 있어야 한다.
- `README.md`는 사람이 스킬의 목적, 설치 위치와 AGENTS 연결 방법을 확인하는 안내서다. 실행 규칙을 중복해서 소유하지 않는다.
- `references/examples.md`는 검토할 때만 필요한 실패·허용 예시를 보관하며, `SKILL.md`가 읽을 조건을 명시한다.
- 스킬은 별도로 이름 붙인 에이전트 파일을 만들지 않고, 실행 시점에 사용할 수 있는 범용 서브에이전트에 검토 역할과 기준을 전달한다.
- AGENTS에는 상시 필요한 작성 원칙과 스킬 호출 조건만 둔다. 스킬 본문과 예시 전체를 AGENTS에 복사하지 않는다.

현재 작업에 적용한 개발 지침은 `docs/dev/README.md`이며, 해당 문서를 검토했다.

## 작업 범위

이번 계획은 다음 파일을 새로 만들거나 수정한다.

- `skills/use-words-review/README.md`
- `skills/use-words-review/SKILL.md`
- `skills/use-words-review/references/examples.md`
- `README.md`
- `src/AGENTS.en.md`
- `src/AGENTS.ko.md`

루트 `AGENTS.md`의 `Writing Natural Korean`은 검토 대상이지만 기본 변경 대상은 아니다. 이 저장소의 `skills/`는 배포 원본이며 Codex의 `.agents/skills/`나 Claude Code의 `.claude/skills/`처럼 자동 탐색되는 위치가 아니다. 설치되지 않은 스킬을 루트 작업 지침이 항상 호출하도록 만들거나, 스킬 호출이 보장되지 않은 상태에서 상시 작성 원칙을 제거하면 현재 저장소의 동작이 약해진다.

`skills/use-design-docs/SKILL.md`, `skills/use-dev-guidance/SKILL.md`, `docs/designs/README.md`, `docs/dev/README.md`는 변경하지 않고 연결 상태만 확인한다. Vale 규칙, `src/vale`, Git 훅, CI와 결정적 문자열 검사는 리뷰 스킬 사용 결과가 쌓인 뒤 진행할 후속 작업이다. 플랫폼별 전용 에이전트 정의 파일과 Codex 전용 UI 메타데이터도 이번 구조에 추가하지 않는다.

## 작업 순서

### 1. `use-words-review`의 실행 책임을 정한다

`SKILL.md`에는 공개 산출물을 만든 뒤, 수정한 뒤, 커밋하거나 공유하기 전에 실행하는 검토 절차를 둔다. 사용자가 명시적으로 리뷰를 요청한 경우도 호출 대상에 포함한다. `description`에는 문서, README, UI 문구, 코드 주석, 커밋·PR·이슈 문구처럼 검토할 산출물과 호출 시점을 앞부분에 적어 자동 선택에 필요한 정보를 제공한다.

스킬은 다음 순서로 실행한다.

1. 현재 변경에서 공개되거나 추적될 산출물과 후보 커밋 메시지를 찾는다.
2. 각 산출물의 독자, 공개 여부와 독자가 알아야 할 일을 확인한다.
3. 적용 중인 AGENTS 지침과 문서별 소유 규칙을 선택하고, 사용할 수 있는 Vale 또는 결정적 검사 결과가 있으면 입력에 포함한다.
4. 변경분을 우선 제공하되 제목과 본문의 관계처럼 전체 문맥이 필요한 파일은 전체 내용을 함께 제공한다.
5. 범용 서브에이전트에 읽기 전용 검토 역할, 입력 범위, 금지 작업과 판정 기준을 전달한다. 작성 에이전트의 진행 보고나 자기평가는 전달하지 않는다.
6. 주 에이전트가 결과를 실제 변경과 대조하고, 서브에이전트가 파일을 바꾸지 않았는지 확인한다.
7. 결과를 `pass`, `needs revision`, `needs human input`, `not applicable`로 보고한다. 수정은 별도 승인된 작업으로 남긴다.

검토 기준은 독자 부적합, 작업 지시 문구의 제목·본문·결정 근거 혼입, 관계없는 요구의 결합, 원문 보존 예외 오용, 개인 경로와 비공개 식별자, 번역체와 불필요한 기호를 포함한다. 저장소별 설계·개발 문서는 해당 저장소의 `docs/designs/README.md`와 `docs/dev/README.md`가 존재하고 적용되는 경우에만 추가 기준으로 읽는다.

원문 비교가 명시적으로 필요한 경우에만 최소 원문을 일시 입력으로 전달한다. 요구사항 문서, 승인된 문구, 평가 자료, 최소 재현 입력과 비공개 실행 기록의 보존 여부를 스킬이 임의로 바꾸지 않는다. 범용 서브에이전트를 사용할 수 없거나 수정 권한을 제한할 수 없는 환경에서는 독립 검토나 권한 제한이 완료됐다고 쓰지 않고 제약을 결과에 남긴다.

### 2. 예시 자료를 검토 기준과 분리한다

`references/examples.md`에는 실제 저장소 이름, 개인 경로와 작업 지시 원문을 사용하지 않은 합성 예시를 둔다. 각 문제 예시는 비슷하지만 허용되는 문장과 짝을 이루어, 단어 하나의 존재가 아니라 독자·근거·문맥으로 판정하게 한다.

첫 예시 묶음은 다음 범위를 다룬다.

- 작업 완료 보고처럼 쓰인 사용자 문구와 독자가 수행할 일을 설명하는 문구
- 작업 지시가 제목이나 저장소 사실을 대신한 문장과 검증된 근거에서 다시 쓴 문장
- 서로 관계없는 요구를 한 문서에 묶은 구조와 소유 문서별로 나눈 구조
- 한국어 직역, 뜻이 없는 상투어와 문맥에 맞게 다시 쓴 표현
- 불필요한 이모지·특수 기호와 일반 문장부호
- 개인 절대 경로·비공개 식별자와 저장소 상대 경로·안전한 자리표시자
- 보존하면 안 되는 원문과 목적상 필요한 최소 인용

`SKILL.md`는 한국어 표현을 검토하거나 판정이 모호한 경우에만 이 파일을 읽도록 안내한다. 예시를 판정 규칙처럼 기계적으로 적용하거나, 예시에 없는 표현을 자동 통과시키지 않는다.

### 3. 사람용 README에 설치와 AGENTS 연결 방법을 작성한다

`skills/use-words-review/README.md`는 다음 정보를 제공한다.

- 스킬이 해결하는 문제와 검토할 공개 산출물
- `SKILL.md`와 `references/examples.md`의 역할
- 배포 원본인 `skills/use-words-review/`를 사용하는 도구가 인식하는 저장소·사용자·플러그인 위치로 설치해야 한다는 조건
- 자동 호출은 `SKILL.md`의 `description`이 판단하며 README 자체는 실행 시 자동으로 읽히지 않는다는 설명
- 스킬을 설치한 저장소의 AGENTS에 추가할 짧은 호출 조건
- 기존 `Public Outputs` 또는 이에 해당하는 절에 호출 조건을 두는 방법
- 설계 문서와 개발 지침을 자주 다루는 저장소에서 `Documentation Work` 또는 이에 해당하는 절이 스킬을 중복 호출하지 않고 공개 전 검사로 연결되는 방법
- 범용 서브에이전트 기능이 없을 때 독립 검토가 수행되지 않았음을 보고하는 방법

AGENTS 예시는 판정 항목을 다시 싣지 않고, 어떤 변경 뒤에 스킬을 호출할지와 스킬 결과를 주 에이전트가 검증해야 한다는 내용만 담는다. 설치하지 않은 저장소가 예시 문장만 복사해 존재하지 않는 스킬을 호출하지 않도록 설치와 지침 추가 순서를 함께 설명한다.

루트 `README.md`의 스킬 목록에는 새 스킬의 목적과 사람용 README 링크를 추가한다. 기존 두 `use-*` 스킬과 역할이 다르다는 점만 설명하고 검토 규칙을 복사하지 않는다.

### 4. AGENTS 참고 문서의 호출 조건과 글쓰기 원칙을 조정한다

`src/AGENTS.en.md`와 `src/AGENTS.ko.md`의 공개 산출물 절에, 스킬이 설치된 경우 공개 전 검토에서 `use-words-review`를 호출한다는 선택형 지침을 추가한다. 두 파일은 독립적인 참고 문서이므로 문장을 번역해 맞추지 않고 각 독자와 기존 용어에 맞게 작성한다.

`Documentation Work`와 `문서 작업` 절에는 설계 문서와 개발 지침의 기존 검증 절차를 유지한다. 새 문장이 필요하다면 문서 검증을 대체하는 별도 리뷰가 아니라, 변경된 문서가 공개 산출물일 때 공개 산출물 절의 스킬 호출까지 수행한다는 연결만 추가한다.

루트 `AGENTS.md`의 `Writing Natural Korean`과 `src/AGENTS.ko.md`의 `올바른 글쓰기`는 다음 기준으로 분류한다.

- 작성 전부터 항상 알아야 하는 독자, 근거, 자연스러운 문장 원칙은 AGENTS에 남긴다.
- 특정 영문 용어와 한국어 표현의 대응처럼 검토 예시로 충분한 내용은 `examples.md`로 옮길 후보로 기록한다.
- 옮긴 뒤 자동 호출되지 않은 작업에서 글쓰기 기준이 사라지거나, AGENTS가 스킬 설치를 전제하게 되면 이동하지 않는다.
- 실제 이동이 상시 지침을 줄이거나 의미를 바꾸면 해당 변경을 멈추고 사람의 승인을 받는다.

따라서 이번 작업의 기본값은 글쓰기 절 전체를 옮기지 않는 것이다. 먼저 스킬 예시가 기존 지침을 중복하지 않고도 검토에 충분한지 확인하고, 이동이 필요한 구체적인 문장만 별도 변경안으로 제시한다.

### 5. 구조와 실제 검토 동작을 검증한다

다음 증거가 모두 있어야 작업을 완료한다.

1. 스킬 검증 도구가 `SKILL.md`의 이름, frontmatter와 디렉터리 구조를 통과시킨다.
2. `SKILL.md`만 읽은 실행자가 README 없이도 입력 수집, 범용 서브에이전트 호출, 결과 검증과 상태 보고를 수행할 수 있다.
3. README만 읽은 사람이 실행 규칙을 오해하지 않고, 설치 후 AGENTS에 어느 정도의 호출 지침을 추가할지 판단할 수 있다.
4. 합성한 문제 사례와 허용 사례를 사용한 전향 검증에서 독자 부적합, 작업 지시 혼입, 번역체, 불필요한 기호와 개인 경로를 구분한다.
5. 요구사항 문서나 승인된 인용처럼 원문 보존이 필요한 사례를 일괄 오류로 판정하지 않는다.
6. 검토를 맡은 범용 서브에이전트가 파일을 수정하지 않았고, 주 에이전트가 결과를 실제 변경과 대조한다.
7. `src/AGENTS.*.md`의 호출 지침은 스킬 설치를 전제로 하며, `Public Outputs`와 `Documentation Work`의 책임을 중복하지 않는다.
8. `skills/use-design-docs/SKILL.md`와 `skills/use-dev-guidance/SKILL.md`가 각 README를 계속 단일 기준으로 사용하고 새 검토 규칙을 중복 소유하지 않는다.
9. `git diff --check`가 통과하고, 변경 파일에 개인 홈 경로, 비공개 프로젝트 식별자, 원문에서 가져온 특징적인 문장, `TODO`, `TBD`, `FIXME`가 없다.
10. 변경된 모든 문서를 실제 독자의 관점에서 읽고, 스킬을 만든 작업 과정이나 작업 지시자에게 보내는 보고가 남지 않았는지 확인한다.

## 중단 조건과 후속 작업

다음 상황에서는 범위를 임의로 넓히지 않고 중단한다.

- 범용 서브에이전트를 쓰려면 플랫폼별 전용 에이전트 파일을 만들어야 한다.
- AGENTS의 글쓰기 원칙을 줄여야만 `examples.md`의 중복을 피할 수 있다.
- 설치 방법을 설명하려면 아직 승인되지 않은 플러그인 배포 구조나 패키지 형식을 확정해야 한다.
- 검토 결과를 자동 차단으로 사용할지, 어떤 결과에서 사람이 승인해야 하는지 새 정책 결정이 필요하다.
- 요구사항에서 허용한 원문 보존 사례의 공개 범위나 승인 주체를 추가로 정해야 한다.

리뷰 스킬을 실제 작업에 적용해 반복되는 오탐과 누락을 확인한 뒤 Vale 후보 규칙을 선정한다. Vale 작업은 `src/vale`의 원본 규칙, 합성 검증 사례, 설치 README와 버전 고정 방법을 별도 계획으로 다루며, 리뷰 스킬 구현과 같은 커밋에 묶지 않는다.
