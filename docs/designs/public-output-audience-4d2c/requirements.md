# AI를 프로젝트에 활용할 때 발생하는 문제에 대한 요구사항

## AI가 누구에게 답변을 작성해야 하는지 구분하지 못하는 문제

AI를 여러 애플리케이션 개발 프로젝트, 자료 수집 프로젝트에, 문제에 대한 리서치 프로젝트에 사용하면서 다음과 같은 문제가 발생했습니다.

AI(Codex, Claude Code 등)는 AI 본인이 작성하는 글이 "작업 지시자를 위한 글인지, 애플리케이션을 사용하는 사용자를 위한 글인지, 애플리케이션 개발에 참여하는 개발자를 위한 글인지" 구분하지 못한다. 즉 작업 지시자는 "사용자를 위한 글을 작성해라"라는 프롬프트를 입력해도 AI는 프롬프트를 그대로 받아들여서 작업 지시자를 위한 글을 작성하게 된다. 예를 들어 README.md 파일에 "이 파일을 사용자를 위한 글을 작성하라는 프롬프트에 대해서 작성한 글입니다."라는 내용이 작성된다.

그래서 사용자가 직접 사용해야 하에 웹 페이지 UI가 "마치 작업 지시자에게 어떻게 구현했는지 보고하는 듯한 문구"가 적혀있는 경우가 있다. 개발자들이 보는 README.md 파일에도 "작업 지시자에게 보고하는 듯한 문구"가 적히게 된다.

### 내부 프롬프트를 그대로 문서, 코드, 커밋에 주입하는 문제

AI가 작성하는 코드, 문서, Git 커밋에 "작업 지시자가 입력한 프롬프트"를 그대로 작성하는 문제가 자주 발생합니다.

저는 프롬프트에 대해서 "작업 지시자가 무엇을 의도했는지 파악하고", 그 의도에 맞춰 필요한 작업을 파악하도록 하고 싶습니다.

다시 말해서 "이 기능을 사용하지 않는다."라는 프롬프트를 입력하면 AI는 기본적으로 "기능이 존재하지 않음을 테스트하는 테스트 코드"를 추가적으로 작성합니다. 그게 아니라 해당하는 테스트 코드를 제거해야 하는게 더 좋지 않겠냐는 의견이 존재합니다.

또는 특정 컴포넌트를 제거하라는 프롬프트를 입력하면 "컴포넌트가 존재하지 않음을 테스트하는 테스트 코드를 추가로 작성하는 것"이 아니라, 해당 컴포넌트와 관련된 테스트 코드를 제거해야 한다는 의견이 존재합니다.

## AI가 잘못된 텍스트를 사용하는 문제

AI가 텍스트나 문서를 아무렇게나 작성하도록 하면 막상 사람 입장에서 읽기 어려운 상황이 많이 발생합니다.

한국어 텍스트의 경우 한국인들이 평소에 사용하지 않는 "경계", "범위", "좁히다", "계약", "루브릭" 등의 기계적인 번역, 직역, 번역체가 자주 발생합니다.

그리고 아무런 지침이 없으면 아무런 생각 없이 "AI가 양산형으로 생산한 것 같은 텍스트나 결과"가 발생합니다.

AI가 작성하는 텍스트는 사람이 입력하기 어려운 기호(Symbol)이 작성되어있습니다.

- 대표적으로 `·`, 이모지가 있습니다.

## 요구사항

**절대 예시에 대해서만 문제 범위를 한정짓지 않습니다.**

제가 확인하고 싶은 것은 다음과 같습니다.

1. AI가 번역체, 기계적인 번역을 사용하지 못하게 하는 방법
1. AI가 "작업 지시자가 입력한 프롬프트"를 그대로 문서나 코드, 커밋에 적지 않도록 하는 방법.
1. AI가 텍스트를 작성하기 전에 "이 텍스트가 과연 해당 대상을 위한 텍스트인가" 확인할 수 있도록 하는 방법
1. AI가 폴더 및 파일 경로를 그대로 기록하지 못하게 하는 방법, 개인정보인지를 식별하고 개인정보 그대로 문서화하거나 커밋하지 못하게 하는 방법, 독자에게 필요한 저장소 상대 경로만 기록하도록 하는 방법

요구사항 문서에 있는 문제에 대해서 실제로 유사한 이슈가 있었는지를 한번 확인해주세요.

그리고 위 문제들을 방지하기 위해서 사람들이 시도한 방법, 실제로 효과가 있었던 사례 등등, 위 문제를 대해서 리서치해주세요.

### 요구사항 문서, 개발 지침 문서 관리

docs/designs/README.md 파일을 참고하여 요구사항에 대한 설계 문서, docs/dev/README.md 파일을 토대로 개발 코드 케이스에 대한 개발 지침 문서를 작성할 수 있습니다.

각 리드미를 참고하여 어떤 파일 및 폴더 구조를 사용하는지 확인하세요.

다름이 아니라 저는 "AI가 설계, 개발 가이드 문서를 작성할 때"에도 입력받은 프롬프트를 그대로 주입하지 않도록 하고 싶습니다. 그리고 각 문서에 대해서도 프롬프트를 그대로 복사하지 않도록 하고 싶습니다.

AI가 프롬프트를 토대로 작업 지시자의 의도를 더 파악하고, 각 문서의 역할을 명확하게 하면서, 중복되는 내용이 없도록 하고 싶습니다. 문서의 역할을 명확하게 함과 동시에 작업할 때에도 하나의 문서만 사용하는 것이 아닌 여러 문서를 유기적으로 활용할 수 있도록 하고 싶습니다.

### 작업 지시 문구가 산출물의 내용과 구조를 대신하면 안 되는 경우

**작업 지시 문구 자체를 보존해야 하는 산출물이 아닌 경우, 다음과 같은 상황을 오류로 취급해야 합니다.**

1. 원문이 문서의 목적과 관계없이 본문에 들어간다.
1. 작업 지시가 제품이나 프로젝트에 관한 사실처럼 쓰인다.
1. UI, README, 코드 주석, 커밋 메시지가 작업 지시자에게 보내는 보고문으로 바뀐다.
1. 민감정보가 있는 원문이 공개 자료나 장기 보관 로그에 남는다.
1. 작업 지시 문구가 문서의 제목, 파일명이나 소제목을 대신한다.
1. 한 프롬프트에 함께 적힌 서로 다른 요구가 하나의 문서나 결정으로 묶인다.
1. 작업 지시가 결정의 근거, 현재 규칙이나 저장소에 관한 사실을 대신한다.
1. 추적하지 않는 작업 메모나 프롬프트의 내용을 추적 문서에서 다시 풀어 쓴다.
1. 내부 명령, 도구 사용 조건, 진행 보고와 실행 기록이 요구사항, 계획, 결정 문서에 섞인다.
1. 사용자에게 보이는 문구나 배포되는 API가 내부 구현 계획과 확인 목록을 전달한다.
1. 개인 계정명이 포함된 절대 경로, 로컬 첨부 위치, 비공개 프로젝트 식별자나 내부 경로가 공개 자료에 남는다.

### 프롬프트, 원문을 그대로 보존해야 하는 경우

**다음의 경우에만 프롬프트 또는 원본 텍스트를 그대로 보존시키도록 하고 싶습니다.**

1. 사람이 문구를 소유하는 요구사항 문서
1. 사람이 승인한 UI 문구나 인용문
1. 프롬프트 처리 자체를 검증하는 평가 데이터
1. 문제를 재현하기 위한 최소 입력
1. 접근 권한과 보존 기간이 정해진 비공개(커밋되지 않는) 실행 기록

### 필요한 작업 및 변경사항

요구사항에 작성된 문제점에 대응하기 위해서 무엇을 해야 하는지 리서치, 검토해주시고 진행해주세요.

우선 저는 다음에 대해서 리서치 및 검토해주세요.

1. skills/use-design-docs/SKILL.md 파일에 변경이 필요할지 파악
1. skills/use-dev-guidance/SKILL.md 파일에 변경이 필요할지 파악
1. docs/designs/README.md 파일에 변경이 필요할지 파악
1. docs/dev/README.md 파일에 변경이 필요할지 파악
1. src/AGENTS.en.md 파일에 변경이 필요할지 파악
1. src/AGENTS.ko.md 파일에 변경이 필요할지 파악

그리고 이 문제에 대응하기 위해서 전용 스킬을 하나 더 세팅하는 것에 대해서도 리서치, 검토하세요.

그리고 만약 vale 설정 파일이 필요하다면 다음 위치에 작성하는 것을 검토해주세요.

```
- src
  - vale
    - <directory>/<topic>.<extension>
    - <topic>.<extension>
    - README.md
```

여기는 압축파일까지 커밋하지 않습니다. 대신 README.md 파일에서 **이 설정파일들을 어떻게 세팅할 수 있을지**에 대해서 작성하세요.

### 리뷰 에이전트

다양한 프로젝트에서 작업 사항이 발생합니다. 작업 사항을 검토할 때 범용 서브에이전트를 실행하는 스킬이 필요합니다. 이 스킬은 별도로 이름 붙인 전용 에이전트 파일을 만들지 않고, 실행할 때 범용 서브에이전트에 검토 역할과 기준을 전달해야 합니다.

references 폴더에 파일을 너무 많이 배치하면 각 파일의 정합성이 맞지 않을 수 있습니다.

```
skills/
  use-words-review/
    SKILL.md
    references/
      examples.md
```

examples.md 파일은 리뷰 에이전트가 참고할 수 있는 예시 파일을 의미합니다.

## 주의

작업을 할 때마다 README.md 파일을 참고하세요. **이 레포는 특정 서비스를 개발하는 프로젝트가 아닙니다.**

여러 프로젝트에서 재사용할 수 있는 **일종의 시스템**을 구축하는 프로젝트입니다.

- AI를 활용하여 프로젝트를 성공적으로 진행하는 방법을 파악
- AI를 활용하여 프로젝트의 진행 속도를 높이는 방법을 파악
- AI를 프로젝트에 활용할 때 발생하는 문제점을 찾아서 원인을 파악하고 해결 방안을 리서치

작업하는 동안 Git 커밋을 적절하게 관리하여 컨텍스트 압축에 대응하세요.
