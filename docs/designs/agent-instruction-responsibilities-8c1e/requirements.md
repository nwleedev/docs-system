# 에이전트 지침의 책임 분리

## 목표

여러 저장소에 공통으로 적용할 작업 원칙은 유지하면서, 항상 읽히는 AGENTS.md와 필요할 때 읽는 Skill 및 저장소 문서가 같은 규칙을 중복해서 관리하지 않도록 책임을 나눈다.

`skills/`는 완성된 Plugin이나 그대로 설치하는 제품이 아니다. 각 프로젝트 담당자가 필요한 Skill과 연결 문서를 선택하고, 대상 저장소의 구조와 정책에 맞게 수정할 수 있는 참고 구현으로 제공한다.

`use-design-docs`와 `use-dev-guidance`는 저장소별 기준 문서를 처음 마련할 수 있도록 각각 `references/_README.md`를 포함한다. 사용자가 Skill 디렉터리 전체를 설치 위치로 옮기면 이 참고 파일도 함께 설치된다. Skill은 설치된 참고 파일을 현재 저장소의 기준으로 직접 사용하지 않고, 저장소 기준 README가 없으며 사용자가 생성을 승인한 경우에만 그 내용으로 정해진 위치의 README를 만든다.

각 `_README.md`의 문서 시작 부분에는 대응하는 `docs/designs/README.md` 또는 `docs/dev/README.md`와 내용을 비교하고 공통 규칙이 바뀌었으면 `_README.md`를 교체하라는 관리용 HTML 주석을 한 줄 둔다. 이 주석은 참고 구현을 관리하는 사람을 위한 것이므로 저장소 기준 README를 만들 때에는 제외한다.

## 유지할 전역 원칙

- 모든 프롬프트에서는 인터넷 자료를 조사한다.
- 공식 문서, 표준, 원문과 공식 저장소 등 1차 자료를 최소 다섯 개 확보하려고 시도한다.
- 최종 답변에는 독자가 판단 근거를 확인할 수 있는 출처를 포함한다.
- 외부 의존성을 선택하거나 변경할 때에는 직접 및 전이 의존성의 디자인 패턴을 조사한다.
- 파일 변경이 승인된 작업에서는 컨텍스트 압축 뒤에도 복구할 수 있도록 안전한 작업 단위의 커밋을 선호한다.
- Git 저장소의 변경 작업에는 워크트리, 작업 브랜치와 정해진 디렉터리 구성을 사용한다.
- 새 worktree 브랜치는 사용자가 생성을 명시적으로 요청했을 때 만든다. AGENTS.md는 요청 뒤 적용할 브랜치, 위치와 커밋 규칙을 제공한다.
- `use-design-docs`는 저장소의 `docs/designs/README.md`를 먼저 확인한다. 파일이 없고 현재 작업에 설계 문서 기준이 필요하면 사용자에게 생성을 제안하고, 사용자가 승인하면 설치된 `references/_README.md`의 내용으로 `docs/designs/README.md`를 만든 뒤 새 파일 전체를 읽는다.
- `use-dev-guidance`는 저장소의 `docs/dev/README.md`를 먼저 확인한다. 파일이 없고 현재 작업에 개발 지침 기준이 필요하면 사용자에게 생성을 제안하고, 사용자가 승인하면 설치된 `references/_README.md`의 내용으로 `docs/dev/README.md`를 만든 뒤 새 파일 전체를 읽는다.
- 사용자가 기준 문서 생성을 거절하면 요청한 파일 작성을 일괄 중단하지 않는다. 저장소 지침과 기존 폴더 구조를 확인하여 근거가 있는 위치에 파일을 작성하고, 저장소 근거만으로 위치를 정할 수 없으면 사용자에게 확인한다.
- 저장소에 기준 README가 이미 있으면 `_README.md`로 덮어쓰거나 자동으로 맞추지 않는다. 기존 README를 현재 저장소의 기준으로 사용한다.
- `_README.md`를 갱신할 때에는 관리용 주석이 가리키는 저장소 README와 비교한다. 설계용 기본본은 공통 내용 전체를 반영하고, 개발용 기본본은 현재 저장소에만 적용되는 문서 링크와 지침을 제외한 공통 내용으로 교체한다.

## 완료 조건

- 재사용할 외부 조사 결과와 저장소 근거가 설계 패키지에 기록되어 있다.
- 사용자가 확정한 전역 원칙과 그 영향을 결정 문서에서 확인할 수 있다.
- 현재 전역 지침과 축소 예시의 차이가 규칙별로 분석되어 있으며, 사라진 규칙마다 유지, 이전 또는 제거 판단과 새 담당 파일을 확인할 수 있다.
- 축소 뒤에도 세 `use-*` Skill의 호출, 기존 동작과 검사 보호, 저장 문서의 문체와 근거 검토를 맡는 파일과 호출 조건이 명시돼 있다.
- Skill 또는 필수 참고 자료가 없을 때 에이전트가 규칙을 추정하지 않고 중단하도록 전역 예시와 각 Skill의 책임이 연결돼 있다. 저장소 기준 README만 없는 경우에는 생성 승인 또는 저장소 구조를 따르는 대체 절차를 사용한다.
- 작업이 끝난 뒤 사용할 한국어와 영어 전역 AGENTS.md 예시는 각각 `src/AGENTS.ko.md`와 `src/AGENTS.en.md`에서 확인할 수 있다.
- Skills 및 docs의 현재 담당과 후속 보완점은 조사 문서에서 구분되어 있다.
- `skills/use-words-review/scripts/`의 기존 검사 스크립트는 제거하거나 대체하지 않는다.
- README는 `skills/`를 사용자가 수정할 수 있는 참고 구현으로 설명하고, 완성된 Plugin이나 자동 설치 가능한 배포물로 안내하지 않는다.
- 두 Skill을 설치할 때 `_README.md`가 함께 설치된다는 점과, 승인 뒤 그 내용으로 생성할 저장소 README의 정확한 위치를 확인할 수 있다. 사용자가 생성을 거절하면 저장소 지침 및 폴더 구조를 따르는 절차도 확인할 수 있다.
- 각 `_README.md`에서 한 줄의 관리용 HTML 주석으로 비교할 저장소 README와 교체 조건을 확인할 수 있으며, 생성된 저장소 README에는 이 주석이 남지 않는다.
- 후속 적용은 설계 패키지, README, 두 `src/AGENTS.*.md`, `skills/use-design-docs`, `skills/use-dev-guidance`와 두 저장소 기준 README로 제한한다. 실제 사용자 AGENTS.md와 설정 파일은 변경하지 않는다.
- 자동 설치기, Plugin 패키지와 별도의 Git workflow Skill은 만들지 않는다.
