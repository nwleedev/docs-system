# 에이전트 지침을 계층별로 나누는 근거

## 조사 질문

여러 저장소에 공통으로 적용할 조사, 출처, 의존성, 커밋과 워크트리 원칙을 유지하면서도 AGENTS.md가 모든 실행 절차를 떠안지 않게 하려면 각 규칙을 어느 계층에서 관리해야 하는가.

이 조사는 `requirements.md`의 전역 원칙과 `src/AGENTS.ko.md`, `src/AGENTS.en.md`의 책임 분배를 뒷받침한다. 자료는 2026년 8월 8일에 확인했다.

## 항상 적용할 규칙은 전역 AGENTS.md에서 시작한다

Codex는 작업 전에 전역 지침과 저장소 지침을 차례로 결합한다. Codex home의 AGENTS.md는 모든 저장소에 적용할 기본값을 제공하고, 저장소 루트와 현재 디렉터리에 가까운 파일은 더 구체적인 규칙으로 앞선 지침을 보완하거나 덮어쓴다. Codex home은 기본적으로 `~/.codex`다. 전역 파일에는 모든 저장소에서 필요한 원칙과 다음 문서를 선택하는 조건을 우선해서 둬야 한다. [OpenAI의 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

Codex는 프로젝트 AGENTS 문서를 합칠 때 기본 32 KiB 한도를 적용한다. 중요한 호출 조건과 안전 원칙을 전역 파일에 간결하게 남기고, 저장소별 세부 지침도 필요한 내용만 두면 하위 지침이 잘릴 위험과 반복 문맥을 함께 줄일 수 있다. [OpenAI의 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

AGENTS.md 형식은 루트 파일에 프로젝트 전반의 지침을 두고 큰 저장소에서는 하위 AGENTS.md로 적용 대상을 좁히도록 안내한다. 이 구조는 개인의 공통 기본값과 저장소별 실행 명령을 서로 다른 계층에서 관리하는 방식과 맞는다. [AGENTS.md 형식 안내](https://agents.md/)

## 반복 절차는 Skill이 맡는다

Codex는 처음에는 Skill의 이름과 설명만 확인하고, 작업이 명시 호출이나 설명과 일치할 때 SKILL.md 전체를 읽는다. 따라서 AGENTS.md는 호출 조건을 유지하고, 조사 순서, 분기, 검사와 실패 처리는 해당 Skill이 맡을 수 있다. Skill이 많으면 초기 목록이 축약되거나 일부가 생략될 수 있으므로 전역 필수 절차는 AGENTS.md에서 명시적으로 호출해야 한다. [OpenAI의 Skills 안내](https://learn.chatgpt.com/docs/build-skills)

Agent Skills 명세도 SKILL.md에 핵심 절차를 두고 상세 자료와 실행 파일은 필요할 때 읽는 보조 파일로 분리하도록 권고한다. 이 방식은 개발 지침과 한국어 검토 기준을 AGENTS.md에 반복해서 싣지 않고도 재사용할 수 있게 한다. [Agent Skills 명세](https://agentskills.io/specification)

Plugin은 Skills, 연결 도구와 선택형 화면 구성을 함께 배포하는 단위다. [OpenAI의 Plugins 안내](https://learn.chatgpt.com/docs/plugins)

## 실행 환경 설정과 작업 규칙을 분리한다

Codex의 사용자 설정은 홈의 `config.toml`, 저장소 설정은 `.codex/config.toml`에 둘 수 있다. 검색 모드, 승인 정책, sandbox와 MCP 등록처럼 도구의 가용성과 권한을 정하는 값은 AGENTS.md의 작업 절차가 아니라 설정 파일이 관리한다. AGENTS.md는 인터넷을 조사해야 하는 조건을 정하고, 설정은 사용할 검색 방식과 권한을 제공한다. [OpenAI의 Codex 설정 안내](https://learn.chatgpt.com/docs/config-file/config-basic)

OpenAI의 모델 지침은 같은 지침을 한 번만 명시하고, 반복 설명과 예시는 줄이며, 중요한 승인 조건과 성공 기준은 유지하도록 권고한다. 전역 원칙을 AGENTS.md 한 곳에서 선언하고 세부 절차를 Skill과 문서로 연결하면 같은 규칙을 여러 파일에 복사하지 않아도 된다. [OpenAI의 모델 지침](https://developers.openai.com/api/docs/guides/latest-model)

## 워크트리 기본값에는 실행 환경에 따른 예외가 필요하다

Codex 데스크톱 앱의 Worktree 모드는 여러 작업을 별도 checkout에서 실행하지만 기본적으로 detached HEAD에서 시작한다. Git은 같은 브랜치를 두 checkout에서 동시에 사용할 수 없으므로, 수동으로 만드는 워크트리의 경로와 앱이 관리하는 워크트리의 위치를 같은 규칙으로 강제할 수 없다. 전역 지침은 격리와 브랜치 확인을 요구하고, 저장소 문서는 수동 워크트리의 경로와 이름을 정해야 한다. [OpenAI의 Worktrees 안내](https://learn.chatgpt.com/docs/environments/git-worktrees)

Git 공식 문서는 하나의 저장소에 여러 작업 트리를 연결해 서로 다른 브랜치를 동시에 checkout할 수 있다고 설명한다. 워크트리 규칙은 병렬 작업을 격리하는 수단이지만, 브랜치와 작업 디렉터리의 실제 이름은 저장소 관례와 충돌 여부를 확인한 뒤 정해야 한다. [Git의 git-worktree 문서](https://git-scm.com/docs/git-worktree)

## 조사 결과

- 모든 저장소에서 빠지면 안 되는 조사, 출처, 변경 권한과 Git 안전 원칙은 전역 AGENTS.md가 관리해야 한다.
- 작업 종류에 따라 달라지는 조사, 문서 작성, 의존성 검토와 문구 검수 절차는 해당 Skill이 관리해야 한다.
- 저장소의 기술, 명령, 보호 브랜치, 커밋 형식, 선택한 의존성 패턴과 예외는 저장소 AGENTS.md 또는 docs가 관리해야 한다.
- 검색 모드, sandbox, 승인 정책과 도구 등록은 Codex 설정이 관리해야 한다.
- 정확하게 판정할 수 있는 문서 구조, 비밀정보, 브랜치 보호와 정적 검사 규칙은 scripts, hooks 또는 CI로 확인해야 한다.

## 한계와 적용 영향

공식 문서는 사용자가 요구한 “모든 답변에 출처를 포함한다”거나 “공식 자료를 최소 다섯 개 조사한다”는 품질 기준을 정하지 않는다. 이 두 기준은 제품 제약이 아니라 사용자가 승인한 전역 작업 원칙이다. AGENTS.md에는 이 의무를 유지하되, 자료를 다섯 개 확보하지 못했을 때 저품질 자료로 숫자를 채우지 않고 확인 범위와 한계를 밝히는 실패 처리가 필요하다.

요구사항 작성자는 축약 초안을 두 `src` 예시에 적용하도록 요청하면서 직접 및 전이 의존성을 모두 조사하는 범위를 확정했다. 디자인 패턴이 적용되지 않는 전이 의존성에는 패턴 이름을 만들지 말고 적용할 패턴이 없다는 사실과 근거를 기록해야 한다.

## 축소 예시와 현재 전역 지침의 차이

2026년 8월 8일에 기존 전역 지침과 사용자가 제공한 축약 초안을 비교했다. 축약 초안은 Skill 호출문만 남긴 문서가 아니다. 검사 무력화 금지, 기존 동작과 API 및 데이터 보존, 기존 코드 패턴을 자동으로 답으로 삼지 않는 규칙, 조사 원칙, 서브에이전트 조건, 비밀정보, 임시 파일과 Git 규칙을 직접 유지한다.

삭제된 내용은 애플리케이션의 무조건적인 브라우저 검증, 문서 검사 상태의 상세 절차, 저장하거나 공유할 글의 전체 확인 목록, 기술에 종속된 주석 형식이다. 이 내용은 모든 저장소에 같은 문장으로 적용하기보다 작업에 맞는 Skill과 저장소 문서가 맡는 편이 적합하다. 다만 전역 호출 조건과 새 담당 문서가 함께 정해지지 않으면 삭제가 아니라 규칙 손실이 된다.

사용자가 제공한 축약 초안은 그대로 배포할 수 없었다. 현재 두 `src` 예시는 다음 세 문제를 언어별로 바로잡았다.

- `금칙어에 가까운`이라는 표현은 한국어 참고 자료의 “후보는 금칙어가 아니다”라는 판정과 충돌한다.
- `use-words-review` 호출문은 한국어 저장물만 가리켜 영어 README, 커밋, PR과 UI 문구를 빠뜨린다. 파일 저장 없이 특정 문구 검토를 요청한 경우도 호출 조건에 없다.
- 작성 전 한국어 참고 자료를 읽는 책임을 읽기 전용 검토 Skill에 돌리고 있다. 작성 전 로딩 조건은 AGENTS.md가 직접 정해야 한다.

현재 두 `src` 예시는 개발 변경의 호출 범위와 실행 검증 절차를 보완했다. 다음 문제는 이번 요구사항에서 별도 변경을 승인하지 않았으므로 조사 결과로 남긴다.

- 외부 조사를 모든 요청에 적용하면서 검색, 연결 도구 또는 서브에이전트로 보낼 비공개 자료의 최소화와 제거 조건을 정하지 않는다.

## 줄어든 지침을 지키게 하는 책임 구조

### 전역 AGENTS.md

모든 저장소에 공통인 결과, 금지 사항, 변경 승인 조건, 반드시 실행할 Skill 이름, Skill이나 필수 문서가 없을 때의 중단 조건을 둔다. 기존 동작과 외부 API, 저장 데이터, 오류 처리 및 호환성 보존과 검사 무력화 금지는 Skill 실행 전에도 적용되어야 하므로 전역 파일에 남긴다. 일반 채팅에는 언어와 무관하게 문장과 문단의 주체, 대상, 조건과 결과를 다시 읽는 짧은 기준을 둔다. 번역체와 한국어 표현 검사는 한국어 결과에만 적용한다.

전역 지침은 저장소 지침보다 절대적으로 높은 계층이 아니다. Codex는 전역에서 현재 디렉터리까지 지침을 결합하고 가까운 파일을 뒤에 놓는다. 저장소 지침은 전역 원칙을 구체화할 수 있지만 변경 권한, 비밀정보, 기존 동작과 검사 보호를 조용히 비활성화해서는 안 된다. [OpenAI의 AGENTS.md 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

### Skills

`use-design-docs`는 요구사항, 조사 자료, 결정과 계획의 작업 순서를 맡고 `docs/designs/README.md`를 저장소 기준으로 삼는다. 저장소 기준이 없고 현재 작업에 필요하면 설치된 `references/_README.md`와 생성 위치를 밝히고 승인을 받아 기준 README를 만든다. 사용자가 거절하면 저장소 지침과 기존 구조에서 근거가 있는 위치를 선택하며, 근거가 없으면 위치를 확인한다.

`use-words-review`는 모든 언어의 저장하거나 공유할 글과 이름을 읽기 전용으로 검토한다. 한국어가 있을 때만 기존 `references/korean.md`와 세 검사 스크립트를 사용한다. 현재 본문, 참고 자료와 스크립트는 유지한다.

`use-dev-guidance`는 소스 코드, 테스트, 스크립트, 라이브러리, API, 빌드, CI, 설정과 의존성 변경의 현황 파악, 조사, 적용과 검증 절차를 맡는다. 저장소 기준 README가 없을 때에는 `use-design-docs`와 같은 승인 및 대체 위치 절차를 사용한다. 보호할 동작의 기준선, 기존 패턴을 다시 쓰지 않을 판단 근거, 실행 중 관찰해야 하는 동작, 프로세스 수명주기와 의존성 통합 패턴 조사도 이 Skill이 맡는다.

Codex는 처음에 Skill 이름과 설명만 읽고 선택한 뒤에 본문을 읽는다. Skill 목록이 커지면 설명이 축약되거나 일부 항목이 생략될 수 있으므로 필수 Skill은 전역 AGENTS.md에서 정확한 이름으로 호출하고, 각 설명은 잘려도 적용 조건을 알아볼 수 있게 첫 문장에 주요 트리거를 둬야 한다. [OpenAI의 Skills 안내](https://learn.chatgpt.com/docs/build-skills)

### 저장소 AGENTS.md와 docs

저장소 AGENTS.md는 실제 명령, 보호 브랜치, 수동 worktree 위치, 언어와 저장소별 예외를 정한다. `docs/designs`는 요구사항, 조사 근거, 승인된 결정과 계획을 관리하고, `docs/dev`는 현재 기술과 버전에 적용되는 재사용 개발 규칙 및 검사 방법을 관리한다. 같은 규칙을 전역 파일과 저장소 문서에 복사하지 않는다.

`docs/dev/README.md`는 재사용할 의존성 통합 지침, 사용자가 관찰할 동작에 실행 환경 또는 브라우저 검사가 필요한 조건과 프로젝트 명령이 없을 때의 승인 절차를 관리한다. `use-dev-guidance`는 이 기준에 따라 실제 작업의 기준선과 검사를 선택한다.

## 축소 과정에서 빠진 규칙의 담당 위치

다음 목록은 기준 전역 지침에서 축소 예시로 바뀌며 삭제되거나 다시 쓰인 규칙을 문구의 첫 부분으로 식별한다. 후속 변경에서는 기준 자료와 이 목록을 대조해 빠진 항목이 없는지 확인한다.

### 전역 AGENTS.md에 유지하거나 명확하게 다시 쓸 규칙

- **“모든 답변과 문서는 두괄식”과 언어 기본값.** 전역 예시는 결론 우선과 기본 대화 언어를 유지하되, 주석을 지원하지 않는 파일에 예외 설명을 강제하지 않는다. 저장소가 다른 언어를 정하면 그 값을 사용한다.
- **“코드 구현”, “테스트 코드 작성”과 “TDD”의 명시 요청.** 세 작업은 서로 다른 변경 권한이므로 하나의 요청에서 나머지까지 승인됐다고 추정하지 않는 문구로 유지한다.
- **“작업의 범위를 임의로 변형시키지 않는다”.** 조사, 검토와 계획은 변경 권한을 만들지 않고 변경 요청도 명시된 로컬 범위만 허용한다는 전역 문구로 유지한다.
- **“컨텍스트가 압축되면 AGENTS.md”와 “Git 히스토리부터 파악”.** 전역 파일은 지침, 브랜치, Git 상태와 최근 복구용 커밋을 다시 확인하게 한다.
- **“워크트리 브랜치의 생성을 요구”.** 전역 파일은 모든 Git 변경의 격리를 유지하고 실행 환경이 관리하는 위치와 수동 위치를 구분한다.
- **“이모지를 사용하지 않는다”.** 일반 채팅과 저장 결과물에 적용되는 사용자 전역 기본값으로 유지한다.
- **“주석의 설명과 코드의 동작이 일치”.** 전역 파일에는 코드로 알 수 없는 호출 제약과 구현 이유만 기록하고 코드와 일치시킨다는 결과를 남긴다. 기술별 형식은 `docs/dev`가 맡는다.
- **“타입 검사”, “요구사항이나 기능”과 “테스트 실패”.** 검사나 기능을 비활성화하거나 lint 예외, skip, 테스트 삭제와 assertion 약화로 실패를 숨기지 않는 전역 금지로 유지한다.
- **“기존 기능, API, 저장 데이터, 오류 처리와 호환성”.** 사용자 요청이 바꾸지 않은 관찰 가능한 동작을 보존하는 전역 결과로 유지하고 상세 기준선은 `use-dev-guidance`가 맡는다.
- **“기존 코드는 현재 기능을 파악하는 자료”.** 반복되거나 가까운 코드가 자동 모범이 아니라는 결과는 전역에 남기고 패턴 선택 절차는 `use-dev-guidance`가 맡는다.
- **“모든 프롬프트의 인터넷 조사”, “공식 자료 다섯 개”와 “모든 답변의 출처”.** 모든 요청에서 유지하고, 자료 부족과 외부 조사가 금지된 경우의 처리도 함께 명시한다.
- **“조사 결과가 변경 권한을 만들지 않는다”.** 라이선스, 정책, 검사와 문서가 없다는 발견만으로 추가하지 않는 승인 조건으로 유지한다.
- **“서브에이전트의 보고를 완료 증거로 보지 않는다”.** 독립 작업만 병렬로 실행하고 메인 에이전트가 실제 파일과 검사 결과를 확인하는 최소 조건으로 유지한다.
- **“돌이킬 수 없는 명령”과 “사용자가 만든 변경”.** 승인 없는 파괴 작업과 사용자 변경 되돌리기 금지는 전역 파일에 남긴다.

### 현재 전역 예시에 유지한 저장소 작업 규칙

- **“.env와 테스트 fixture의 민감값 처리”.** 두 `src` 예시는 비밀정보 커밋 금지, 환경변수와 테스트 fixture 사용 규칙을 유지한다.
- **“임시 파일은 `temps/<scope>-<nonce>/`에 저장”.** 두 `src` 예시는 임시 파일의 위치와 이름 규칙을 유지한다.
- **“Playwright 또는 Chrome DevTools 스크린샷 위치”.** 두 `src` 예시는 MCP가 만든 스크린샷에도 같은 임시 파일 규칙을 적용한다.
- **“`.gitignore`에 등록된 파일을 커밋하지 않는다”.** 두 `src` 예시는 이 금지 사항과 커밋 전 민감정보 검사를 유지한다.
- **브랜치 종류의 `feature`, `fix`, `hotfix`, `refactor`, `test`, `docs`, `chore`.** 두 `src` 예시는 허용 값과 브랜치 이름 형식을 유지한다.
- **보호 브랜치, worktree 위치와 브랜치 이름.** 두 `src` 예시는 보호 브랜치 직접 수정 금지, 수동 worktree 위치와 이름 규칙을 유지한다.
- **커밋 제목, 본문과 푸터 형식.** 두 `src` 예시는 커밋 형식을 유지하고 공개 문구 검토는 `use-words-review`가 맡는다.
- **시각 조사 도구와 GitHub 조사 명령.** 두 `src` 예시는 MCP와 `gh` 사용 규칙을 유지한다.
- **진행하지 않는 worktree 정리 제안.** 두 `src` 예시는 제거 가능성을 교차 검증해 제안하는 규칙을 유지한다.

이 목록은 후속 변경의 필요성을 판단하기 위한 책임 지도다. 자동 설치, fixture 또는 새 평가 체계는 이번 적용에 포함하지 않는다.

## 현재 적용 범위

이 저장소의 `skills/`는 사용자가 프로젝트에 맞게 수정할 수 있는 참고 구현이다. 완성된 Plugin, 자동 설치나 자동 업그레이드를 제공하지 않으며, 사용자는 실행 환경이 지원하는 위치에 선택한 Skill 디렉터리 전체를 직접 옮긴다.

AGENTS.md 형식은 여러 도구가 읽지만 `$skill` 호출과 Skill 탐색 위치는 실행 환경마다 다르다. README는 확인된 실행 환경의 위치를 안내하되 자동 발견을 약속하지 않는다. 새 worktree 브랜치는 사용자가 명시적으로 요청한 뒤 만든다. [OpenAI의 Skills 안내](https://learn.chatgpt.com/docs/build-skills)
