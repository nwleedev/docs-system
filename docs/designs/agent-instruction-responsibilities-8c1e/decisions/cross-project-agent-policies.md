# 여러 저장소에 공통으로 적용할 에이전트 작업 원칙

## 결정이 필요한 이유

AGENTS.md의 크기를 줄이더라도 여러 저장소에서 조사 품질, 출처 표시, 의존성 검토, 작업 복구와 Git 격리 원칙이 빠지면 안 된다. 동시에 절차를 여러 AGENTS.md와 Skill에 복사하면 서로 다른 버전의 규칙이 적용될 수 있다.

이 결정은 `requirements.md`의 목표와 전역 원칙을 만족해야 한다.

## 검토한 구성

### 모든 절차를 AGENTS.md에 유지한다

전역 규칙을 빠뜨릴 가능성은 낮지만, 모든 작업이 사용하지 않는 세부 절차까지 매번 문맥에 포함된다. Skill과 저장소 문서가 같은 절차를 다시 설명하면 어느 파일을 고쳐야 하는지도 불분명해진다.

### AGENTS.md에는 Skill 호출문만 둔다

항상 읽는 문맥은 가장 작아지지만 Skill을 찾지 못하거나 호출 조건이 너무 좁으면 조사, 출처, 변경 권한과 Git 안전 원칙도 함께 사라진다. Plugin이 관리하는 범위와 저장소별 필수 정보도 Skill 호출문만으로 설명할 수 없다.

### 전역 원칙과 실행 절차를 나눈다

AGENTS.md는 모든 저장소에서 유지할 결과와 호출 조건을 정한다. Skills는 반복 가능한 실행 절차를 맡고, 저장소 AGENTS.md와 docs는 현재 저장소의 값, 근거, 결정과 예외를 기록한다. 설정과 자동 검사는 도구의 가용성과 기계적으로 판정할 수 있는 규칙을 맡는다.

## 승인된 결정

요구사항 작성자는 다음 원칙을 여러 프로젝트에 공통으로 적용하기로 결정했다.

- 모든 프롬프트에서는 인터넷 자료를 조사한다.
- 공식 자료를 최소 다섯 개 확보하려고 시도한다.
- 모든 최종 답변에는 판단 근거를 확인할 수 있는 출처를 포함한다.
- 외부 의존성을 선택하거나 변경할 때 직접 및 전이 의존성의 디자인 패턴을 조사한다.
- 파일 변경이 승인된 작업에서는 컨텍스트 압축에 대비해 안전한 작업 단위의 커밋을 선호한다.
- Compound Engineering이 관리하는 Codex 도구 매핑 범위는 사용자가 직접 수정하지 않는다.
- Git 저장소의 변경 작업에는 워크트리, 작업 브랜치와 정해진 디렉터리 구성을 사용한다.
- 새 worktree 브랜치는 사용자가 생성을 명시적으로 요청한 뒤 만든다.
- `skills/`는 완성된 Plugin이나 자동 설치 제품이 아니라 프로젝트 담당자가 선택하고 수정하는 참고 구현으로 제공한다.
- `use-design-docs`와 `use-dev-guidance`는 저장소 기준 README가 없을 때 사용할 시작 자료를 각각 `references/_README.md`에 포함한다.
- Compound Skills는 선택 사항이며, 설치되지 않은 환경에서도 같은 Git 원칙을 Git 기능으로 직접 적용한다.

## 결정이 남기는 제약

- 모든 저장소에서 위 원칙을 읽을 수 있어야 하며 저장소별 지침은 이를 조용히 비활성화하지 않는다.
- 조사와 검토는 의존성, 설정, 검사 또는 문서 변경 권한을 만들지 않는다.
- 안전한 커밋은 파일 변경이 승인된 작업에서만 만들며 사용자 변경사항을 포함하지 않는다.
- Compound Engineering이 관리하는 Codex 도구 매핑은 다른 문서에서 복제하거나 다시 정의하지 않는다.
- 저장소 기준 README가 이미 있으면 Skill의 `_README.md`로 덮어쓰거나 자동으로 맞추지 않는다.
- 저장소 기준 README가 없고 작업에 필요할 때에는 정확한 생성 위치와 사용할 `_README.md`를 밝힌 뒤 사용자의 승인을 받는다. 사용자가 기준 README 생성을 거절하면 저장소 지침과 기존 구조에 근거해 원래 요청한 설계 문서 또는 개발 파일의 위치를 정하되, 파일 작성이 승인된 요청에서만 변경한다.
- `use-words-review`의 기존 검사 스크립트는 책임 재분배를 이유로 제거하거나 다른 계층에 복제하지 않는다.
- 한국어와 영어 전역 예시는 각각 [`src/AGENTS.ko.md`](../../../../src/AGENTS.ko.md)와 [`src/AGENTS.en.md`](../../../../src/AGENTS.en.md)에 기록한다. Skills와 docs에서 이번 요구사항에 포함된 절차는 함께 보완하고, 그 밖의 제안은 조사 문서에 남긴다.

## 다시 검토할 조건

- Skill이 설치되지 않은 환경에서 전역 원칙이 반복해서 누락된다.
- 공식 자료 다섯 개 기준이 단순 작업에서 정확성을 높이지 못하고 지연만 일으킨다는 평가 결과가 쌓인다.
- 전이 의존성 전체를 개별 조사하는 비용이 정확성 향상보다 크다는 근거가 쌓인다.
- Codex 또는 Compound Engineering이 관리 범위와 지침 로딩 방식을 변경한다.
- 저장소별 워크트리 규칙이 Codex 데스크톱 앱의 관리 방식과 충돌한다.
