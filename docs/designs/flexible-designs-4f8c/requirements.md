# 유연한 설계를 위한 요구사항 관리

요구사항 생성과 보완은 입력의 뜻을 보존한 최소 작성으로 수행한다. 기존 문서를 활용하고, 상세 작성과 구조 정리를 구분하며, 추가 결정의 이유와 계획 변경을 추적할 수 있어야 한다. 스킬 이름은 `use-flexible-design`로 바꾸고 `use-design-docs`는 제거한다.

## 문서 구조와 연결

현재의 `docs/designs/<topic>-<short-id>/` 구조를 유지한다. 같은 폴더 안에서 `requirements.md`, `plan.md`, `references/<research-topic>.md`와 `decisions/<decision-topic>.md`를 관리하며, 필요한 문서만 생성한다. 폴더 이름의 짧은 식별자는 유지하고 요구사항, 플랜, 리서치와 결정 문서 및 그 안의 항목에는 별도 ID를 부여하지 않는다.

문서 간 관계는 파일의 상대 링크와 설명적인 제목 및 절 이름으로 연결한다. 기존 문서를 보완하거나 같은 작업의 플랜, 리서치와 결정을 추가할 때에는 기존 폴더를 사용한다. 같은 자료를 여러 플랜에서 사용하면 원래 파일을 참조하며 문서 연결을 위해 내용을 복제하거나 별도 식별자 목록을 만들지 않는다.

## 빈 문서 생성

빈 문서만 준비하는 요청에는 폴더와 빈 `requirements.md`를 생성하는 `.mjs` 스크립트를 제공한다. 기존 문서의 내용은 빈 문서 준비 요청으로 변경하지 않는다.

스크립트에는 실제 입력과 반환값을 설명하는 JSDoc을 작성한다. `any`, `object`, `Record<string, any>`, `unknown`처럼 값의 구조를 설명하지 않는 타입을 사용하지 않으며 외부 패키지에 의존하지 않는다.

## 기존 문서 활용

새 문서를 만들기 전에 같은 주제와 목적의 요구사항이 있는지 찾는다. 유사한 문서가 있으면 위치를 안내하고 기존 문서의 최소 보완으로 목적을 달성할 수 있는지 검토한다. 같은 내용이 이미 있으면 중복 추가하지 않는다. 제목이나 단어가 비슷하다는 이유만으로 서로 다른 목적의 요구사항을 합치지 않는다.

## 내용 작성과 구조 정리

요구사항 생성 또는 보완 요청에서는 입력을 바탕으로 필요한 내용만 작성한다. 별도의 직접 작성 표현을 요구하지 않는다. 상세 작성 요청에서는 명시된 동작과 조건을 더 자세히 정리하되, 상세함을 이유로 확인되지 않은 기능이나 조건을 추가하지 않는다. 일부 보완과 문서 전체 작성은 모두 가능해야 한다.

직접 파일을 편집하지 않고도 대화 내용이나 임시 첨부 자료를 바탕으로 요구사항을 작성하거나 보완할 수 있어야 한다. 빈 문서 준비, 작성, 검토와 구조 정리는 현재 요청과 앞서 확인된 작성 의도로 구분한다. 입력 방식이나 첨부 사실만으로 작성 범위를 확대하지 않는다. 기록할 목표나 조건이 없으면 내용을 추정하지 않고 필요한 정보를 확인한다.

요구사항으로 옮길 때 뜻, 수치, 조건, 예외와 필수 여부를 보존한다. 프롬프트 원문이나 대화 경위를 붙여 넣는 대신 필요한 요구사항으로 정리한다. 조사 결과와 제안을 확정된 요구사항으로 바꾸어 넣지 않는다. 기존 내용과 새 내용이 충돌하거나 뜻을 확정할 수 없으면 임의로 선택하거나 병기해 확정하지 않는다.

기존 요구사항에는 누락된 정보, 작업 착수에 필요한 조건과 개발에 필요한 조건을 조사해 제안한다. 조사와 제안만으로 원문을 수정하지 않는다. 구조 정리 요청이 있으면 의미, 조건과 범위를 보존하며 내용을 재배치할 수 있어야 한다.

## 추가 결정과 계획 변경

작업 도중 추가 결정이 필요하면 결정할 질문과 선택지를 구분하고, 확정된 결정의 이유와 영향을 결정 문서에 기록한다. 관련 계획에도 반영하여 변경 이력을 파악할 수 있어야 한다. 확정되지 않은 선택을 결정된 것으로 기록하지 않는다.

## 완료 조건

- 기존 폴더 구조와 폴더 이름의 짧은 식별자를 유지하고, 네 종류의 문서와 항목에 별도 ID를 추가하지 않는다.
- 플랜에서 요구사항, 리서치와 결정의 근거를 파일 및 절 이름으로 따라갈 수 있다.
- 빈 문서 생성이 내용 작성 권한과 무관하게 가능하고 기존 파일을 덮어쓰지 않는다.
- 빈 문서 준비, 최소 작성, 상세 작성과 구조 정리에서 각각 허용되는 작업을 구분할 수 있다.
- 요구사항 생성과 보완은 최소 작성을 기본으로 하며, 빈 문서 요청과 읽기 전용 검토에서는 본문을 작성하지 않는다.
- 기존 문서의 유무와 작업 목적에 따라 위치 안내, 기존 문서 보완과 새 문서 생성을 선택할 수 있다.
- 대화와 첨부 자료로 작성할 때 뜻과 조건을 보존하고 기존 내용과 중복되거나 충돌하는 사항을 구분할 수 있다.
- 부족한 정보의 조사 결과와 제안은 요구사항 본문과 분리되어 있다.
- 추가 결정 문서와 관련 계획에서 결정 이유와 영향을 따라갈 수 있다.
- 현재 사용하는 스킬과 호출 지침이 `use-flexible-design`를 가리키며 기존 이름의 스킬은 남지 않는다.
