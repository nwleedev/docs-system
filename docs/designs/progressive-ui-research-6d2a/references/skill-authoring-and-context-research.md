# 스킬 지침과 참고 자료 구성 조사

후속 스킬 문서 작업자는 이 자료를 참고해 `use-progressive-user-interfaces`를 구성하고, 사실과 계획상 판단을 구분한다. 이 자료 자체가 새로운 사용자 요구사항을 추가하지는 않는다.

조사 자료는 2026-09-25에 확인했다. 버전이 표시되지 않은 공식 웹 문서는 확인일 기준 내용으로 취급한다.

## 조사 질문

- 실제 UI 조사 절차를 충분히 구체화하면서도 모든 작업에 불필요한 지침을 한꺼번에 읽히지 않게 하려면 스킬 파일을 어떻게 나눌 것인가?
- 수정 후 스킬이 후보 탐색, 실제 화면 확인, 선택 비교와 검증을 요구사항에 맞게 이어 가는지 무엇으로 확인할 것인가?

## 저장소에서 확인한 현재 상태

현재 `skills/use-progressive-user-interfaces/SKILL.md`는 43줄이며, `references/`에는 탐색, 사용자 선택, 구현 입력과 검증 문서가 있다. 탐색 문서는 목표와 사용자 작업을 먼저 확인하지만 후보 검색, 실제 화면 관찰, 접근 실패와 후보 제시를 한 절차에 함께 둔다. 구현 입력 문서는 색, 배경, 글자, 간격, 형태, 테두리와 그림자 중심으로 규칙을 전달한다.

`preferences.md`는 사용자의 확인된 선택, 미결정 상태, AI 가설, 잠정 구현안, 검증된 규칙과 탐색 차례를 구분한다. `validation.md`는 최신 실행 화면에서 변경 영향을 받은 상태와 조건을 확인하고 같은 규칙을 어느 화면까지 재사용할지 판단한다. 이번 요구사항에서도 이 원칙을 유지한다. 자세한 기준은 [요구사항의 유지 항목](../requirements.md#현재-유지해야-하는-부분)과 기존 [점진적 UI 선호 탐색 계획](../../progressive-ui-design-system-7c9e/plan.md)을 따른다.

현재 요구사항 패키지의 [실제 UI 리서치 근거](research-evidence.md)는 Web Search와 Browser의 역할, 데스크톱 내장 Browser와 Cloud Browser의 차이, 접근성 및 구성 요소 상태에 관한 공식 자료를 이미 정리한다. 이 계획 자료에서는 이 사실을 복사하지 않고 필요한 때 그 문서를 재사용한다.

## 공식 자료에서 확인한 내용

[OpenAI의 스킬 작성 안내](https://developers.openai.com/plugins/build/skills)는 스킬을 분명한 사용자 목표에 연결하고, 입력, 작업 순서, 산출물, 추론하지 말아야 할 사실, 질문하거나 멈출 조건과 참고 자료를 설명하도록 권한다. `SKILL.md`에는 필요한 안내를 두고 세부 내용은 단계별 참고 문서에 나누며, 각 참고 자료를 언제 읽을지 루트 문서에서 안내하도록 한다. 이 원칙은 탐색, 화면 점검과 비교 분석을 작업 단계에 맞춰 읽는 구조를 뒷받침한다.

OpenAI의 [GPT-6 Astra용 스킬 및 프롬프트 작성 안내](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)는 2026-09-11 게시 자료다. 작업 절차가 여러 개인 스킬은 루트 파일을 간결한 안내자로 두고 작업에 필요한 참고 자료만 읽게 하며, 지나치게 상세한 절차는 모델의 판단을 불필요하게 제한할 수 있다고 설명한다. 따라서 요구사항의 세부 항목을 모두 `SKILL.md`에 붙여 넣지 않고, 조건이 다른 하위 절차에 배치한다.

[Agent Skills 명세](https://agentskills.io/specification)는 `SKILL.md`와 선택적 `references/` 파일의 구조를 정의하고, 참고 자료를 필요에 따라 읽는 점진적 공개 방식을 설명한다. 또한 루트 문서의 권장 분량, 참고 파일의 집중도, 스킬 루트 기준 상대 링크와 깊은 참조 연결을 피하는 방법을 제시한다. 이 저장소의 루트 스킬은 이미 짧으므로 분량 제한을 맞추기 위해 나눌 이유는 없다. 분리 여부는 각 절차의 입력과 산출물이 다른지에 따라 판단한다.

OpenAI의 [스킬 개발자 문서](https://developers.openai.com/api/docs/guides/tools-skills)도 `SKILL.md`와 필요할 때 읽는 보조 자료를 나누는 구조를 설명한다. OpenAI의 스킬 작성 안내는 수정 뒤 직접 요청, 간접 요청, 불완전한 입력, 스킬을 실행하지 않아야 할 요청과 근거 없는 행동을 피해야 하는 예를 대표 사례로 확인하라고 권한다. 이 확인 방법은 새 자동화 도구를 추가하지 않고 요구사항의 성공 기준을 검토하는 데 활용할 수 있다.

[OpenAI 플러그인 스킬 안내](https://developers.openai.com/plugins/concepts/skills)는 MCP 기반 플러그인 스킬이 도구를 사용할 시점과 순서, 도구 응답이 불완전할 때의 처리, 최종 응답을 정하는 절차를 제공한다고 설명한다. 플러그인 문서이므로 일반 스킬 형식의 규칙으로 확대하지 않고, 도구를 선택하는 절차도 스킬이 맡을 수 있다는 보조 근거로만 사용한다.

## 자료를 계획에 적용한 판단

후보 탐색, 실제 UI 관찰과 선택지 비교는 입력과 완료 근거가 서로 다르다. 이에 따라 `discovery.md`는 후보 탐색과 탐색 종료 판단을 맡고, 새 `inspection.md`는 실제 화면과 상호작용을 확인하는 조건을 맡으며, 새 `rationale.md`는 사례별 분석을 마친 뒤 차이와 장단점을 비교하도록 계획한다. 이 파일 분리는 요구사항의 제안에 근거한 계획상 선택이며, 승인된 새 사용자 요구사항으로 취급하지 않는다.

루트 스킬은 현재 사용자의 작업과 미결정 디자인 질문에 따라 필요한 절차만 안내한다. 새 `sources.md`, 별도 자료 저장 서비스, 자동 조사 스크립트 또는 새 외부 의존성은 계획하지 않는다. 출처를 현재 자료와 대조할 때는 기존 `research-evidence.md`를 사용하고, 실행 시점에 바뀔 수 있는 외부 지침을 스킬 본문에 복사하지 않는다.

기존 `preferences.md`의 응답 대기, 선택을 어디에 적용하는지와 기본 탐색 횟수 처리는 보존한다. 구현 입력과 검증도 `implementation.md` 및 `validation.md`에 남기되, 새 분석 절차에서 전달한 근거와 사용 조건이 빠지지 않도록 연결한다.

## 조사 한계

공식 문서는 스킬 파일을 구성하는 권장 방법을 설명하지만, 현재 스킬에 새 참고 문서 두 개를 추가하는 것이 성과를 얼마나 높이는지 실험한 자료는 아니다. 파일 분리가 적절한지는 각 단계의 판단 근거가 다른 절차에 섞이지 않는지와 요구사항의 확인 사례를 연결해 검토해야 한다.

Browser 이용 가능 여부와 웹사이트 접근 조건은 실행 환경에 따라 달라진다. 실제 화면을 확인할 때는 실행 환경에서 Browser를 쓸 수 있는지와 대상 사이트에 접근할 수 있는지 확인한다. 이 조건과 UI 관찰 근거는 기존 [실제 UI 리서치 근거](research-evidence.md)를 참조한다.
