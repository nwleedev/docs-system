# `use-better-terms` 재작성 검토 강화 계획

## 기준과 범위

이 계획은 [재작성 검토 강화 요구사항](./requirements.md)의 `목표`, `문제 후보를 검토하는 방법`, `유지할 동작`, `적용 조건`과 `완료 증거`를 기준으로 한다. 조사 근거는 [자연스러운 재작성과 능동문 및 피동문 선택 조사](./references/active-passive-rewrite-research.md)를 따르고, 검사 결과 구조와 대안 탐색 순서는 [출력 구조 유지와 대체 표현 우선 탐색](../korean-scanner-coverage-9b4e/decisions/output-structure-and-alternative-search.md)을 유지한다.

후속 변경은 `skills/use-better-terms/SKILL.md`와 `skills/use-better-terms/references/korean.md`의 검토 절차를 강화하고 대표 평가 사례를 추가한다. 검사 스크립트, 규칙 목록, 입력 방식, JSON 결과 구조와 종료 상태는 바꾸지 않는다.

스크립트가 알린 모든 항목은 검토 대상이 된다. 각 항목에서 수정이 필요한지 검사하고, 현재 문장과 주변 문장만으로 판단할 수 없으면 문맥을 더 확인해야 하는지도 검사한다. 수정하지 않기로 판정하려면 검토한 대안과 원문 유지 근거가 있어야 한다.

스크립트의 회귀 검증에는 [Development Guidance](../../dev/README.md)와 [Node.js MJS 명령줄 검사기](../../dev/node/mjs-cli.md)를 적용한다. 스크립트 변경이 필요하다고 확인되면 계획에 포함하지 않은 변경이므로 구현을 멈추고 요구사항과 계획을 다시 검토한다.

## 구현 결정

- 스크립트는 문제 후보만 알리고 수정 여부는 정하지 않는 현재 책임을 유지한다. 후속 판정 절차가 각 경고의 수정 필요성과 추가 문맥 확인 필요성을 검사한다.
- 경고된 표현마다 자연스러운 대안을 찾은 뒤 적용 여부를 정한다. 원문을 유지할 때에는 대안과 유지 근거를 남긴다.
- 능동문과 피동문은 문법 형식만으로 우열을 정하지 않는다. 행동 주체와 책임이 필요한지, 대상의 상태나 처리 결과가 중심인지에 따라 비교하며 태 선택이 적용되지 않는 경고에는 이 비교를 요구하지 않는다.

## 작업 단위와 순서

### 대표 평가 사례를 정한다

**목표:** 강화된 검토 절차가 내려야 할 판정과 보호할 동작을 사례별로 확인할 수 있게 한다.

**요구사항:** `문제 후보를 검토하는 방법`과 `완료 증거`

**의존성:** 없음

**파일:**

- 새로 작성: `docs/designs/better-terms-rewrite-depth-7c1d/references/rewrite-review-evaluation-cases.md`
- 근거로 확인: `docs/designs/better-terms-rewrite-depth-7c1d/requirements.md`
- 근거로 확인: `docs/designs/better-terms-rewrite-depth-7c1d/references/active-passive-rewrite-research.md`

**접근 방법:**

1. 경고가 발생한 합성 문장과 필요한 주변 문맥을 함께 기록한다.
2. 각 사례에 수정 필요성, 추가 문맥 확인 필요성, 검토한 대안, 최종 판정과 판정 근거를 기록한다.
3. 책임 주체를 밝혀야 하는 능동문, 상태나 처리 결과가 중심인 피동문, 원문 유지, `needs human input`과 태 선택이 적용되지 않는 경고를 포함한다.
4. 능동문과 피동문이 모두 가능한 사례에는 두 표현을 비교하고 선택 이유를 기록한다.

**검증 사례:** 평가 문서가 요구사항의 대표 사례를 빠짐없이 포함하고, 경고가 발생했다는 이유만으로 수정 또는 원문 유지를 확정하지 않아야 한다. 원문 유지 사례에는 자연스러운 대안과 유지 근거가 함께 있어야 한다.

**완료 증거:** 요구사항의 각 대표 사례를 평가 문서의 제목이나 판정 항목으로 추적할 수 있고, 판정에 필요한 문맥이 없는 사례는 `needs human input`으로 남아야 한다.

### 경고별 재작성 판정 절차를 강화한다

**목표:** 모든 경고에서 수정 필요성과 추가 문맥 확인 필요성을 검사하고, 더 자연스러운 문장 구조를 찾도록 스킬의 실행 순서를 명확히 한다.

**요구사항:** `목표`, `문제 후보를 검토하는 방법`, `유지할 동작`과 `적용 조건`

**의존성:** 대표 평가 사례를 정한 뒤 진행한다.

**파일:**

- 수정: `skills/use-better-terms/SKILL.md`
- 수정: `skills/use-better-terms/references/korean.md`
- 평가: `docs/designs/better-terms-rewrite-depth-7c1d/references/rewrite-review-evaluation-cases.md`

**접근 방법:**

1. `SKILL.md`는 `sources`, 두 `checks`, 각 `catalog`, 연결된 `rules`, 모든 `warnings`와 `summary`를 확인해야 검토가 끝난다는 완전성 조건을 계속 맡는다. 익숙한 표현이나 예상 판정이 있는 경고도 검토에서 제외하지 않는다.
2. 각 경고에서 수정 필요성과 추가 문맥 확인 필요성을 모두 검사한다. 수정하지 않는 경고도 자연스러운 대안과 원문 유지 근거를 확인하며, 판단 근거가 부족한 경고는 검토를 마친 것으로 처리하지 않는다.
3. 모든 경고를 검토한 뒤 저장하거나 공유할 단위와 그 단위에 적용되는 기준마다 `pass`, `needs revision`, `needs human input` 또는 `not applicable`을 정한다. 기존 판정 상태를 관리한다는 말은 네 상태의 이름과 의미를 유지한다는 뜻이며, 이전 판정을 재사용하거나 일부 경고의 검토를 생략한다는 뜻이 아니다.
4. `references/korean.md`는 문장과 주변 문장을 확인한 뒤 수정 필요성과 추가 문맥 확인 필요성을 나누어 판단하는 순서를 관리한다.
5. 단어를 바꾼 첫 대안이 문제를 해결하지 못하면 주어와 서술어 변경, 명사 표현을 동사로 풀어 쓰기, 문장 분리와 태 전환을 계속 검토하게 한다.
6. 두 파일에 같은 판정 규칙을 반복하지 않고, `SKILL.md`에서 한국어 판정 자료를 읽고 적용하도록 연결한다.
7. 네 판정 상태의 의미, 민감정보와 개인 위치 검사, 수정 뒤 재검사 절차를 그대로 유지한다.

**검증 사례:**

- 행동 주체와 책임이 빠진 경고는 확인되지 않은 주체를 만들지 않고 `needs human input`으로 판정해야 한다.
- 뜻을 보존하는 더 자연스러운 표현이 있는 경고는 대안을 적용하거나 `needs revision`으로 판정해야 한다.
- 원문이 가장 정확한 경고는 검토한 대안과 유지 근거가 있을 때만 `pass`로 판정해야 한다.
- 상태가 중심인 피동문과 태 선택이 적용되지 않는 경고는 형식적인 능동문 전환 없이 각 경고의 기준으로 판정해야 한다.

**완료 증거:** 대표 평가 사례를 새 절차로 판정했을 때 기대 상태, 대안과 근거가 일치하고 판정하지 않은 경고가 없어야 한다. 기존 `pass`, `needs revision`, `needs human input`과 `not applicable`의 의미가 달라지지 않아야 한다.

### 검사기 동작과 검토 절차의 회귀를 확인한다

**목표:** 검토 절차를 강화한 뒤에도 검사기 동작과 기존 검토 절차가 유지됐음을 실행 기록으로 확인한다.

**요구사항:** `유지할 동작`과 `완료 증거`

**의존성:** 경고별 재작성 판정 절차를 강화한 뒤 진행한다.

**파일:**

- 검사 대상: `skills/use-better-terms/scripts/scan.mjs`
- 검사 대상: `skills/use-better-terms/scripts/korean-expressions.mjs`
- 검사 대상: `skills/use-better-terms/scripts/long-paragraphs.mjs`
- 검토 대상: `skills/use-better-terms/SKILL.md`
- 검토 대상: `skills/use-better-terms/references/korean.md`
- 평가 대상: `docs/designs/better-terms-rewrite-depth-7c1d/references/rewrite-review-evaluation-cases.md`

**접근 방법:**

1. 검사기 자체 검사와 저장소 정적 검사를 실행한다.
2. 대표 입력을 `--stdin`과 `--source-name`, `--file`, `--changed`로 검사하고 `--help` 사용법을 확인한다.
3. 변경 전후 결과에서 입력 방식, 두 검사 결과, 경고 위치, JSON 필드, 결과 순서와 종료 상태를 비교한다.
4. 검사 스크립트와 의존성 파일이 바뀌지 않았고, 스킬이 실행 중 네트워크 요청이나 외부 패키지를 새로 요구하지 않는지 확인한다.
5. 최종 문서를 독자의 관점에서 읽고 요구사항, 조사, 스킬 절차와 평가 사례가 같은 판정 순서를 설명하는지 확인한다.

**검증 사례:** 경고가 있는 정상 입력은 온전한 JSON을 출력하고 정상 종료해야 한다. 잘못된 입력은 기존 오류 처리와 종료 상태를 유지해야 한다. 스킬 판정은 대표 평가 사례에서 수정 필요성과 추가 문맥 확인 필요성을 모두 검사해야 한다.

**완료 증거:** `scan.mjs --self-test`, `--help`, 대표 `--stdin` 및 `--source-name`, `--file`, 최종 `--changed` 검사와 저장소 lint 결과를 남긴다. 검사기와 의존성 파일의 변경이 없고, 결과 구조와 종료 상태의 차이가 없으며, 모든 새 경고를 판정해야 한다.

## 중단 조건과 사람의 판단이 필요한 항목

- 검사 스크립트, 규칙 목록, 입력 방식, JSON 결과 구조나 종료 상태를 바꿔야만 검토 절차를 강화할 수 있으면 구현을 멈추고 요구사항과 계획을 다시 검토한다.
- 원문에서 행동 주체, 대상, 조건 또는 결과를 확인할 수 없으면 자연스러운 문장을 추측해 만들지 않고 `needs human input`으로 판정한다.
- 능동문과 피동문 중 하나를 선택하면 확인되지 않은 뜻이 생기거나 문장의 초점이 달라지는 경우에는 선택을 확정하지 않는다.
- 기존 판정 상태의 의미, 민감정보 검사 또는 수정 뒤 재검사 절차를 줄여야 하는 충돌이 생기면 그 변경을 멈추고 판단을 요청한다.

현재 확인된 구현 차단 항목은 없다.
