# 재작성 판정 절차 평가 사례

## 결론과 사용 방법

이 문서는 `use-better-terms`를 관리하고 검토하는 사람이 강화된 재작성 절차의 판정을 사례별로 비교하는 평가 입력이다. 모든 사례는 검사 스크립트가 알리는 표현을 포함하며, 현재 문장과 판정에 필요한 주변 문맥을 함께 제공한다. 검토 절차는 각 경고에서 수정 필요성과 추가 문맥 확인 필요성을 모두 검사한 뒤 대안, 최종 판정과 근거를 남겨야 한다.

사례의 문장, 역할과 조건은 평가를 위해 합성했으며 실제 저장소의 책임 관계나 동작을 설명하지 않는다. 검토 과정에서 새 역할을 보태서는 안 되며, 각 사례의 주변 문맥에 적힌 역할만 확인된 근거로 사용할 수 있다.

최종 판정은 현재 [`use-better-terms` 절차](../../../../skills/use-better-terms/SKILL.md)의 의미를 따른다. 수정한 대안을 적용했거나 원문 유지 근거가 확인되면 `pass`, 고칠 내용과 뜻을 보존하는 대안이 확인됐지만 적용하지 못하면 `needs revision`, 뜻이나 책임 관계를 정할 근거가 없으면 `needs human input`으로 판정한다. `not applicable`은 해당 판정 항목을 경고에 적용할 수 없을 때만 사용한다. 태 선택이 적용되지 않는 경고도 경고 자체는 검토해야 하므로, 태 선택 항목만 `not applicable`로 기록하고 한국어 표현 기준의 최종 판정을 따로 정한다.

## 평가 근거

- [재작성 검토 강화 요구사항](../requirements.md)의 `문제 후보를 검토하는 방법`과 `완료 증거`가 필요한 주변 문맥, 대안 탐색 범위와 대표 사례의 종류를 정한다.
- [자연스러운 재작성과 능동문 및 피동문 선택 조사](./active-passive-rewrite-research.md)는 책임 주체가 필요하면 능동문을 우선 검토하고, 처리 뒤 상태가 중심이면 피동문이나 상태 설명을 유지할 수 있다고 결론 내린다.
- [한국어 표현 후보 정의](../../../../skills/use-better-terms/scripts/korean-expressions.mjs)에 따라 아래 합성 문장은 `ko.by-passive`, `ko.path`, `ko.middle-dot` 또는 `ko.about` 규칙이 찾는 표현을 그대로 포함한다.

## 사례 1. 승인 책임을 드러내는 능동문

**경고 문장:**

> 변경은 검토에 의해서 승인됩니다.

**경고:** `ko.by-passive`가 `에 의해서`를 알린다.

**주변 문맥:** 이 절은 배포 승인 책임을 설명한다. 검수자는 변경 내용과 검사 기록을 확인한다. 승인 책임자만 배포를 승인할 수 있다.

**수정 필요성:** 필요하다. 경고 문장은 검수와 승인을 한 행동처럼 묶고, 두 행동을 맡은 역할을 드러내지 않는다.

**추가 문맥 확인 필요성:** 필요하지 않다. 주변 문맥이 검수자와 승인 책임자의 행동을 구분한다.

**검토한 대안:**

- 능동문: `검수자가 변경 내용과 검사 기록을 확인하고, 승인 책임자가 배포를 승인합니다.`
- 피동문: `검수자의 확인이 끝나면 승인 책임자의 결정에 따라 배포가 승인됩니다.`

**태 선택:** 능동문을 선택한다. 두 대안 모두 확인된 순서를 나타내지만, 독자는 누가 내용을 확인하고 누가 승인 책임을 지는지 알아야 한다. 능동문은 두 역할의 행동을 직접 연결한다.

**최종 판정:** 능동문 대안을 적용한 뒤 `pass`.

**판정 근거:** 대안은 검수와 승인 순서를 보존하면서 행동 주체와 책임을 분명히 한다. 확인되지 않은 역할이나 조건을 보태지 않는다.

## 사례 2. 처리 뒤 상태를 중심에 둔 피동문

**경고 문장:**

> 임시 파일은 정리 절차에 의해서 삭제됩니다.

**경고:** `ko.by-passive`가 `에 의해서`를 알린다.

**주변 문맥:** 이 절은 배포가 끝난 뒤 임시 파일이 남아 있는지 확인하는 방법을 설명한다. 배포 절차는 마지막 단계에서 임시 파일을 자동으로 삭제한다. 운영자는 삭제 동작을 시작하지 않고 파일이 남지 않았는지만 확인한다.

**수정 필요성:** 필요하다. `정리 절차에 의해서`는 처리 주체와 시점을 어색하게 나타내며, 운영자가 확인해야 할 상태를 뒤로 미룬다.

**추가 문맥 확인 필요성:** 필요하지 않다. 주변 문맥에서 자동 삭제 시점과 운영자의 다음 행동을 확인할 수 있다.

**검토한 대안:**

- 능동문: `배포 절차가 마지막 단계에서 임시 파일을 자동으로 삭제합니다.`
- 피동문: `배포가 끝나면 임시 파일은 자동으로 삭제됩니다.`

**태 선택:** 피동문을 선택한다. 두 대안은 같은 처리 동작을 나타내지만, 이 절의 독자는 처리 주체보다 배포 뒤 파일이 남지 않는 상태를 확인해야 한다. 피동문은 확인 대상과 시점을 먼저 보여 준다.

**최종 판정:** 피동문 대안을 적용한 뒤 `pass`.

**판정 근거:** 대안은 확인된 자동 삭제 동작과 시점을 보존하고 불필요한 행위자를 만들지 않는다. 피동 형식 자체를 이유로 능동문을 강제하지 않는다.

## 사례 3. 정확한 기술 용어인 원문 유지

**경고 문장:**

> 설정 파일 경로는 `config/app.yml`입니다.

**경고:** `ko.path`가 `경로`를 알린다.

**주변 문맥:** 이 절은 저장소 안에서 설정 파일을 찾을 위치를 안내한다. `config/app.yml`은 저장소 최상위 디렉터리를 기준으로 한 파일 경로다.

**수정 필요성:** 필요하지 않다. `경로`는 식별할 수 있는 파일 위치를 가리키는 정확한 기술 용어다.

**추가 문맥 확인 필요성:** 필요하지 않다. 기준 디렉터리와 파일 위치가 주변 문맥에 명시돼 있다.

**검토한 대안:** `설정 파일은 저장소의 \`config/app.yml\`에 있습니다.`

**태 선택:** `not applicable`. 경고는 파일 위치를 나타내는 명사 표현에 관한 것이며 행동 주체나 처리 결과를 나타내는 문장이 아니다.

**최종 판정:** 원문을 유지하고 `pass`.

**판정 근거:** 대안도 뜻을 보존하지만 원문은 값이 파일 경로라는 성격을 더 직접적으로 밝힌다. 코드 표기와 저장소 기준 위치도 분명하므로 표현을 바꿀 근거가 없다.

## 사례 4. 책임 주체를 확인할 때까지 판단을 보류

**경고 문장:**

> 위험이 발견되면 배포는 검토에 의해서 중단됩니다.

**경고:** `ko.by-passive`가 `에 의해서`를 알린다.

**주변 문맥:** 자동 검사가 위험을 알리면 검토가 시작된다. 기존 자료에는 검사기가 배포를 자동으로 막는지, 검수자가 중단을 요청하는지, 승인 책임자가 중단을 결정하는지 적혀 있지 않다.

**수정 필요성:** 필요하다. 경고 문장은 검토와 중단의 관계만 나타내고 중단을 결정하거나 실행하는 주체를 감춘다.

**추가 문맥 확인 필요성:** 필요하다. 배포 중단의 결정 주체, 실행 주체와 자동화 여부를 확인해야 한다.

**검토한 대안:**

- `검사기가 위험을 확인하면 배포를 자동으로 중단합니다.`
- `검수자가 위험을 확인한 뒤 승인 책임자에게 배포 중단을 요청합니다.`
- `검토에서 위험이 확인되면 배포가 중단됩니다.`

**태 선택:** 확정하지 않는다. 첫 두 대안은 서로 다른 책임 관계를 만들고, 세 번째 대안은 확인해야 할 책임 주체를 계속 감춘다.

**최종 판정:** `needs human input`.

**판정 근거:** 수정 필요성은 확인됐지만 어느 대안도 현재 근거만으로 뜻을 보존한다고 판단할 수 없다. 능동문을 만들기 위해 역할을 추측하거나 피동문으로 책임 관계를 감추지 않는다.

## 사례 5. 태 선택이 적용되지 않는 문장부호 경고

**경고 문장:**

> 검사기는 표현 후보·긴 문단 후보를 JSON으로 기록합니다.

**경고:** `ko.middle-dot`이 가운뎃점을 알린다.

**주변 문맥:** 표현 후보와 긴 문단 후보는 검사 결과에 나란히 포함되는 두 항목이다. 승인된 이름이나 문자 처리 사례가 아니므로 가운뎃점을 그대로 보존할 이유가 없다.

**수정 필요성:** 필요하다. 조사로 두 항목의 관계를 자연스럽게 나타낼 수 있다.

**추가 문맥 확인 필요성:** 필요하지 않다. 두 항목의 관계와 가운뎃점을 유지할 필요가 없는 이유가 제시돼 있다.

**검토한 대안:**

- `검사기는 표현 후보와 긴 문단 후보를 JSON으로 기록합니다.`
- `검사기는 두 종류의 후보를 JSON으로 기록합니다. 하나는 표현 후보이고 다른 하나는 긴 문단 후보입니다.`

**태 선택:** `not applicable`. 경고 원인은 문장부호이며 원문에도 행동 주체와 행동이 이미 나타난다. 능동문이나 피동문으로 바꿔도 경고 원인이 해결되지 않는다.

**최종 판정:** 첫 번째 대안을 적용한 뒤 `pass`.

**판정 근거:** 첫 번째 대안은 뜻과 문장 구조를 유지하면서 두 항목의 관계를 자연스럽게 나타낸다. 태 선택이 적용되지 않아도 수정 필요성과 문맥 확인 필요성은 모두 검사했다.

## 사례 6. 수정 권한이 없어 대안만 제시

**경고 문장:**

> 검사 결과에 대해서 설명합니다.

**경고:** `ko.about`이 `에 대해서`를 알린다.

**주변 문맥:** 검토 대상은 다른 공유 단위에 있는 문장이다. 현재 검토자는 그 문장을 수정할 권한이 없고, 의미를 보존하는 대안만 제시할 수 있다.

**수정 필요성:** 필요하다. 조사를 줄여도 뜻이 달라지지 않으며 설명 대상을 더 직접적으로 나타낼 수 있다.

**추가 문맥 확인 필요성:** 필요하지 않다. 설명 대상과 수정 권한이 모두 확인돼 있다.

**검토한 대안:** `검사 결과를 설명합니다.`

**태 선택:** `not applicable`. 조사 선택의 문제이며 대안도 원문과 같은 능동문이다.

**최종 판정:** `needs revision`.

**판정 근거:** 고칠 표현과 뜻을 보존하는 대안을 확인했지만 현재 공유 단위에는 대안을 적용할 권한이 없다. 대안을 적용하지 않은 채 `pass`로 판정하지 않는다.

## 사례 전체에서 확인할 조건

- 모든 경고에서 수정 필요성과 추가 문맥 확인 필요성을 각각 판단한다.
- 능동문과 피동문이 모두 성립하는 사례 1과 사례 2에서는 두 형태를 비교하고 문장의 초점과 책임 관계로 선택한다.
- 원문을 유지하는 사례 3에는 검토한 대안과 유지 근거가 함께 있다.
- 사례 4에서는 책임 주체를 추측하지 않고 `needs human input`으로 남긴다.
- 사례 5와 사례 6에서는 태 선택이 적용되지 않아도 경고 검토를 생략하지 않는다.
- `not applicable`을 경고를 검토하지 않았다는 뜻이나 다른 최종 판정의 대체값으로 사용하지 않는다.

## 한계와 후속 적용

이 사례는 강화할 판정 순서를 비교하기 위한 합성 입력이며, 실제 문서의 모든 문맥과 한국어 표현을 대표하지 않는다. 사례를 통과했다는 사실만으로 검토 절차 전체가 올바르게 구현됐다고 판단할 수 없다. 후속 변경에서는 이 문서의 기대 판정과 실제 스킬 판정을 비교하고, 검사 스크립트의 입력 방식, 결과 구조와 종료 상태가 달라지지 않았는지 별도로 확인해야 한다.
