# `use-better-terms` 재작성 검토 강화 요구사항

이 문서는 `use-better-terms`를 관리하고 후속 변경을 검토하는 사람이 자연스러운 대안 탐색을 강화하면서 기존 검사기와 검토 절차를 유지하는 데 필요한 요구사항을 정한다.

## 목표

검사 스크립트가 알린 문제 후보를 검토할 때 처음 찾은 대안에 머무르지 않고, 원문의 뜻을 더 자연스럽고 분명하게 전달할 문장 구조를 적극적으로 찾는다. 행동 주체, 대상, 조건과 결과를 확인하고, 능동문과 피동문 가운데 어느 쪽이 그 문맥에 알맞은지도 함께 검토한다.

이 개선으로 기존 검사 스크립트가 찾아내는 후보와 사용법을 바꾸거나 `use-better-terms`의 현재 판정 절차를 줄이지 않는다.

## 문제 후보를 검토하는 방법

- 스크립트가 알린 항목은 수정해야 한다고 확정하지 않고, 문맥 확인이 필요한 후보로 본다.
- 후보가 포함된 문장과 판단에 필요한 주변 문장을 읽고, 실제 행동 주체, 대상, 행동, 적용 조건과 결과를 확인한다.
- 단어 하나만 바꾼 문장이 경고 원인을 해결하지 못하면 검토를 끝내지 않는다. 주어와 서술어 변경, 명사 표현을 동사로 풀어 쓰기, 문장 분리와 능동문 또는 피동문 전환을 포함해 뜻을 더 분명하게 전달할 방법을 찾는다.
- 능동문과 피동문이 모두 같은 뜻을 나타낼 수 있으면 두 형태를 각각 검토한다. 행동 주체와 책임을 알아야 하는 문장에서는 그 주체를 드러내고, 대상의 상태나 처리 뒤에 달라진 점이 중심이며 행동 주체가 필요하지 않은 문장에서는 피동문이나 상태 설명을 사용할 수 있다.
- 한 형태로 바꾸면 확인되지 않은 행동 주체가 생기거나 원문의 초점이 달라지는 경우에는 그 형태를 대안으로 채택하지 않는다.
- 검토한 대안이 원문보다 정확하거나 자연스러우면서 확인된 뜻을 보존하면 대안을 적용한다. 원문을 유지할 때에는 검토한 대안과 원문을 유지한 이유를 기록한다.
- 뜻, 행동 주체, 조건 또는 결과가 근거에서 확인되지 않으면 문장을 추측해서 완성하지 않고 `needs human input`으로 판정한다.
- 문장부호, 코드 표기와 개인 위치처럼 능동문과 피동문의 선택이 적용되지 않는 경고에는 형식적인 태 변환을 요구하지 않는다. 그 경고의 실제 판정 기준만 적용한다.

## 유지할 동작

후속 변경은 [기존 검사기 요구사항](../better-terms-scanner-reliability-5063/requirements.md), [검사 결과 구조를 유지하기로 한 결정](../korean-scanner-coverage-9b4e/decisions/output-structure-and-alternative-search.md), 현재 [`use-better-terms` 절차](../../../skills/use-better-terms/SKILL.md)와 [한국어 판정 기준](../../../skills/use-better-terms/references/korean.md)이 정한 다음 동작을 유지해야 한다.

- `--changed`, `--file`, `--stdin`, `--source-name`, `--self-test`와 `--help`의 의미를 유지한다.
- `sources`와 두 `checks`, 각 검사의 `catalog`, `rules`, `warnings`와 `summary`를 포함하는 결과 구조와 결정적인 결과 순서를 유지한다.
- 표현 후보와 긴 문단 후보를 모두 찾으며, 후보 발견만으로 실행을 실패시키거나 자동으로 수정하지 않는다.
- 문맥 없는 문자열 치환을 하지 않고 확립된 용어, 승인된 이름, 코드 식별자와 필요한 표기를 유지할 수 있게 한다.
- 검토 결과에 `pass`, `needs revision`, `needs human input`과 `not applicable`을 계속 사용한다.
- 수정한 공유 단위를 다시 검사하고 새로 생긴 경고를 판정하는 절차를 유지한다.
- 민감정보, 개인 위치와 외부에 드러내면 안 되는 식별자를 공유할 문서와 문구에서 찾는 기존 검토를 유지한다.
- 배포되는 스킬은 외부 패키지나 실행 중 네트워크 요청 없이 동작한다.

## 적용 조건

- 이번 작업은 요구사항과 조사 내용을 기록하는 데까지다. 스킬, 참고 자료, 검사 스크립트와 테스트의 변경은 별도 작업에서 진행한다.
- 능동문과 피동문의 문법 형식만으로 자연스러움을 판정하지 않는다. 의도한 독자, 문장의 초점과 책임 관계를 함께 확인한다.
- 영어 기술 문서의 능동태와 수동태 지침은 명료성을 비교하는 자료로만 사용한다. 한국어 문장의 판정은 한국어 자료와 실제 문맥을 우선한다.

## 완료 증거

- 조사 문서가 현재 스킬과 검사기의 보호할 동작을 확인하고, 자연스러운 대안 탐색을 강화할 지점을 구분한다.
- 조사 문서가 한국어 능동문과 피동문의 관계, 불필요한 피동 표현의 문제와 피동문을 유지할 수 있는 조건을 공식 자료로 설명한다.
- 후속 변경의 대표 평가 사례에는 행동 주체를 밝혀야 하는 능동문, 상태나 처리 후 변화를 중심에 둔 피동문, 원문 유지, `needs human input`과 태 선택이 적용되지 않는 경고가 포함된다.
- 능동문과 피동문이 모두 성립하는 대표 사례에는 검토한 두 표현, 선택한 표현과 선택 이유가 기록된다.
- 대안을 적용한 대표 사례는 경고된 단어만 바꾸지 않고 행동 주체, 대상, 조건과 결과가 전보다 분명해졌는지 확인한다.
- 후속 변경 전후에 검사기의 자체 검사와 저장소 검사를 실행하고, 기존 입력 방식, 결과 구조, 경고 위치와 종료 상태가 유지되는지 비교한다.
- 요구사항과 조사 문서가 같은 개선 목표와 보호 조건을 설명하며, 구현을 완료했다고 주장하지 않는다.
