# 한국어 스캐너 활용형 탐지와 대체 표현 탐색 계획

## 기준과 이번 작업의 범위

이 계획은 [한국어 스캐너 활용형 탐지와 대체 표현 제안 요구사항](./requirements.md)의 `목표`, `적용 조건`과 `완료 증거`를 기준으로 한다. 탐지 방식과 규칙 추가는 [활용형 자모 매칭과 닫다 규칙 추가](./decisions/jamo-matching-and-close-rule.md), 출력 구조와 검토 절차는 [출력 구조 유지와 대체 표현 우선 탐색](./decisions/output-structure-and-alternative-search.md)을 따른다.

변경 대상은 `skills/use-words-review/scripts/korean-expressions.mjs`, `scripts/scan.mjs`의 self-test, `SKILL.md`와 `references/korean.md`다. `long-paragraphs.mjs`와 `references/examples.md`는 바꾸지 않는다. 검사 결과의 JSON 구조인 `sources`, `checks`, 각 검사의 `id`, `catalog`, `rules`, `warnings`, `summary`와 경고의 필드는 그대로 유지한다.

`.mjs` 구현은 [Node.js MJS 명령줄 검사기](../../dev/node/mjs-cli.md)의 규칙을 따르고, import 제한은 `eslint.config.mjs`의 현재 설정을 유지한다. 이 지침의 literal 탐색 서술이 자모 매칭과 충돌하면, 충돌 지점을 보고하고 지침 갱신 승인을 받은 뒤 같은 작업 단위에서 갱신한다.

## 작업 단위와 순서

### 1. `korean-expressions.mjs`에 자모 분해 매칭을 추가한다

규칙 표현과 원문을 `String.prototype.normalize("NFD")`로 분해해 자모열 접두 매칭을 수행한다. 매칭 방식은 규칙 내부 자료로만 관리하고 출력 `catalog`의 `id`, `kind`, `expressions`에는 새 필드를 추가하지 않는다.

- 경고의 `line`, `startUtf16`, `endUtf16`과 `quote`는 원본 UTF-16 기준을 유지한다. 원본 문자별 NFD 길이로 매핑 테이블을 만들고, 음절 중간에서 끝난 매칭은 그 음절의 끝을 `endUtf16`으로 사용한다.
- `ko.narrow`의 표현 `좁히`와 `좁혀`를 자모 매칭으로 전환해 `좁힘`, `좁힐`, `좁힌`, `좁힙니다`, `좁혔다`를 찾는다.
- 다른 규칙은 현재 음절 매칭을 유지하고, 자모 매칭이 필요한 규칙만 개별적으로 전환한다. [한글 활용형 탐지 방법 조사](./references/hangul-conjugation-detection.md)가 확인한 오탐 위험 때문에 받침 없는 음절로 끝나는 짧은 표현은 전환 전에 대표 원문으로 오탐 여부를 확인한다.

**완료 증거.** self-test에 다음 사례를 추가하고 통과해야 한다: `좁힘`, `좁힐`, `좁힌`, `좁힙니다` 출현이 `ko.narrow` 경고로 잡히고, 경고 위치가 원본 UTF-16 기준으로 정확하며, 자모 매칭이 없는 규칙의 기존 위치 사례가 그대로 통과한다. 기존 `catalog` 개수 assertion은 실제 규칙 수로 갱신한다.

### 2. `닫다` 계열 규칙을 추가한다

`korean-expressions.mjs`에 `닫` 계열 규칙을 추가한다. 어간 받침 ㄷ이 첫 음절에 유지되므로 현재 음절 매칭으로 `닫다`, `닫힘`, `닫힌`, `닫혔다`, `닫는다`를 찾을 수 있고, 자모 매칭 전환 여부는 1단계와 같은 기준으로 정한다. 판정 질문과 문제 및 정상 사례는 [닫다, 닫히다, 좁히다 용법 조사](./references/close-and-narrow-usage.md)의 기준을 따른다: 개폐의 은유가 유지되는 UI 대상과 결합한 사용은 유지하고, 작업이나 검토 같은 상태와 절차를 목적어나 주어로 삼는 사용은 실제 행위를 쓸 수 있는지 확인한다. 사례 문장은 실패 구조만 남긴 합성 문장으로 작성한다.

**완료 증거.** [한글 활용형 탐지 방법 조사](./references/hangul-conjugation-detection.md)의 재현 입력을 다시 실행했을 때 `좁힘`, `좁힐`, `좁힌`과 `닫힘`, `닫는다`, `닫혔다`에서 경고가 발생해야 한다. self-test가 새 규칙의 필수 필드와 사례를 검증해야 한다.

### 3. 검토 절차에 대체 표현 우선 탐색을 넣는다

`references/korean.md`의 `문맥을 판정하는 순서`에 다음 단계를 추가한다: 검토자는 경고된 표현마다 항상 다른 표현을 먼저 찾아보고, 더 자연스러운 표현이 없다고 확인한 경우에만 원래 표현을 그대로 유지하며, 유지할 때에는 확립된 전문용어, 승인된 이름 또는 문장이 대상, 행동, 조건과 결과를 밝힌다는 근거를 함께 기록한다. `SKILL.md`의 한국어 판정 기준이 이 단계를 요구하도록 연결하되 같은 규칙을 두 파일에 복사하지 않는다.

경고가 자동 실패가 아니라는 기존 조건과 후보 표현이 금칙어가 아니라는 원칙은 유지한다. 이 단계는 판정의 기본 순서를 바꾸는 것이지 특정 단어를 금지하지 않는다.

**완료 증거.** 두 파일의 변경을 문장별로 대조해 규칙이 한 곳에만 있고 기존 검토 범위, 중단 조건과 판정 상태가 유지돼야 한다. 대표 검토 사례에서 경고된 표현의 판정 결과에 대체 표현 제안 또는 유지 근거가 나타나야 한다.

### 4. 대표 실행과 최종 검증

macOS에서 `node skills/use-words-review/scripts/scan.mjs --self-test`를 실행해 종료 상태 `0`을 확인하고, 재현 입력과 기존 대표 입력을 `--changed`, `--file`, `--stdin` 세 입력 방식으로 실행해 결과를 확인한다. `pnpm lint`로 import 제한과 정적 규칙을 확인한다. 변경한 한국어 문서와 규칙 사례는 커밋 전에 `use-words-review`로 검토한다.

**완료 증거.** self-test와 lint의 종료 상태, 재현 입력의 경고 목록과 검토 결과가 기록돼야 한다. 출력 JSON의 구조가 변경 전과 같은 필드를 유지하는지 변경 전후 결과를 대조한다.

## 중단 조건과 사람의 판단이 필요한 항목

- 오프셋 매핑이 기존 경고 필드의 의미를 바꿔야만 구현할 수 있으면 작업을 멈추고 결정 소유자에게 보고한다. 출력 구조 유지가 승인된 결정이다.
- 자모 매칭 전환 후보 규칙에서 오탐이 확인되면 그 규칙은 음절 매칭을 유지하고 확인 결과를 보고한다.
- 대체 표현 탐색 단계가 기존 검토 범위나 중단 조건을 지워야만 들어갈 수 있으면 작업을 멈추고 요구사항 소유자에게 판단을 요청한다.
- `닫다` 규칙의 사례 문안이 용법 조사에서 확인하지 못한 규범 판정을 전제해야 하면 그 문안은 넣지 않고 확인된 기준만 사용한다.

## 커밋 단위

1. 승인된 결정과 이 계획
2. `korean-expressions.mjs`의 자모 매칭, `닫다` 규칙과 `scan.mjs` self-test 갱신
3. `SKILL.md`와 `references/korean.md`의 대체 표현 우선 탐색 절차
4. 대표 실행에서 발견한 누락 보정과 최종 검증 결과

각 커밋 전에 변경된 한국어 문구를 `use-words-review`로 검토하고, 변경 단위가 통과하지 않으면 다음 단위로 넘어가지 않는다.
