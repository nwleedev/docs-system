# 검사 도구의 대체 표현 제안 방식 조사

## 조사 질문

검사 스크립트가 후보를 알린 뒤 검토 단계에서 후보가 근거 없이 통과되는 문제를 구조로 막을 방법을 조사했다. 확립된 검사 도구들이 경고와 대체 후보를 어떻게 함께 전달하고, 자동 적용 대신 선택 제시로 물러나는 기준이 무엇인지 확인했다. 이 조사는 [요구사항의 목표](../requirements.md#목표) 가운데 대체 표현 제안 방향에 해당한다. 조사일은 2026년 8월 20일이다.

## 현재 구조와 문제 위치

현재 규칙 자료는 `message`, `queries`, `negatives`, `positives`로 판정을 돕고, 스킬은 경고를 자동 실패가 아니라 판정할 문맥으로 정의한다. [한국어 후보 표현 검사기 소스 조사](../../korean-writing-review-6f3a/references/korean-candidate-expression-linter-research.md)는 규칙에 `replacement`와 자동 수정 자료를 넣지 않는 구현 기준을 기록했다. 이 구조에서 경고를 유지로 판정할 때 요구되는 근거의 형식이 없으므로, 검토자가 확립된 용법인지 확인하지 않고 통과시켜도 결과 형식상 드러나지 않는다. 문제는 경고 생성이 아니라 경고 이후 판정 결과에 요구되는 정보에 있다.

## 기존 도구의 공통 구조

네 도구를 확인한 결과, 경고문과 교체 후보를 구조화된 데이터로 함께 제공하되 적용 주체를 분리하는 형태가 공통이다.

- **Vale**의 substitution 규칙은 잘못된 표현과 선호 표현의 쌍을 `swap`에 담고, 후보가 여러 개면 파이프로 나열하며 `action: replace`로 편집기에 선택 목록을 제공한다. 교체를 도구가 실행하지 않고 편집기의 사용자가 고른다. [Vale의 substitution 문서](https://docs.vale.sh/checks/substitution)에서 확인했다.
- **ESLint**는 자동 적용되는 fix와 사용자가 골라 적용하는 suggestion을 구분한다. 수정이 동작을 바꿀 수 있거나 의도에 따라 유효한 수정이 여럿이면 fix 대신 suggestion을 쓰라고 명시하고, suggestion은 작은 단일 변경에 집중하라고 요구한다. [ESLint의 custom rules 문서](https://eslint.org/docs/latest/extend/custom-rules)에서 확인했다.
- **textlint**는 fixer를 제공하지만 적용은 `--fix`를 지정한 실행에서만 일어나고, 수정 단위를 최소화하도록 안내한다. [textlint의 fixable rule 문서](https://github.com/textlint/textlint/blob/master/docs/rule-fixable.md)에서 확인했다.
- **LanguageTool**은 검사 응답의 각 일치 항목에 `replacements` 배열을 제공하며 빈 배열도 허용한다. 적용 여부는 호출자가 정한다. [LanguageTool의 HTTP API 명세](https://languagetool.org/http-api/languagetool-swagger.json)에서 확인했다.

의미가 바뀔 수 있고 유효한 고침이 여럿인 한국어 문장 재작성은 ESLint의 구분으로는 정확히 suggestion에 해당한다. 자동 치환을 금지한 기존 결정은 이 도구들의 기준과도 일치하며, 문제는 후보 제시가 없다는 점이지 자동 치환이 없다는 점이 아니다.

## 개선 방향 제안

다음은 조사 결과에서 도출한 제안이며 승인된 결정이 아니다. 두 방향은 함께 적용할 수도 있다.

**검토 결과 형식을 강화하는 방향.** 스킬 절차를 바꿔, 표현 경고를 `pass`로 판정하려면 해당 분야에서 확립된 용법이라는 근거나 문장이 대상, 행동, 조건과 결과를 밝힌다는 확인을 결과에 적게 하고, 그 근거가 없으면 사전 갈래에 맞는 구체적 대체 문장을 함께 제시하게 한다. 규칙 자료와 스크립트는 바뀌지 않고 `SKILL.md`의 결과 형식만 바뀐다. 근거 없는 통과가 결과 형식에서 바로 드러나는 대신, 절차 준수는 여전히 검토자의 실행에 달려 있다.

**규칙 자료에 대체 후보를 넣는 방향.** 각 규칙에 복수의 대체 표현 후보 필드를 추가해 경고와 함께 전달한다. Vale의 후보 나열과 LanguageTool의 `replacements`처럼 자동 치환이 아니라 선택 자료다. 검토자가 대체 문장을 처음부터 만들지 않아도 되지만, 고정 후보가 문맥과 맞지 않는 경우를 판정 질문으로 걸러야 한다. 또한 위 조사 문서가 기록한 `replacement` 제외 기준과 충돌하므로, 그 기준이 승인된 결정인지 조사 문서의 구현 기준일 뿐인지 결정 소유자가 먼저 확인한 뒤 재검토 여부를 정해야 한다.

어느 방향을 채택할지는 [요구사항의 미해결 질문](../requirements.md#미해결-질문)대로 결정 소유자가 판단한다.

## 한계

- Grammarly의 후보 제시 방식은 공개 1차 자료를 확보하지 못해 비교에서 제외했다.
- Vale CLI의 JSON 출력에 교체어 전용 필드가 있는지는 확인하지 않았고, 문서상 메시지 문자열과 `action`으로 전달된다는 사실까지 확인했다.
- 결과 형식 강화가 실제로 근거 없는 통과를 줄이는지는 대표 사례 평가로 확인해야 하며, 이번 조사에서는 수행하지 않았다.
