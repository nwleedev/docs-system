# 반복 집계의 이전 선택과 현재 적용 범위

현재 후속 구현은 세 고정 표현 후보 추가와 근거 대조를 통한 문서별 의미 판단이다. 새 반복 집계는 적용하지 않는다. 이 결정 기록은 스킬을 관리하는 개발자가 [요구사항](../requirements.md)의 현재 범위와 이전 선택을 구분하는 데 사용한다.

## 반복 집계 적용 중단과 이유

반복 횟수의 계산과 그 표현을 써도 되는지의 판단은 다른 문제다. 알려진 네 명사의 형태를 합치는 설계는 미등록 표현의 조사 변형을 일반적으로 처리하지 못한다. 원문 표기를 세는 기능이 있더라도 문서의 다양한 표현을 의미에 따라 재검토한다는 목적을 그 집계만으로 충족하지 못한다.

선택지는 명사 목록을 확장하며 집계를 계속하는 방법, 일반 형태 분석과 새 검사를 더 설계하는 방법, 고정 후보 추가와 기존 의미 판단 절차를 개선하는 방법이었다. 현재 범위는 마지막 방법이다. 대상과 조건의 누락, 근거의 시점과 필요한 반복 여부는 횟수만으로 판단되지 않으므로 [근거 대조 조사](../references/semantic-review-without-frequency.md)의 대응을 계획에 반영한다. 빈도 계산 자체가 불가능하다고 결론 내린 것은 아니다.

3회 및 1%, 20,000 코드 포인트, 명사 합산 목록, 알고리즘과 별도 JSON 항목은 현재 구현 지시에서 제외한다. 기존 두 검사와 세 배포 파일을 유지한다. `업무`, `지위`, `소비`의 고정 후보 추가 요구는 유지하며, 목록 밖 표현은 스킬의 문서별 판단에 포함한다. 스킬과 스크립트는 구현 이전 상태를 후속 변경의 출발점으로 삼는다.

이전 계획의 반복 계산과 CLI 연결 작업은 [현재 계획](../plan.md)으로 대체한다. 아래 내용은 당시 비교와 선택을 보존한 이력이며, 현재 동작을 요구하지 않는다. 향후 집계가 필요해지면 실제 누락 문맥과 기대 결과를 먼저 정하고 형태 처리, 탐지 범위와 운영 비용을 다시 결정한다.

## 이전 설계의 결론

반복 후보는 파일별 전체 빈도로 찾으며, 반복 검사는 한 실행의 원문 합계 20,000 코드 포인트까지 처리한다. 후보 기준은 3회 이상과 토큰 비율 1% 이상을 모두 만족하는 것이다. 기존 두 검사는 유지하고 `checks`에 반복 항목을 추가한다. 이 문서는 [요구사항](../requirements.md)을 구현할 개발자가 현재 설계와 그 선택 이력을 확인하는 결정 기록이다. 구현 완료나 한국어 품질 기준의 입증을 뜻하지 않는다.

## 비교한 방식과 선택 이유

문단별 집계는 여러 문단에 흩어진 반복을 놓칠 수 있고, 일정한 문장 구간을 이동하며 세는 방식은 겹치는 후보의 처리 규칙이 필요하다. 문서 전체 집계는 문단 구분과 무관하게 반복을 찾는다. 입력 크기 제한은 한 번에 처리할 내용의 양을 통제하지만, 빈도가 높은 표현이 부적절하다는 뜻은 아니다. 구체적인 숫자의 근거와 한계는 [입력 크기 조사](../references/repetition-input-size.md)에 둔다.

출현마다 기존 표현 경고를 만들면 같은 반복을 여러 번 판단하게 되고, 집계 대상을 설명하기 어렵다. 기존 검사 안에 다른 유형을 섞으면 경고 필드와 요약의 의미를 읽는 절차가 달라진다. 별도 검사 항목은 반복 횟수와 위치들을 함께 전달하면서 기존 표현 경고와 문장 수 경고의 의미를 보존한다.

## 앞서 확정한 기본 방향

기본 집계는 문서 전체의 빈도나 비율을 사용한다. 같은 문단에서 3회 이상이라는 이전 제안은 채택하지 않았다. 입력 크기 제한과 별도 반복 항목을 먼저 정하고, 당시에는 수치와 세부 형식을 미결정으로 남겼다. 비교 말뭉치 구축이나 장기간의 문서 수집은 포함하지 않는다.

출력은 단일 JSON의 `sources`와 `checks` 구조를 유지한다. 기존 표현 검사와 긴 문단 검사 뒤에 별도 반복 검사를 추가하고, 각 검사의 `catalog`, `rules`, `warnings`와 `summary` 구조를 활용한다. 같은 파일의 같은 표현에 속한 출현 위치들은 한 경고로 묶는다. 반복 묶음의 경고 수와 그 안의 출현 횟수는 다른 값으로 설명한다.

## 입력 상한과 초과 처리의 결정 이력

초기 제안은 실행 전체 20,000 코드 포인트였으며, 10,000자와 50,000자 및 파일별 상한을 비교했다. [최초 길이 비교](../references/repetition-input-size.md)에서 13,139자인 조사 문서를 통째로 받을 수 있었고, [추가 알고리즘 조사](../references/repetition-design-tradeoffs.md)에서는 입력량뿐 아니라 분리와 JSON 생성도 제한해야 함을 확인했다. 이를 근거로 20,000을 첫 운영값으로 채택한다. 파일별로만 제한하면 묶음 전체의 계산량이 늘어나므로 실행 합계에 적용한다.

크기는 기존 UTF-8 decoder가 만든 source 문자열을 정규화하기 전에 센다. 공백, Markdown 표기와 중간 U+FEFF를 포함한다. CRLF는 두 코드 포인트다. 기존 decoder가 제거하는 맨 앞 BOM은 문자 수에서 빠지지만 기존 byte 제한에는 계속 포함된다. 파일마다 문자열을 분리해 세고 합계만 더한다. 코드 포인트 20,001개를 확인하면 나머지 개수를 세지 않고 초과로 판정한다. 코드 포인트 배열을 만들지 않는다.

공통 CLI 거부, 자동 분할과 반복 검사만 미실행 처리하는 안을 비교했다. 기존 입력의 표현 검사와 긴 문단 검사를 보존하기 위해 마지막 안을 선택한다. 초과 시 어떤 파일의 반복도 계산하지 않고 `repetition.status`를 `skipped`, `skipReason`을 `input-too-large`로 전달한다. 기존 byte, UTF-8 또는 I/O 오류는 여전히 종료 상태 2의 실행 실패다. 반복 상한만 넘은 정상 입력은 기존 두 검사와 명시적인 미실행 상태를 담은 JSON을 상태 0으로 반환한다. 상태 0은 전체 문구 검토 통과가 아니다.

여러 파일은 온전한 파일 단위로 실행을 나눌 수 있다. 한 파일 자체가 20,000자를 넘으면 반복 검토는 미완료로 남기며 상한을 재결정하기 전까지 조각의 집계를 파일 전체의 집계로 대체하지 않는다. 문서 자동 수정, 자동 분할이나 상한 우회 CLI 옵션은 추가하지 않는다. 정당한 문서가 자주 거부되면 실제 시간, 메모리와 경고량을 근거로 이 상한을 다시 결정한다.

## 후보 판정식과 본문 선택의 결정 이력

횟수만 사용, 비율만 사용, 상위 K개만 선택, 비교 말뭉치와 대조하는 안을 비교했다. 짧은 글의 한두 번 출현과 긴 글의 낮은 비중을 함께 제외하도록 파일별 `count >= 3`이면서 `count * 100 >= tokenCount`인 표현을 후보로 정한다. 정수 비교를 사용하고 반올림한 비율로 판정하지 않는다. `tokenCount`가 0이면 후보가 없다. 이전의 문단 3회 기준을 승인한 것이 아니라, 전체 비율 조건과 함께 최소 횟수 3을 새로 채택한 것이다.

토큰은 제외 구간 밖에서 Unicode 문자와 결합 문자 및 십진 숫자가 연속된 최대 구간이다. 줄바꿈, 공백과 나머지 문장부호 및 기호에서 나눈다. 숫자만 있거나 문자 없이 결합 문자만 있는 구간은 버린다. 분모에는 남은 모든 토큰을 넣으며, 후보는 NFC 키의 코드 포인트가 두 개 이상인 것만 허용한다. 한 글자 토큰도 분모에는 남는다. 영어 대소문자는 합치지 않으며 일반 stopword 사전과 여러 토큰짜리 구문 탐지는 추가하지 않는다.

초기 본문 선택은 다음과 같이 고정한다. 완전한 CommonMark parser가 아니라 반복 검사의 보수적인 추출 규칙이다.

- 제목과 목록의 산문을 포함한다. 블록 인용 표시 `>`로 시작하는 줄, 세로줄이 있는 줄, 탭 또는 공백 네 개 이상으로 시작하는 줄은 제외한다. 따라서 깊은 목록과 실제 표가 아닌 세로줄 문장도 빠질 수 있다. 일반 따옴표 속 글은 포함한다.
- 공백 세 개 이하 뒤의 backtick 또는 tilde 세 개 이상을 fence 시작으로 본다. 같은 기호가 시작 길이 이상이고 뒤에 공백만 있는 줄에서 닫으며, 닫히지 않으면 끝까지 제외한다. fence 안의 다른 구문은 해석하지 않는다.
- 첫 줄이 정확히 `---`이면 다음 `---` 또는 `...` 줄까지 front matter로 제외하고, 닫히지 않으면 끝까지 제외한다. 일반적인 수평선 사용도 제외될 수 있는 정책이다.
- 나머지 줄에서 backtick은 같은 길이의 다음 기호 묶음까지 제외한다. 여러 줄을 연결하지 않으며 닫는 묶음이 없으면 줄 끝까지 제외한다. `<`부터 다음 `>`까지도 제외하고, 닫히지 않으면 줄 끝까지 제외한다. `<`로 시작한 줄은 HTML 후보로 줄 전체를 제외한다. HTML 주석 시작부터 닫는 표기까지는 여러 줄이어도 제외하고, 닫히지 않으면 끝까지 제외한다.
- `http://`, `https://`, `www.`로 시작한 부분은 다음 공백까지 제외한다. 링크 목적지는 `](` 다음부터 같은 줄의 짝이 맞는 닫는 괄호까지 제외하고, 닫히지 않으면 줄 끝까지 제외한다. 대괄호 뒤 콜론으로 시작하는 링크 정의 줄은 통째로 제외한다. 링크 표시 글은 포함하되 이미지 대체 글은 이미지의 여는 `![`부터 닫는 대괄호까지 제외한다. 참조형 링크의 두 번째 대괄호 구간은 제외한다. escape와 여러 줄 링크는 완전 해석하지 않는다.

제외 구간을 삭제해 양옆 단어를 붙이지 않는다. 원문 offset 구간으로 관리하고 각 구간에서 토큰을 끝낸다. 분석 정책은 `catalog`에 나타내며, 제외 규칙이 의미 판단까지 수행한다고 설명하지 않는다. 코드 예시와 인용 때문에 경고가 증가하는 문제를 줄이는 대신 일부 산문을 놓치는 선택이다. 목록과 문장부호의 정상 산문 누락이 실제 판단을 방해하면 해당 제외 규칙만 재검토한다.

## 형태 합산의 결정 이력

정확한 표기만 사용, 모든 조사 추정 제거, 문서 안의 원형 존재를 조건으로 제거, 외부 형태소 분석과 명시한 형태만 합산하는 안을 비교했다. 오합산을 줄이고 기존 활용 생성을 재사용하기 위해 마지막 안을 선택한다. 미등록 표현까지 형태소 분석했다고 설명하지 않는다.

NFC는 비교 키에만 적용하고 원문과 UTF-16 위치는 바꾸지 않는다. 명사 합산 목록은 `검토`, `업무`, `지위`, `소비`로 시작한다. 기본형과 `이`, `가`, `은`, `는`, `을`, `를`, `의`, `에`, `에서`, `에게`, `도`, `만`, `과`, `와`, `로`, `으로` 중 하나가 붙은 전체 토큰만 같은 명사로 센다. 조사를 두 번 자르거나 접미사를 재귀적으로 제거하지 않는다. 이 제한은 문법 교정기가 아니라 명시적 표면형 목록이다. `검토에서는`과 `소비자`는 기본형과 합치지 않는다. `검토`의 명사 등록은 고정 문제 표현 추가를 뜻하지 않는다.

등록 동사와 형용사는 기존 `buildForms()`를 재사용해 표면형에서 표제어로 가는 비공개 색인을 만든다. 하나의 표면형에 여러 표제어가 가능하면 정확한 표기 키로 남기고 임의로 합치지 않는다. `ruleId`나 공개 경고를 합산 키로 사용하지 않는다. `phrase` 규칙은 여러 토큰 조건을 포함하므로 이번 표제어 합산에서 제외하고 해당 토큰을 표기대로 센다. 기존 고정 검사의 phrase 탐지와 부분 일치, 활용형 및 겹치는 경고는 그대로 유지한다.

명사와 유일한 표제어 후보가 충돌해도 표기 키로 남긴다. 토큰 하나는 한 키에만 기여한다. `surface`, `noun`, `lemma`를 키 종류로 구분해 우연히 같은 문자열인 서로 다른 해석을 합치지 않는다. 일반 명사의 조사 누락이 반복적으로 확인되면 합산 명사 자료를 추가할 수 있지만 새 문제 표현 등록과는 별도로 판단한다.

## 알고리즘과 파일 구성의 결정 이력

반복 계산은 `korean-expressions.mjs`에 `scanRepetition(sources)`로 둔다. 같은 파일의 명사 자료, 활용 생성과 위치 및 인용 계산 중 의미가 같은 함수를 재사용한다. 진입점에서 새 named export를 정적으로 가져오되 파일은 기존 세 개로 유지한다. 반복 전용 Markdown 제외 계산은 긴 문단 계산과 포함 대상 및 offset 의미가 달라 그대로 공통화하지 않는다. 별도 반복 모듈과 공용 morphology 모듈로 나누는 안은 이번 한 기능에 배포 파일 및 import 변경을 늘리므로 채택하지 않는다.

상한 확인 후 원문을 순차 추출하고 키별 횟수와 출현 위치를 `Map`에 기록한다. 한 파일의 키는 다른 파일과 공유하지 않는다. 기호의 짝과 같은 길이의 다음 backtick 묶음은 한 번 만든 위치 색인 또는 단방향 cursor로 찾는다. 닫는 표기를 찾는 데 실패할 때마다 같은 접미 구간을 재탐색하지 않는다. 링크의 괄호 짝 계산에는 깊이 카운터나 스택을 사용하며 재귀 호출과 전체 접미 문자열 복제를 사용하지 않는다.

입력 C, 토큰 N, 키 U에 대해 키 조회 N번과 원문 길이에 비례한 문자열 처리를 목표로 한다. 후보 정렬은 파일별 출현 수 내림차순, 첫 출현 offset 오름차순을 사용한다. 각 토큰은 한 키에만 속하므로 서로 다른 키의 첫 출현 위치도 달라 문자열 사전순 비교가 필요 없다. source 순서는 기존 입력 순서를 유지한다. 숫자 비교 정렬 비용은 U log U이고, 문자열 해시 비용을 C에 포함하며 Map 접근을 평균 상수로 가정할 때 기대 계산량은 O(C + U log U), 추가 저장량은 O(C + N)이다. 표제어 색인의 생성 비용은 별도로 더하며, ECMAScript가 Map의 최악 상수 시간을 보장하지 않는다는 제한을 유지한다.

후보에만 첫 출현의 원문 인용을 한 번 만든다. 전체 위치는 보존하되 출현마다 같은 문맥 문자열을 복제하지 않는다. 기존 표현 검사의 전체 계산량까지 이 식으로 설명하지 않는다. 상한 입력에서 종료하지 않거나 같은 구간의 재탐색이 입력에 비례해 늘어나면 구현 완료로 보지 않는다. 먼저 재탐색과 불필요한 복제를 없애고, 실제로 남은 비용이 확인되기 전까지 Worker나 스트리밍 별도 프로토콜은 추가하지 않는다.

## JSON과 생략 처리의 결정 이력

출현별 경고와 기존 검사 안에 유형을 섞는 안 대신 별도 `repetition`을 채택했다. 세부 형식은 다음과 같다.

- `id`는 `repetition`이다. `catalog`는 `text.repetition` 규칙 하나와 입력 상한, 최소 횟수, 비율, 토큰 및 제외 정책을 항상 포함한다. `rules`는 후보가 있을 때만 같은 규칙의 질문과 유지 사례를 담는다.
- `status`는 `complete` 또는 `skipped`다. `skipReason`은 정상 집계일 때 null, 초과일 때 `input-too-large`다. 초과 시 `warnings`와 `rules`는 빈 배열, `summary`는 모두 0이다. 0이라는 집계보다 먼저 상태를 읽어야 한다. 빈 입력은 `complete`이며 후보가 없다.
- 각 경고는 `ruleId`, `sourceId`, `expression`, `normalization`, `count`, `tokenCount`, `occurrences`, `quote`를 가진다. `normalization`은 `surface`, `noun`, `lemma` 중 하나이며 `expression`은 NFC 표기 또는 표제어다. `count`는 토큰 출현 수, `tokenCount`는 그 파일의 분모다. 백분율 필드는 중복 저장하지 않는다.
- `occurrences`는 원문 순서의 `{line, startUtf16, endUtf16, surface}` 배열이다. 전체 토큰의 1부터 시작하는 줄과 UTF-16 열, 끝 다음 열 및 정규화하지 않은 토큰을 보존한다. 위치 하나를 여러 키에 넣지 않는다. 줄바꿈 규칙은 기존 LF, CRLF와 단독 CR을 유지한다.
- `quote`는 첫 출현을 포함하는 줄의 최대 480 UTF-16 단위 문맥이며 surrogate pair를 자르지 않는다. 토큰 자체가 480을 넘으면 앞부분을 안전하게 잘라 인용하고, 온전한 토큰은 출현의 `surface`로 제공한다. 인용이 원문 전체를 대신하지 않는다.
- 묶음 안의 위치는 생략하지 않는다. 최대 20,000개 경고와 검사별 32 MiB라는 기존 상한을 재사용하되, byte 상한에 걸리면 경고 묶음 전체를 생략한다. `summary.total`은 모든 후보 묶음 수, `shown`은 담은 묶음 수, `omitted`는 그 차이다. 표시된 묶음의 `count`는 항상 `occurrences.length`와 같다.

첫 5개 위치만 남기는 별도 상한은 입력 상한 아래에서 필요성이 확인되지 않았고, 누락 위치를 다시 얻는 인터페이스까지 만들게 되므로 도입하지 않는다. 입력 제한과 묶음당 한 인용으로 크기를 먼저 통제한다. 모든 위치를 남겨도 byte 상한으로 묶음이 생략되면 의미 검토는 미완료로 남기고 온전한 파일 단위 재실행을 사용한다. 한 파일만으로 생략되면 별도 재검토 전까지 전체 통과로 기록하지 않는다.

`limitCheckByBytes()`는 새 상태 필드를 버리지 않도록 수정해야 한다. 기존 두 검사에는 새 상태 필드를 억지로 추가하지 않는다. 스킬은 세 검사 모두 읽고, 반복 미실행과 생략을 오류 없음으로 해석하지 않는다. 같은 고정 표현과 반복 경고가 있으면 파일과 위치로 근거를 연결하지만 기존 경고를 삭제하지 않는다. 별도 SARIF 변환과 JSONL은 도입하지 않는다.

## 기존 결정과 구현에 미치는 영향

이번 개선에서는 [출력 구조 유지 결정](../../korean-scanner-coverage-9b4e/decisions/output-structure-and-alternative-search.md)의 완전한 구조 동결 대신 기존 두 검사 결과를 유지하면서 별도 항목을 추가한다. 대체 문장을 먼저 찾고 정확한 용어는 근거를 남겨 유지한다는 기존 판단 순서는 바꾸지 않는다.

[모듈과 출력 상한 결정](../../korean-writing-review-6f3a/decisions/scanner-modules-and-output-limits.md)의 정확히 두 검사라는 전제는 반복 기능을 구현할 때 갱신해야 한다. 현재 `SKILL.md`는 두 검사를 읽도록 하고, `scan.mjs`의 자체 검사는 검사 식별자 배열을 두 항목과 비교한다. 새 결과 항목이 추가돼도 수정 없이 호환된다고 설명하지 않는다.

별도 검사 항목과 별도 파일은 다르다. 세 배포 파일과 기존 두 로컬 import 위치는 유지하며, 같은 표현 모듈에서 named export 하나를 추가하는 구성으로 정했다. 등록 표현의 활용형 탐지와 외부 패키지 없는 실행 조건은 유지한다. 이번 기록은 스크립트와 검사 설정을 변경하거나 구현 완료를 선언하지 않는다.

## 결정의 적용과 다시 검토할 조건

현재 초기 구현을 막는 동작 선택은 남기지 않는다. 20,000자와 3회 및 1%의 적정성, 형태 처리 누락률과 실제 실행 비용은 구현 후 확인할 불확실성이다. 이 사실을 수치가 미결정이라는 설명이나 효과가 입증됐다는 설명으로 바꾸지 않는다. 각 선택의 비교 근거는 [추가 조사](../references/repetition-design-tradeoffs.md)에 연결한다.

입력 상한 때문에 하나의 설명이 반복해서 분리되거나, 높은 빈도의 정확한 용어가 판단량 대부분을 차지하거나, 출력 생략으로 출현의 문맥을 확인할 수 없으면 상한과 후보 판정식을 다시 비교한다. 재검토는 필요에 따른 변경 판단이며, 별도 비교 환경 구축을 선행 조건으로 만들지 않는다.
