# 고정 표현 후보와 근거 대조를 개선하는 계획

스크립트에는 `업무`, `지위`, `소비`를 고정 후보로 추가하고, 스킬에는 문서와 근거를 대조해 의미를 판단하는 절차와 사례를 보완한다. 목록 밖 표현도 문서별 판단에서 다룬다. 새 반복 집계는 구현하지 않는다. 이 문서는 `use-better-terms`를 수정할 개발자를 위한 후속 계획이며 구현 결과나 효과 입증을 뜻하지 않는다.

## 적용할 기준과 이전 계획의 변경

기준은 [요구사항](requirements.md)의 `개선할 결과`, `스크립트에 추가할 고정 표현 후보`, `스크립트만으로 해결할 수 없는 문제`, `반복 집계 설계의 적용 상태`와 `완료를 확인할 자료`다. 고정 후보는 U1, 의미 판단 절차는 U2, 적용 사례는 U3, 관찰할 완료 근거는 U4에서 다룬다.

이전 계획의 반복 계산과 세 번째 CLI 검사 연결은 현재 실행 대상에서 제외한다. 입력 상한, 판정식, 명사 합산과 새 JSON 필드의 적용 상태는 [결정 이력](decisions/repetition-aggregation-and-output.md)에 둔다. 당시 알고리즘 자료를 새 구현의 선행 조건으로 사용하지 않는다.

[근거 대조 조사](references/semantic-review-without-frequency.md)의 대응을 기존 절차에 반영한다. [문서 이해 조사](references/document-comprehension-research.md)의 여러 후보를 모두 구현하거나 서로 다른 스킬로 비교하지 않는다. [개발 지침](../../dev/README.md)과 [Node.js ESM CLI 지침](../../dev/node/mjs-cli.md)을 적용하며, 기존 두 검사, 세 배포 파일, 외부 패키지 없는 실행과 입력 오류 처리를 보존한다.

## 실행 순서

U1에서 고정 표현 자료를 추가하고, U2에서 기존 스킬의 근거 수집과 의미 판단을 구체화한다. U3은 U2를 설명하는 사례를 기존 한국어 참고 자료에 보완한다. U4는 전체 변경이 끝난 뒤 한 번 수행한다. 작업 중에는 자체 검사, 별도 리뷰와 후보별 평가를 반복 실행하지 않는다.

각 작업은 나중에 변경 이유와 대상을 확인할 수 있는 단위로 커밋한다. 검증하지 않은 단계의 커밋을 기능 완료나 효과 입증으로 기록하지 않는다.

## U1. 세 표현을 고정 검사 후보에 추가

변경 대상은 [korean-expressions.mjs](../../../skills/use-better-terms/scripts/korean-expressions.mjs)의 기존 규칙 자료다. 세 표현 각각에 문맥 확인 질문과 정확한 사용의 유지 사례를 둔다. 반복 횟수 조건과 자동 치환을 추가하지 않는다. 일반 반복 검사나 명사 합산 목록으로 이 요구를 대신하지 않는다.

[scan.mjs](../../../skills/use-better-terms/scripts/scan.mjs)의 기존 자체 검사에는 세 표현이 각각 한 번 등장해도 그 표현의 규칙이 나오는 사례를 포함한다. 다른 표현의 경고나 전체 경고 수만으로 성공을 판단하지 않는다. 기존 규칙의 부분 일치, 활용형과 겹치는 경고는 유지한다. 실제 실행은 U4에서 모아서 한다.

관찰할 결과는 `업무`, `지위`, `소비` 각각의 직접 경고와 기존 두 검사 형식의 유지다. 실제 맡은 일을 뜻하는 `업무`, 법률상 `지위`, 전력 `소비`는 경고가 나더라도 문맥상 유지할 수 있다.

## U2. 원문 근거와 독자의 질문을 기존 절차에 연결

변경 대상은 [SKILL.md](../../../skills/use-better-terms/SKILL.md)의 기존 `Collect evidence and run checks`와 `Improve and judge the outputs`다. 근거를 모으는 위치와 최종 의미를 판단하는 위치의 역할을 구분하고 같은 지시를 양쪽에 복제하지 않는다.

근거 수집에서는 독자가 문서에서 결정하거나 실행할 사항을 파악하고 관련 원문을 찾는다. 원문의 주체, 행동, 조건과 시점을 확인하며 공식 설명, 코드와 실행 기록이 서로 다르면 차이를 남긴다. 별도 파일이나 모든 문장에 적용할 고정 양식은 만들지 않는다.

기존 문서별 판단은 스크립트의 경고 유무와 관계없이 본문 전체에 적용한다. 목록 밖 표현도 여러 문맥에서 같은 행동을 가리키는지 살피며, 조사나 활용형이 다르다는 이유로 같은 표현의 문제를 건너뛰지 않는다. 같은 대상을 정확히 가리키면 이름을 유지하고, 포괄적 명사가 서로 다른 동작을 가리면 각 동작과 조건을 쓴다.

자료에 있는 정보만 복원하고, 자료에도 없는 정보와 미결정 정책은 확인 질문으로 남긴다. 자료가 있는지 모르는 상태를 자료 부재로 단정하지 않는다. 전문용어를 풀어 쓰면서 서로 다른 개념을 합치지 않는다. 결론은 현재 판단과 남은 조건, 다음 행동을 드러내도록 구성한다.

관찰할 결과는 문서의 주장에 연결된 원문 근거, 의미를 보존한 대안이나 정확한 이름의 유지 이유, 자료로 해결되지 않는 질문이다. 빈도 수치, 경고 수와 전체적으로 자연스럽다는 평가는 이 결과를 대신하지 않는다.

## U3. 근거가 있는 경우와 없는 경우의 사례 보완

변경 대상은 [한국어 판정 기준](../../../skills/use-better-terms/references/korean.md)의 `번역체와 감춰진 행동 주체`, `기존 문구와 반복되는 글의 짜임`, `문장과 문단 사이의 관계`다. 기존 [재작성 평가 사례](../better-terms-rewrite-depth-7c1d/references/rewrite-review-evaluation-cases.md)와 조사 자료의 가상 문맥을 활용한다. 새 테스트 체계나 별도 스킬은 만들지 않는다. 실제 다른 저장소의 구성과 원문을 사례로 복사하지 않는다.

사례에서는 다음 문제를 구분한다. 필요한 근거와 독자가 찾을 답을 함께 설명하고, 모든 사례를 같은 문장 수나 형식에 맞추지 않는다.

- 목록 밖의 같은 명사가 여러 동작을 가리는 경우와 정확한 기능 이름을 반복해야 하는 경우
- 근거에 주체가 있지만 글에서 빠진 경우와 근거에도 없어 확인 질문을 남겨야 하는 경우
- 현재 기록을 변경 후 효과의 증거로 잘못 쓰거나 서로 다른 조건을 하나로 읽게 하는 경우
- 작성자의 보류 문구를 지우면서 유일한 불확실성 설명도 없애는 경우
- 전문용어나 조사 결합을 고치면서 대상 또는 조건이 달라지는 경우
- 결론 제목은 있지만 독자가 결정하거나 확인할 사항에 답하지 않는 경우

각 사례의 설명은 스캐너 성공 여부가 아니라 근거와 재작성 결과의 관계를 보여 준다. 이미 명확한 문장을 유지하는 사례도 포함한다. 지침 본문의 원칙을 사례마다 다시 늘어놓지 않는다.

## U4. 마지막 단계의 확인과 완료 근거

전체 변경이 끝나면 요구사항의 `주의`에 따라 검증과 의미 검토를 한 번에 모은다. 새 검토 역할이나 반복 자기수정 절차를 추가하지 않는다. 필요한 확인을 실행할 수 없으면 해당 결과를 미확인으로 남긴다.

스크립트는 기존 `--self-test`, `pnpm lint`와 구문 검사로 확인한다. 세 표현의 독립 탐지, 기존 두 검사 순서와 필드, 오류 처리 및 외부 패키지 없는 실행을 확인한다. 반복 전용 export, 상한, 형태 합산과 세 번째 검사 코드가 남아 있지 않아야 한다. 확인한 Node.js 버전과 운영체제의 범위를 넘어 호환성을 주장하지 않는다.

문서 의미는 U3의 문맥과 원문 근거를 읽어 판단한다. 등록하지 않은 표현도 발견하고 대안을 만들 수 있는지, 정확한 이름은 유지하는지, 근거가 있는 관계는 복원하고 없는 관계는 추측하지 않는지 확인한다. 독자가 본문에서 대상과 행동, 조건과 시점, 현재 판단과 미확인 사항을 찾아 답할 수 있어야 한다.

최종 결과에는 수정한 문맥, 보존한 뜻이나 유지 이유, 남은 질문을 필요한 만큼 남긴다. 새 점수표나 모든 문장에 대한 별도 장부를 요구하지 않는다. 한 번의 관찰을 모델의 재현성이나 전체 탐지 정확도가 입증된 것으로 설명하지 않는다.

## 중단 조건과 다시 결정할 사항

현재 계획은 세 고정 후보와 기존 의미 판단 절차의 보완까지 실행할 수 있다. 일반 반복 집계, 한국어 형태소 분석, 외부 의미 평가 모델과 자동 치환은 포함하지 않는다. 이 기능들이 필요해지면 누락된 실제 문맥과 필요한 결과를 근거로 요구사항부터 갱신한다.

근거에 없는 사실이나 충돌하는 자료 때문에 의미를 정할 수 없으면 해당 문장의 확정을 멈추고 구체적인 질문을 남긴다. 기존 용어의 뜻이나 승인 상태를 바꾸어야만 자연스러운 대안을 만들 수 있어도 임의로 고치지 않는다. 확인되지 않은 문장을 통과로 기록하거나 필요한 의미 판단을 비활성화해 완료시키지 않는다.
