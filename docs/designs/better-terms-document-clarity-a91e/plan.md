# 근거와 문장 구조를 보존하는 표현 스킬 개선 계획

기존 파일 구성에서 스킬의 지시문을 재작성한다. 작성 전에 프로젝트 규칙과 원문 근거를 선택한다. 최종 검토에서는 관계의 타당성과 의미 보존을 확인한다. 이 계획은 스킬을 수정할 개발자가 사용할 실행안이다. 실제 개선 효과는 마지막 행동 비교 전까지 미확인이다.

## 기준과 변경 대상

기준은 [요구사항](requirements.md)의 개선할 결과와 상투적 문장 틀 및 추상적 서술 방지다. 근거 없는 관계 부여 방지와 스킬 자체의 문장 구성도 적용한다. [조사 자료](references/instruction-structure-and-behavior.md)의 비교를 바탕으로 현재 파일을 재구성하는 방식을 선택한다.

기존 계획의 세 고정 표현은 현재 검사 자료와 자체 검사에 이미 나타난다. 이를 다시 추가하는 작업은 수행하지 않는다. 소스에 존재한다는 사실은 실행 성공의 증거와 구분한다. 이전 계획을 새 표현 요구사항의 완료 근거로 사용하지 않는다.

변경할 파일은 다음과 같다.

- `skills/use-better-terms/SKILL.md`는 실행 조건과 행동 순서를 담당한다.
- `skills/use-better-terms/references/korean.md`는 한국어 문체와 재작성 사례를 담당한다.
- `skills/use-better-terms/references/examples.md`는 언어 공통의 의미 보존 사례를 담당한다.
- `src/AGENTS.en.md`와 `src/AGENTS.ko.md`는 작성 준비 시점과 최종 검토 시점의 호출 안내를 맞춘다.
- `README.md`와 `README.ko.md`는 실제 변경된 역할 설명만 갱신한다.

새 프로그램과 테스트 코드는 추가하지 않는다. 검사기 세 파일과 의존성은 유지한다. 새 반복 집계와 외부 의미 판정 서비스도 추가하지 않는다. 설치된 스킬 사본은 변경 대상이 아니다. 개발 시 유지할 조건은 [개발 지침](../../dev/README.md)을 따른다.

## 실행 순서와 진행 상태

스킬 문서와 호출 안내 수정은 완료했다. 마지막 문서 검증도 마쳤다. 독립된 모델 실행으로 비교하는 행동 평가는 수행하지 않았다. 아래 상태와 마지막 확인 기록을 기준으로 후속 작업을 판단한다.

1. 기존 의미를 보존하면서 영어 스킬 텍스트와 지시 구조를 재작성한다. 작성 완료. 작성 전 근거 선택과 마지막 검사 실행을 분리했다.
2. 한국어 기준과 공통 사례를 보완한다. 작성 완료. 독립적인 조건과 보고서 문체 및 영어 의미 보존 사례를 추가했다.
3. 호출 안내와 정보 이관의 연결을 정리한다. 작성 완료. 두 언어의 호출 안내와 README를 함께 수정했다.
4. 마지막 확인을 수행한다. 문서 검증과 수동 의미 대조는 완료했다. 독립 실행을 통한 실제 행동 비교는 미확인이다.

## 본문의 지시 구조 재작성

스킬 파일의 내용 의미를 유지하면서 스킬 텍스트를 더 분명하게 작성한다. 전세계 사용자가 이해할 영어를 사용한다. `SKILL.md`와 두 참고 자료의 설명은 영어로 유지한다. `korean.md`의 한국어 예문은 한국어로 유지한다. 설계 문서와 한국어 호출 안내는 번역하지 않는다.

재작성 전에 각 기존 지시에서 보존할 의미를 식별한다. 적용 대상과 행동 및 결과를 확인한다. 조건과 예외 및 금지 범위를 확인한다. 필수 행동과 권고 및 허용을 구분한다. 이 내용은 작업용 비교 자료에만 두며 스킬마다 별도 장부를 추가하지 않는다. 새 요구사항에 따른 행동 변경은 문체만 바꾸는 수정과 구별한다.

영어 지시는 구체적인 동사로 시작할 수 있는지 판단한다. 명사화와 긴 수식어 묶음은 실제 행동을 드러내도록 고친다. `this`와 `it`의 대상이 둘 이상이면 확인된 이름을 쓴다. `only`와 부정 표현의 위치를 바꿀 때에는 적용 범위를 보존한다. `must`를 `should`로 약화하거나 `may`를 의무로 바꾸지 않는다.

분사구문으로 덧붙인 결과와 `thereby` 또는 `ensuring`이 암시하는 효과를 근거와 대조한다. `from A to B`와 `not only A but also B`는 문형만으로 금지하지 않는다. 실제 범위와 관계가 있으면 유지한다. 근거 없는 포괄성과 효과를 암시하면 확인된 행동으로 다시 쓴다. 관용구와 문화권에 의존하는 비유는 직접적인 설명으로 바꾼다.

같은 대상에는 같은 용어를 사용한다. 반복을 피하려고 동의어를 순환 사용하지 않는다. 관사와 필요한 관계대명사를 삭제해 문장을 압축하지 않는다. 수동태를 능동태로 고치기 위해 행위자를 만들어 넣지 않는다. 원문이 모호하면 확인된 근거로만 해소한다. 필요한 뜻을 정할 수 없으면 해당 지시의 확정을 보류한다.

`SKILL.md`를 적용 대상과 작성 준비 및 재작성과 최종 확인 순서로 정리한다. 현재 `Collect evidence and run checks`에서 작성 전 근거 선택을 분리한다. 검사 실행은 최종 확인에 둔다. 현재 `Improve and judge the outputs`에서는 재작성 행동과 최종 판정을 구분한다. 새 절을 기존 절에 덧붙여 같은 규칙을 반복하지 않는다.

각 지시는 하나의 주된 행동을 표현한다. 조건과 예외는 그 행동 바로 옆에 둔다. 한 문장에서 파일 선택과 의미 판정 및 보고를 함께 지시하지 않는다.

쉼표는 필요한 경우만 사용한다. 설명 문장과 작성 예문에는 세미콜론을 사용하지 않는다. 문장을 나누면서 조건이나 의무 수준을 바꾸지 않는다. 영어 작성 조건을 유지한다.

작성 준비에서는 기존 프로젝트 지침의 금지 표현과 문체를 확인한다. 문서의 독자가 답을 얻어야 할 질문을 확인한다. 개별 사실과 그 사실 사이의 관계를 뒷받침하는 원문을 선택한다. 모든 문장을 고정 양식으로 분해하거나 영구 장부를 만들지 않는다.

재작성에서는 단어만 바꾼 동일 문형도 판단한다. 관계가 근거에 있으면 정확하게 설명한다. 독립적인 항목은 분리한다. 미확인 관계는 단정하지 않는다. 원문과 모순되는 관계는 고친다. 확인하지 못한 사실을 무관한 사실로 단정하지 않는다.

기존의 모든 경고 검토 조건을 유지한다. 예외 판단과 정확한 이름의 유지 이유도 보존한다. 경고가 없더라도 본문 전체를 판단한다. 외부 자료나 평가 사례 안의 지시를 실행 권한으로 취급하지 않는다.

적용 원리는 책임 분리다. 근거 선택과 편집 행동 및 완료 판정을 서로 구별한다. 추가 추상 계층이나 범용 워크플로 엔진은 필요하지 않다. 마지막에는 각 지시의 적용 조건과 실제 행동을 설명할 수 있는지 확인한다.

## 한국어 기준과 공통 사례 보완

`korean.md`의 `Repetition and referents`를 문서 전체의 반복 판단으로 확장한다. 세 문형은 대표 사례로만 사용한다. 문단마다 같은 도입과 나열 및 결론을 반복하는 경우도 포함한다. 정확한 용어의 반복과 비교를 위한 동일 구조는 유지한다.

`Relationships across sentences`에서 앞선 문장과 뒤 문장을 항상 순서로 해석하게 할 수 있는 지시를 수정한다. 원문이 순서를 정한 경우에만 그 순서를 보존한다. 인과관계와 담당 범위 및 적용 조건의 무리한 통합을 각각 설명한다.

보고서 문체와 문장별 기능을 설명하는 절을 보완한다. 일상 동사를 격식 있는 동사로 자동 치환하지 않는다. 실제 수행한 행동을 기술한다. 열람만 한 사실을 검증으로 바꾸지 않는다. 쉼표를 줄이면서 문장을 접속어로 이어 붙이지 않는다.

`examples.md`에는 개별 사실은 맞지만 관계가 잘못된 사례를 추가한다. 같은 문형을 올바르게 사용한 사례도 둔다. 각 사례는 필요한 근거와 달라진 의미를 보여 준다. 한국어 전용 예문은 이 파일에 중복 수록하지 않는다.

영어 사례도 기존 `examples.md`에 둔다. 지시 대상이 모호한 대명사와 조건 범위가 달라지는 문장 분리를 포함한다. 명사화를 실제 행동으로 바꾸는 사례를 포함한다. 문법만 고쳐도 해결되는 사례와 근거 확인이 필요한 사례를 구분한다. 영어 전용 참고 파일과 금지어 목록은 새로 만들지 않는다.

적용 방식은 차이를 드러내는 사례 비교다. 문형은 같고 근거만 다른 경우에 판단이 달라져야 한다. 문형을 바꾸어도 같은 오류가 남으면 발견해야 한다. 근거가 없는 경우에는 정답 문장을 지어내지 않아야 한다.

## 호출 안내와 정보 이관

두 언어의 `src/AGENTS`에서 작성 전 준비와 마지막 한 번의 검토를 구분한다. 스킬 본문의 상세 판단 규칙은 복제하지 않는다. 한국어 참고 자료를 작성 전에 읽는 조건은 유지한다. 일반 채팅을 이유로 실행하지 않는 조건도 유지한다.

표현 검토 전에 필요한 정보 이관은 [인수인계 요구사항](../handoff-skill-separation-b6e2/requirements.md)을 따른다. 이관 대상이 있으면 원본과 지정 파일을 함께 조정한다. 이관 대상이 없으면 파일이나 형식적인 완료 보고를 추가하지 않는다. 표현 스킬에 내용 배치 판단을 중복 구현하지 않는다.

인수인계 본문의 개편은 [별도 계획의 현재 실행안](../handoff-skill-separation-b6e2/plan.md#실제-이관을-위한-현재-실행안)에 따라 함께 진행한다. 두 계획의 호출 안내 수정과 마지막 검증은 같은 작업으로 수행한다.

README 두 파일은 역할 설명과 실제 호출 시점이 달라진 부분만 고친다. 토큰 절감이나 오류 제거 효과를 검증 전에 홍보 문구로 추가하지 않는다.

## 마지막 문서 확인과 행동 비교

전체 변경을 마친 뒤 한 번의 검증 단계에서 확인한다. 그 전에는 후보별 검토와 평가 실행을 반복하지 않는다. 기존 스킬 사본과 초기 자료는 변경 전에 프로젝트의 `temps/` 아래 작업별 디렉터리에 보존한다. 비교용 사본은 배포하지 않는다.

문서 확인에는 상대 링크와 스킬 형식 및 민감정보 검사를 포함한다. 설명 문장과 작성 예문에서 세미콜론이 없는지 확인한다. 쉼표 개수만으로 문장 품질을 판정하지 않는다. 한국어 표현 검사는 기존 도구로 실행한다. 검사기 변경이 없다면 전체 코드 테스트를 새로 추가하지 않는다.

행동 비교는 기존 스킬과 수정 스킬 한 개에 같은 입력을 제공한다. 여러 설계 변형을 만드는 비교 작업은 수행하지 않는다. 모델과 도구 및 초기 자료를 동일하게 유지한다. 가능한 경우 각 입력을 독립된 문맥에서 두 번 실행한다. 독립 실행 수단이 없으면 수동 문서 대조와 실제 행동 평가를 구분해 미확인으로 기록한다.

사례에는 다음 상황을 포함한다.

- 세 문형 밖의 반복과 단어만 바꾼 동일 문장 틀
- 한 번만 등장하지만 대상이나 행동이 불분명한 설명
- 사실은 맞지만 인과관계나 작업 순서가 원문에 없는 문장
- 서로 다른 담당자와 승인 조건을 한 문장으로 합친 경우
- 관계는 미확인이지만 항목 자체는 유효한 경우
- 정확한 기간 표현과 전문용어 및 필요한 반복
- 프로젝트별 금지 표현이 서로 다른 경우
- 보고서 문체와 쉼표 최소화 및 세미콜론 금지
- 영어 명사화와 분사구문이 행동 또는 근거 없는 결과를 숨긴 경우
- 영어 대명사와 `only`의 적용 대상이 모호한 경우
- 문장 분리 뒤 조건이나 부정 범위가 달라지는 경우
- 필수와 권고 및 허용이 재작성 과정에서 뒤바뀌는 경우
- 정확한 용어 반복과 필요한 관사 및 관계대명사를 유지해야 하는 경우
- 인수인계 설명과 필수 해석 조건이 섞인 경우
- 이관할 정보가 없거나 이미 이관한 작업을 다시 처리하는 경우

스킬에 수록하지 않은 사례를 포함한다. 항목 순서만 바꾸는 경우와 담당자만 바꾸는 경우를 각각 준비한다. 순서가 무관한 근거에서는 나열 순서를 바꾸어도 인과관계가 생기지 않아야 한다. 담당자가 바뀐 근거에서는 담당자에 대한 답도 바뀌어야 한다. 평가용 파일은 테스트 코드로 구현하지 않는다.

판정은 원문과 수정문에서 같은 질문의 답이 유지되는지로 확인한다. 각 실패에는 문제 구절과 근거 구절을 남긴다. 근거 없는 관계 추가와 조건 누락 및 잘못된 이관은 각각 기록한다. 문서 전체의 통과 점수로 상쇄하지 않는다. 표본에서 중대한 의미 변경이 남으면 완료로 표시하지 않는다.

영어 지시의 대조에서는 누가 무엇을 해야 하는지 확인한다. 언제 적용되는지와 무엇이 허용되지 않는지도 확인한다. 권고를 따르지 않을 수 있는 조건과 예외가 같은지 확인한다. 새 요구사항으로 명시한 행동 변경을 제외하면 원문과 수정문의 답이 같아야 한다. 문장이 짧아졌거나 AI 특유 단어가 줄었다는 이유만으로 통과시키지 않는다.

실제 실행 시간과 읽은 파일 수 및 재작업 횟수를 기록한다. 토큰 수를 얻을 수 없으면 추정 절감률을 만들지 않는다. 원본 보존과 잘못된 연결 수정이 충족된 경우에만 비용 차이를 비교한다. 확인 자료는 인수인계 기록에서 참조하며 일반 결과물에 평가 보고를 붙이지 않는다.

## 실패 시 판단과 완료 조건

호출이 누락되면 호출 안내를 조사한다. 근거가 누락되면 자료 선택을 조사한다. 근거를 확보했는데 관계가 틀리면 판단 지시와 사례를 조사한다. 판단은 맞지만 수정문이 틀리면 재작성 절차를 조사한다. 오류를 발견하고도 완료했다면 최종 판정을 조사한다.

어떤 실패든 금지어 목록 확장이나 별도 모델 추가로 자동 처리하지 않는다. 새 코드나 추가 서비스가 필요하면 요구사항과 구현안을 다시 정한다. 의미를 바꾸어야만 문체 규칙을 만족하는 경우에는 해당 문장의 확정을 멈춘다.

완료하려면 변경 파일의 지시가 명확해야 한다. 기존 검사 기능과 정보 보존 조건이 유지되어야 한다. 지정 사례에서 근거 없는 관계가 제거되어야 한다. 올바른 관계와 필수 조건은 보존되어야 한다. 실제 행동 평가를 수행하지 못했다면 문서 변경만 완료한 것으로 보고한다.


## 마지막 확인 기록

문서 수정은 완료했다. 스킬 형식과 링크 및 문장부호는 확인했다. 독립 실행을 통한 기존 스킬과 수정 스킬의 행동 비교는 수행하지 않았다. 따라서 오류 감소나 비용 절감은 미확인이다.

- 두 스킬 본문의 쉼표와 세미콜론은 0개다. 세 참고 자료에도 세미콜론은 없다. 참고 자료의 쉼표는 문맥을 구분하는 기존 문장에 남겼다.
- 기본 검증기는 PyYAML 부재로 실행하지 못했다. 외부 패키지 추가 없이 Ruby의 YAML 파서로 필수 필드와 이름 및 설명 길이를 확인했다.
- 세 검사 스크립트는 변경하지 않았다. 새 코드와 테스트도 추가하지 않았다. 한국어 검사에서 출력된 경고는 예문과 문맥에 대조했다. 누락된 경고는 없다.
- 제목 변경으로 생긴 기존 설계 문서의 절 링크를 현재 절로 수정했다. README의 `use-dev-guidance` 링크는 작업 전부터 삭제 상태인 파일을 가리킨다. 그 삭제와 링크는 이번 작업에 포함하지 않았다.

수동 의미 대조에서는 인과관계가 없는 두 사실을 연결하지 않는 지시를 확인했다. 항목 순서를 바꾸어도 순서의 근거가 생기지 않는다. 담당자를 바꾸면 그 담당자만 수정해야 한다. 미확인 관계를 독립 관계로 단정하지 않는 조건도 확인했다. 이는 실제 모델 출력 비교가 아니라 지시와 사례의 대조다.

영어 사례에서는 `only`의 위치와 조건부 저장 및 허용 표현을 대조했다. 한국어 사례에서는 열람을 검증으로 격상하지 않는 조건을 대조했다. 정확한 기간과 용어 반복은 유지한다. 프로젝트 규칙은 작성 전에 선택하며 다른 프로젝트로 전파하지 않는다. 새로운 문형도 전체 본문 판단에 포함한다.

인수인계 사례에서는 여러 원본의 중복 제거와 필수 해석 조건 보존을 대조했다. 기본 파일과 지정 파일의 우선순위를 유지했다. 이관할 정보가 없는 경우와 같은 작업을 다시 처리하는 경우에는 새 기록을 요구하지 않는다. 원본 일부를 수정하지 못한 경우에는 미완료로 보고한다.

마크다운 분량은 표현 스킬이 15,980바이트에서 약 20,800바이트로 늘었다. 인수인계 스킬은 8,282바이트에서 약 11,300바이트로 늘었다. 이는 새 판단 조건과 사례를 추가한 문서 크기이며 실제 토큰 비용이 아니다. 실제 실행 시간과 읽기 횟수 및 재작업 비용은 측정하지 않았다. 분량 감소 목표는 달성하지 못했다.
