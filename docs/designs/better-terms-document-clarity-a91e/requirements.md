# 기술 설명의 대상과 판단을 분명하게 하는 요구사항

`use-better-terms`를 개선해 독자가 문서에서 대상, 행동, 조건과 시점을 구분하고, 무엇이 사실이며 무엇을 더 결정하거나 확인해야 하는지 이해할 수 있게 한다. 이 문서는 스킬을 관리하는 개발자가 개선 범위와 완료 조건을 확인하는 데 사용한다.

## 주의

리뷰(검토, 검증 포함)의 경우 각 작업의 마지막 단계에 최대 1회 실행한다.

서브에이전트가 필요하다고 판단하면 각 작업마다 서브에이전트를 최대 2개 생성하고 작업을 진행한다. 그리고 각 작업이 끝날 때마다 서브에이전트를 종료한다.

특정 방법을 의존하지 않는다. 여러 방안에 대해서 리서치하고 최선의 결정을 하거나 선택지를 제시한다.

## 개선할 결과

낯설거나 추상적인 낱말을 바꾸는 데서 끝내지 않고, 문장과 문서에서 빠진 관계를 확인해 설명한다. 문구를 쉽게 바꾸더라도 전문용어의 뜻과 확인된 사실, 조건, 불확실성을 유지한다.

### 대상과 행동

- 포괄적인 명사나 명사 나열이 실제 동작을 가리면, 누가 무엇을 받아서 실행하고 기록하는지 구분할 수 있게 쓴다.
- 역할, 승인 여부와 실행 상태를 같은 표현으로 뭉뚱그리지 않는다. 문장이 묻는 대상이나 결정할 조건을 직접 적는다.
- 일반적인 단어라도 여러 뜻으로 읽히면 실제 문맥에 맞게 설명한다. 전문용어는 정확한 대상을 식별하는 데 필요하면 유지하고, 독자에게 필요한 설명을 붙인다.
- 조사 결합이나 문장 성분의 호응이 잘못되어 관계가 흐려지는 문장도 개선 대상에 포함한다.

### 조건과 근거의 시점

- 서로 다른 실패 상황과 그 결과를 구별할 수 있게 쓴다. 나열된 조건의 적용 대상과 선후 관계가 달라지지 않아야 한다.
- 현재 상태를 확인하는 기록과 변경 후 효과를 확인할 자료를 구분한다. 아직 적용하지 않은 제안의 효과를 현재 기록으로 입증한 것처럼 쓰지 않는다.
- 문서가 설명하는 동작, 코드에 작성된 동작과 실제 실행 기록을 구분한다. 자료 간 차이가 있으면 어느 자료의 어떤 값이나 설명이 다른지 드러나야 한다.
- 합의로 정할 사항과 자료로 확인할 사실을 구분하고, 필요한 자료나 결정 대상을 구체적으로 적는다.

### 결론과 미확인 사항

- 문서 앞부분에서 현재 판단, 그 판단을 제한하는 조건과 독자가 다음에 결정하거나 확인할 사항을 알 수 있게 한다.
- 작성자의 해석 방침만 설명하는 문장은 확인된 사실이나 미확인 대상이 드러나도록 바꾼다. 불확실성을 알리는 데 필요한 내용은 남긴다.
- 제안, 채택 결정과 실제 적용을 구별한다. 문장을 명료하게 고쳤다는 이유로 승인이나 실행 사실이 생겨서는 안 된다.
- 문맥에 없는 주체, 조건이나 근거를 추측해 문장을 완성하지 않는다. 확인이 필요한 내용을 구체적으로 남긴다.

## 먼저 적용할 개선

후속 스킬 변경은 `SKILL.md`의 기존 문서별 판단 항목 한 곳을 구체화하는 것부터 시작한다. 표현을 고치기 전에 독자의 판단에 필요한 대상, 행동, 조건과 시점을 확인하도록 한다. 필요한 정보가 자료에 있으면 문장에 드러내고, 자료에도 없으면 추측하지 않고 미확인 사항으로 남긴다. 전문용어를 바꿀 때에는 서로 다른 개념이 합쳐지지 않게 한다.

같은 요구를 여러 지침에 덧붙이지 않는다. 여러 스킬 변형, 별도 비교 환경이나 새 점수표를 먼저 만드는 일을 이 변경의 선행 조건으로 두지 않는다. 실제 문서의 마지막 판단에서 필요한 정보가 남았는지 확인하되, 한 번의 성공을 안정적인 개선의 증거로 설명하지 않는다.

## 반복 표현 탐지와 대안 탐색

`업무`, `지위`, `소비`를 스크립트가 알리는 표현 후보에 추가하는 요구를 포함한다. 반복 횟수가 적어도 문맥을 확인할 수 있어야 하며, 다른 단어가 탐지됐다는 이유로 세 표현의 탐지가 구현됐다고 보지 않는다. 세 표현은 금칙어가 아니며 정확한 전문용어나 이름은 유지할 수 있다.

미리 등록하지 않은 표현도 문서 전체의 빈도를 기준으로 스크립트가 반복 후보로 제시하고, 에이전트가 자연스러운 대체 문장을 적극적으로 찾게 한다. 후보는 파일별로 3회 이상이면서 분석 대상 토큰의 1% 이상인 표현이다. 같은 문단 3회라는 이전 제안과는 다른 기준이며, 수치는 초기 운영값이지 검증된 한국어 품질 기준이 아니다.

반복 검사에 전달하는 원문은 한 실행 합계 20,000 Unicode 코드 포인트까지 받는다. 초과하면 기존 두 검사는 유지하고 반복 검사의 미실행을 명시한다. 자동 절단하거나 일부 파일만 골라 집계하지 않는다.

스크립트는 출현 위치와 집계 근거를 제공하고, 대안 탐색과 의미 보존 판단은 기존 스킬 절차가 맡는다. 반복 횟수만으로 오류를 확정하거나 자동 치환하지 않는다.

반복 기준은 문서 전체의 빈도, 가까운 문장에서의 집중과 여러 문서에 걸친 과다 사용을 구분해 조사한다. 한국어 조사와 활용 때문에 다른 형태로 나타나는 경우, 코드와 인용문, 동일한 전문용어의 필요한 반복도 다룬다. 제안한 수치는 검증된 한국어 품질 기준과 구분한다.

대안은 동의어 교체에 한정하지 않는다. 같은 명사가 서로 다른 동작이나 상태를 대신하면 실제 동작과 조건을 적고, 같은 대상을 정확히 가리키는 반복이면 이름을 유지한다. 필요한 정보가 없으면 문장을 임의로 완성하지 않는다. 목록 밖의 표현에도 현재의 대안 탐색과 유지 근거 기록을 적용한다.

반복 후보는 기존 표현 검사와 긴 문단 검사 뒤에 `repetition` 검사 항목으로 전달한다. 반복 검사도 `catalog`, `rules`, `warnings`와 `summary`를 제공하며, 같은 파일의 같은 표현은 출현 위치들을 한 경고로 묶는다. 등록 표현의 기존 활용형 탐지는 유지하고, 반복 합산에는 표제어가 하나로 정해지는 활용형과 명시한 명사만 사용한다. 미등록 표현은 정준 정규화한 표기대로 세며 임의로 조사를 제거하지 않는다. 배포 파일은 기존 세 개를 유지한다. 세부 동작과 기존 결정에 미치는 영향은 [반복 검사 결정 이력](decisions/repetition-aggregation-and-output.md)을 따른다.

## 반복 검사의 적용 조건

제목, 목록과 일반 산문을 분석하며, 코드와 URL 및 인용문 등을 제외하는 정확한 규칙은 결정 기록에서 정한다. 토큰의 정의와 분모는 같은 추출 절차를 사용한다. 제외된 부분이나 미등록 조사 결합형을 모두 분석했다고 설명하지 않는다. 문서 전체란 이 규칙을 적용한 파일 전체이며, 여러 파일이나 잘린 조각을 하나의 문서로 합치지 않는다.

집계는 토큰별 색인을 사용하고, 토큰끼리의 전수 비교와 각 출현마다 원문 처음부터 다시 탐색하는 방식을 피한다. 입력 상한, 실제 집계 비용과 JSON 생성 비용을 각각 확인한다. 숫자, 형태 처리와 결과 형식의 선택 이유 및 재검토 조건은 결정 기록에 남긴다. 초기 구현에 필요한 동작 선택은 확정했으며, 의미 판단 정확도와 실행 비용은 구현 후 확인할 사항으로 남는다.

## 조사와 적용 범위

문제와 유사한 외부 사례를 조사하고, 현재 `use-better-terms` 기준과 비교해 해결 방법을 찾는다. 외부 연구에서 확인한 사실, 저장소에서 확인한 기준과 개선 제안을 구분한다. 조사 결과와 제안의 근거는 [문서 이해와 의미 보존 조사](references/document-comprehension-research.md)와 [반복 표현 탐지와 재작성 조사](references/repeated-expression-research.md)에 기록한다.

이번 산출물은 요구사항, 조사 문서, 결정 이력과 실행 계획이다. 입력 크기의 최초 비교는 [입력 크기 조사](references/repetition-input-size.md), 추가 비교와 알고리즘 근거는 [반복 검사 설계 비교](references/repetition-design-tradeoffs.md)에 기록한다. 스킬이나 검사 스크립트의 수정, 코드와 테스트 작성은 이번 문서화에 포함하지 않는다. 다른 저장소의 이름, 구성과 원문은 문서에 옮기지 않는다.

## 완료를 확인할 자료

- 조사 문서에서 대상과 행동의 누락, 조건과 시점의 혼동, 작성자 중심 설명, 결론 배치와 전문용어의 의미 손실을 각각 설명하고 개선 방법을 찾을 수 있다.
- 외부 사례에는 확인 날짜, 출처, 실제로 관찰된 문제나 지침의 내용, 이 체계에 적용할 때의 한계가 함께 있다.
- 기존 기준으로 다루는 문제와 보완할 사항을 구분해 같은 규칙을 다시 만드는 일을 피할 수 있다.
- 후속 개선의 결과에서는 독자가 문서만으로 대상과 행동, 적용 조건, 근거의 시점, 결정할 사항과 미확인 사항을 구별할 수 있어야 한다. 표현이 자연스러워져도 이 정보가 빠지거나 원래 뜻이 달라지면 완료로 보지 않는다.
- 요구사항과 조사 문서의 작성 완료를 스킬 개선 효과가 입증된 것으로 설명하지 않는다.
- 세 표현의 후보 추가, 목록 밖의 반복 탐지와 의미를 보존하는 재작성을 구분하고, 현재 구현 여부와 후속 변경에 필요한 결정을 확인할 수 있다.
- 반복 탐지 기준의 근거와 한계, 필요한 반복을 유지하는 사례와 생성 과정의 반복 현상을 다룬 연구를 확인할 수 있다.
- 문서 전체 집계, 입력 상한, 판정식, 형태 처리와 세부 형식의 현재 결정 및 이전 제안을 구별할 수 있다. 외부 서비스의 처리 한도, 현재 스크립트의 byte 제한과 실제 문서 크기의 차이, 입력 증가에 따른 계산과 출력 비용이 설명되어 있다.
- 계획에서 요구사항별 변경 대상, 실행 순서, 관찰할 동작과 중단 조건을 찾을 수 있다. 문서의 커밋을 구현이나 성능 확인 완료로 설명하지 않는다.
