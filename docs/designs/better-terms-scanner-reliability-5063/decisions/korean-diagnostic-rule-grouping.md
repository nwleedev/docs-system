# 한국어 표제어의 진단 규칙 구성

## 결정

`좁다`, `좁히다`, `박다`와 `박히다`의 형태 matcher는 표제어와 품사별로 나눈다. matcher는 각 표제어의 활용, 융합형, 형태 조건과 오탐 방지 사례를 독립적으로 판정하고 사용자에게 보여 줄 진단 rule에 연결한다.

`좁다`는 상태를 확인하는 새 rule ID와 검토 질문 및 안내 문구를 사용한다. 기존 `ko.narrow`는 `좁히다`에 유지하고, 누가 무엇을 줄였는지와 변화 전후를 확인하는 현재 진단 책임을 이어 간다. 새 rule ID의 실제 문자열은 이 결정에서 정하지 않는다.

`박다`와 `박히다`는 별도 matcher로 판정하되 기존 `ko.fix-in-place`를 공유한다. 검토 질문과 안내 문구는 누가 무엇을 넣거나 고정한 행동과, 무엇이 어디에 남아 있거나 고정된 상태를 모두 정확히 확인하게 해야 한다.

형태 matcher의 식별자는 외부 JSON에 추가하지 않는다. `warnings`의 `ruleId`, `expression`과 원문 위치를 비롯한 현재 결과 구조를 유지한다. 네 표제어에서 발견한 표현은 모두 [공통 판정 절차](../requirements.md#공통-판정-절차)에 따라 자연스러운 대체 문장을 먼저 검토한다.

## 결정이 필요한 이유

[표현 탐지 요구사항](../requirements.md#표현-탐지)은 네 표제어의 활용형을 찾으면서 현재 JSON 결과 구조를 유지하도록 요구한다. 현재 [표현 탐지 모듈](../../../../skills/use-better-terms/scripts/korean-expressions.mjs)은 rule 하나에 `id`, `message`, `queries`, `negatives`와 `positives`를 한 묶음으로 둔다. 경고는 `ruleId`와 `expression`으로 그 묶음을 가리키므로, 같은 rule ID를 쓰는 matcher에는 같은 질문과 안내가 적용된다.

현재 `ko.narrow`의 질문은 줄이는 대상과 변화 전후를 확인한다. 이 질문은 사동사 `좁히다`에는 맞지만 현재 상태를 나타내는 형용사 `좁다`에는 존재하지 않는 변화 행동을 전제할 수 있다. 반면 `ko.fix-in-place`는 물리적 고정과 기술 문서의 비유를 구분한다는 목적을 `박다`와 `박히다`에 함께 적용할 수 있고, 이미 `박힌`과 `박혀`를 같은 rule ID로 보고한다.

## 검토한 선택

### 표제어 쌍마다 하나의 진단 공유

`좁다`와 `좁히다`를 `ko.narrow`에, `박다`와 `박히다`를 `ko.fix-in-place`에 각각 연결하는 선택이다. 기존 ID를 유지할 수 있지만 한 rule에 질문 묶음이 하나뿐인 현재 구조에서는 `좁다`에 행동 중심 질문을 적용하거나 `좁히다`에 필요한 변화 정보를 약하게 만드는 문제가 있다.

### 네 표제어의 진단을 모두 분리

각 표제어가 독립된 rule ID와 판정 자료를 갖는 선택이다. 표제어마다 질문을 정밀하게 만들 수 있지만 기존 `박힌`과 `박혀` 경고의 `ruleId`가 바뀌고, 같은 글쓰기 문제와 후속 행동을 중복해서 관리하게 된다.

### 상태와 행동의 차이 및 기존 호환성에 따라 구성

`좁다`와 `좁히다`의 진단은 나누고 `박다`와 `박히다`의 진단은 공유하는 선택이다. 상태에 행동 중심 질문을 적용하는 오류를 막으면서 기존 `ko.narrow`, `ko.fix-in-place` 경고의 ID를 보존한다. 이 선택을 승인했다.

## 영향

- 후속 구현은 네 표제어별 matcher와 검증 사례를 독립적으로 둔다.
- `좁다` 경고에는 상태, 비교 기준과 실제 대상을 묻는 새 진단 자료를 연결한다.
- `좁히다` 경고는 기존 `ko.narrow`를 유지하고 주체, 대상과 변화 전후를 확인한다.
- `박다`와 `박히다` 경고는 기존 `ko.fix-in-place`를 공유한다. 공통 문구는 능동 행동과 결과 상태 중 어느 쪽에도 치우치지 않아야 한다.
- 기존에 탐지되는 `좁히다`, `박다`와 `박히다` 활용의 `ruleId`는 바꾸지 않는다.
- 새 matcher ID나 표제어 필드를 외부 JSON에 추가하지 않는다.
- 새 `좁다` rule ID의 이름, 허용할 어미 분류와 구체적인 형태 조건은 후속 결정에서 정한다.

## 다시 검토할 조건

`박다`와 `박히다`에 필요한 대체 문장 작성법, 정상 용례, 심각도 또는 억제 조건이 반복해서 다르게 나타나거나, 한 안내 문구가 두 경우를 조건문처럼 나열해야만 정확해지면 rule ID를 분리할지 다시 확인한다. matcher별 안내를 제공하면서 하나의 rule ID를 유지할 수 있는 하위 진단 구조를 별도로 승인하면 현재 구성을 다시 비교한다.
