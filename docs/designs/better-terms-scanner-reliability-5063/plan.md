# `use-better-terms` 표현 검사기 신뢰성 구현 계획

## 결론

후속 구현은 네 표제어의 형태 판정, 도움말과 실행 비용을 기존 두 스크립트 안에서 보완한다. `korean-expressions.mjs`에는 사용자 진단과 분리된 표제어별 matcher를 두고, `scan.mjs`에는 독립된 도움말 실행과 회귀 사례를 둔다. 외부 package, 새 배포 파일과 외부 JSON 필드는 추가하지 않는다.

형태 판정은 어간 부분 문자열 하나나 표면형 전수 목록에 의존하지 않는다. 표제어, 품사, 제한된 어미 분류, 검증된 융합형, token 조건과 확실한 비표제어 사례를 조합한다. 문맥만으로 판단할 수 있는 정상 용례와 중의적인 표현은 검사 단계에서 없애지 않고 다른 경고와 같은 공통 판정 절차로 전달한다.

현재 검색 방식은 입력 길이에 대해 제곱으로 증가한다고 볼 근거가 없으므로 먼저 유지한다. 전체 CLI의 시간, peak RSS와 결과를 변경 전후에 같은 입력으로 측정한다. 정한 기준을 넘을 때만 전체 일치 정렬과 보관을 줄이는 변경을 적용하며, Aho-Corasick 도입은 이번 작업에서 제외한다.

구현을 마친 뒤 자체 검사, ESLint, 대표 입력의 자식 process 실행과 JSON 대조로 각 작업 단위의 완료 근거를 수집한다.

## 구현에서 적용할 선택

형태 matcher 분리와 사용자 진단 연결은 승인된 결정을 따른다. 새 rule ID, 내부 형태 자료, 도움말 조합과 성능 판정 방식은 요구사항의 열린 질문을 조사 근거로 구체화한 계획 판단이다. 이 선택이 요구사항이나 승인된 결정과 충돌하는 증거가 나오면 구현으로 확정하지 않고 [실행 중단 조건](#실행-중단-조건)에 따른다.

### 사용자 진단과 형태 matcher를 분리한다

`rules`는 외부 `catalog`, 발견된 `rules`와 `warning.ruleId`가 가리키는 사용자 진단을 계속 관리한다. 같은 파일의 내부 matcher 자료는 표제어, 품사, 어간 및 융합형, 허용 어미 분류, token 조건, 제외 조건, 보고할 expression과 연결할 진단 위치를 관리한다. matcher 식별자와 표제어 필드는 JSON에 추가하지 않는다.

`좁다`는 새 rule ID `ko.narrow-state`에 연결한다. 진단은 무엇이 어떤 기준에서 제한된 상태인지와 실제 폭, 수량 또는 선택 가능 범위를 더 정확히 말할 수 있는지 확인하게 한다. `좁히다`는 기존 `ko.narrow`와 기존 경고의 rule ID를 유지한다.

`박다`와 `박히다` matcher는 각각 둔다. 두 matcher는 기존 `ko.fix-in-place`에 연결한다. 공통 진단은 누가 무엇을 넣거나 고정한 행동과, 무엇이 어디에 남아 있거나 굳어진 상태를 모두 확인하게 한다. 기존 `박다`, `박아`, `박은`, `박힌`과 `박혀` 경고의 rule ID를 바꾸지 않는다.

기존에 보고되던 표면형의 `warning.expression`, UTF-16 위치, 겹치는 일치와 선언 순서는 그대로 둔다. 새 활용형의 `warning.expression`은 matcher가 선택한 검증된 표면형 계열을 가리키고, 경고 범위는 원문의 해당 표제어 활용 부분을 가리킨다. catalog에는 matcher가 보고할 수 있는 표면형 계열만 싣고, 내부 matcher 식별자는 싣지 않는다.

### 제한된 어미 분류와 융합형을 내부 자료로 둔다

어미 자료는 현대 표준 한국어 문어에서 네 표제어가 실제로 결합할 수 있는 분류만 포함한다. 표면 문자열을 모두 사람이 나열하지 않고, 다음 분류를 표제어와 품사별 허용 목록으로 재사용한다.

- 종결과 높임: `-다`, `-요`, `-습니다`, `-습니까` 및 표제어에 맞는 결합형
- 연결: `-고`, `-지`, `-지만`, `-거나`, `-는데` 또는 `-은데`, `-면` 또는 `-으면`, `-니` 또는 `-으니`, `-며` 또는 `-으며`, `-아서` 또는 `-어서`, `-도록`, `-게`
- 관형: 동사의 `-는`, 동사와 형용사에 맞는 `-ㄴ` 또는 `-은`, `-ㄹ` 또는 `-을`, `-던`
- 명사형: `-기`, `-ㅁ` 또는 `-음`
- 선어말: `-시-` 또는 `-으시-`, `-았-` 또는 `-었-`, `-겠-`, `-더-` 가운데 사전 자료와 회귀 사례로 확인한 결합
- 인용과 전성: `-다고`, `-다는`, `-다면`처럼 앞 분류만으로 token의 나머지를 잘못 거부할 수 있는 검증된 결합

matcher는 품사에 맞지 않는 결합을 허용하지 않는다. 예를 들어 현재 관형형 `-는`은 동사 matcher에서만 사용하고, `좁다`의 현재 관형형은 `좁은`으로 판정한다. 받침 어간 `좁-`, `박-`과 모음 어간 `좁히-`, `박히-`는 필요한 매개 모음과 어미 이형태를 따로 적용한다.

융합형은 별도 표면형 자료로 관리한다. 최소한 `좁아`, `좁았-`, `좁혀`, `좁혔-`, `박아`, `박았-`, `박혀`, `박혔-`를 포함한다. NFD는 정준 동등성과 종성이 붙은 융합 음절을 원문 위치로 되돌리는 데만 사용하고, 어간과 어미를 판정하는 수단으로 일반화하지 않는다.

활용형 matcher는 한국어 token 시작에서만 표제어 후보를 연다. token의 나머지는 허용된 어미 조합으로 끝까지 설명되거나, `-아` 또는 `-어`, `-고` 뒤에 붙는 검증된 보조 용언 결합으로 설명되어야 한다. 이 조건은 `좁아지다`, `박아 두다`, `박혀 있다`처럼 표제어가 다른 용언과 이어진 경우를 다루면서 임의의 뒷문자를 허용하지 않게 한다.

`좁쌀`, `박물관`, `박사`와 `박수`는 허용 어미 조합이 아니므로 제외한다. `호박`, `압박`과 `대박`은 token 시작 조건에서 제외한다. 이 문자열은 실행 중 예외 목록을 계속 늘리는 근거가 아니라 matcher 조건을 확인하는 부정 사례로 둔다.

이 계획에서 두었던 단일 문맥 제외 조건은 후속 [한국어 스캐너 규칙 일반화 요구사항](../korean-scanner-rule-generalization-2d05/requirements.md)에 따라 제거한다. 형태 규칙이 허용하는 입력과 `못을 박다` 같은 물리적 용례는 후보로 남기고, 공통 판정 절차에서 대체 문장과 유지 근거를 판단한다.

호환 자모, zero-width 문자로 나뉜 어절과 Markdown 구문이 형태소 중간에 끼어든 입력은 이번 matcher의 대상이 아니다. 해당 입력을 지원하려면 원문 위치와 문서 구문 처리 방식을 별도로 결정한다.

### 도움말은 독립된 입력 mode로 제공한다

정확한 `--help`는 도움말을 stdout에 쓰고 상태 `0`으로 끝낸다. stderr는 비어 있어야 하며 출력은 마지막 LF를 포함한다. `-h`, `--he`와 다른 이름은 허용하지 않는다.

도움말에는 설명 한 줄, 실제 다섯 호출형, option 이름과 값, `--file` 반복, `--stdin`과 `--source-name`의 결합, `--self-test`의 유지보수 용도를 한 출력에 표시한다. 실행 이름은 저장소에서 직접 실행할 수 있는 `node skills/use-better-terms/scripts/scan.mjs`로 표시한다.

도움말은 다른 option과 함께 사용할 수 없는 독립 mode다. `--help --file <path>`, `--file <path> --help`, `--help --help`와 값이 필요한 option의 누락은 기존 사용 오류 형식과 상태 `2`를 사용한다.

`help` positional과 짧은 option은 추가하지 않는다. 입력, Git, 파일, stdin, 두 탐지기와 JSON 직렬화는 도움말 mode에서 실행하지 않는다.

### 성능 변경은 측정 기준을 넘을 때만 적용한다

변경 전 기준과 변경 후 결과는 같은 Node.js 버전, 같은 process 조건과 같은 입력으로 비교한다. 최소 실행 환경인 Node.js 22와 구현 시점의 현재 Node.js release를 따로 측정한다. 각 사례를 예열한 뒤 다섯 번 이상 실행한 중앙값과 peak RSS를 사용하며, 순수 표현 탐지와 전체 CLI를 나눠 기록한다.

입력은 후보가 없는 ASCII와 한글, 첫 글자만 matcher와 같은 입력, 일반 및 NFD 일치가 조밀한 입력, 겹치는 일치, 긴 quote와 경고 상한, source 하나와 여러 source, source별 2 MiB 및 전체 32 MiB 상한을 포함한다. 모든 비교는 `summary.total`, 경고 순서, `ruleId`, `expression`, 원본 UTF-16 위치, quote와 JSON byte 제한 결과가 같다는 조건 아래에서만 유효하다.

현재 검색 방식을 유지하는 기준은 다음과 같다. 실행 환경과 사용 빈도가 정해지지 않았으므로 절대 실행 시간, peak RSS 또는 허용 퇴행률은 이 플랜에서 만들지 않는다.

- 입력 상한에서 비정상 종료와 메모리 부족이 없다.
- 네 배씩 커지는 세 크기 이상의 입력에서 중앙 실행 시간의 증가 추세가 선형 또는 `N log N` 분석과 일치하고 제곱 증가를 뒷받침하지 않는다.
- 형태 matcher 추가 전후의 중앙 실행 시간과 peak RSS 차이를 입력군별로 기록해 다음 성능 예산 결정에 사용할 수 있다.
- 한 차례의 재측정에서 같은 증가 추세나 실패가 재현되지 않으면 측정 잡음으로 기록하고 알고리즘을 바꾸지 않는다.

제곱 증가 또는 입력 상한의 메모리 실패가 재현되면 일반 literal 실행과 matcher 실행에서 이미 정렬된 일치 흐름을 시작 위치와 선언 순서로 병합한다. 상세 경고 상한 뒤에는 전체 일치를 배열에 보관하지 않고 전체 수와 발견된 rule만 갱신한다. 이 변경으로 기존 결과 순서, 겹치는 일치, NFD 원본 위치와 전체 count가 달라지면 채택하지 않는다.

순수 JavaScript Aho-Corasick, Trie 전환, 정규식 alternation과 외부 검색 package는 이번 작업에서 사용하지 않는다. matcher 수가 현재 계획보다 크게 늘고 국소 변경 뒤에도 같은 기준을 넘는 측정이 생기면 별도 설계 결정으로 다시 비교한다.

1. 현재 catalog, 기존 대표 경고, 겹치는 일치, NFD 위치와 출력 상한 결과를 기준 자료로 고정한다.
2. 변경 전 순수 탐지 및 전체 CLI의 시간과 peak RSS를 정한 입력군에서 측정한다.
3. 사용자 진단 자료와 내부 matcher descriptor, 어미 분류, 융합형, token 및 제외 조건의 책임을 같은 탐지 모듈 안에서 나눈다.
4. 기존 외부 필드와 matcher 내부 자료 사이의 변환 지점을 하나로 둔다.

**통합 검증에서 확인할 근거:** 기존 대표 입력의 JSON과 경고 위치가 변경 전 기준과 같고, 성능 비교에 같은 입력과 출력 대조가 사용됐음을 확인한다.

### 네 표제어의 활용형 탐지 구현

**목표:** `좁다`, `좁히다`, `박다`와 `박히다`의 검증된 활용형을 놓치지 않고 공통 판정 절차에 전달한다.

**요구사항:** [`공통 판정 절차`](requirements.md#공통-판정-절차), [`표현 탐지`](requirements.md#표현-탐지), [`완료 증거`](requirements.md#완료-증거)

**선행 작업:** 형태 판정 기준과 기준 결과 고정

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. `ko.narrow-state` 진단과 네 표제어별 matcher를 추가한다.
2. 표제어와 품사별 허용 어미, 융합형, NFD 변환, token 조건과 확실한 제외 조건을 연결한다.
3. 기존 `ko.narrow`와 `ko.fix-in-place`의 외부 ID 및 기존 경고 결과를 유지한다.
4. `ko.fix-in-place`의 판정 자료가 능동 행동과 결과 상태를 모두 확인하도록 고친다.
5. 표제어별 정상 탐지, 기존 동작, 부정 사례와 중의적 사례를 자체 검사에 추가한다.

**통합 검증에서 확인할 근거:** 여섯 재현 입력, `박히다` 대표 활용, 각 어미 분류와 융합형의 대표 사례가 의도한 rule ID와 원본 UTF-16 위치를 보고한다. 부정 사례는 보고하지 않고, `박지.`와 `못을 박다`는 후보로 남는다.

### 도움말 mode 구현

**목표:** 사용자가 입력 방식과 option 관계를 검사 실행 없이 이해하게 한다.

**요구사항:** [`명령줄 도움말`](requirements.md#명령줄-도움말), [`유지해야 할 동작`](requirements.md#유지해야-할-동작)

**선행 작업:** 형태 판정 기준과 기준 결과 고정

**대상 파일:**

- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. `parseArgs()`에 `help`를 등록하고 다른 mode와 같은 출현 횟수 및 배타성 검사를 적용한다.
2. 도움말 내용을 한 상수 또는 한 순수 함수가 관리하게 하고 `main()`에서 입력 제공자를 만들기 전에 출력한다.
3. 다섯 호출형, option 값, 반복 및 종속 조건과 유지보수용 자체 검사를 설명한다.
4. 도움말 정상 실행, 긴 option 축약 거부, mode 충돌과 기존 오류를 실제 자식 process 사례에 추가한다.

**통합 검증에서 확인할 근거:** `--help`가 도움말 stdout, 빈 stderr와 상태 `0`을 내며 스캔 JSON을 만들지 않는다. `-h`, 혼합 입력과 `--he`는 빈 stdout, 외부 오류 한 줄과 상태 `2`를 낸다.

### 측정 결과에 따른 검색 비용 개선

**목표:** 측정으로 확인된 문제만 고치고 현재 결과의 의미를 유지한다.

**요구사항:** [`실행 비용`](requirements.md#실행-비용), [`유지해야 할 동작`](requirements.md#유지해야-할-동작), [`완료 증거`](requirements.md#완료-증거)

**선행 작업:** 네 표제어의 활용형 탐지 구현, 도움말 mode 구현

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- 기준 초과가 JSON 제한 과정에서 확인된 경우에만 `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 변경 전과 변경 후 측정값을 같은 조건에서 비교한다.
2. 모든 기준을 만족하면 현재 첫 단위 색인, NFD 검색과 정렬 방식을 유지하고 알고리즘 변경을 끝낸다.
3. 기준 초과가 재현되면 정렬된 일치 흐름 병합과 경고 상한 이후의 일치 보관 축소를 적용한다.
4. 개선안이 결과 동일성을 어기면 채택하지 않는다. 다른 입력군의 실행 시간과 peak RSS가 나빠지면 수치와 영향을 제시하고 성능 예산을 정할 담당자의 판단을 받는다.

**통합 검증에서 확인할 근거:** 알고리즘을 유지한 경우 기준 충족 측정값이 있고, 바꾼 경우에는 같은 JSON 결과와 재현 가능한 시간 또는 peak RSS 개선이 함께 있다.

### 통합 검증

**목표:** 기존 개발 지침을 적용해 형태 matcher, 도움말, 검색 비용과 유지 동작을 함께 판정한다.

**요구사항:** [`유지해야 할 동작`](requirements.md#유지해야-할-동작), [`완료 증거`](requirements.md#완료-증거)

**선행 작업:** 네 표제어의 활용형 탐지 구현, 도움말 mode 구현, 측정 결과에 따른 검색 비용 개선

**대상 파일:**

- `skills/use-better-terms/scripts/korean-expressions.mjs`
- `skills/use-better-terms/scripts/scan.mjs`

**작업 내용:**

1. 자체 검사가 운영 parser, 형태 matcher, literal 탐색, NFD 위치 계산, 직렬화와 자식 process의 stream 및 상태를 직접 실행하는지 확인한다.
2. 여섯 재현 입력, 대표 활용형, 부정 사례와 중의적 사례의 rule ID, expression 및 UTF-16 위치를 대조한다.
3. 기존 입력 mode, 오류 형식, JSON 구조, 겹치는 일치, 결과 순서와 상한을 변경 전 기준과 대조한다.
4. 측정 입력과 결과 동일성 조건을 확인하고 검색 방식을 유지할지 국소 개선을 적용할지 판정한다.

**통합 검증에서 확인할 근거:** `node skills/use-better-terms/scripts/scan.mjs --self-test`, 저장소 ESLint, 대표 자식 process 실행과 변경 전후 JSON 대조가 모두 통과한다. 외부 package, 네트워크 접근, 새 배포 파일, 외부 필드와 개인 위치가 변경에 포함되지 않는다.

## 실행 중단 조건

다음 중 하나가 확인되면 영향을 받는 작업을 멈추고 요구사항 또는 결정 담당자의 판단을 받는다.

- 네 표제어의 요구된 활용을 찾으려면 외부 형태 분석기, 새 runtime dependency 또는 외부 JSON 필드가 필요하다.
- `박다`와 `박히다`가 하나의 안내를 공유하면 실제 검토 질문이나 유지 조건이 서로 충돌한다.
- 기존 경고의 rule ID, expression, UTF-16 위치, 겹치는 일치, 결과 순서 또는 전체 count를 바꾸지 않고는 matcher를 연결할 수 없다.
- 도움말을 독립 mode로 두는 선택이 확인된 호출자나 자동화와 충돌한다.
- 성능 개선이 결과 동일성을 깨거나 다른 입력군의 실행 시간 또는 peak RSS를 나쁘게 만든다.
- 실행 시간 또는 peak RSS의 절대 예산이 있어야만 다음 선택을 할 수 있다.
- 기존 개발 지침을 적용하려면 이번 작업과 무관한 저장소 정책을 바꿔야 한다.

현재 확인된 착수 차단 사항은 없다.

## 완료 조건

- 네 표제어와 계획에 포함한 활용형이 올바른 사용자 진단 및 원본 위치에 연결된다.
- 확실한 비표제어는 제외되고 중의적 용례와 물리적 `박다`는 공통 판정 절차에 남는다.
- `--help`가 정한 호출 설명을 정상 출력하며 다른 입력 및 기존 오류 동작은 유지된다.
- 성능 변경 여부가 같은 입력과 결과를 사용한 시간 및 peak RSS 측정으로 결정된다.
- 기존 JSON 구조, 출력 순서, 상한, 오류 형식, 외부 package 없음과 네트워크 없음이 유지된다.
- 적용되는 개발 지침에 따라 각 작업 단위의 완료 근거를 확인할 수 있다.
