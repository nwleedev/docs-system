# `use-better-terms` 표현 탐지, 도움말과 성능 요구사항

## 목표

`use-better-terms` 검사기는 활용이나 문장 형태가 달라져도 같은 판정 기준으로 검토해야 할 한국어 표현을 찾아야 한다. 이번 변경에서는 `좁다`, `좁히다`, `박다`와 `박히다`의 탐지 누락을 보완한다. 이 네 표제어를 포함해 검사기가 알린 모든 표현에는 현재 `use-better-terms`의 공통 판정 절차를 적용한다. `--help`를 입력하면 사용자가 세 입력 방식과 자체 검사 호출법을 이해할 수 있는 설명을 제공해야 한다. 표현 수와 입력 크기가 늘어날 때의 실행 비용을 분석하고, 불필요한 반복 탐색이 확인되면 기존 탐지 결과를 유지하는 방식으로 개선해야 한다.

이 문서는 검사기 구현 담당자가 후속 변경의 범위와 완료 증거를 정할 때 사용하는 요구사항이다. 검사기, Skill 지침과 개발 지침은 변경하지 않는다.

## 공통 판정 절차

검사기가 알린 모든 표현은 [`use-better-terms` Skill](../../../skills/use-better-terms/SKILL.md)과 [한국어 글과 문구 판정 기준](../../../skills/use-better-terms/references/korean.md)에 따라 검토한다. 작성자는 경고가 나온 표현마다 실제 문맥에 맞는 자연스러운 대체 문장을 먼저 만들고, 확인된 근거만으로 뜻을 보존할 수 있으면 같은 작업 단위에서 적용한다. 원문은 확립된 용어, 승인된 이름, 코드 식별자, 필요한 표기이거나 검토한 대안보다 가장 정확한 표현일 때만 유지하며, 검토한 대안과 유지 근거를 기록한다.

이 절은 네 표제어에만 적용할 새 기준을 정하지 않는다. 네 표제어는 공통 판정 절차가 적용될 수 있도록 이번 변경에서 탐지 범위를 보완할 사례다. 후보 발견은 자동 실패나 문맥을 무시한 자동 치환을 뜻하지 않는다.

## 표현 탐지

검사기는 `좁다`, `좁히다`, `박다`와 `박히다`의 활용형을 모두 검토 대상으로 삼는다. 네 표제어의 탐지 범위는 [네 표제어의 탐지 범위](decisions/korean-lexeme-review-purpose.md)에 기록한다. 발견된 표현의 교체 또는 유지 여부는 특정 표제어에만 별도 기준을 두지 않고 [공통 판정 절차](#공통-판정-절차)에 따라 정한다.

판정 자료는 작성자가 원문에서 가리키는 상태나 행동을 확인하고 공통 판정 절차를 수행할 수 있게 해야 한다.

검사기는 다음 입력에서 문제 후보가 있는 정확한 표현 위치를 찾아야 한다.

- `좁다`
- `좁은 변경이다`
- `좁혔다`
- `범위가 좁았습니다.`
- `코드를 박지`
- `목표를 박음`

`박히다`의 대표 활용형도 같은 방식으로 원본 위치와 판정 자료에 연결되어야 한다.

문장에 다른 후보 표현이 함께 있어도 그것을 찾은 결과로 완료를 판정하지 않는다. 예를 들어 `범위가 좁았습니다.`에서는 `범위` 경고와 별도로 `좁았습니다`가 `좁다` 계열의 판정 자료에 연결되어야 한다.

제시된 사례 이외에도 현재 방식이 놓칠 수 있는 활용형, 파생형과 표기 형태를 조사한다. 조사 결과는 현재 탐지되는 형태, 탐지되지 않는 형태, 같은 규칙으로 다룰 근거, 정상 용례가 함께 잡힐 위험과 구현 선택이 필요한 사항을 구분해야 한다.

## 명령줄 도움말

`node skills/use-better-terms/scripts/scan.mjs --help`는 검사기를 실행하지 않고 호출 방법을 설명해야 한다. 설명만 읽어도 다음 실행 형태와 각 option의 관계를 구분할 수 있어야 한다.

- `--changed <repo>`
- 하나 이상 반복하는 `--file <path>`
- `--stdin --source-name <name>`
- `--self-test`
- `--help`

도움말은 `codex --help`처럼 usage, option 이름, 필요한 값과 각 option의 역할을 한 출력에서 확인할 수 있어야 한다. 도움말과 다른 option을 함께 입력했을 때의 처리, 짧은 option `-h`의 제공 여부와 문안은 조사 결과를 바탕으로 결정해야 한다.

## 실행 비용

현재 반복문의 모양만으로 제곱 시간이라고 단정하지 않는다. 입력의 UTF-16 길이, 규칙과 표현 수, 표현 길이, NFD 매칭 표현 수와 총 일치 수를 각각 변수로 두고 현재 탐색, 원본 위치 변환, 정렬과 결과 조립의 시간 및 공간 비용을 분석해야 한다.

후속 구현은 현재 방식과 대안을 같은 입력과 같은 출력 조건에서 측정할 수 있어야 한다. 측정 자료에는 후보가 없는 긴 입력, 같은 첫 글자로 시작하는 표현이 많은 입력, NFD 후보가 많은 입력, 겹치는 일치가 많은 입력과 경고 상한을 넘는 입력이 포함되어야 한다. 측정 결과 없이 중첩 반복문을 없애는 것 또는 특정 문자열 검색 알고리즘을 채택하는 것을 완료로 판정하지 않는다.

## 유지해야 할 동작

이번 요청이 변경하지 않은 검사기 동작은 유지한다. 구체적인 기준은 [한국어 문서 검토 재발 방지 요구사항](../korean-writing-review-6f3a/requirements.md), [한국어 스캐너 활용형 탐지와 대체 표현 제안 요구사항](../korean-scanner-coverage-9b4e/requirements.md)과 [Node.js MJS 명령줄 검사기](../../dev/node/mjs-cli.md)에 따른다.

- Node.js 표준 기능만 사용하고 배포되는 Skill에 외부 package와 실행 중 네트워크 요청을 추가하지 않는다.
- 기존 `--changed`, `--file`, `--stdin`, `--source-name`과 `--self-test` 입력의 의미를 바꾸지 않는다.
- `sources`와 두 `checks`, 각 검사의 `catalog`, `rules`, `warnings`와 `summary`를 포함한 JSON 결과 형식, 원본 UTF-16 위치, 겹치는 출현과 결정적인 결과 순서를 유지한다.
- 후보 발견은 자동 실패나 자동 수정 명령이 아니며, 판정 자료와 원문의 문맥을 읽는 절차를 유지한다.

## 완료 증거

- 여섯 재현 입력과 `박히다`의 대표 활용 입력을 각각 검사했을 때 의도한 규칙이 문제 후보 표현의 원본 UTF-16 위치를 보고한다.
- `좁다`, `좁히다`, `박다`와 `박히다`의 탐지 결과에도 다른 모든 경고와 같은 공통 판정 절차가 적용된다.
- 네 표제어만을 위한 별도 교체 또는 유지 기준을 도입하지 않았음을 요구사항과 결정 기록에서 확인할 수 있다.
- 추가 누락 가능성과 정상 용례의 오탐 위험이 공식 자료, 현재 코드와 재현 결과를 근거로 문서화되어 있다.
- `--help` 실행은 호출법을 사람이 읽을 수 있는 형태로 제공하며 정상 도움말 실행과 잘못된 인수 실행을 구분할 수 있다.
- 현재 구현의 복잡도 식과 병목 후보, 대안의 비용, 비교 측정 입력 및 판정 방법이 문서화되어 있다.
- 후속 구현에서 기존 자체 검사와 저장소 검사를 통과하고, 변경 전후 대표 입력의 JSON 구조 및 경고 위치가 대조되어 있다.

## 결정이 필요한 질문

- `좁다`와 `좁히다`가 하나의 rule ID, 검토 질문과 안내 문구를 공유할지, 표제어마다 나눌지 결정해야 한다.
- `박다`와 `박히다`가 하나의 rule ID, 검토 질문과 안내 문구를 공유할지, 표제어마다 나눌지 결정해야 한다.
- 네 표제어의 활용형을 찾기 위해 제한된 어미 분류, 검증한 융합형과 형태 조건을 어떤 내부 자료로 나타낼지 결정해야 한다.
- `--help`를 다른 option보다 우선할지, 다른 option과 함께 쓰면 사용 오류로 처리할지 결정해야 한다.
- `-h`를 `--help`와 같은 기능으로 제공할지 결정해야 한다.
- 현재 규칙 수와 입력 상한에서 허용할 실행 시간 및 메모리 기준과, 기준을 넘었을 때 채택할 검색 방식을 결정해야 한다.
