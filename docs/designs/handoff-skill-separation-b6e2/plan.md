# 인수인계 스킬 신설과 표현 스킬 조정 계획

`use-better-handoff`에 인수인계 정보의 배치와 파일 관리를 맡기고, `use-better-terms`에는 표현과 언어 검사를 남긴다. 규칙을 관리할 파일과 읽는 조건을 먼저 정하고 의미 중복을 줄인다. 기본 또는 사용자 지정 인수인계 파일에서 같은 동작을 수행하는지 확인한다.

기준은 [인수인계 파일의 지정](./requirements.md#인수인계-파일의-지정), [인수인계 정보 보관](./requirements.md#인수인계-정보의-보관), [참조 방향과 프로젝트 파악](./requirements.md#참조-방향과-프로젝트-파악), [두 스킬의 책임](./requirements.md#두-스킬의-책임), [스킬의 작성 언어](./requirements.md#스킬의-작성-언어), [다양한 상황의 인식](./requirements.md#다양한-상황의-인식), [마크다운 구성과 실행 성능](./requirements.md#마크다운-구성과-실행-성능)과 [확인할 결과](./requirements.md#확인할-결과)다. [구성 근거](./references/handoff-workflow-research.md)는 현재 자료와 공식 지침을 대조한 분석이며, 새 스킬의 실행 성과를 뜻하지 않는다.

이번 실행안은 `skills/`의 연구 자료와 필요한 호출 및 설치 안내를 조정하는 범위다. 개인 환경에 설치된 스킬을 변경하거나 이 저장소에 운영용 `HANDOFF.md`를 생성하는 작업은 포함하지 않는다. 스크립트, 테스트 코드와 외부 패키지를 새로 만들지 않는다.

## 실행 상태

1. 규칙 분류와 파일별 책임: 완료. [규칙 이관과 보존 기준](./references/handoff-behavior-cases.md#규칙의-이관과-보존)에 기존 절별 처리와 읽는 조건을 기록했다. 세 검사 스크립트는 변경 대상에서 제외했다.
2. 인수인계 스킬 구성: 작성 완료. [본문](../../../skills/use-better-handoff/SKILL.md)에 파일 선택, 보관과 읽기 및 갱신을, [사례](../../../skills/use-better-handoff/references/examples.md)에 여섯 상황의 대조를 작성했다. 최종 적용 확인은 5단계에서 수행한다.
3. 표현 스킬 조정: 작성 완료. [본문](../../../skills/use-better-terms/SKILL.md)에 공통 판정과 상태 정의를 모으고, [한국어 자료](../../../skills/use-better-terms/references/korean.md)의 설명을 영어로 작성했다. [한국어 자료의 기준 보존](./references/handoff-behavior-cases.md#한국어-자료의-기준-보존)을 별도로 대조했다. 내용 선정 파일을 제거했고 기존 검사 스크립트는 변경하지 않았다. 삭제된 자료를 가리키는 연결은 4단계에서 정리한다.
4. 호출과 설치 안내: 작성 완료. `src/AGENTS.en.md`, `src/AGENTS.ko.md`와 두 README에 선택 가능한 호출 절과 순서를 반영했다. 삭제된 내용 선정 자료의 문서 링크를 이관 위치로 바꾸고 이전 적용 기록에는 당시 구성임을 표시했다.
5. 적용과 비용 확인: 완료. 두 독립 묶음 52건과 보완 후 재적용 1건, 같은 표현 스킬을 고정한 수동 대조 4쌍을 확인했다. [적용 관찰](./references/handoff-behavior-cases.md#실제-적용-관찰)과 [분량 및 읽은 자료](./references/handoff-behavior-cases.md#분량과-읽은-자료)에 최초 오류, 보완, 기존 표현 판단과 비교의 한계를 기록했다. 기존 검사기의 자체 검사와 Ruby의 YAML 확인은 통과했다. 기본 Python 검증기는 PyYAML 부재로 실행하지 못했으며 패키지는 추가하지 않았다.

다섯 단계를 완료했다. 표현 스킬은 마크다운 32,434바이트에서 15,980바이트로 줄었고 세 검사 스크립트는 유지됐다. 실제 설치 환경과 운영용 인수인계 파일은 변경하지 않았다. 적용 관찰과 한계를 문서에 남겼으며 임시 적용 자료는 정리했다. 최종 마크다운 20개의 상대 링크 136개, 공백과 민감정보 확인을 마쳤다.

5단계에서 축약안이 발표문의 금액 조건과 별도 표의 지연 시간을 같은 주장으로 취급해 금액 설명을 바꾼 사례를 확인했다. 서로 다른 주장의 자료를 근거로 교정하지 않도록 인수인계 판단을 보완했다. 원문으로 시작한 별도 입력에서는 금액 설명, 발표 지시와 CSV가 유지됐다. 최초 관찰과 보완 후 관찰은 구분해 기록했다.

## 1. 규칙을 분류하고 파일별 책임과 읽는 조건을 정한다

[파일별 구성 제안](./references/handoff-workflow-research.md#각-스킬의-파일별-내용-제안)에 따라 새 스킬은 `SKILL.md`와 조건부 사례 자료 `references/examples.md`로 구성한다. 표현 스킬에는 `SKILL.md`, 한국어 자료와 공통 사례를 유지하되 내용 선정 자료의 책임을 이관한다. 기존 검사 스크립트는 바꾸지 않는다.

두 스킬의 `SKILL.md`와 모든 마크다운 참고 자료에는 표를 사용하지 않는다. 내용은 소제목, 문단과 목록으로 구성한다.

두 스킬의 `description`, 본문, 참고 자료의 지침과 판정 설명을 영어로 작성한다. [영어 작성 기준](./references/handoff-workflow-research.md#스킬을-영어로-작성하는-기준)에 따라 필요한 조건을 명시하고 관용구와 문화에 의존하는 예시는 피한다. 언어 자체를 판단하는 예문과 정확한 인용은 원어를 유지한다. 스킬의 작성 언어를 결과물이나 인수인계 기록의 언어를 바꾸라는 지시로 확장하지 않는다. 이 설계 문서와 기존 한국어 및 영어 설치 안내의 언어는 유지한다.

[상황별 조사](./references/handoff-situation-research.md)를 바탕으로 화면과 디자인 시안, 기술 문서, 코드와 API 설명, 측정 보고서, 설치 및 운영 안내, 발표 자료와 표 계산 문서의 사례를 보강한다. 유형마다 작성자나 검토자를 위한 부연과 독자가 과제를 수행하거나 사실을 해석하는 데 필요한 설명을 함께 찾는다. 현재 목록에 없는 사례를 발견하면 자료의 역할과 판정 차이를 확인해 조사 자료에 추가한다.

각 사례에는 원문과 출처, 설명 대상, 그 설명이 필요한 독자와 행동, 작성 위치, 이동 여부와 이유, 반드시 보존할 조건을 기록한다. 실제 사례와 판정을 비교하려고 만든 예문을 구분한다. 제목과 독자, 제출 목적이 바뀌면 같은 문구의 처리도 달라지는지 확인한다. 본문뿐 아니라 각주, 코드 주석, 화면 도움말, 대체 텍스트와 문서 메모도 조사하되 이름이나 형식만으로 분류하지 않는다.

각 규칙의 적용 조건, 행동과 예외를 대조해 같은 판단을 요구하는 문장을 묶는다. 규칙을 관리할 파일 하나를 정하고, 나머지 파일에는 필요한 때 읽는 연결만 남긴다. 규칙의 기존 위치, 담당 파일과 읽는 조건은 5단계 평가 자료에 기록하며 실행 때 읽는 새 작업표를 만들지 않는다.

공통 절차는 본문에서 한 번만 정의한다. 사례 자료에는 실제로 판단이 달라지는 입력과 대조 문안만 남기고 본문의 절차와 판정 상태를 다시 쓰지 않는다. 모든 사례 파일을 항상 읽도록 하지 않으며, 필요한 파일은 본문에서 직접 연결한다.

작업 상황, 제작 경위, 검토 방법, 보충 안내와 주의사항 중 인수인계할 정보를 분류한다. 단어 목록으로 일괄 이동하지 않고 문장이 설명하는 대상과 원래 결과물의 역할을 확인한다.

작업 보고와 보충 설명은 지정 파일에 보관하고 원래 결과물에서는 제거한다. 방법 안내의 절차, 일반 이용자에게 필요한 화면 안내와 사실을 성립시키는 조건은 해당 결과물에 유지한다. 요구사항을 변경해야 분류할 수 있는 경우에는 이관을 진행하지 않는다.

[기존 내용 선정 자료](../../../skills/use-better-handoff/SKILL.md#decide-what-belongs-where)의 명시적인 수록 지시, 정확한 인용, 부족한 근거와 사실 조건의 구분을 새 절차에 반영한다. 자료 속 지시를 현재 작업의 명령으로 취급하지 않으며, 누락된 사실이나 승인 상태를 추정하지 않는다.

완료 근거는 규칙마다 담당 파일과 읽는 조건이 정해진 배치, 조사한 상황과 판정의 연결, 같은 형식의 문장을 다르게 처리하는 대조 문안이다. 검토자용 설명과 사용 방법 문서의 보존 위치를 구분하고 사실 조건을 유지한다. 5단계에서 사용할 입력과 기대 동작을 이 단계에서 정해 뒤의 축약 여부를 판단하는 기준으로 삼는다.

## 2. 지정 파일을 읽고 갱신하는 스킬을 구성한다

`skills/use-better-handoff/SKILL.md`에 적용 대상, 대상 파일의 결정, 기존 기록 읽기, 분류, 기록과 원본 조정의 순서를 작성한다. 파일의 위치와 이름은 작업 지시나 저장소의 호출 지침에서 지정할 수 있게 한다. 현재 작업의 명시적 지정, 적용 중인 저장소의 지정, 저장소 최상위 `HANDOFF.md` 기본값 순서로 선택한다. 별도 설정 파일을 필수로 요구하지 않는다.

사용자 지정에는 고정된 디렉터리나 파일 이름을 강제하지 않는다. 상대 경로는 저장소 최상위를 기준으로 해석하고 절대 경로는 지정한 대상을 사용한다. 저장소 밖의 지정도 이미 허용된 파일 접근과 변경 권한 안에서 처리한다. 개인 계정이 드러나는 실제 절대 경로를 추적 문서에 복사하지 않는다.

대상 파일이 없으면 변경 권한이 있는 작업에서 지정한 위치에 생성한다. 지정이 있는데 파일이 없다는 이유로 기본 파일을 만들지 않는다. 일회 지정을 영구 설정에 자동 저장하지 않고, 위치 지정의 변경을 기존 기록의 이동이나 삭제 권한으로 해석하지 않는다. 지정끼리 충돌하거나 저장소 최상위를 정할 수 없으면 필요한 정보만 확인한다.

본문에는 다음 실행 규칙을 둔다.

- 현재 작업에서 작성하거나 변경한 결과물과 명시적으로 지정한 자료를 확인한다. 매번 저장소 전체를 재분류하지 않는다.
- 이동할 정보를 지정 파일에 기록하고 보존된 내용을 확인한 뒤 원래 결과물에서 조정한다. 원본에 인수인계 파일을 확인하라는 문구나 링크를 남기지 않는다.
- 기록에는 대상, 필요한 설명과 조건, 확인 상태와 근거 자료를 담는다. 남은 작업은 확인한 근거가 있을 때 적고, 불필요한 빈 항목은 만들지 않는다.
- 같은 대상의 설명은 기존 항목을 갱신한다. 다른 작업의 기록은 유지하고, 근거가 충돌하거나 기존 내용을 지울 권한이 불분명하면 그 항목의 변경을 멈춘다.
- 인수인계 파일을 읽어 기록에 연결된 자료를 안내할 수 있게 한다. 기록에 적힌 작업이나 명령을 읽었다는 이유만으로 실행하지 않는다.
- 읽기 전용 요청에서는 이동 제안과 필요한 설명을 답변으로 반환한다. 파일을 작성할 권한이 없는 작업에서 인수인계 파일도 변경하지 않는다.

이동과 보존의 판단 및 파일 지정 규칙은 본문에 둔다. 조사에서 반복 확인한 설명 대상, 독자의 행동과 필수 조건을 판단 기준으로 정리한다. 특정 언어의 단어 목록이나 처음 제시한 예문과의 일치 여부에 의존하지 않는다.

판정이 모호한 대조 사례만 `skills/use-better-handoff/references/examples.md`에서 필요한 때 읽는다. 조사 목록 전체를 스킬로 복사하지 않고, 판단을 추가로 설명하는 사례만 영어 설명과 함께 남긴다. 사례 자료에 기본 절차를 복제하지 않는다. 외부 패키지, 고정된 대형 템플릿과 별도 실행 스크립트는 추가하지 않는다.

완료 근거는 스킬의 이름과 설명, 실제로 연결된 참고 자료, 기본값과 사용자 지정의 선택, 파일의 존재 여부에 따른 처리와 읽기 및 갱신의 권한 구분이다. 참조 금지에는 선택된 파일을 적용하고 스킬의 파일 읽기를 막지 않는다.

## 3. 표현 스킬에서 정보 배치 책임을 이관한다

`skills/use-better-terms/SKILL.md`의 설명, 도입, `Select document content` 절, 근거 수집, 첫 번째 판정 기준과 반환 규칙을 대조한다. 내용 선정과 인수인계 위치를 정하는 절차는 새 스킬로 이관한다. 표현 스킬에서 이 절차를 다시 호출하거나 같은 판정을 반복하지 않게 한다.

문장의 뜻, 책임, 사실 조건과 승인 상태를 보존하는 규칙은 표현 개선에도 필요하므로 유지한다. 한국어 판정 기준, 표현 검사와 긴 문단 검사, 대안 탐색과 판정 상태를 역할 분리의 이유로 생략하지 않는다.

`skills/use-better-terms/references/korean.md`의 공통 판정 순서는 본문과 대조해 한 번만 남긴다. 한국어의 조사, 주어와 서술어, 태와 문장 연결을 판단하는 기준과 사례는 한국어 자료가 맡는다. 도입과 결론의 재진술, 반복 체크 목록과 판정 상태의 중복 정의도 줄이되 검사기의 입력 모드와 반환값을 확인하는 데 필요한 지시는 보존한다.

한국어 자료의 제목, 판정 기준과 이유를 영어로 다시 작성하되 판단에 필요한 한국어 문장, 조사와 대조 예문은 보존한다. 영어 설명만 읽고도 어떤 차이를 확인하는지 알 수 있게 한다. 번역하면서 조건, 책임과 판정 상태를 바꾸거나 한국어 문구의 차이를 영어 예문으로 대체하지 않는다.

`skills/use-better-terms/references/examples.md`에서 파일 간 정보 배치 예시는 새 담당 자료로 옮기고, 단어와 문장 관계를 설명하는 예시는 유지한다. `references/document-content.md`는 사용 중인 참조를 먼저 확인한 뒤 새 자료와 역할이 겹치지 않도록 정리한다. 파일이나 절을 없애면 영향을 받는 연결만 고치며, 과거 설계의 판단과 실행 결과는 다시 쓰지 않는다.

완료 근거는 정보 배치와 언어 공통 판정 규칙이 각각 한곳에서 관리되고 기존 표현 검사가 유지되는 구성이다. 각 마크다운의 전체 크기와 실제 읽는 본문 분량은 5단계에서 구분해 비교한다. 줄 수를 줄이기 위해 조건과 예외를 생략하거나 여러 문장을 읽기 어려운 한 문장으로 압축하지 않는다.

## 4. 호출 순서와 설치 안내를 맞춘다

`src/AGENTS.ko.md`와 `src/AGENTS.en.md`에 인수인계 스킬의 적용 조건과 표현 검토에 앞서는 순서를 같은 뜻으로 작성한다. 결과물을 작성하거나 조정하는 단계에서 인수인계 정보를 배치하고, 공유할 결과물과 인수인계 파일을 묶어 기존 표현 검토를 한 번 실행하도록 한다. 두 스킬이 서로를 반복 호출하는 구조를 만들지 않는다.

호출 조건을 역할에 맞게 짧게 쓰고 두 스킬의 설명에 같은 작업을 넓게 나열하지 않는다. 인수인계 파일의 지정 값은 호출 지침에서 전달할 수 있게 하며, 설명과 설치 안내에 기본 이름을 필수 파일명으로 적지 않는다.

일반 채팅만을 이유로 파일을 만들거나 작업 보고를 계속 누적하지 않는다. 파일을 읽고 파악하는 요청과 파일을 갱신하는 요청의 차이를 호출 지침에도 유지한다. 상세 분류와 갱신 절차는 호출 지침에 복사하지 않는다.

`README.md`와 `README.ko.md`에는 새 스킬의 역할, 선택할 디렉터리와 함께 복사할 호출 절을 추가한다. 참고 자료가 있는 `skills/`와 도구가 실제로 읽는 설치 위치를 구분한다. 기존 설치 환경을 자동으로 변경하거나 별도 설치 프로그램을 만들지 않는다.

완료 근거는 두 언어에서 일치하는 실행 조건과 순서, 스킬 디렉터리와 호출 절을 함께 선택할 수 있는 설치 안내다. 안내 문서가 역할을 설명하는 것과 실제 결과물에서 인수인계 파일로 독자를 보내는 것을 구분한다.

## 5. 같은 입력에서 동작과 문맥 비용을 비교한다

`references/handoff-behavior-cases.md`에 입력, 필요한 근거, 기대되는 보관 위치와 실제 결과를 기록한다. 실제 적용 전에는 결과를 채우거나 통과했다고 적지 않는다. 평가용 문안과 임시 작업 파일은 `temps/` 아래의 작업별 디렉터리에서 사용하고 완료 뒤 제거한다.

대표 입력은 1단계에서 조사한 각 상황에 연결한다. 인수인계할 부연과 원래 자료에 유지할 설명을 짝지어 확인하며, 필수 경고, 측정 조건, 접근성 안내와 API 사용 조건을 옮겨 버리는 오류도 기록한다. 기존 기록을 다시 갱신하는 경우와 읽기 전용 요청도 확인한다. 같은 설명이 반복됐을 때 중복이 늘지 않는지 살핀다.

스킬에 실은 예문의 재현에 그치지 않고 새로운 표현, 위치와 문서 목적을 조합한 입력도 사용한다. 영어, 한국어, 조사에서 확보한 다른 언어와 언어가 섞인 사례를 포함한다. 언어별 확인 결과를 구분하며 확인하지 않은 언어까지 동일하게 작동한다고 주장하지 않는다. 인수인계 기록과 원래 자료의 언어가 영어로 강제 변환되지 않는지도 확인한다.

파일 지정은 생략, 이름만 변경, 위치만 변경, 둘 다 변경, 지정 파일의 신규 생성으로 나눠 확인한다. 하위 디렉터리에서 시작한 상대 경로와 명시적으로 허용한 절대 경로도 포함한다. 선택하지 않은 기본 파일이 생성되거나 갱신되지 않아야 한다. 참조 검사는 `HANDOFF.md`라는 문자열에 한정하지 않고 실제 선택한 파일과 그 연결을 확인한다.

실제 결과물에는 인수인계 대상 설명과 파일을 열라는 대체 안내가 없어야 한다. 지정 파일에는 옮긴 설명과 유효한 연결이 남아야 하며, 필요한 기능과 사실 조건은 원래 결과물에 유지돼야 한다. 스킬을 직접 지정하지 않은 작성 요청에서도 선택되는지 관찰하되, 한 번 선택됐다는 사실을 매번 호출된다는 뜻으로 확대하지 않는다.

기존 표현 스킬에서는 보호할 판정과 대안 적용을 확인한다. 새 인수인계 기능의 비용까지 기존 구성과 단순 비교하지 않는다. 분량 최적화는 같은 기능과 같은 기대 동작을 가진 새 구성의 초안과 축약안을 비교한다.

비교할 때 모델과 설정, 요청, 초기 자료, 도구와 권한을 같게 둔다. 과제 완수, 필요한 조건의 보존, 호출 누락, 불필요한 호출과 재작업을 기록한다. 스킬 이름을 명시한 입력과 명시하지 않은 입력, 실행하지 않아야 하는 일반 채팅을 구분한다.

비용은 전체 마크다운의 줄 수와 바이트 수, 실제 읽은 파일과 본문 분량, 도구 출력과 제공되는 토큰 수를 구분한다. 입력 및 출력 토큰을 확인할 수 없으면 그 값을 추정 절감률로 바꾸지 않는다. 파일 수가 줄었다는 이유만으로 문맥 비용이 줄었다고 판단하지 않는다.

이동, 보존과 표현 검사를 모두 만족하는 안에서 불필요한 읽기와 재작업이 줄었는지 확인한다. 축약 뒤 판정이 달라지면 없앤 조건이나 사례가 원인인지 확인하고 필요한 부분만 복원한다. 마크다운을 짧게 만드는 일 자체를 완료 조건으로 삼지 않는다.

완료 근거는 영어로 작성된 스킬 지침, 파일의 이동 전후 내용, 기존 기록의 보존과 갱신, 조사 상황별 인식과 보존 결과, 규칙별 담당 위치, 실제 읽은 스킬과 참고 자료, 같은 조건에서의 비교 기록이다. 문서의 지침이 존재한다는 사실만으로 동작 확인을 대신하지 않는다.

## 완료 확인과 중단 조건

1단계에서 규칙의 담당 위치와 평가 기준을 정하고 2단계와 3단계에서 스킬을 조정한다. 이후 4단계의 호출과 설치 안내를 맞추고 5단계에서 동작과 비용을 비교한다. 중복을 줄이는 상세 기준은 [의미 중복 판정 방법](./references/handoff-workflow-research.md#의미-중복을-판정하는-방법)을 적용한다.

적용할 개발 지침은 [docs/dev/README.md](../../dev/README.md)다. 이번 실행안에는 소스 코드나 검사 설정 변경이 없으므로 MJS 검사기의 구현 지침을 새로 적용하지 않는다. 기존 `use-better-terms` 검사 스크립트는 최종 공유 단위의 표현 검사에 그대로 사용한다. 파일 형식, 상대 링크, 공백과 민감정보 확인도 최종 변경 묶음에서 수행한다.

스킬의 형식이나 필요한 참고 자료를 확인할 수 없거나, 설명을 옮기는 일이 기능, 접근성 또는 필수 문서 내용을 바꾸는 경우에는 관련 변경을 멈춘다. 기존 기록과 근거가 충돌하는 경우도 임의로 어느 한쪽을 덮어쓰지 않는다. 새로운 코드, 외부 의존성 또는 전역 설정 변경이 필요해지면 현재 실행안의 범위에서 진행하지 않는다.

완료 시에는 요구사항의 각 확인 결과를 실제 근거와 연결한다. 검토는 최종 변경 묶음에서 한 번 수행한다. 평가 자료 자체가 요청된 기록인 경우와 일반 결과물에 부연 보고를 덧붙이는 경우를 구분한다.
