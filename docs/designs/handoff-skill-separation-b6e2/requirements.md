# 인수인계 기록과 표현 검토를 분리하는 요구사항

`use-better-handoff`는 작업 보고, 안내사항, 지침과 주의사항을 찾아 지정된 인수인계 파일에 보관한다. `use-better-terms`는 표현 검사, 언어 검사와 자연스러운 대체 표현의 적용을 맡는다. 두 책임을 분리해 스킬의 역할을 분명하게 하고 기존 표현 스킬의 크기를 줄인다.

## 인수인계 파일의 지정

기본 파일은 레포 최상위의 `HANDOFF.md`다. 사용자는 파일의 위치와 이름을 자유롭게 지정할 수 있다. 보관, 읽기, 갱신과 일반 결과물의 참조 금지에는 기본 이름이 아니라 실제로 지정한 파일을 적용한다.

## 인수인계 정보의 보관

문서, 코드, 웹 페이지와 보고서 등 결과물에 섞이는 작업 보고와 보충 설명은 삭제하는 대신 지정된 인수인계 파일에서 관리한다. 디자인 시안을 이해하는 데 도움이 되는 동작 설명도 인수인계 정보로 활용할 수 있어야 한다.

인수인계 대상에 해당하는 설명은 지정 파일에만 보관한다. 일반 결과물에 같은 설명을 남기거나 인수인계 파일을 열어 보라는 문구로 대체하지 않는다.

## 참조 방향과 프로젝트 파악

일반 문서, 코드와 웹 페이지는 지정된 인수인계 파일을 참조하거나 열어 보도록 안내하지 않는다. `use-better-handoff`는 이 파일을 읽고 갱신할 수 있어야 한다.

인수인계 파일은 관련 코드와 문서를 참조하고 프로젝트를 파악하는 진입점으로 작동한다. 인수인계 스킬이 사용하는 파일 지정과 일반 결과물의 안내 문구를 같은 금지 대상으로 취급하지 않는다.

## 두 스킬의 책임

`use-better-handoff`는 인수인계할 설명을 찾고 관련 파일을 조정하는 절차를 맡는다. `use-better-terms`에 같은 내용 선정 절차를 중복해서 남기지 않는다.

`use-better-terms`는 기존 표현 검사와 언어 검사를 유지하고, 확인한 뜻을 보존하는 자연스러운 표현을 찾아 개선한다. 역할 분리를 이유로 기존 표현 검사를 약화하지 않는다.

매번 같은 프롬프트를 입력하는 대신 재사용할 수 있는 스킬로 구성한다. 이 저장소의 `skills/`가 다른 프로젝트에서 선택하고 수정해 쓰는 연구 자료라는 성격은 유지한다.

## 스킬의 작성 언어

전 세계 사용자가 활용할 수 있도록 `use-better-handoff`와 `use-better-terms`는 영어로 작성한다.

## 다양한 상황의 인식

`use-better-handoff`가 안내형 문구, 주의사항, 지침과 작업 보고를 더 다양한 상황에서 인식할 수 있도록 조사한다. 처음 제시한 예시에 한정하지 않고 조사한 상황을 스킬의 판단 기준과 사례에 반영한다.

## 마크다운 구성과 실행 성능

각 스킬의 파일과 내용 구성을 조사하고 플랜의 실행 절차에 반영한다. 스킬 안의 마크다운 파일에서 같은 뜻의 규칙과 겹치는 설명이 반복되지 않게 한다.

마크다운 분량과 토큰 소모를 줄이면서 스킬이 의도한 작업을 수행하는 성능을 높인다. 인수인계 정보를 보관하는 동작과 기존 표현 검사는 유지한다.

## 확인할 결과

- 파일 지정을 생략하면 기본 파일을 사용하고, 위치나 이름을 지정하면 그 파일을 사용한다.
- 두 스킬의 설명과 실행 지침에서 인수인계 정보의 배치와 표현 개선을 각각 맡는다는 사실을 확인할 수 있다.
- 처리한 결과물에는 인수인계 대상 설명과 지정 파일을 확인하라는 대체 안내가 남지 않는다.
- 인수인계 파일에는 옮긴 정보와 관련 코드 또는 문서의 연결이 남아 내용을 파악할 수 있다.
- 새 스킬은 인수인계 파일을 읽고 관리하며 일반 결과물은 그 파일을 참조하지 않는다.
- 기존 표현 검사와 자연스러운 대체 표현의 적용은 유지되고, `use-better-terms`에서 이관한 절차의 중복과 크기 변화를 확인할 수 있다.
- 두 스킬의 실행 지침과 참고 자료의 설명이 영어로 작성돼 있다.
- 여러 상황에서 발견한 안내형 문구, 주의사항, 지침과 작업 보고가 조사 자료, 스킬의 판단 기준과 적용 확인에 연결돼 있다.
- 조사 자료와 플랜에 파일별 책임, 의미 중복을 줄이는 절차와 실행 성능의 확인 기준이 명시돼 있다.

## 결과물에서 인수인계 정보를 실제로 이관

스킬의 완료 기준은 인수인계 파일의 추가가 아니라 원래 결과물에 섞인 AI 인수인계 정보의 이관이다. 요구사항과 계획뿐 아니라 서비스 코드와 UI 및 보고서도 처리 대상에 포함한다. 현재 작업에서 작성하거나 수정하는 여러 파일을 함께 확인한다.

프롬프트의 작업 지시와 작성 경위는 일반 결과물에 추가하지 않는다. 열람 시 주의사항이나 서비스 사용 주의사항도 AI가 후속 작업을 수행하기 위한 정보라면 지정된 인수인계 파일로 옮긴다. 구현 과정을 설명하는 부연과 요구사항에 불필요한 설명에도 같은 기준을 적용한다. 예시에 없는 문장도 정보의 목적에 따라 판단한다.

이관 후 원래 결과물에는 같은 정보가 남지 않아야 한다. 문장을 그대로 복사한 뒤 원문을 유지하거나 주석과 툴팁에 숨기는 것으로 완료하지 않는다. 인수인계 파일을 열라는 대체 문구도 추가하지 않는다.

옮길 정보가 없으면 인수인계 파일을 생성하거나 형식적인 작업 보고를 추가하지 않는다. 기존 기록으로 충분한 정보는 중복 기록하지 않는다. 후속 AI가 작업을 이어가는 데 필요한 정보만 보존한다.

### 이관 여부의 판단 조건

기존의 필수 정보 보존 조건을 유지한다. 실제 요구사항과 승인된 결정은 담당 문서에 남긴다. 사용자에게 필요한 오류 안내와 접근성 정보도 남긴다. 데이터의 의미를 정하는 조건은 작성자의 부연과 구분한다. 서로 다른 목적의 내용이 섞인 문장은 필요한 부분만 분리해 이관한다.

### 보완 사항의 완료 근거

- 여러 대상 파일의 이관 전후 내용과 지정된 인수인계 기록을 대조할 수 있다.
- 원래 결과물에서 AI를 위한 설명이 제거되고 지정 파일에 필요한 내용이 보존된다.
- 이관 대상이 없는 작업에서 불필요한 기록이 늘지 않는다.
- 같은 작업을 다시 처리해도 동일한 정보가 누적되지 않는다.
- 필수 데이터 해석 조건을 포함한 문장에서는 작성자 부연만 분리된다.

제시된 사례의 확인 범위와 구분이 필요한 사항은 [이관 목적과 사례 조사](references/artifact-cleanup.md)에 기록한다.
