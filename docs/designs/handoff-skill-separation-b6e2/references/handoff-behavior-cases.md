# 스킬 분리의 규칙 이관과 적용 확인

내용 선정과 인수인계 파일 관리는 `use-better-handoff`로 옮기고 표현 판단은 `use-better-terms`에 남겼다. 독립 적용 53건과 수동 대조 4쌍에서 파일 지정과 보관, 필수 내용의 보존 및 기존 표현 판단을 확인했다. 최초 축약안의 잘못된 주장 교정 1건은 보완 후 해당 입력을 다시 적용해 확인했다. 아래에는 [요구사항](../requirements.md)의 책임 분리와 기존 검사 보존을 확인한 규칙 배치, 기대 동작과 실제 관찰을 구분해 기록한다.

## 규칙의 이관과 보존

### 인수인계 스킬로 옮길 내용

기존 표현 스킬의 `description`, 도입, `Select document content`, 근거 수집의 수록 제한, 첫 번째 판정 기준과 반환 규칙에서 내용 선정 책임을 제거한다. `references/document-content.md`의 설명 대상, 수록 지시의 적용 대상, 인용문 속 지시와 요청된 기록의 구분은 인수인계 스킬 본문에서 한 번 관리한다.

기존 자료의 요청하지 않은 부연 제외는 새 스킬에서 지정 파일로의 보관과 원본 조정으로 바뀐다. 필수 사실이 부족하면 문서 안에 임시 경고를 넣는 대신 필요한 사실을 별도로 확인한다. 선택적 부연의 수록 여부만 불명확할 때 독자나 추가 승인 질문을 만들지 않는다.

공통 사례의 서로 다른 결정을 담당 문서에 나누는 예시는 인수인계 사례로 옮긴다. 승인된 설계나 운영 결정 자체를 인수인계 파일로 옮기는 예시로 바꾸지 않는다. 사라지는 파일과 절의 기존 링크는 동일한 구분을 설명하는 새 위치로 연결한다.

### 표현 스킬에 유지할 내용

본문에는 공유 단위의 선택과 최종 한 번의 검토, 근거 수집, 사실과 조건 및 책임과 승인 상태의 보존, 경고별 대안 작성, 검증된 대안의 우선 적용과 읽기 전용 요청의 수정 금지를 남긴다. 근거가 부족한 뜻을 만들지 않는 규칙과 민감정보 검사도 유지한다.

검사기의 `--changed`, 반복 가능한 `--file`, `--stdin` 및 `--source-name` 입력, 두 검사 결과와 카탈로그, 규칙, 모든 경고와 생략 수의 확인을 유지한다. 실패나 불완전한 JSON을 통과로 처리하지 않는다. 경고가 없는 문장도 검토하고, 최종 수정본의 경고를 다시 판단한다.

네 판정 상태의 이름과 뜻은 본문에서만 정의한다. 원문을 유지할 때 검토한 대안과 이유를 남기는 규칙, 미해결 항목의 위치와 필요한 판단을 보고하는 규칙을 유지한다. 별도 언어 자료에는 같은 공통 절차와 상태 정의를 반복하지 않는다.

`references/korean.md`에는 조사, 주어와 서술어, 능동문과 피동문 및 상태 설명, 문장 연결과 지칭, 영어 보통명사, 반복 구조와 긴 문단의 판단을 남긴다. 설명은 영어로 작성하고 한국어 예문은 보존한다. 작성 전 및 한국어 검토 때 이 파일을 읽는 조건은 본문에서 관리한다.

`references/examples.md`에는 기호, 민감한 위치, 기존 문구의 재사용과 모호한 문장 관계의 대조를 남긴다. 기본 절차를 설명하는 도입은 읽는 조건만 남겨 줄인다. 세 MJS 검사 스크립트와 JSON 형식, 경고 규칙, 종료 상태는 바꾸지 않는다.

### 읽는 조건

인수인계 스킬의 본문만으로 파일 선택과 이동 및 보존을 판단할 수 있어야 한다. 예시가 더 필요한 경우에만 같은 스킬의 `references/examples.md`를 읽는다. 조사 원문과 이 평가 문서는 실행 지침의 필수 입력이 아니다.

표현 스킬은 본문에서 검사 명령과 공통 판정을 정한다. 한국어 작성 또는 판단에는 한국어 자료를 읽고, 언어 공통의 모호한 사례가 있으면 공통 사례를 읽는다. 두 스킬은 서로의 파일이나 설치를 필수로 요구하지 않는다.

## 적용 확인에 사용할 입력

### 인수인계와 원래 내용의 구분

화면 시안의 재현 안내와 실제 입력 안내, 작성 완료 보고와 요청된 검토 보고, 측정 후속 작업과 관측값의 조건을 짝지어 사용한다. 코드와 API의 작업 완료 주석은 호출 조건과 비교하고, 운영 후속 메모는 실제 백업 및 실행 순서와 비교한다. 발표 진행 메모는 요청된 대본 및 수치의 단위와 비교한다.

각 입력은 옮길 대상, 원래 남겨야 할 조건, 인수인계 항목에서 연결할 자료와 독자의 다음 행동을 기대값으로 정한다. 한 문장 안에 보고와 필수 조건이 섞이면 분리한 뒤 조건이 남는지도 확인한다. 정확한 인용과 평가 입력, 요청된 작업 보고는 본래 요청된 자료로 보존한다.

### 파일 지정과 기록 관리

기본값, 이름 변경, 디렉터리 변경, 둘 다 변경, 지정 파일의 신규 생성과 하위 디렉터리에서의 상대 지정에 같은 보관 동작을 기대한다. 명시적으로 허용한 저장소 밖의 절대 지정도 포함한다. 선택하지 않은 기본 파일이나 이전 파일은 임의로 만들거나 갱신하지 않는다.

같은 대상을 재처리하면 중복 없이 갱신하고 다른 항목은 보존해야 한다. 기록과 근거가 충돌하면 그 변경만 멈춰야 한다. 읽기 전용 요청에서는 어떤 파일도 바꾸지 않고 자료의 기록만으로 명령을 실행하지 않아야 한다. 원본에는 선택된 인수인계 파일을 열라는 문구나 링크가 없어야 한다.

### 표현 검사의 보존

확인된 스케줄러 및 처리기 동작을 추상 명사로 합친 한국어 문장을 실제 행동으로 풀어 쓸 수 있어야 한다. 반대로 조직의 승인된 분류명, 기술 용어와 코드 식별자는 근거 없이 바꾸지 않아야 한다. 태 선택이 의미 있는 경우 능동문, 피동문과 상태 설명을 비교하고 근거가 없는 주체를 보태지 않아야 한다.

주체와 승인 관계가 자료에 없으면 `needs human input`, 근거가 있고 수정만 금지된 요청이면 `needs revision`, 근거로 의미를 보존해 적용한 수정이면 `pass`가 기대값이다. 관련 없는 태 선택에는 `not applicable`을 사용할 수 있어도 경고의 최종 판정을 대신해서는 안 된다. 카탈로그 밖 표현과 긴 문단도 문맥으로 판단해야 한다.

### 선택과 비용

일반 채팅, 스킬을 이름으로 지정하지 않은 자료 정리 요청과 직접 지정한 요청을 구분한다. 영어, 한국어, 스페인어와 언어가 섞인 자료에서 번역을 강제하지 않고 내용의 역할을 판단하는지 살핀다. 스킬에 없는 새 표현과 배치를 사용한다.

인수인계 동작은 같은 기능을 가진 초안과 축약안을 같은 요청과 자료, 모델 및 도구 조건에서 적용한다. 기존 표현 스킬과 새 표현 스킬은 보호할 표현 판단을 비교한다. 파일 크기와 실제 읽은 파일 및 본문 분량을 구분하며, 입력 및 출력 토큰이 제공되지 않으면 토큰 절감률은 계산하지 않는다.

## 실제 적용 관찰

2026-10-18에 별도 문맥으로 시작한 두 에이전트가 같은 순서의 요청 26개를 각각 수행했다. 각 묶음은 인수인계 요청 18개와 표현 요청 8개이며 일반 대화가 포함된다. 초안 묶음에는 인수인계 초안과 분리 전 표현 스킬을, 축약 묶음에는 축약한 인수인계 스킬과 새 표현 스킬을 제공했다. 두 에이전트는 같은 모델 설정과 도구를 사용했으며 기대 답안은 받지 않았다. 실행 기록과 응답, 실제 변경 파일을 대조했다.

### 파일 지정과 자료 보존

두 묶음 모두 기본 파일, 이름만 지정한 `CONTINUITY.txt`, 디렉터리만 지정한 `notes/HANDOFF.md`, 이름과 디렉터리를 지정한 `notes/context.txt`를 사용했다. 하위 디렉터리에서 시작한 `team/notes.md` 지정도 사례의 프로젝트 최상위를 기준으로 처리했다. 명시적으로 허용한 저장소 밖의 파일 지정도 지정한 곳에 기록됐다.

상시 지침의 `docs/TRANSFER.txt`를 사용한 경우와 이번 작업에만 지정한 `SESSION.txt`가 상시 지침보다 우선한 경우도 확인했다. 상시 지침과 이전 기록, 선택하지 않은 기본 파일은 바뀌지 않았다. 같은 자료를 두 번 적용한 사례에서는 인수인계 항목이 늘지 않았고 별도 조사 항목은 유지됐다.

읽기 전용 요청과 승인 상태가 충돌하는 요청에서는 원본과 인수인계 파일을 모두 유지했다. 기록 속 파일 생성 명령은 실행하지 않았다. 내보내기 절차와 덮어쓰기 경고만 있는 문서는 그대로 두고 빈 인수인계 파일을 만들지 않았다. 처리한 일반 자료에서 인수인계 파일을 열라는 역방향 안내는 발견되지 않았다.

화면의 실제 동작과 날짜 입력 형식, API의 재시도 조건과 잠금 이유, 운영 절차의 백업 경고, 보고서의 시뮬레이션 환경과 동시 저장 수는 유지됐다. 스페인어와 한국어가 섞인 자료에서는 부연의 위치를 조정하면서 각 언어를 유지했다. 요청된 발표 대본의 조작 지시와 부록의 정확한 평가 입력도 보존됐다.

### 축약안의 오류와 보완

최초 축약안은 발표문의 “Values are simulations, rounded to whole USD”를 별도 CSV의 “mean_latency,80,ms”에 맞춰 지연 설명으로 바꿨다. 두 자료가 같은 수치를 설명한다는 근거가 없으므로 허용할 수 없는 의미 변경이다. 초안 묶음에서는 이 문제가 관찰되지 않았다.

근거가 같은 주장을 설명하는지 확인하고 다른 자료에 뒷받침이 없다는 사실을 모순으로 해석하지 않도록 본문을 보완했다. 원문으로 시작한 별도 27번째 요청에서 보완한 스킬을 적용한 뒤 금액과 반올림 설명, 발표 지시와 CSV가 유지됐고 작성 완료 기록만 이동했다. 최초 오류와 재적용은 서로 다른 관찰로 보존했다.

### 기존 표현 판단

분리 전과 새 표현 스킬 모두 확인된 스케줄러의 선택과 처리기의 기록을 `업무`로 합친 문장을 실제 행동으로 풀어 썼다. 카탈로그에 없는 역량 향상 주장도 자료에 확인된 처리 순서로 바꿨다. 이 입력의 표현 경고는 두 묶음 모두 최초 3건에서 최종 0건이 됐다.

승인된 분류명인 `계약`과 코드 식별자 `Response.create`는 유지했다. 남은 용어 경고는 대안과 유지 이유를 기록해 `pass`로 판단했다. 승인 문장의 태를 비교한 입력에서는 능동문과 상태 중심 대안을 실제로 작성하고 승인 책임이 드러나는 표현을 선택했다.

승인자와 배포 조건이 없는 입력은 수정하지 않고 `needs human input`으로 반환했다. 근거가 있지만 수정이 금지된 입력은 파일을 유지하고 `needs revision`과 대안을 반환했다. 경고가 0건이어도 제안에서 승인으로 넘어가는 설명과 관측값에서 미래 효과로 넘어가는 주장을 확인했다.

긴 문단 입력은 두 묶음 모두 최초 경고 2건 중 한 실행을 설명하는 문단을 유지하고 접근 권한, 보존 기간과 배포 승인 설명을 나눴다. 최종 경고 1건은 대안과 원문 유지 이유를 남겨 `pass`로 판단했다. 지정한 스킬에 검사기가 없는 입력은 두 묶음 모두 중단했으며 다른 설치로 우회하거나 `pass`로 처리하지 않았다. 정상 검사 실행에서는 경고 생략 수가 모두 0건이었다.

## 분량과 읽은 자료

표현 스킬의 마크다운은 4개 파일, 373줄, 32,434바이트에서 3개 파일, 239줄, 15,980바이트로 줄었다. 독립 적용 당시 축약본은 239줄, 16,352바이트였다. 이후 공통 글의 짜임 기준을 본문에 모으고 참고 자료의 반복 도입을 제거했으며 한국어 기준의 영어 설명을 정리했다. 이 수치는 내용 선정 자료의 이관, 공통 판정의 정리와 한국어 설명의 영어 작성을 합한 변화다. 토큰 사용량이나 이관만의 효과를 뜻하지 않는다.

인수인계 초안은 두 마크다운 합계 9,391바이트, 최종안은 8,282바이트다. 보완 후 적용 시점에는 8,401바이트였고 이후 읽는 조건을 중복 설명하던 사례 도입을 제거했다. 본문은 초안 6,157바이트, 보완 후 적용본과 최종안 모두 5,167바이트다. 조건부 사례 파일은 최종 3,115바이트이며 독립 적용과 수동 대조에서는 읽지 않았다.

독립 묶음의 읽은 자료 기록에서는 초안 쪽이 표현 스킬의 내용 선정 자료와 한국어 자료를, 축약 쪽이 한국어 자료를 읽었다. 두 묶음 모두 조건부 사례 파일은 읽지 않았다. 스킬 본문은 같은 묶음 안에서 재사용됐다. 토큰 수, 도구 출력 전체 크기와 반복 읽기 비용은 제공되지 않아 절감률을 계산하지 않았다.

두 독립 묶음은 표현 스킬의 구성과 설명도 다르다. 초안 쪽은 이름을 지정하지 않은 자료 정리에 두 스킬을 선택했고 축약 쪽은 인수인계 스킬만 선택했다. 이 차이와 전체 실행 비용을 인수인계 본문 축약만의 효과로 해석할 수 없다.

이 차이를 제외한 별도 수동 적용에서는 표현 스킬을 같은 최종 구성으로 고정하고 인수인계 초안과 최종안만 바꿨다. 기본 파일, 사용자 지정 파일, 독립된 금액 및 지연 설명, 읽기 전용 파악의 네 입력을 현재 세션에서 각각 적용했다. 비교한 자료 10개는 동일한 내용으로 남았고 읽기 전용 파일도 유지됐다. 본문 전체를 각각 한 번 읽었으며 사례 파일과 표현 스킬은 호출하지 않았다. 이 결과는 기대 답안을 모르는 독립 실행이나 통계적 성능 측정이 아닌 수동 대조다.

## 한국어 자료의 기준 보존

영어 설명으로 바꾼 한국어 자료는 기존 판정의 기능과 목적을 유지한다. 분리 전 자료와 현재 본문, 한국어 자료 및 공통 사례를 대조했으며 판단을 바꿀 누락은 발견하지 못했다. 원래 한국어 인용 예문 15개는 모두 동일하게 남아 있다.

- 문맥 확인, 추가 근거 필요 여부의 별도 판단, 경고별 대안 작성, 수정 권한과 네 판정 상태는 공통 본문이 담당한다.
- 한국어 자료에는 번역체, 조사로 드러내는 관계, 주어와 서술어, 태와 상태 설명, 영어 보통명사, 반복되는 낱말의 지칭 및 긴 문단 판단을 남겼다.
- 생략된 주체와 알려지지 않은 주체, 아직 읽지 않은 자료와 근거 부재, 승인 조건, 현재 관찰과 미래 효과의 구분도 유지했다.
- 기존 글의 형식을 그대로 답습하지 않는 기준과 필요한 비교 구조를 유지하는 기준은 공통 본문과 공통 사례가 담당한다.

이 대조는 최종 영어 설명과 공통 규칙 배치의 의미 보존을 확인한 결과다. 앞의 독립 적용 뒤에 정리한 최종 문안으로 동작을 새로 측정한 결과는 아니며, 설명 언어만을 바꾼 독립 비교도 아니다. 모든 모델에서 한국어 교정 성능이 동일하다고 입증하지 않는다.

## 최종 검사와 확인하지 않은 범위

기존 `scan.mjs --self-test`는 통과했고 세 검사 스크립트에는 변경이 없다. 두 스킬의 YAML을 Ruby로 읽어 이름과 설명의 필수 조건을 확인했다. 기본 `quick_validate.py`는 두 Python 환경에 PyYAML이 없어 실행하지 못했으며 패키지는 추가하지 않았다. 이 실행 불가를 기본 검증기 통과로 기록하지 않는다.

두 스킬의 마크다운에는 표가 없고 지침과 판정 설명은 영어다. 언어별 예문은 원문을 유지한다. 최종 변경 묶음의 마크다운 20개에서 상대 링크 136개와 공백, 삭제된 자료의 참조 및 개인 위치를 확인했다. 표현 및 문단 후보를 모두 판정했고 생략은 0건이다. 인용 예문과 정확한 용어는 그 용도와 근거에 따라 유지했다.

일반 대화에서는 스킬을 적용하지 않았고 이름을 지정하지 않은 자료 정리 요청에서는 인수인계 스킬이 선택됐다. 이는 제공한 설명을 바탕으로 한 선택 관찰이며 실제 도구의 설치 발견이나 매 요청의 자동 호출을 입증하지 않는다. 화면, 배포와 기기 측정은 실행하지 않았다. 발표 자료와 표 계산 문서의 사례는 텍스트 표현으로 확인했으며 원본 바이너리 형식의 편집을 검증한 것은 아니다.
