# 에이전트 지침과 Skill 최적화 계획

이 계획은 각 지침 파일의 책임과 현재 동작을 유지하면서 중복 문구와 불필요한 실행 절차를 줄이고, `use-words-review`를 `use-better-terms`로 바꾸는 작업을 다룬다. 서브에이전트 호출을 요구하거나 권하는 지침은 배포 대상에서 제거한다.

현재 단계에서는 계획만 갱신한다. 파일 축소, 이름 변경, 동작 변경과 대표 사례 평가는 이 계획이 승인된 뒤 별도 구현 작업에서 수행한다. 계획의 승인이나 이번 문서 검사를 구현이나 평가를 마쳤다는 근거로 사용하지 않는다.

## 기준과 적용 범위

기준 문서는 [`requirements.md`](./requirements.md)의 "목표", "문제에 대한 대응", "완료 전 확인할 사항"과 "주의점"이다. 다음 조사 문서에서 확인한 파일 책임, 비용 발생 지점과 보존 조건을 적용한다.

- [에이전트 작업 분리와 검증 구조 조사](./references/agent-workflow-and-review-research.md)는 서브에이전트 비용, 문구 대체 우선 절차와 출처 판정의 한계를 설명한다.
- [지침 크기와 금지 문구 설계 조사](./references/instruction-size-and-prohibition-research.md)는 항상 읽는 절차와 조건부 참고 자료의 분리, 단일 README의 보존 조건과 축소 전후 비교 방법을 설명한다.
- [구현 세션, 리뷰 세션과 Goal 운용 조사](./references/session-review-tdd-and-goal-research.md)는 작업 세션과 리뷰 세션이 나뉜 경우의 책임과 리뷰 대상 확정 조건을 설명한다.

변경 대상은 다음과 같다.

- `src/AGENTS.en.md`와 `src/AGENTS.ko.md`
- `skills/use-design-docs/SKILL.md`와 `skills/use-design-docs/references/_README.md`
- `skills/use-dev-guidance/SKILL.md`와 `skills/use-dev-guidance/references/_README.md`
- `skills/use-words-review/`에서 이름이 바뀔 Skill, 참고 자료와 검사 스크립트
- 이름, 설치 방법과 검사 대상을 연결하는 `README.md`, `README.ko.md`, `eslint.config.mjs`, `docs/dev/node/mjs-cli.md`와 저장소 내부 참조
- 두 `_README.md`의 배포본인 `docs/designs/README.md`와 `docs/dev/README.md`

작업 중인 애플리케이션 저장소의 코드, Git 기록과 비공개 검토 자료는 변경 근거나 평가 입력으로 사용하지 않는다. 외부 패키지는 추가하지 않는다. `.mjs` 검사 스크립트를 수정할 때에는 [`docs/dev/README.md`](../../dev/README.md)와 [Node.js MJS 명령줄 검사기](../../dev/node/mjs-cli.md)를 적용한다.

## 파일별로 유지할 책임

파일 크기는 임의의 바이트 수나 감소율로 판정하지 않는다. 현재 파일이 맡은 책임과 확인 가능한 동작을 먼저 고정하고, 같은 책임을 다른 파일에 복제하지 않은 후보만 비교한다.

### 배포용 AGENTS 문서

두 `src/AGENTS.*.md`는 저장소 전체에서 항상 적용할 원칙, 안전 조건, Git 규칙과 Skill 호출 조건을 제공한다. Skill의 입력 구성, 세부 실행 순서, 참고 자료의 판정 질문과 결과 형식은 반복하지 않는다.

서브에이전트를 사용하라고 요구하거나 조건부로 권하는 절과, 그 지침만을 위해 존재하는 작업 분배 및 결과 종합 절차는 제거한다. 순차 의존, 요구사항 변경, 민감정보와 Git 안전처럼 단일 담당 세션에서도 필요한 규칙은 원래 책임에 맞는 절에 남긴다.

작업 세션과 리뷰 세션을 분리한 경우에는 리뷰 요청의 Git 정보와 저장소에서 확인한 규칙으로 검토 대상을 정하고, 필요한 정보가 없거나 서로 맞지 않으면 영향받은 리뷰를 시작하지 않는 원칙만 남긴다. 별도 리뷰 절차의 세부 동작은 배포용 AGENTS 문서에서 정하지 않는다.

### `use-design-docs`와 `use-dev-guidance`

두 `SKILL.md`는 저장소 기준 README의 위치를 확인하고, 요청에 필요한 작업을 선택해 의존 순서대로 실행하며, 적용할 참고 자료와 중단 조건을 정하는 어댑터다. 기준 README가 관리하는 문서 구조, 작성 권한, 필수 정보, 금지 내용과 검증 기준을 Skill 본문에 다시 쓰지 않는다.

서브에이전트에 작업을 전달하는 절과 전달 메시지 구성 절차는 제거한다. 파일 변경 권한, 요구사항과 결정의 구분, 기존 동작 보존, 의존성 조사와 확인 책임처럼 각 Skill의 고유 동작은 유지한다.

### 두 `_README.md`

`skills/use-design-docs/references/_README.md`와 `skills/use-dev-guidance/references/_README.md`는 각각 애플리케이션 저장소의 `docs/designs/README.md`와 `docs/dev/README.md` 한 파일로 복사되는 시작 자료다. 복사된 한 파일만으로 문서 생성 조건, 작성 권한, 필수 정보, 금지 내용과 검증 방법을 알 수 있어야 한다.

두 파일은 나누지 않고 복사 대상도 늘리지 않는다. 공통 규칙은 파일 안에서 한 번만 설명하고, 문서 종류나 작업 종류별 절에는 그 종류에만 필요한 차이만 남긴다. 이 저장소에만 적용되는 링크나 유지 관리 설명은 배포본에 섞지 않는다.

### `use-better-terms`

이 Skill은 저장, 커밋, 게시 또는 공유할 글과 이름을 더 나은 표현으로 다듬고, 근거가 없어 고칠 수 없는 문장을 구분한다. 이름 변경 뒤에도 현재 `use-words-review`가 제공하는 다음 동작은 유지한다.

- 같은 커밋이나 공유 단위의 산출물을 한 번에 다루고 일반 채팅과 진행 알림은 제외한다.
- 저장소가 제공하는 문구 검사와 한국어 검사 스크립트를 실행한다. `--changed`, 반복 가능한 `--file`, `--stdin` 입력과 두 검사 결과의 JSON 구조를 유지한다.
- 검사 경고를 자동 실패로 보지 않고 원문 문맥에서 판정한다. 한국어가 있으면 `references/korean.md`를 읽고, 공통 사례가 필요한 경우에만 `references/examples.md`를 읽는다.
- 독자, 행동 주체, 조건, 결과, 문장 사이의 관계, 출처 근거, 승인 상태, 민감정보, 기호와 자연스러운 한국어를 확인한다.
- `pass`, `needs revision`, `needs human input`, `not applicable` 판정과 위치, 근거 및 독자에게 생기는 영향을 남긴다.

현재 Skill의 읽기 전용 검토 책임은 대체 표현을 우선 적용하는 작성 절차로 바꾼다. 검사기가 알린 후보에는 먼저 문맥에 맞는 자연스러운 대체 문장을 만들고, 저장소 근거나 승인된 뜻만으로 의미를 보존할 수 있으면 같은 작업에서 바꾼다. 확립된 전문용어이거나 더 나은 표현이 없을 때만 원래 표현을 유지하고 근거를 남긴다. 대체하려면 새 뜻, 역할 또는 승인 상태를 정해야 하는 경우에는 문구를 추정하지 않고 `needs human input`으로 남긴다.

검토 모델을 따로 선택하거나 다른 에이전트에 의미 판정을 맡기는 절차는 제거한다. 작성과 의미 판정은 현재 담당 세션에서 공유 단위마다 한 번 수행한다. 결정적 검사, 참고 자료 선택, 판정 기준과 판정 상태는 이 변경과 관계없이 유지한다.

## 작업 단위와 순서

### 파일 책임과 중복 위치를 먼저 고정한다

**목표.** 삭제 전후에 비교할 책임과 현재 동작을 저장소 파일에서 확인한다.

**대상 파일.** 앞 절에 나열한 배포용 AGENTS 문서, 세 Skill 묶음, 두 `_README.md`, 두 기준 README와 이름 참조 파일을 읽는다. 대표 사례와 측정 결과를 보존할 필요가 생기면 `docs/designs/agent-workflow-reliability-c7e4/references/instruction-optimization-evaluation.md` 하나에만 기록한다.

**진행 방법.** 각 규칙을 항상 적용할 전역 조건, Skill 실행 절차, 조건부 판정 자료, 독립 실행 기준 또는 저장소 연결 정보 중 하나로 분류한다. 동일한 규칙이 여러 파일에 있으면 현재 파일의 목적과 기존 기준 README의 권한을 근거로 전문을 관리할 파일을 정하고, 다른 파일에는 필요한 호출 조건이나 링크만 남긴다. 내용이 비슷하다는 이유만으로 책임이 다른 문장을 합치지 않는다.

현재 줄 수와 바이트 수, Skill이 대표 작업에서 읽도록 요구하는 파일, 검사 스크립트가 받는 입력과 반환하는 JSON 구조를 변경 전 값으로 기록한다. 실행 환경이 제공하지 않는 토큰 값은 추정하지 않는다. 이번 계획 갱신에서는 이 측정과 대표 사례 실행을 시작하지 않는다.

**검증.** 모든 변경 대상에 보존할 책임, 중복 후보와 전문을 관리할 파일이 지정돼 있어야 한다. 근거 없이 만든 목표 크기, 역할이 정해지지 않은 삭제 후보와 여러 파일에 남은 동일 절차가 없어야 한다.

### Skill 이름과 저장소 참조를 바꾼다

**의존 관계.** 파일 책임 확인이 끝난 뒤 수행한다.

**목표.** `use-words-review`를 `use-better-terms`로 이름을 바꾸고 저장소에서 실행되는 참조가 새 이름과 위치를 가리키게 한다.

**대상 파일.** `skills/use-words-review/` 전체를 `skills/use-better-terms/`로 옮기고, `src/AGENTS.en.md`, `src/AGENTS.ko.md`, `README.md`, `README.ko.md`, `eslint.config.mjs`, `docs/dev/node/mjs-cli.md`와 현재 파일 위치를 참조하는 문서를 확인한다.

**진행 방법.** Skill frontmatter의 `name`, 제목, 호출명, 설치 안내, 관리용 표시 이름, ESLint 대상과 명령 예시를 함께 바꾼다. 현재 사용 지침이나 실행 명령은 새 이름으로 바꾼다. 과거 상태를 설명하는 조사 문장은 그 당시 이름을 보존하되, 이동한 파일을 가리키는 링크와 실행 가능한 명령이 끊기지 않게 고친다. 같은 Skill의 이전 이름 디렉터리를 복제해서 남기지 않는다.

**검증.** 새 디렉터리의 `SKILL.md` frontmatter와 호출명이 일치하고, 현재 실행 지침, 설치 안내, ESLint 설정과 명령 예시가 존재하는 위치를 가리켜야 한다. 역사적 설명을 제외한 활성 참조에 이전 호출명이나 이전 파일 위치가 남지 않아야 한다. 저장소 상대 링크도 모두 해석돼야 한다.

### `use-better-terms`의 작성 절차와 본문을 줄인다

**의존 관계.** 이름 변경이 끝난 뒤 수행한다.

**목표.** 현재 검사의 적용 대상을 유지하면서 대체 표현 우선 절차를 기본 동작으로 만들고, 별도 에이전트 호출을 전제로 한 내용을 제거한다.

**대상 파일.** `skills/use-better-terms/SKILL.md`, `skills/use-better-terms/references/korean.md`, `skills/use-better-terms/references/examples.md`와 같은 디렉터리의 세 검사 스크립트다.

**진행 방법.** `SKILL.md`에는 적용 대상, 입력 선택, 결정적 검사, 참고 자료 선택, 의미를 보존한 수정, 중단 조건과 결과 형식처럼 매번 필요한 절차만 남긴다. 모델 선택, 도입 평가, 전달 문맥 작성, 위임, 별도 판정 대조와 대체 실행 절은 제거한다. 언어별 사례와 긴 판정 설명은 실제로 필요한 조건부 참고 파일 한 곳에서만 관리한다.

한국어 후보는 검사 결과를 받은 같은 작업에서 대체 표현을 먼저 적용한다. 정확한 용어를 유지하거나 뜻을 정할 수 없어 수정하지 못한 경우만 보고한다. 단순 문자열 치환은 하지 않으며, 스크립트의 경고와 긴 문단 탐지는 계속 의미 판정 후보만 제공한다.

**검증.** 기존 검사 스크립트의 자체 검사를 한 번 실행하고 JSON의 `sources`, `checks`, `catalog`, `rules`, `warnings`와 `summary`가 유지되는지 확인한다. 승인된 대표 사례를 실행할 때에는 자연스러운 대체가 가능한 문장, 정확한 기술 용어, 근거가 없어 뜻을 정할 수 없는 문장, 민감정보와 문장 관계 오류를 포함한다. 같은 공유 단위의 의미 판정은 한 번만 수행하고, 판정이 기존 네 상태로 구분되는지 확인한다.

### 설계 문서 Skill과 단일 README를 줄인다

**의존 관계.** 파일 책임 확인과 새 Skill 호출명 확정 뒤 수행한다.

**목표.** 설계 문서의 작성 권한과 검사 기준을 유지하면서 `use-design-docs`와 설계용 README의 중복을 제거한다.

**대상 파일.** `skills/use-design-docs/SKILL.md`, `skills/use-design-docs/references/_README.md`와 `docs/designs/README.md`다.

**진행 방법.** `SKILL.md`에는 저장소 기준 README 확인, 생성 승인, 필요한 작업 선택, 요구사항 기준 확정, 작업 순서와 중단 조건만 남긴다. 위임 절차와 README가 관리하는 문서별 상세 규칙은 제거한다. `_README.md`와 현재 기준 README에서는 공통 규칙을 한 번만 설명하고 문서 종류별 차이만 각 절에 남긴다. 관리용 첫 줄을 제외한 배포 원본과 이 저장소 기준의 공통 내용은 같은 뜻을 유지한다.

**검증.** README가 없는 경우의 생성 승인, 기존 README 사용, 요구사항 작성 권한, 참고 자료와 결정 및 계획의 생성 조건, 필수 정보, 금지 내용과 네 가지 판정 상태를 대표 사례로 한 번 확인한다. `_README.md` 하나만 복사한 상태에서도 같은 판정을 내릴 수 있어야 한다.

### 개발 지침 Skill과 단일 README를 줄인다

**의존 관계.** 파일 책임 확인과 새 Skill 호출명 확정 뒤 수행한다.

**목표.** 기술별 근거와 검사 선택 책임을 유지하면서 `use-dev-guidance`와 개발용 README의 중복을 제거한다.

**대상 파일.** `skills/use-dev-guidance/SKILL.md`, `skills/use-dev-guidance/references/_README.md`와 `docs/dev/README.md`다.

**진행 방법.** `SKILL.md`에는 기준 README 확인, 현재 저장소 조사, 공식 자료 확인, 필요한 작업 선택, 가장 단순하고 신뢰할 수 있는 검사 선택, 변경 권한과 중단 조건을 남긴다. 위임 절차와 README가 관리하는 기록 형식은 제거한다. `_README.md`는 하나의 독립 기준으로 유지하면서 공통 작성 권한, 근거, 안티패턴 기록 요소, lint의 판정 한계와 검증 방법을 한 번만 설명한다.

**검증.** 기준 README가 없는 경우, 기존 지침 사용, 공개 안티패턴 조사, 의존성 변경, lint로 확인할 수 없는 동작과 코드 변경 권한이 없는 요청을 대표 사례로 한 번 확인한다. Skill과 README가 같은 규칙의 전문을 각각 갖지 않고도 같은 중단 및 진행 판정을 내리는지 확인한다.

### 배포용 AGENTS 문서와 설치 안내를 정리한다

**의존 관계.** 세 Skill 묶음의 최종 이름과 책임이 정해진 뒤 수행한다.

**목표.** 항상 읽는 전역 지침을 줄이고 두 언어의 호출 조건과 설치 안내를 일치시킨다.

**대상 파일.** `src/AGENTS.en.md`, `src/AGENTS.ko.md`, `README.md`와 `README.ko.md`다.

**진행 방법.** 두 AGENTS 문서에서 서브에이전트 사용 절과 Skill 내부 절차를 제거한다. 각 Skill을 실행할 조건, 필요한 Skill을 읽지 못했을 때의 중단 조건, 저장소 기준 README의 권한, 민감정보와 Git 안전 규칙은 남긴다. `use-better-terms` 구간은 작성 전에 필요한 한국어 자료를 읽고, 저장할 공유 단위에서 대체 표현을 먼저 적용한 뒤 한 번 판정하도록 바꾼다.

두 루트 README는 세 Skill의 목적, 복사할 디렉터리, AGENTS에 추가할 구간과 제거 방법만 설명한다. Skill 본문의 실행 순서나 참고 자료의 판정 기준은 복제하지 않는다.

**검증.** 두 언어 문서의 Skill 호출 조건, 권한, 중단 조건, Git 규칙과 설치 및 제거 안내를 같은 순서로 대조한다. 현재 배포용 AGENTS와 세 `SKILL.md`에서 서브에이전트 호출을 요구하거나 권하는 문장이 남지 않았는지 확인한다. 단일 담당 세션에도 필요한 순차 의존과 요구사항 변경 규칙이 함께 사라지지 않았는지도 확인한다.

## 전체 검증과 완료 조건

각 작업 단위는 최종 후보에서 문구 판정과 그 작업 단위의 대표 사례를 각각 한 번만 수행한다. 다음 작업 단위에서는 이미 끝난 검토를 반복하지 않고, 앞 commit에서 확인한 내용과 새 변경이 만나는 부분만 확인한다. 모든 단위가 끝난 뒤 저장소 전체 검사는 한 번 실행한다.

- `node skills/use-better-terms/scripts/scan.mjs --self-test`가 성공하고 기존 JSON 구조와 입력 방식이 유지된다.
- `pnpm lint`와 `git diff --check`가 최종 상태에서 성공한다.
- 현재 실행 지침, 설치 안내, 설정과 명령 예시가 모두 `use-better-terms`를 사용하며 이전 디렉터리를 필요로 하지 않는다.
- 현재 배포용 AGENTS와 세 Skill에 서브에이전트 호출을 요구하거나 권하는 절차가 없다.
- 두 AGENTS 문서는 전역 조건과 Skill 호출 시점만 관리하고, 세 Skill은 각 실행 절차만 관리하며, 두 기준 README는 저장소 기준만 관리한다.
- `use-better-terms`는 현재 문구 검사의 적용 대상, 결정적 검사, 문맥 판정과 네 판정 상태를 유지하면서 대체 가능한 표현을 같은 작업에서 먼저 바꾼다.
- 두 `_README.md`는 각각 한 파일로 복사해 독립적으로 사용할 수 있고, 문서 생성 조건, 작성 권한, 필수 정보, 금지 내용과 검증 방법이 남아 있다.
- 변경 전후 줄 수와 바이트 수, 대표 작업에서 읽은 파일과 제공되는 경우의 토큰 및 경과 시간을 기록한다. 수치를 제공하지 않는 항목은 추정하지 않는다.
- 변경한 한국어와 영어 산출물을 같은 공유 단위로 한 번 판정하고, 개인 절대 위치, 비공개 식별자, 인증정보, 미해결 표시와 끊어진 저장소 상대 링크가 없는지 확인한다.

문서 크기가 줄었다는 사실만으로 완료하지 않는다. 위 보존 조건과 대표 사례를 충족한 후보 중에서 실제로 읽는 문장이 줄어든 변경만 채택한다.

## 커밋 단위

1. Skill 디렉터리 이름과 현재 실행 참조 변경
2. `use-better-terms`의 대체 표현 우선 절차와 본문 축소
3. `use-design-docs`와 설계용 단일 README 축소
4. `use-dev-guidance`와 개발용 단일 README 축소
5. 두 언어 AGENTS, 루트 README와 저장소 전체 연결 정리
6. 대표 사례 판정과 최종 크기 측정 기록이 필요한 경우의 문서화

각 commit은 그 단위의 파일만 stage한다. 이름 변경 commit은 이전 위치 삭제와 새 위치 추가 및 그 위치를 사용하는 참조를 함께 포함해 중간 상태에서도 실행 가능한 구성을 유지한다. 한 단위의 결정적 검사가 실패하거나 보존할 책임이 사라지면 다음 commit으로 넘어가지 않는다.

## 중단 조건

- 현재 파일과 기준 README에서 책임을 확인할 수 없는 규칙은 크기만을 이유로 삭제하지 않는다.
- 승인된 이름 변경, 대체 표현 우선 절차와 서브에이전트 지침 제거를 넘어 공개 동작, 작성 권한, 판정 상태나 검사 출력 구조를 바꿔야 하면 영향받은 작업을 멈추고 요구사항 작성자에게 묻는다.
- 이전 Skill 이름을 계속 실행 가능한 별도 복사본으로 유지해야만 호환성을 지킬 수 있다면 중복 디렉터리를 만들지 않고 필요한 호환 조건을 먼저 확인한다.
- `_README.md`를 여러 파일로 나누거나 복사 대상 파일을 늘려야만 크기를 줄일 수 있으면 그 축소안을 적용하지 않는다.
- 두 언어 AGENTS 문서가 같은 뜻을 유지하지 못하거나 역사적 설명과 현재 실행 참조를 구분할 수 없으면 그 묶음을 commit하지 않는다.
- 외부 패키지, 네트워크 의존성 또는 저장소 전체 정책 변경이 필요하면 현재 계획에 포함하지 않고 영향과 대안을 요구사항 작성자에게 설명한다.
- 요구사항, 승인된 결정, 기존 동작 또는 실제 측정 없이 목표 크기와 통과 수치를 정해야 하면 그 수치를 만들지 않는다.
