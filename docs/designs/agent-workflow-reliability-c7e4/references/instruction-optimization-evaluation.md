# 지침 최적화 크기 측정과 동작 보존 평가

## 결론

지침 파일의 책임을 전역 규칙, Skill 실행 절차, 저장소 기준과 조건부 참고 자료로 다시 나눈 뒤, 평가 대상인 13개 문서의 합계가 2,092줄, 184,163바이트에서 1,315줄, 109,629바이트로 줄었다. 모든 문서의 크기를 줄이는 수치 목표를 먼저 정하지 않았으며, 승인된 제거 항목과 보존할 판정이 확인된 변경만 반영했다.

최종 파일은 `use-better-terms`의 세 입력 방식과 JSON 구조, 네 판정 상태, 두 기준 README의 단독 사용 조건, AGENTS 문서의 Skill 호출 및 Git 안전 규칙을 유지한다. 배포 대상에서 서브에이전트 호출 절차와 프롬프트 또는 내부 작업 결정의 유출 여부를 판정하는 책임은 제거됐다.

줄 수와 바이트 수는 저장소에서 다시 측정할 수 있지만, 이번 실행 환경은 입력 및 출력 토큰과 작업 단위별 경과 시간을 제공하지 않았다. 이 값은 바이트 수로 환산하거나 추정하지 않았다. 실제 애플리케이션 저장소에서의 호출 빈도, 토큰, 지연과 판정 정확도는 이번 평가로 확인할 수 없다.

## 평가 질문과 근거

이 평가는 [`requirements.md`](../requirements.md)의 Skill 크기, 단일 `_README.md`, 서브에이전트 의존성, 문구 대체 우선 처리와 완료 조건을 대상으로 한다. 실행 순서와 보존 조건은 [`plan.md`](../plan.md)를 기준으로 삼았다. 파일 크기만으로 불필요한 내용을 판정할 수 없고 같은 대표 작업의 행동을 함께 확인해야 한다는 근거는 [지침 크기와 금지 문구 설계 조사](instruction-size-and-prohibition-research.md)에 기록돼 있다.

평가 독자는 이 저장소의 배포 지침과 Skill을 관리하는 사람이다. 독자가 내려야 할 판단은 최종 후보가 명시된 책임을 유지하면서 반복 입력을 줄였는지, 그리고 후속 애플리케이션 평가가 필요한 항목이 무엇인지다.

평가일은 2026년 8월 28일이다. 변경 전 기준은 계획 파일을 마지막으로 갱신한 직후의 저장소 상태이며, 최종 기준은 계획의 첫 번째부터 다섯 번째 커밋 단위를 적용한 뒤 이 평가 파일을 추가하기 직전의 상태다. `git show`로 변경 전 파일을 읽고 현재 파일과 같은 방식으로 줄바꿈 수와 UTF-8 바이트 수를 셌다. 토큰 값을 대신하기 위한 계산은 하지 않았다.

## 대표 판정

### `use-better-terms`

- 자연스러운 대체가 가능했던 `앞 작업의 결과`는 문장의 의존 관계를 직접 밝히는 `앞 작업에서 만든 내용`으로 바뀌었다. 뜻을 추가하지 않고 대체할 수 있어 수정 뒤 `pass`로 판정했다.
- `Git revision`은 리뷰 요청에 지정된 Git 객체를 가리키는 기술 용어이므로 유지했다. 일반 한국어로 바꾸면 대상이 덜 정확해져 유지 뒤 `pass`로 판정했다.
- 표현을 바꾸려면 빠진 책임 주체나 승인 상태를 정해야 하는 입력은 수정하지 않고 `needs human input`으로 판정하는 절차가 남아 있다.
- 근거로 확인한 문제와 의미를 보존하는 수정안이 있지만 읽기 전용 요청이라 적용할 수 없는 입력은 `needs revision`으로 판정한다.
- 한국어가 없는 영어 전용 입력에는 한국어 표현 기준을 `not applicable`로 판정할 수 있다.
- 검사기 자체 검사는 반복 가능한 `--file`, `--stdin --source-name`, `--changed` 입력을 실제 자식 프로세스로 실행한다. JSON 객체에는 `sources`, 두 `checks`, 각 검사의 `catalog`, `rules`, `warnings`, `summary`가 남아 있다.

### 설계 문서 기준

- 기존 `docs/designs/README.md`가 있으면 그 파일을 완독하고 시작 자료와 동기화하지 않는 판정이 남아 있다.
- 기준 README가 없고 지속해서 사용할 기준이 필요하면 정확한 복사 위치를 제시하고 생성 승인을 받는다. 승인이 없으면 임의로 만들지 않으므로 `needs human input`이다.
- 요구사항 작성 권한, 참고 자료와 결정 및 계획의 생성 조건, 문서별 필수 정보와 금지 내용, 네 판정 상태가 단일 README에 남아 있다.
- 시작 자료의 관리용 첫 줄을 제외한 본문과 현재 설계 README를 비교했을 때 차이가 없다.

### 개발 지침 기준

- 기존 `docs/dev/README.md`가 있으면 현재 저장소의 기준으로 사용하고, 없을 때에만 지속 기준의 필요성과 생성 승인을 확인한다.
- GitHub에서 소스 코드를 확인할 수 있는 오픈소스 애플리케이션의 고정 revision과 확인된 실패 또는 변경 이유를 공식 자료와 함께 조사하도록 한다. 안티패턴 코드, 권장 코드, 권장 이유, 적용 조건과 예외, lint 예시와 lint가 판단하지 못하는 항목이 한 파일에 남아 있다.
- lint가 동작을 정확히 판정하지 못하면 부정확한 대체 규칙을 만들지 않고 type, schema, 테스트, 실행, 브라우저 검사 또는 책임 있는 리뷰를 선택한다.
- 조사 요청은 코드, 의존성, 설정 또는 문서 변경 권한을 만들지 않는다.

### AGENTS와 설치 안내

- 두 언어 AGENTS 문서는 같은 순서로 Skill 호출 조건, 읽기 실패 시 중단, 순차 의존, 요구사항 변경, 민감정보와 Git 안전 규칙을 설명한다.
- 작업 세션과 리뷰 세션이 나뉘면 리뷰 요청의 Git revision과 저장소 규칙으로 대상을 정한다. revision이 빠졌거나 저장소 상태와 맞지 않으면 영향을 받는 리뷰를 시작하지 않는다.
- 배포용 AGENTS와 세 Skill에는 서브에이전트를 호출하라고 요구하거나 권하는 절차가 없다.
- 두 루트 README의 저장소 상대 링크는 현재 파일을 가리키고, 설치와 제거 안내는 `use-better-terms` 이름을 사용한다.

## 최종 통합 검사

최종 후보에는 다음 검사를 한 번 적용한다.

- `node skills/use-better-terms/scripts/scan.mjs --self-test`: 입력 방식과 JSON 구조를 포함한 자체 검사 통과
- `pnpm lint`: 저장소가 설정한 ESLint 검사 통과
- `git diff --check`: 공백 오류 없음
- 변경한 Markdown 파일의 저장소 상대 링크 검사: 존재하지 않는 대상 없음
- 활성 지침의 이전 Skill 이름, 서브에이전트 호출 절차와 제거하기로 한 프롬프트 유출 판정 책임 검색: 발견 없음
- 설계 시작 자료와 현재 설계 README의 공통 본문 비교, 개발 시작 자료와 현재 개발 README의 공통 본문 비교: 의도한 저장소 전용 링크 외 차이 없음
- 변경 파일의 개인 절대 위치, 인증정보, 비공개 URL, 비공개 저장소 참조와 미해결 표시 검색: 발견 없음

이 검사는 문서와 실행 파일의 현재 구성을 확인한다. 실제 애플리케이션 구현의 품질이나 별도 리뷰 세션의 독립성을 증명하지 않는다.

## 판정과 남은 측정

- `pass`: 문서별 책임, 승인된 제거 항목, 문구 검사기의 입력 방식과 JSON 구조, 단일 README의 독립 사용 조건, Skill 호출과 Git 안전 규칙이 계획의 확인 방법과 일치한다.
- `pass`: 모든 평가 대상 문서의 변경 전후 줄 수와 바이트 수를 같은 방식으로 기록했고, 줄이거나 유지한 이유를 파일 책임과 연결했다.
- `not applicable`: 실행 환경이 토큰과 작업 단위별 경과 시간을 제공하지 않아 이번 전후 비교에는 적용할 수 없다.
- `needs human input`: 실제 애플리케이션 저장소에서 호출 빈도, 입력 및 출력 토큰, 지연, 놓친 문제와 잘못 지적한 문제를 비교할 표본과 책임자를 정해야 한다. 이 후속 평가는 현재 저장소의 지침 변경 완료를 막지 않는다.
- `needs revision`으로 남은 현재 파일 문제는 없다.

후속 평가는 같은 애플리케이션 작업 표본에서 변경 전후에 실제로 읽은 파일, 토큰, 경과 시간, 기대 판정 일치, 누락과 잘못된 지적을 기록해야 한다. 이번 크기 측정치를 토큰 절감이나 리뷰 정확도 향상의 증거로 대신 사용하면 안 된다.
