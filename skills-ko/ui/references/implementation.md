# HTML 시안과 구현에 넘길 자료

합의한 방향으로 확인 가능한 HTML 서비스 화면을 만들고 요청한 요소를 수정한다. 구현에 필요한 자료는 적용 범위를 정해 제공한다.

## 현재 화면의 기본 규칙 정리

확인할 수 있는 목표, 시나리오, 정보 관계, 제약, 기존 규칙, 선택과 미해결 질문을 사용한다. 글자, 간격, 정렬, 페이지 영역, 밀도, 배경과 패널 표현 및 행동 강조의 현재 규칙을 정한다. 필요한 주 행동, 보조 행동, 파괴적 행동과 선택, 비활성, 포커스, 오류, 로딩, 빈 상태 및 반응형 표현을 포함한다.

각 규칙을 의도한 사용과 시나리오 제약에 연결한다. 수치보다 원칙을 먼저 정한다. 실제 분야에 맞는 내용과 정보량, 뜻이 분명한 이름, 긴 내용과 상태 정보를 사용한다. 화면을 풍부하게 보이게 하려고 능력을 추가하거나 어디에나 쓸 수 있는 카드와 임시 내용으로 영역을 채우지 않는다.

## 시안 생성과 확인

기본 규칙이 없거나 바뀌면 [현재 기본 규칙](#현재-화면의-기본-규칙-정리)을 사용한다.

새 방향에서는 첫 본격 시안 전에 [테마 비교](research.md#테마-비교-제시)에 대한 피드백을 받는다. 합의한 위치에 독립 HTML을 만든다. 서버 없이 여는 시안은 필요한 CSS와 JavaScript를 파일에 포함하고 빌드나 백엔드가 필요한 의존성을 피한다. 허용되면 기존 자료를 사용한다. 이미지 생성은 이미지나 시각 비교를 보조할 수 있지만 HTML과 상호작용 확인을 대신하지 않는다.

시나리오를 전체 구성에 반영한다. 실제에 맞는 내용과 정보량, 정보 우선순위, 행동, 기본 규칙, 필요한 상태와 뷰포트, 확정 특징과 잠정 기본값을 포함한다. 내용을 전달하는 데 적합하면 분야에 맞는 이미지, 다이어그램, 공간 관계, 조작 요소나 다른 시각 형식을 사용한다. 모든 관계와 행동을 설명문과 버튼으로 바꾸지 않는다. 시각 요소 수를 채우려고 장식이나 기능을 지어내지 않는다.

요청한 상호작용을 시안에 구현한다. 목록 재정렬에 드래그 앤 드롭이 필요하면 실제 드래그로 순서가 바뀌게 한다. 키보드나 다른 접근성 대안은 이를 보완한다. 텍스트 버튼만으로 그 요구사항을 충족할 수 없다. 모의 구현의 한계와 미연결 백엔드는 대화에서 설명한다. 실제 거래가 성공한 것처럼 꾸미거나 필수 상호작용을 구현하지 않은 이유로 미구현 기능 경고를 붙이지 않는다.

렌더링 전에 [서비스 내용 규칙](#서비스-내용에-집중한-화면)을 적용한다. 실제 HTML을 열어 렌더링된 화면을 확인하고 영향을 받는 상호작용을 실행한다. 파일 생성, 소스 확인이나 도구 응답 성공만으로 외관과 동작이 입증되지는 않는다. 세부 요소보다 전체 화면부터 확인한다.

- 정보 우선순위, 주 행동, 영역 계층과 균형이 시나리오를 뒷받침한다.
- 정렬, 간격, 글자, 밀도, 배경과 패널 표현 및 행동 강조가 같은 기본 규칙을 따른다.
- 해당 분야의 내용이 그럴듯하고 읽을 수 있으며 잘림이나 채우기용 문구가 없다.
- 필요한 상태, 요청한 상호작용과 반응형 조건을 가능한 곳에서 확인한다. 확인할 조건이 없으면 미검증으로 남긴다.
- 구조와 강조에는 시나리오에 따른 이유가 있고 익숙한 조작 요소를 이해할 수 있다.

결함을 고치고 영향을 받는 결과를 확인한다. 고치지 못했거나 반복해도 나아지지 않으면 그 조건은 미완료로 보고하고 다음 행동을 적는다. 파일이나 볼 수 있는 화면을 제공한다. 방향, 모의 구현한 동작과 미검증 조건은 대화에서 설명한다. 의미 있는 선택에는 [비교](decisions.md#선택-요청과-답변-해석)를 읽는다.

렌더링이나 상호작용 확인에 실패하면 사용할 수 없는 기능과 영향을 받는 근거를 밝힌다. 스크린샷은 외관 판단을 뒷받침할 수 있지만 상호작용을 입증하지 않는다. 통과했다고 주장하거나 지정 참고 자료를 말없이 바꾸지 말고 그 검사를 미룬다.

## 서비스 내용에 집중한 화면

실제로 사용할 서비스의 내용, 상태와 조작 요소를 렌더링한다. HTML을 쓰기 전에 표시할 내용과 작성 메모를 구분한다. 시안 소개, 설계 이유, 결정 이력, 작성 또는 구현 과정, 진행 보고와 검토 안내는 대화나 지정한 인수인계 기록에 둔다. 검토 메뉴, 피드백 패널, XPath 복사 도구나 숨겨진 검토 모드를 HTML에 추가하지 않는다.

각 문구를 독자, 의미, 근거와 행동에 미치는 영향으로 판단한다. 서비스 사용에 도움이 되지 않으면 일반적인 면책 문구, 중복 안내, 설명 없는 경고와 이해할 수 없는 표현을 제거한다. 이는 불필요한 AI Caption의 예시이며 모든 금지 표현을 나열한 것은 아니다. 의도한 뜻이 불분명하면 그럴듯한 설명을 지어내지 말고 확인한다.

필요한 이름표, 입력 조건, 실제 진행 상태와 오류 피드백, 복구 안내, 접근성 정보와 필수 고지는 유지한다. 현재 행동과 상태에 맞게 구체적으로 쓴다. 불필요한 문구 예시와 비슷하다는 이유만으로 유용한 안내를 제거하지 않는다. 보고서에는 조사 결과를 이해하는 데 필요한 방법과 근거를 유지한다. 에이전트가 파일을 쓴 과정 자체를 요청하지 않았으면 그 과정 설명은 제외한다.

## 시안 밖에서 요소 선택

대화에서 절차를 설명한다. 개발자 도구가 있는 브라우저로 HTML을 열고 대상 요소를 검사한다. DOM 노드를 선택한 뒤 브라우저의 전체 XPath 복사 명령을 사용한다. Chrome DevTools에서는 Elements의 노드에서 **Copy > Copy full XPath**를 선택한다. 브라우저나 내장 미리보기에 이 명령이 없으면 서비스 화면에 복사 도구를 넣지 말고 적합한 외부 브라우저를 사용한다.

복사한 XPath와 원하는 변경을 대화에 붙여 넣도록 요청한다. 현재 문맥으로 식별할 수 없을 때만 파일이나 필요한 상태를 추가로 받는다. 고정 피드백 양식, 새 서버나 에이전트 자동 연결은 필요하지 않다. [요청 해석](decisions.md#xpath-수정-요청-해석)과 [수정](#복사한-전체-xpath로-수정)으로 이어간다.

## 복사한 전체 XPath로 수정

현재 HTML 파일과 렌더링 상태를 확인한다. 받은 전체 XPath를 실제 DOM, 요소의 내용과 문맥 및 이를 만드는 소스와 대조한다. XPath는 DOM 위치를 가리키며 소스 줄 번호가 아니다. 문법상 유효하다는 사실만으로 의도한 대상이라고 확인되지는 않는다. 구조나 목록 순서가 달라지면 다른 요소를 가리킬 수 있다.

대상이 없거나 모호하거나 요청과 맞지 않으면 그 수정을 멈추고 필요한 현재 노드, 상태나 설명만 받는다. 비슷한 요소를 추정해 고르지 않는다. iframe, Shadow DOM이나 동적으로 만든 노드는 문서 또는 루트와 필요한 상태부터 확인한다. 문서 수준 XPath 하나로 모두 탐색할 수 있다고 약속하지 않는다. 실제 DOM을 확인할 수 없으면 충분한 현재 근거를 받을 때까지 대상을 미검증으로 유지한다.

일치한 요소에 허용된 변경을 적용하고 무관한 확정 동작을 보존한다. 구조가 바뀌면 이전의 위치 기반 XPath를 재확인 없이 재사용하지 않는다. 수정한 화면과 영향받는 동작을 확인한다. 필요한 경우 필수 드래그나 입력 행동도 실행한다.

대화에서 변경 파일, 반영한 요청과 남은 검사를 보고한다. 보려면 파일을 다시 열거나 새로고침하도록 안내한다. 자동 새로고침을 약속하거나 서비스 화면 안에 수정 상태를 표시하지 않는다.

## 검증 조건 정의

승인된 요구사항, 시나리오와 기존 지침에서 대표 대상과 영향받는 상태, 화면 크기, 테마와 언어를 고른다. 전문 용어나 CSS 결정을 요구하지 않고 설명한다. 범위나 방향이 크게 달라지면 [질문 분류](decisions.md#질문-필요-여부-판단)를 따른다.

공통 규칙을 제안할 때는 적용할 수 있는 다른 기존 대상을 확인한다. 없으면 현재 대상만 검증하고 재사용 검증은 미완료로 남긴다.

## 구현에 넘길 자료 준비

현재 변경의 목표, 시나리오, 지원할 행동, 보존할 기능과 구체적으로 바꿀 외관을 다음 내용과 함께 반환한다.

- 설계 논지, 정보 관계, 채택한 전략과 근거 및 제외한 대안
- 적용할 기존 원칙이나 토큰, 기본 규칙, 확정 선택, 예외와 적용 범위
- 잠정값, 미해결 근거나 선택, 적용해서는 안 되는 충돌과 피할 특징
- 기존 재사용 대상을 포함한 [검증 조건](#검증-조건-정의)의 대표 대상과 조건

원칙, 토큰, CSS 변수, 테마나 컴포넌트 사용 규칙 등 필요한 형식으로 제시한다. 기존 지침은 복제하지 말고 참조한다. 별도 허용을 받은 코드 변경 뒤에는 [현재 UI 검증](validation.md#근거와-범위-확인)을 사용한다.
