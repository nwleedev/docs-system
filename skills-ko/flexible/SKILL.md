# 프로젝트 설계

## 프로젝트 문서 관리 방식 파악

1. 현재 레포에 대해서 레포 최상위 기준으로 문서를 탐색한다. 요구사항, 설계, 플랜 등이 어떻게 관리되고 있는지 파악한다. 문서가 없어도 별도의 문서 관련 규칙이 있는지 탐색한다.
1. 레포가 문서를 관리하는 별도의 규칙이 있다면 그 규칙을 준수하여 요구사항, 설계, 계획을 관리한다.
1. 문서 또는 문서에 대한 규칙이 없다면 `docs/designs/README.md` 파일을 생성할 것을 요청할 수 있다. 해당 파일은 프로젝트에 대한 설계를 조율하는 역할이다. README.md 파일을 생성할 땐 `references/_README.md` 파일의 내용을 복사하는 방식이다. README.md 파일을 생성하기 전 `_README.md` 파일의 내용을 전수 파악한다.

## 설계에 필요한 절차 확인

프로젝트의 상세 내용, 현재 상황, 제약 조건, 히스토리를 다양한 수단을 통해 파악한다.

- 작성된 코드 및 Git 히스토리
- 프로젝트 리드미 또는 인수인계 문서
- 프로젝트에서 그동안 관리된 설계 문서

## 요구사항 구체화

요구사항 문서에 대해서 모호한 부분이 있는지 파악합니다. 요구사항 관련 필요한 정보를 리서치하고 결정사항을 구성합니다.

현재 요구사항을 그대로 진행했을 때 여러가지 상황이 발생할 수 있으면 질문한다. 선택지를 제시할 때 각 결정에 따라서 발생할 수 있는 상황을 설명한다.

현재 상황을 파악하기 위해서 프로젝트 내 파일과 외부 자료를 리서치한다. 질문에 대해서 답변을 받았을 때 각 답변마다 진행해야 하는 절차가 달라지면 각 절차에 대해서도 리서치한다.

## 플랜 작성

### 스크립트 활용

스크립트를 통해 요구사항 문서를 생성할 수 있다. `docs/designs/README.md` 파일이 존재하는 상황에서 Node.js 22.0.0 이상으로 아래 스크립트를 실행한다. 해당 스크립트는 스킬 디렉터리 폴더 내에 위치한다. 스크립트를 실행하면 폴더와 내용 없는 요구사항 파일이 생성된다. 내용 작성을 요청했으면 별도로 작성한다.

만약 특정 레포에서 `docs/designs/README.md`에 명시된 요구사항 관리 방식을 사용하지 않는 경우 스크립트를 실행하지 말고 기존에 존재하는 레포 규칙과 위치를 준수한다.

```sh
node scripts/requirements/create.mjs --repo <repository-root> --topic <topic-slug>
```

`--help`를 통해 필요한 인자 및 실패 시 대응 방안을 확인할 수 있다. 기존 문서를 업데이트하기 위해 스크립트를 다시 실행하지 않는다. 조사 및 결정 디렉터리의 경우 해당 파일이 필요한 상황에서만 생성한다. 첨부된 파일 및 프롬프트를 레포에 복사하지 않는다.
